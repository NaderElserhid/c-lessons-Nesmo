الفصل التاسع: Rectangular Geometry (هندسة المستطيلات المحاذية للمحاور)

هذا الفصل يتناول المستطيلات التي تكون أضلاعها موازية لمحوري الإحداثيات (axis-aligned). سنتعلّم كيف نمثّل النقاط والمستطيلات ببُنى (structs) بسيطة، وكيف نحسب المساحة، وكيف نتحقّق من تقاطع مستطيلين ونحسب منطقة التقاطع نفسها — ثم نرى أن كل هذه الأفكار لها نظير أبسط في بُعد واحد (فترات على خط الأعداد)، وننهي بمسألة حقيقية من USACO تطبّق هذه الفكرة الأحادية البعد مباشرة.

هندسة المستطيلات المحاذية للمحاور

تتناول هندسة المستطيلات المحاذية للمحاور المستطيلات التي تكون أضلاعها موازية لمحوري الإحداثيات. يغطّي هذا القسم العمليات الأساسية المستخدمة مع هذا النوع من المستطيلات.

ملحوظة: نفترض طوال هذا الفصل أن محور x الموجب يشير إلى اليمين، وأن محور y الموجب يشير إلى الأعلى — تمامًا كنظام الإحداثيات الرياضي المعتاد.

تمثيل النقاط والمستطيلات

تحتوي النقطة على زوج من الإحداثيات: إحداثي x وإحداثي y. يمكننا تجميعهما معًا في بُنية (struct):

point.cpp
struct Point {
    int x;
    int y;
};

يمكن تمثيل المستطيل المحاذي للمحاور بنقطتيه: أسفل اليسار (bottom-left) وأعلى اليمين (top-right). نجمع هاتين النقطتين في بُنية أخرى:

rectangle.cpp
struct Rectangle {
    Point bottom_left;
    Point top_right;
};

على مدار هذا القسم، نفترض أن كل مستطيل مُطبَّع (normalized)، أي:

  • bottom_left.x ≤ top_right.x
  • bottom_left.y ≤ top_right.y

العرض والارتفاع والمساحة

العرض (width) هو المسافة الأفقية بين الضلعين: width = r.top_right.x - r.bottom_left.x

الارتفاع (height) هو المسافة الرأسية بين الضلعين: height = r.top_right.y - r.bottom_left.y

المساحة (area) هي حاصل ضرب العرض في الارتفاع: area = width * height

area.cpp
int area(Rectangle r) {
    int width = r.top_right.x - r.bottom_left.x;
    int height = r.top_right.y - r.bottom_left.y;
    return width * height;
}

التحقّق من التقاطع (Checking for Intersection)

يتقاطع مستطيلان بمساحة موجبة فقط عندما يتداخل مداهما على محور x وعلى محور y معًا. من الأسهل التحقّق من الحالة المعاكسة (عدم التقاطع).

يكون المستطيلان منفصلين أفقيًا إذا انتهى أحدهما عند أو قبل بداية الآخر. وبالمثل يكونان منفصلين رأسيًا وفق الشرط المقابل على محور y. إذا تحقّق أي انفصال، فالمستطيلان لا يتقاطعان.

rectangles_intersect.cpp
bool rectangles_intersect(Rectangle a, Rectangle b) {
    bool separated_x = a.top_right.x <= b.bottom_left.x ||
        b.top_right.x <= a.bottom_left.x;
    bool separated_y = a.top_right.y <= b.bottom_left.y ||
        b.top_right.y <= a.bottom_left.y;

    return !separated_x && !separated_y;
}

ملحوظة: إذا تلامس مستطيلان عند ضلع أو زاوية فقط، فإن مساحتهما المشتركة تساوي صفرًا، لذلك لا نعتبرهما متقاطعَين — وهذا سبب استخدام <= (وليس <) في شرط الانفصال أعلاه.

مختبر تفاعلي 1: تقاطع مستطيلين

غيّر إحداثيات المستطيلين وشاهد التقاطع يُحسَب فعليًا

المستطيل A (أزرق)
المستطيل B (برتقالي)

المنطقة الخضراء المظلّلة هي مستطيل التقاطع الفعلي المحسوب بواسطة rectangle_intersection — جرّب تحريك المستطيل B بعيدًا (مثلًا bl.x=20) لترى حالة عدم التقاطع.

إيجاد التقاطع (Finding the Intersection)

إذا كان المستطيلان a وb متقاطعين، فإن تقاطعهما هو مستطيل آخر. نقطة أسفل اليسار الخاصة به تستخدم الإحداثي الأكبر بين الحدّين السفليّين على كل محور، بينما نقطة أعلى اليمين تستخدم الإحداثي الأصغر بين الحدّين العلويّين.

rectangle_intersection.cpp
#include <algorithm>
using namespace std;

Rectangle rectangle_intersection(Rectangle a, Rectangle b) {
    Rectangle c;
    c.bottom_left.x = max(a.bottom_left.x, b.bottom_left.x);
    c.bottom_left.y = max(a.bottom_left.y, b.bottom_left.y);
    c.top_right.x = min(a.top_right.x, b.top_right.x);
    c.top_right.y = min(a.top_right.y, b.top_right.y);
    return c;
}

استدعِ rectangle_intersection فقط بعد أن يتأكّد rectangles_intersect من وجود تقاطع فعلي. استدعاؤها على مستطيلين غير متقاطعين سيُنتج "مستطيلًا" ذا عرض أو ارتفاع سالب — أي بيانات لا معنى لها.

نشاط: مراجعة سريعة للمستطيلات

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

مستطيلان يتلامسان عند ضلع واحد فقط (بدون تداخل مساحة) يُعتبران متقاطعين حسب تعريف هذا الفصل.

نقطة أسفل اليسار لمستطيل التقاطع تُحسب بأخذ الحد الأدنى (min) لإحداثيات النقطتين السفليّتين.

المستطيل المُطبَّع (normalized) يحقّق دائمًا bottom_left.x ≤ top_right.x.

الهندسة أحادية البعد (One-Dimensional Geometry)

تنطبق الأفكار نفسها في بُعد واحد، حيث نعمل مع الفترات (intervals) بدلًا من المستطيلات. تحتوي الفترة على طرف أيسر وطرف أيمن:

interval.cpp
struct Interval {
    int left;
    int right;
};

نفترض أن كل فترة مُطبَّعة، أي left ≤ right.

الطول (Length)

طول الفترة هو: length = segment.right - segment.left

length.cpp
int length(Interval segment) {
    return segment.right - segment.left;
}

التحقّق من التقاطع

تتقاطع فترتان بطول موجب ما لم تنتهِ إحداهما عند أو قبل بداية الأخرى:

intervals_intersect.cpp
bool intervals_intersect(Interval a, Interval b) {
    return a.right > b.left && b.right > a.left;
}

كما هو الحال مع المستطيلات، الفترتان اللتان تتشاركان نقطة طرف واحدة فقط لهما تداخل يساوي صفرًا ولا تُعتبران متقاطعتين.

إيجاد التقاطع

إذا تقاطعت الفترتان a وb، فإن تقاطعهما يبدأ عند الطرف الأيسر الأكبر وينتهي عند الطرف الأيمن الأصغر:

interval_intersection.cpp
#include <algorithm>
using namespace std;

Interval interval_intersection(Interval a, Interval b) {
    Interval c;
    c.left = max(a.left, b.left);
    c.right = min(a.right, b.right);
    return c;
}

لاحظ التماثل التام بين المستطيلات والفترات: max على الحدود السفلى/اليسرى، وmin على الحدود العليا/اليمنى — نفس الفكرة تمامًا، لكن بمحور واحد بدل محورين.

مختبر تفاعلي 2: تقاطع الفترات والطول المغطّى الكلي

غيّر الفترتين وشاهد التقاطع والتغطية الكلية تُحسَبان فعليًا

القيم الافتراضية أعلاه (7,10 و4,8) هي بالضبط مثال مسألة Fence Painting بالأسفل — لاحظ أن "الطول المغطّى الكلي" المعروض هنا هو نفسه إجابة تلك المسألة.

مسألة تطبيقية: Fence Painting

USACO 2015 December Contest, Bronze — Problem 1

نتعامل مع السياج كخط أعداد أحادي البعد. يطلي Farmer John الفترة من x=a إلى x=b. أما Bessie فتطلي الفترة من x=c إلى x=d، والتي قد تتداخل جزئيًا أو كليًا مع فترة Farmer John. المطلوب: حساب الطول الكلي للسياج المطليّ الآن (بغضّ النظر عن التداخل).

القيود

  • a < b وc < d

  • كل القيم a, b, c, d ضمن المدى 0 .. 100

مثال

Input (paint.in): 7 10 4 8 Output (paint.out): 6

هنا، 6 وحدات من السياج مغطّاة بالطلاء، من x=4 حتى x=10.

الحل

نجمع طولَي الفترتين، ثم نطرح الطول المشترك بينهما (التداخل). إذا لم تتداخل الفترتان، فإن الطول المشترك يساوي صفرًا:

total = length(a) + length(b) - overlap_length(a, b)
paint.cpp
#include <algorithm>
#include <cstdio>
#include <iostream>
using namespace std;

struct Interval {
    int left;
    int right;
};

int length(Interval segment) {
    return segment.right - segment.left;
}

int overlap_length(Interval a, Interval b) {
    int left = max(a.left, b.left);
    int right = min(a.right, b.right);
    return max(0, right - left);
}

int main() {
    freopen("paint.in", "r", stdin);
    freopen("paint.out", "w", stdout);

    Interval a, b;
    cin >> a.left >> a.right >> b.left >> b.right;

    int total = length(a) + length(b) - overlap_length(a, b);
    cout << total << "\n";
}

تحقّق يدوي مطابق للمثال الرسمي: length(a)=10-7=3، length(b)=8-4=4، التداخل: left=max(7,4)=7، right=min(10,8)=8، فـoverlap=max(0,8-7)=1. المجموع: 3+4-1=6 ✓ مطابق تمامًا للمخرجات الرسمية.

لماذا max(0, right-left) ذكية؟ إن لم تتداخل الفترتان أصلًا، فإن right - left ستكون سالبة (لأن right < left) — والدالة max(0, ...) تحوّل هذه القيمة السالبة تلقائيًا إلى صفر، دون الحاجة لفحص شرط منفصل بـif. هذا أنظف من استدعاء intervals_intersect أولًا ثم التفرّع.

ملحوظة عن الإدخال/الإخراج: مسائل USACO تتطلّب عادةً القراءة من ملف والكتابة إلى ملف (freopen("paint.in", "r", stdin) وfreopen("paint.out", "w", stdout)) بدلًا من الإدخال/الإخراج القياسي المباشر — تأكّد دائمًا من التحقّق من صيغة الإدخال/الإخراج المطلوبة قبل إرسال حلّك.

مختبر تفاعلي 3: احسب طول السياج المطليّ لأي مدخلات

أدخل a, b, c, d (وفق قيود المسألة: كل قيمة بين 0 و100)

اضغط "احسب الطول الكلي".

نقاط يجب الانتباه لها

التلامس ليس تقاطعًااستخدام <= في شرط الانفصال (وليس <) يضمن أن المستطيلات/الفترات المتلامسة فقط عند حافة واحدة تُعتبر غير متقاطعة، لأن مساحتها/طولها المشترك صفر بالفعل.
لا تستدعِ دالة التقاطع بلا تحقّقrectangle_intersection وinterval_intersection تفترضان أن التقاطع موجود بالفعل — استدعاؤهما على أشكال غير متقاطعة يُنتج نتائج بلا معنى (عرض أو طول سالب).
افتراض التطبيع (normalization)كل الدوال في هذا الفصل تفترض أن bottom_left ≤ top_right (أو left ≤ right) مسبقًا؛ إن كانت بياناتك غير مُطبَّعة، طبّعها أولًا (بمقارنة/تبديل الإحداثيات) قبل استخدام هذه الدوال.
overlap_length مع max(0, ...)في حل Fence Painting تحديدًا، استخدام max(0, right-left) يجعل الكود يعمل بشكل صحيح دائمًا دون الحاجة لفحص التقاطع بشكل منفصل أولًا.

نشاط: مراجعة سريعة للفترات ومسألة Fence Painting

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

في حل Fence Painting، إن لم تتداخل الفترتان إطلاقًا، فإن overlap_length تُعيد صفرًا.

الفترتان اللتان تتشاركان نقطة طرف واحدة بالضبط (مثل [2,5] و[5,9]) تُعتبران متقاطعتين حسب intervals_intersect.

الصيغة العامة للتغطية الكلية لفترتين هي: طول الأولى + طول الثانية - طول التداخل بينهما.

خلاصة سريعة

المستطيل المحاذي للمحاور يُمثَّل بنقطتَي أسفل اليسار وأعلى اليمين، مع افتراض التطبيع دائمًا.
المساحة = العرض × الارتفاع.
عدم التقاطع أسهل للفحص من التقاطع: يكفي انفصال واحد (أفقي أو رأسي) لعدم وجود تقاطع.
مستطيل التقاطع: max على الحدود السفلى، min على الحدود العليا — بشرط التأكّد من وجود تقاطع أولًا.
نفس الأفكار تنطبق على الفترات في بُعد واحد، وتُستخدم في حساب "الطول المغطّى الكلي" عبر: length(a)+length(b)-overlap(a,b).

تمارين منزلية

1) تقاطع مستطيلين يدويًا

مستطيل A: bottom_left=(0,0), top_right=(6,6). مستطيل B: bottom_left=(4,2), top_right=(10,5). هل يتقاطعان؟ إن كان الجواب نعم، احسب مستطيل التقاطع ومساحته.

separated_x: 6≤4؟ لا، 10≤0؟ لا → غير منفصلين أفقيًا. separated_y: 6≤2؟ لا، 5≤0؟ لا → غير منفصلين رأسيًا. إذًا يتقاطعان.

bottom_left = (max(0,4), max(0,2)) = (4, 2) top_right = (min(6,10), min(6,5)) = (6, 5) width = 2, height = 3 area = 6

2) مستطيلان متلامسان فقط

مستطيل A: (0,0)-(5,5). مستطيل B: (5,0)-(9,5). هل يتقاطعان حسب تعريف هذا الفصل؟ فسّر لماذا.

لا يتقاطعان. separated_x = (a.top_right.x=5 ≤ b.bottom_left.x=5) → صحيح (5≤5)، إذًا separated_x = true بغضّ النظر عن قيمة separated_y. المستطيلان يتلامسان تمامًا عند الضلع الرأسي x=5 فقط، ومساحتهما المشتركة صفر، لذا لا يُعتبران متقاطعين.

3) طول التغطية الكلي لثلاث حالات فترات

احسب الطول الكلي المغطّى (بنفس منطق Fence Painting) للحالات التالية: (أ) a=[0,5], b=[10,15] (منفصلتان تمامًا). (ب) a=[0,10], b=[3,7] (فترة B بالكامل داخل A). (ج) a=[2,6], b=[6,9] (تتلامسان عند نقطة واحدة فقط).

(أ) length=5+5, overlap=max(0, min(5,15)-max(0,10))=max(0,-5)=0 → total = 10 (ب) length=10+4, overlap=max(0, min(10,7)-max(0,3))=max(0,4)=4 → total = 10 (B بالكامل داخل A فلا يضيف شيئًا) (ج) length=4+3, overlap=max(0, min(6,9)-max(2,6))=max(0,0)=0 → total = 7

الحالة (ب) توضّح لماذا الصيغة العامة (وليس فقط "الجمع البسيط") ضرورية: فترة محتواة بالكامل داخل أخرى لا تضيف أي طول جديد للتغطية.

تحقق من فهمك

١. ما شرط كون المستطيل "مُطبَّعًا" (normalized)؟

لأنه يكفي انفصال واحد (أفقي أو رأسي) لإثبات عدم التقاطع، وهذا أبسط منطقيًا من فحص التداخل على المحورين معًا مباشرة

قاموس المصطلحات

Axis-alignedمحاذٍ للمحاور

شكل هندسي (مستطيل هنا) تكون أضلاعه موازية تمامًا لمحوري الإحداثيات، دون أي ميل أو دوران.

Normalizedمُطبَّع

افتراض أن النقطة الدنيا تأتي فعليًا قبل النقطة العليا في كل إحداثي (bottom_left ≤ top_right، أو left ≤ right للفترات).

Bounding Boxالصندوق المحيط
