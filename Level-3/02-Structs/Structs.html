الفصل الثاني: الهياكل (struct)

حتى الآن كنت تخزّن كل معلومة في متغيّر منفصل. لكن ماذا لو أردت تجميع عدة معلومات مرتبطة ببعضها — مثل وزن وسعر منتج — تحت اسم واحد؟ في هذا الفصل ستتعلّم كيف تصمّم نوع بيانات خاصًّا بك باستخدام struct، وهي لبنة أساسية ستحتاجها كثيرًا في المسائل الأكبر القادمة.

ما هي البنية struct؟

في لغة ++C تسمح لك البنية (struct) بتجميع عدة أجزاء من البيانات تحت اسم واحد. يمكنك التفكير فيها كنوع بيانات مخصّص تقوم أنت بتصميمه بنفسك.

البنية struct تجمع مجموعة من المتغيرات ذات العلاقة (تسمّى أعضاء أو members) وقد تكون من أنواع مختلفة داخل نفس الكيان.

الصيغة العامة

struct_syntax.cpp
struct TypeName {
    member_type1 member_name1;
    member_type2 member_name2;
    // ...
};

  • TypeName → اسم نوع البيانات الجديد الذي تعرّفه.

  • داخل الأقواس المعقوفة { } → الأعضاء (members)، وهي المتغيرات التي تنتمي لهذا النوع.

لاحظ الفاصلة المنقوطة ; بعد القوس المعقوف الأخير } — نسيانها من أشهر الأخطاء عند كتابة struct لأول مرة، وسنرى رسالة الخطأ الفعلية لاحقًا في هذا الفصل.

مثال: بنية product

product.cpp
#include <iostream>
using namespace std;

struct product {
    int weight;     // in grams
    double price;   // in riyals
};

int main() {
    product apple;
    product banana, melon;

    apple.weight = 150;
    apple.price  = 1.99;

    banana.weight = 120;
    banana.price  = 0.99;

    cout << "Apple: "  << apple.weight  << " g, " << apple.price << " SAR" << endl;
    cout << "Banana: " << banana.weight << " g, " << banana.price << " SAR" << endl;
}

في هذا المثال:

  • عرّفنا نوعًا جديدًا اسمه product.

  • هذا النوع يحتوي عضوين: weight من نوع int يمثّل الوزن بالجرام، وprice من نوع double يمثّل السعر بالريال.

  • بعدها أنشأنا متغيّرات (كائنات) من هذا النوع: apple، banana، وmelon، وأعطينا كلًا منها قيمًا خاصة به.

Apple: 150 g, 1.99 SAR Banana: 120 g, 0.99 SAR

مختبر تفاعلي: شاهد البرنامج ينفَّذ سطرًا بسطر

شغّل المحاكاة لمشاهدة كيف يُنشئ البرنامج ثلاثة كائنات من نوع product، ويملأ أعضاء اثنين منها فقط، ثم يطبعهما.

الوصول إلى الأعضاء (Member Access)

نستخدم عامل النقطة . للوصول إلى أعضاء الكائن:

  • apple.weight → عضو من نوع int

  • apple.price → عضو من نوع double

يمكنك القراءة من هذه الأعضاء أو التعديل عليها مثل أي متغير عادي تمامًا.

تعريف كائنات مباشرة بعد تعريف البنية

يمكنك أيضًا تعريف المتغيرات في نهاية تعريف البنية مباشرة:

product_inline.cpp
struct product {
    int weight;
    double price;
} apple, banana, melon;

هنا: product هو اسم النوع (البنية)، وapple، banana، melon هي متغيرات (كائنات) من هذا النوع — تمامًا كما لو كتبتها في سطر منفصل بعد تعريف البنية.

نشاط: مراجعة سريعة لتعريف البنية والوصول لأعضائها

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

البنية struct تسمح بتجميع متغيرات من أنواع مختلفة تحت اسم واحد.

للوصول إلى عضو weight في الكائن apple، نكتب apple-weight.

يجب وضع فاصلة منقوطة ; بعد القوس المعقوف الأخير في تعريف struct.

كل كائن من نوع product (مثل apple وbanana) له نسخته الخاصة من الأعضاء weight وprice.

لماذا نستخدم structs؟

بدون struct، سنضطر لتخزين كل معلومة عن كل منتج في متغيّرات منفصلة تمامًا، مما يصبح فوضويًا بسرعة مع زيادة عدد المنتجات أو عدد الخصائص:

بدون structمع struct
int appleWeight; double applePrice;
int bananaWeight; double bananaPrice;		product apple; product banana;
متغيّران منفصلان لكل منتج، ولا رابط واضح بينهما في الكودكائن واحد يجمع كل خصائص المنتج، والعلاقة واضحة فورًا

الفكرة الأساسية: struct يجعل الكود أقرب لطريقة تفكيرنا — بدلًا من "وزن التفاحة" و"سعر التفاحة" كمتغيّرين منفصلين، نفكّر في "التفاحة" ككائن واحد له خصائص.

أخطاء شائعة

نسيان الفاصلة المنقوطة بعد تعريف البنية: هذا الكود يفشل في الترجمة:

missing_semicolon.cpp
struct product {
    int weight;
    double price;
}  // نسينا ; هنا!

int main() {
    return 0;
}
error: expected ';' after struct definition

الاعتماد على أعضاء لم تُهيَّأ (uninitialized): في مثال product أعلاه، الكائن melon أُنشئ لكن لم نُسند لأعضائه أي قيمة أبدًا. لو حاولنا طباعة melon.weight الآن، سنحصل على قيمة عشوائية غير متوقّعة (garbage value) موجودة مسبقًا في الذاكرة — وليس صفرًا بالضرورة.

دائمًا تأكّد من إسناد قيمة لكل عضو قبل استخدامه، تمامًا كما تفعل مع أي متغيّر عادي.

الخلط بين اسم النوع واسم المتغيّر: product هو اسم النوع (القالب)، بينما apple هو متغيّر (كائن) فعلي من هذا النوع. لا يمكنك كتابة product.weight مباشرة — فـ product نفسه ليس كائنًا، بل هو النوع الذي تُبنى منه الكائنات.

نشاط: مراجعة سريعة للأخطاء الشائعة والفوائد

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

نسيان الفاصلة المنقوطة بعد تعريف struct لا يسبّب أي مشكلة في الترجمة.

الكائن الذي لا نُسند لأعضائه أي قيمة يحتوي على قيم عشوائية غير متوقّعة.

يمكن كتابة product.weight للوصول إلى عضو دون إنشاء كائن أولًا، لأن product نوع بيانات.

استخدام struct يجعل تجميع البيانات المرتبطة أوضح مقارنة بمتغيّرات منفصلة.

خلاصة سريعة

struct تجمع عدة متغيّرات (أعضاء) من أنواع مختلفة تحت اسم نوع واحد تصمّمه بنفسك.
نصل لأعضاء الكائن بعامل النقطة . مثل apple.weight.
يمكن تعريف الكائنات في سطر منفصل، أو مباشرة بعد تعريف البنية.
لا تنسَ الفاصلة المنقوطة بعد }، وتأكّد دائمًا من تهيئة كل الأعضاء قبل استخدامها.

تمارين منزلية

1) بنية Student

عرّف بنية Student تحتوي على name (نص/string)، age (عدد صحيح)، وgpa (عدد عشري). أنشئ كائنًا باسم student1 بالقيم: الاسم "Sara"، العمر 17، المعدّل 3.8، ثم اطبعها بصيغة: الاسم, العمر years old, GPA: المعدل.

student.cpp
#include <iostream>
#include <string>
using namespace std;

struct Student {
    string name;
    int age;
    double gpa;
};

int main() {
    Student student1;
    student1.name = "Sara";
    student1.age = 17;
    student1.gpa = 3.8;

    cout << student1.name << ", " << student1.age
         << " years old, GPA: " << student1.gpa << endl;
}
Sara, 17 years old, GPA: 3.8

2) اكتشف الخطأ

ما الخطأ في هذا الكود، وما رسالة الخطأ التي سيعطيها المترجم تقريبًا؟

find_error.cpp
struct Point {
    int x;
    int y;
}

int main() {
    Point p;
    p.x = 3;
    p.y = 4;
    cout << p.x << " " << p.y << endl;
}

ينقص الكود فاصلة منقوطة ; بعد القوس المعقوف الأخير } في تعريف struct Point.

error: expected ';' after struct definition

الإصلاح: أضف ; مباشرة بعد } التي تغلق تعريف البنية.

3) تتبّع البرنامج (Trace)

بدون تشغيل الكود، حدّد ما الذي ستطبعه السطور الأخيرة:

trace_item.cpp
struct Item {
    int id;
    double cost;
};

int main() {
    Item a, b;
    a.id = 1;
    a.cost = 10.5;
    b.id = 2;
    b.cost = 20.0;

    a.cost = b.cost + 5;

    cout << a.id << " " << a.cost << "\n";
    cout << b.id << " " << b.cost << "\n";
}

السطر a.cost = b.cost + 5; يغيّر فقط عضو cost في الكائن a (يصبح 20.0 + 5 = 25)، ولا يؤثر إطلاقًا على الكائن b — فكل كائن له نسخته المستقلة من الأعضاء.

1 25 2 20

متغيّر يخزّن قيمة عددية
اسم نوع بيانات جديد نصمّمه بأنفسنا

٣. كيف نصل إلى عضو weight في الكائن apple؟

apple->weight فقط

٤. ماذا ينقص هذا الكود ليكون صحيحًا؟ struct Point { int x; int y; }

قوس معقوف إضافي {

٥. في مثال product، الكائن melon أُنشئ لكن لم تُسند لأعضائه أي قيمة. ماذا يحدث لو طُبعت أعضاؤه؟

تكون دائمًا صفرًا تلقائيًا
تحتوي على قيم عشوائية غير متوقّعة (garbage values)
يرفض المترجم تصريف البرنامج

٦. أيّ الطرق التالية تُعرّف كائنات مباشرة بعد تعريف البنية؟

apple = new struct product();

٧. إذا كان لدينا Item a, b; وغيّرنا a.cost فقط، ماذا يحدث لـ b.cost؟

يتغيّر بنفس القيمة تلقائيًا
يبقى دون تغيير، لأن لكل كائن نسخته الخاصة من الأعضاء
يصبح صفرًا

٨. ما الفائدة الأساسية لاستخدام struct بدل متغيّرات منفصلة لكل خاصية؟

تجميع البيانات المرتبطة منطقيًا، مما يجعل الكود أوضح وأسهل للتوسّع
جعل البرنامج يعمل أسرع دائمًا
التخلّص من الحاجة لأنواع بيانات مثل int وdouble

٩. هل يمكن أن تحتوي البنية الواحدة على أعضاء من أنواع مختلفة (مثل int وdouble معًا)؟

نعم، هذا بالضبط أحد أهم فوائد struct
لا، كل الأعضاء يجب أن تكون من نفس النوع
فقط إذا استخدمنا الكلمة المفتاحية class بدلًا من struct

١٠. لماذا نكتب product apple; بدلًا من product.apple;؟

لأن product اسم نوع وليس كائنًا، وapple هو الكائن الذي ننشئه من هذا النوع
لأن الصيغتين متكافئتان تمامًا في ++C
لأن apple اسم عضو داخل product

قاموس المصطلحات

structالبنية

كلمة مفتاحية في ++C تُستخدم لتعريف نوع بيانات جديد يجمع عدة أعضاء تحت اسم واحد.

Memberعضو

متغيّر يقع داخل تعريف البنية، وينتمي لكل كائن يُنشأ من هذا النوع.

Object / Instanceكائن

متغيّر فعلي يُنشأ من نوع البنية، ويملك نسخته الخاصة من كل الأعضاء.

Dot Operator (.)عامل النقطة

الرمز المستخدم للوصول إلى عضو داخل كائن، مثل apple.weight.

Type Definitionتعريف النوع

وصف بنية البيانات (أسماء وأنواع الأعضاء) الذي يُبنى عليه كل كائن لاحقًا.

Uninitializedغير مُهيَّأ

وصف لعضو أو متغيّر لم يُسند له أي قيمة بعد، فيحمل قيمة عشوائية من الذاكرة.
