Bit Strings (سلاسل البتّات)

مسألة عدّ بسيطة جدًا في جوهرها الرياضي (قاعدة الضرب)، لكنها تعلّمنا درسًا أهم بكثير: كيف نتعامل مع إجابة رقمية هائلة الحجم عبر الحساب بالباقي (modulo) خطوة بخطوة، بدل محاولة حساب رقم فلكي الحجم مباشرة.

Easy CSES 1617

نص المسألة

المطلوب حساب عدد سلاسل البتّات (bit strings) التي طولها n. سلسلة البتّات هي متتالية من n رمزًا، كل رمز إمّا 0 أو 1.

مثلًا لو n = 3، فسلاسل البتّات الممكنة هي: 000, 001, 010, 011, 100, 101, 110, 111 — أي 8 سلاسل.

القيود

  • 1 ≤ n ≤ 10⁶

الإدخال والمخرجات

سطر واحد يحتوي n. اطبع الناتج باقي قسمته على 10⁹+7 (لأن الناتج الحقيقي قد يكون ضخمًا جدًا لا يتّسع لأي نوع بيانات اعتيادي).

مثال

Input: 3 Output: 8

فكرة الحل: قاعدة الضرب

  • لكل موقع من مواقع السلسلة الـn، يوجد اختياران مستقلّان تمامًا عن بقية المواقع: 0 أو 1.

  • بقاعدة الضرب (Rule of Product) في التعداد: إن كان لديك n قرارًا مستقلًا، كل واحد منها له عدد ثابت من الخيارات، فعدد التوليفات الكلي هو حاصل ضرب عدد الخيارات في كل قرار.

  • هنا: 2 × 2 × ... × 2 (بتكرار n مرة) = 2ⁿ.

  • المشكلة: 2¹₀₀₀₀₀₀ رقم ضخم جدًا (أكبر بكثير من أي نوع بيانات صحيح اعتيادي مهما كان). الحل: نحسب الباقي على 10⁹+7 في كل خطوة من خطوات الضرب، بدلًا من حساب الرقم كاملًا ثم أخذ الباقي في النهاية.

هذا هو مبدأ الحساب المقياسي (Modular Arithmetic) الذي رأيناه سابقًا: (a × b) mod M = ((a mod M) × (b mod M)) mod M. لهذا يمكننا تطبيق mod M بعد كل عملية ضرب صغيرة دون أن يتغيّر الناتج النهائي.

مختبر تفاعلي 1: خطوة بخطوة (n صغيرة)

شاهد كل عملية ضرب ومعها الباقي على 10⁹+7

اضغط "الخطوة التالية" أو "تشغيل تلقائي" للبدء.

مختبر تفاعلي 2: جرّب n كبيرة (حتى 10⁶)

الحلقة الحقيقية تُشغَّل فعليًا هنا، بغض النظر عن حجم n

اضغط "احسب مباشرة".

حتى مع n = 10⁶، الحلقة تنفّذ مليون عملية ضرب وباقي قسمة فقط — وهذا سريع جدًا لأي حاسوب حديث (تعقيد O(n))، على عكس محاولة تخزين الرقم 2ⁿ الفعلي الذي يحتاج مئات الآلاف من الخانات العشرية.

الحل الكامل

bit_strings.cpp
#include <iostream>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> n;

    long long ans = 1;
    for (long long i = 0; i < n; i++) {
        ans = (ans * 2) % MOD;
    }

    cout << ans << "\n";
    return 0;
}

ملحوظة للمستقبل: حلقة O(n) كافية تمامًا هنا لأن n ≤ 10⁶. لكن لو كانت المسألة تسمح بـn حتى 10¹⁸ مثلًا، فحلقة مليار مليار تكرار مستحيلة زمنيًا؛ عندها نحتاج الأس السريع (Fast/Binary Exponentiation) لحساب 2ⁿ mod M بتعقيد O(log n) بدلًا من O(n).

الدرس الأهم هنا ليس "كيف نحسب 2ⁿ" — بل: كلما رأيت طلبًا لإخراج الناتج "باقي قسمته على رقم كبير"، فهذا إشارة واضحة أن الناتج الحقيقي أكبر من أن يُخزَّن بأي نوع بيانات، ويجب تطبيق الباقي بعد كل عملية حسابية وسيطة، لا في النهاية فقط.
