المسألة 5: Subordinates (عدد المرؤوسين)

في كل مسائل البرمجة الديناميكية التي حللناها حتى الآن (Frog 1، Knapsack 1)، كانت حالة dp[i] مرتبطة بموقع في مصفوفة نتحرك خلاله بترتيب خطي واضح من البداية للنهاية. هذه المسألة تُظهر أن نفس فكرة "ابنِ الحل من حلول أصغر" تعمل أيضًا فوق شجرة — فقط "ترتيب الحساب" يتغيّر من تسلسل خطي إلى ترتيب post-order عبر DFS: احسب كل الأبناء أولًا، ثم الأب.

Easy CSES 1674 — Tree Algorithms

نص المسألة

لدى شركة n موظفًا مرقّمين من 1 إلى n. الموظف رقم 1 هو المدير العام. لكل موظف من 2 إلى n، تُعطى هويّة رئيسه المباشر — وهذا يبني هيكلًا هرميًا (شجرة) للشركة، حيث يمكن أن يكون لدى الرئيس عدد أبناء مباشرين متعدد.

المطلوب: لكل موظف من 1 إلى n، احسب عدد مرؤوسيه الكلي (المباشرين وغير المباشرين معًا).

القيود

  • 1 ≤ n ≤ 2·10⁵

الإدخال

السطر الأول: عدد صحيح n.
السطر الثاني: n-1 عددًا صحيحًا p2 p3 ... pn، حيث pi هو الرئيس المباشر للموظف i.

المخرجات

اطبع n عددًا صحيحًا: لكل موظف من 1 إلى n، عدد مرؤوسيه الكلي.

مثال

Input: 5 1 1 2 3 Output: 4 1 1 0 0

رئيس 2 هو 1، رئيس 3 هو 1، رئيس 4 هو 2، رئيس 5 هو 3. المدير 1 لديه 4 مرؤوسين (الجميع)، 2 لديه 1 (فقط 4)، 3 لديه 1 (فقط 5)، و4، 5 ورقتان بلا مرؤوسين.

مختبر تفاعلي: احسب أحجام الشجرة الفرعية بترتيب Post-Order

هذه هي شجرة المثال الرسمي بالضبط. شغّل المحاكاة لمشاهدة الخوارزمية الحقيقية تعالج الموظفين واحدًا تلو الآخر بترتيب post-order فعلي (كل الأبناء يُحسبون قبل أبيهم دائمًا)، وتحسب s[v] = عدد مرؤوسي كل موظف تدريجيًا:

هيكل الشركة (5 موظفين)

اضغط "الخطوة التالية" أو "تشغيل تلقائي" لبدء الحساب.

لاحظ أن الترتيب الذي تُعالَج به العقد ليس بالضرورة 1, 2, 3, 4, 5 — الترتيب الوحيد المهم هو أن كل عقدة تُعالَج بعد كل أبنائها المباشرين، بغض النظر عن ترقيمها.

كيف نبني على فكرة DP التي نعرفها؟

  • عرّف الحالة: size[v] = عدد الموظفين في الشجرة الفرعية المتجذّرة عند v، شاملًا v نفسه.

  • العلاقة العودية: size[v] = 1 + مجموع size[child] لكل الأبناء المباشرين لـv — تمامًا بنفس روح dp[i] = دمج (dp[الحالات السابقة]) التي رأيناها في Frog 1، لكن "الحالات السابقة" هنا هي الأبناء في الشجرة، وليست i-1 وi-2.

  • الحالة الأساسية: الأوراق (موظفون بلا مرؤوسين مباشرين) لها size[v] = 1 (هم أنفسهم فقط).

  • ترتيب الحساب: بما أن حساب size[v] يحتاج قيم كل الأبناء جاهزة أولًا، يجب معالجة الشجرة بترتيب post-order (DFS يعالج الأبناء قبل الأب) — لا يوجد "من اليسار لليمين" هنا كما في المصفوفة، لكن المبدأ نفسه: لا تحسب حالة قبل أن تكون كل الحالات التي تعتمد عليها جاهزة.

  • الإجابة النهائية: عدد مرؤوسي v = size[v] - 1 (نطرح v نفسه، لأنه ليس مرؤوسًا لنفسه).

تحليل التعقيد

كل موظف يُعالَج مرة واحدة بالضبط في DFS، وكل حافة (رئيس←ابن) تُستخدم مرة واحدة عند بناء قائمة الأبناء.

الزمن = O(n) , الذاكرة = O(n)

الحل الكامل

subordinates.cpp
#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> children;
vector<long long> subCount;

void dfs(int v) {
    long long total = 0;

    // احسب كل الأبناء أولًا (post-order)
    for (int c : children[v]) {
        dfs(c);
        total += subCount[c] + 1;   // الابن نفسه + كل مرؤوسيه
    }

    subCount[v] = total;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    children.assign(n + 1, {});
    for (int i = 2; i <= n; i++) {
        int p;
        cin >> p;
        children[p].push_back(i);
    }

    subCount.assign(n + 1, 0);
    dfs(1);

    for (int i = 1; i <= n; i++) {
        cout << subCount[i] << (i < n ? ' ' : '\n');
    }
    return 0;
}

تحقّقنا يدويًا من هذا الكود على المثال الرسمي بالكامل: dfs(1) تستدعي dfs(2) وترجع 1 (لأن 2 لديها ابن واحد هو 4)، وdfs(3) ترجع 1 بالمثل، فيصبح subCount[1] = (1+1) + (1+1) = 4 — مطابق تمامًا للناتج الرسمي 4 1 1 0 0.

نقاط يجب الانتباه لها

عمق الاستدعاء المتكررإن كانت الشركة سلسلة طويلة (كل موظف رئيس لموظف واحد فقط)، فقد يصل عمق dfs التكراري إلى 2·10⁵ مستوى — نفس المشكلة التي ناقشناها في Frog 1، لكن بحجم أكبر بكثير هنا. الحل الأضمن عند مواجهة هذه المشكلة عمليًا: DFS تكراري بمكدّس يدوي بدلًا من الاستدعاء الذاتي.
طباعة كل الـ n قيمةيجب طباعة عدد مرؤوسي كل موظف من 1 إلى n، بما في ذلك المدير العام والأوراق (قيمتها 0) — وليس فقط من لديه مرؤوسون فعليًا.
لا حاجة لـ long long فعليًاأكبر قيمة ممكنة للنتيجة هي n-1 ≤ 2·10⁵-1، تدخل بارتياح في int. استُخدم long long في الكود أعلاه كعادة أمان لا أكثر.
ترتيب الأبناء لا يهمالعملية جمع تراكمي بحت (commutative)، فلا يهم بأي ترتيب نُعالج الأبناء داخل الحلقة.

هذا هو أبسط شكل ممكن لما يُسمّى Tree DP: حالة واحدة فقط لكل عقدة، تُحسَب تراكميًا من الأبناء. في كل مرة تقابل مسألة تسأل عن معلومة مرتبطة بـ"كل ما تحت هذه العقدة في شجرة" (حجم، مجموع، عدد أوراق...)، فكّر مباشرة بنفس القالب: عرّف الحالة، اكتب علاقتها بالأبناء، واحسبها بترتيب post-order عبر DFS.
