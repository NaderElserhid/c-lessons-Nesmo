المسألة 2: Knapsack 1 (مسألة الحقيبة)

تعلّم كيف تختار أفضل مجموعة من العناصر بحيث تحصل على أعلى قيمة ممكنة دون تجاوز سعة الحقيبة. هذه أول مسألة نرى فيها حالة DP بـبُعدين بدلًا من بُعد واحد — لكن الفكرة الأساسية (خذ أو لا تأخذ) مألوفة تمامًا من فصل البرمجة الديناميكية.

Medium AtCoder DP Contest — D

نص المسألة

لديك حقيبة سعتها W كيلوغرام، وN عنصر. كل عنصر i له وزن wᵢ (كم يزن) وقيمة vᵢ (كم يساوي).

الهدف: اختر مجموعة جزئية من العناصر بحيث:

مجموع الأوزان ≤ W  &  مجموع القيم → أكبر قيمة ممكنة

كل عنصر يمكن أخذه مرة واحدة فقط (لهذا تُسمّى هذه النسخة 0/1 Knapsack) — على عكس بعض نسخ هذه المسألة التي تسمح بأخذ نفس العنصر أكثر من مرة.

القيود

  • 1 ≤ N ≤ 100

  • 1 ≤ W ≤ 100,000

  • 1 ≤ wᵢ ≤ W

  • 1 ≤ vᵢ ≤ 10⁹

الإدخال

السطر الأول: عددان N وW. ثم N سطر، كل سطر يحتوي wᵢ وvᵢ للعنصر i.

مثال 1

Input: 3 8 3 30 4 50 5 60 Output: 90

نختار العنصرين 1 و3: الوزن 3+5=8، والقيمة 30+60=90.

مثال 2 — احذر الفيضان!

Input: 5 5 1 1000000000 1 1000000000 1 1000000000 1 1000000000 1 1000000000 Output: 5000000000

الإجابة هنا 5,000,000,000 — وهذا يتجاوز أكبر قيمة يمكن أن يخزّنها int (32-بت) بكثير! هذا المثال الرسمي من AtCoder موجود خصيصًا لتذكيرك بضرورة استخدام long long.

المحاكاة التفاعلية: شاهد الخوارزمية تعمل

جدول dp[i][j] — الصفوف = العناصر، الأعمدة = السعة المتبقية j

الخلية الحالية مصدر الانتقال محسوبة
اضغط "الخطوة التالية" أو "تشغيل تلقائي" للبدء.

كيف نفكّر في الحل؟ (SRTBOT)

S — تعريف الحالة

dp[i][j] = أكبر قيمة ممكنة بالنظر إلى العناصر من 0 حتى i، بسعة j

أي: ماذا لو أن معنا فقط أول i+1 عنصر، وحقيبتنا سعتها j؟ لاحظ أن الحالة هنا تحتاج بُعدين (i وj) بدلًا من بُعد واحد كما في فيبوناتشي أو Frog 1 — لأن القرار عند كل عنصر يعتمد على كمّ السعة المتبقية فعليًا، وليس فقط على "أين نحن".

R — العلاقة العودية (الانتقال)

عند النظر في العنصر i، لدينا خياران فقط:

  • لا نأخذ العنصر i: dp[i][j] = dp[i-1][j] — القيمة تساوي ما حصلنا عليه من العناصر السابقة بنفس السعة بالضبط.

  • نأخذ العنصر i (فقط إذا j ≥ wᵢ): dp[i][j] = dp[i-1][j-wᵢ] + vᵢ — نضيف قيمته، ونخصم وزنه من السعة قبل النظر للعناصر السابقة.

نأخذ الأكبر بين الخيارين:

dp[i][j] = max( dp[i-1][j] , dp[i-1][j-wᵢ] + vᵢ )

B — الحالة الأساسية

مفهوميًا: dp[-1][j] = 0 لكل j (قبل النظر في أي عنصر، القيمة صفر دائمًا). بما أن المصفوفات في ++C لا تقبل فهرسًا سالبًا، نعالج العنصر الأول (i=0) كحالة خاصة منفصلة في الكود، بدلًا من الاعتماد فعليًا على صفّ i=-1.

O — ترتيب الحساب

نحسب صفًّا كاملًا (كل قيم j) للعنصر i قبل الانتقال للعنصر i+1، لأن كل خلية في الصف i تعتمد فقط على خلايا الصف i-1 (السابق مباشرة)، وليس على خلايا في نفس الصف.

T — التعقيد الزمني والمكاني

  • الزمن: عدد الحالات هو N × W، وكل حالة تُحسب بزمن O(1) → المجموع O(N × W).

  • الذاكرة: نخزّن جدولًا بحجم N × W → O(N × W).

خطوات بناء الحل

  • تعريف مصفوفة dp: نعرّف dp[i][j] بأنها أكبر قيمة يمكن تحقيقها باستخدام أول i+1 عناصر وسعة j.

  • تهيئة المصفوفة بـ -1: نستخدم -1 كقيمة افتراضية للتمييز بين الخلايا المحسوبة وغير المحسوبة (Memoization).

  • معالجة الحالة الأساسية (i = 0): إذا كانت السعة تكفي لأخذ العنصر الأول، نعيد قيمته، وإلا نعيد صفرًا.

  • تطبيق الانتقال الرئيسي: لكل عنصر i وسعة j: نحسب الحالتين (أخذ / عدم أخذ) ونختار الأكبر.

  • استخراج النتيجة: الإجابة هي f(n-1, W) — أي أفضل قيمة باستخدام كل العناصر وكامل السعة.

المتغيرات العامة

knapsack.cpp
long long dp[200][200000];
int v[200], w[200];

  • dp[i][j] — مصفوفة ثنائية الأبعاد تحفظ أفضل قيمة للعناصر من 0 إلى i بسعة j.

  • نستخدم long long لأن القيم قد تصل إلى N × 10⁹ = 10¹¹، مما يتجاوز int العادي بكثير.

  • v[] وw[] تخزنان القيم والأوزان لكل عنصر.

الدالة الرئيسية (Recursive + Memoization)

knapsack.cpp
long long f(int i, int capacity) {
    // الحالة الأساسية: العنصر الأول فقط
    if (i == 0) {
        if (capacity < w[i]) return 0;
        else                 return v[i];
    }
    // إذا سبق حساب هذه الحالة، أعدها مباشرة
    if (dp[i][capacity] != -1) return dp[i][capacity];

    // لا نأخذ العنصر i
    dp[i][capacity] = f(i - 1, capacity);

    // نأخذ العنصر i (إذا وزنه لا يتجاوز السعة)
    if (capacity >= w[i]) {
        dp[i][capacity] = max(dp[i][capacity],
                              f(i - 1, capacity - w[i]) + v[i]);
    }
    return dp[i][capacity];
}

كيف تعمل الدالة؟

  • الحالة الأساسية: إذا وصلنا للعنصر الأول، نتحقق هل يمكن أخذه أم لا.

  • Memoization: إذا حسبنا dp[i][capacity] من قبل، نعيده مباشرة بدلًا من إعادة الحساب — هذا ما يوفّر الوقت!

  • الانتقال: نحسب حالة "عدم الأخذ" أولًا، ثم إذا كان الوزن يسمح، نحسب حالة "الأخذ" ونأخذ الأكبر.

الدالة main

knapsack.cpp
int main() {
    // تهيئة كل الخلايا بـ -1 (لم تُحسب بعد)
    for (int i = 0; i < 200; i++)
        for (int j = 0; j < 200000; j++)
            dp[i][j] = -1;

    int n, weight;
    cin >> n >> weight;

    for (int i = 0; i < n; i++)
        cin >> w[i] >> v[i];

    // نطلب الإجابة: كل العناصر، أقصى سعة
    cout << f(n - 1, weight) << endl;
}

  • نبدأ بتهيئة كل dp بـ -1 لنعرف أي خلايا لم تُحسب بعد.

  • نقرأ المدخلات: N (عدد العناصر) وW (سعة الحقيبة)، ثم وزن وقيمة كل عنصر.

  • نستدعي f(n-1, weight) لأن المصفوفة تبدأ من 0، وn-1 هو آخر عنصر.

الكود الكامل

knapsack_full.cpp
#include <iostream>
using namespace std;

long long dp[200][200000];
int v[200], w[200];

long long f(int i, int capacity) {
    if (i == 0) {
        if (capacity < w[i]) return 0;
        else                 return v[i];
    }
    if (dp[i][capacity] != -1) return dp[i][capacity];

    // i في حالة إستبعاد العنصر
    dp[i][capacity] = f(i - 1, capacity);

    // i في حالة أخذ العنصر
    if (capacity >= w[i]) {
        dp[i][capacity] = max(dp[i][capacity],
                              f(i - 1, capacity - w[i]) + v[i]);
    }
    return dp[i][capacity];
}

int main() {
    for (int i = 0; i < 200; i++)
        for (int j = 0; j < 200000; j++)
            dp[i][j] = -1;

    int n, weight;
    cin >> n >> weight;

    for (int i = 0; i < n; i++)
        cin >> w[i] >> v[i];

    cout << f(n - 1, weight) << endl;
}
مثال 1: 3 8 / 3 30 / 4 50 / 5 60 → 90 مثال 2: 5 5 / 1 1e9 (×5) → 5000000000 مثال 3: 6 15 / ... → 17 المحاكاة (W=10, 4 عناصر أعلاه) → 12

تحققنا من الكود على الأمثلة الرسمية الثلاثة، بالإضافة إلى اختبار عشوائي بأكبر حجم ممكن (N=100, W=100,000)، وقارنّاه بحل Bottom-Up مستقل — وتطابقت النتيجتان تمامًا (وأعطتا نفس الإجابة الصحيحة التي تتجاوز حدود int).

نقاط يجب الانتباه لها

الفيضان (Overflow): كما رأينا في المثال الثاني الرسمي، القيمة الكلية قد تصل إلى N × 10⁹ = 100 × 10⁹ = 10¹¹. هذا الرقم أكبر بكثير من أقصى قيمة لـ int (حوالي 2.1 × 10⁹)، لذا استخدام long long لمصفوفة dp ليس اختياريًا هنا، بل ضروري.

حجم الذاكرة: المصفوفة dp[200][200000] من نوع long long (8 بايت لكل خلية) تستهلك تقريبًا 200 × 200,000 × 8 ≈ 305 ميجابايت — وهذا يتّسع ضمن حدّ الذاكرة الرسمي لهذه المسألة (1024 ميجابايت)، لكنه أكبر بكثير مما نحتاجه فعليًا (بما أن N ≤ 100 وW ≤ 100,000، يكفي dp[101][100001] تقريبًا، أي حوالي 80 ميجابايت فقط). من العادات الجيدة تحجيم المصفوفات بما يقارب الحدّ الفعلي للمسألة، خصوصًا في مسائل ذات حدّ ذاكرة أضيق.

عمق الاستدعاء المتكرر: بما أن N ≤ 100 فقط، فإن عمق الاستدعاءات هنا صغير جدًا (على عكس Frog 1 حيث كان العمق قد يصل إلى 100,000) — لا داعي للقلق بشأن تجاوز المكدس (Stack Overflow) في هذه المسألة تحديدًا.

هذا النمط — "لكل عنصر: خذ أو لا تأخذ، مع تتبّع مورد محدود (السعة)" — هو الأساس لعشرات المسائل الكلاسيكية الأخرى (Subset Sum، Coin Change، Partition Equal Subset Sum، وغيرها). بمجرد أن تُتقن حالتين البُعدين هنا (العنصر + السعة المتبقية)، ستجد الكثير من مسائل DP الأصعب مجرد تنويعات على نفس الفكرة.
