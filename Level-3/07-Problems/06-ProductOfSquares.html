Product of Squares (حاصل ضرب مربعين)

مسألة نظرية أعداد بسيطة الصياغة لكنها تختبئ خلفها فكرة أنيقة: السؤال "هل يمكن كتابة A كحاصل ضرب مربعين x² وy² بحيث x,y > 1؟" يختصر تمامًا إلى سؤالين متتاليين فقط: هل A نفسه مربع كامل؟ وإن كان كذلك، هل جذره التربيعي عدد مركّب (غير أوّلي)؟

Easy

نص المسألة

تُعطى لك أعداد صحيحة موجبة، وعليك لكل عدد A أن تحدّد إن كان يمكن كتابته على الصورة:

A = x² · y² حيث x > 1 و y > 1

القيود

  • 1 ≤ N ≤ 1000 (عدد الاستعلامات)

  • 1 ≤ A ≤ 10¹⁸

تدرّج في الصعوبة: المسألة نفسها تقترح حل نسخة أسهل أولًا إن واجهتك صعوبة: جرّب أولًا بافتراض 1 ≤ A ≤ 10⁵، ثم إن كانت لا تزال صعبة جرّب 1 ≤ A ≤ 10⁴. هذا أسلوب ممتاز لحل أي مسألة صعبة: ابدأ بنسخة أصغر من القيود، تأكّد أن حلّك صحيح عليها، ثم طوّره ليتحمّل القيد الكامل.

الإدخال

السطر الأول: عدد صحيح N. ثم N سطر، كل سطر يحتوي عددًا صحيحًا A يجب التحقق منه.

المخرجات

لكل عدد A، اطبع YES إن حقّق الشرط، أو NO إن لم يحقّقه.

مثال

Input: 3 9 144 234 Output: NO YES NO

9 = 3² والوحيدة، لكن 3 عدد أوّلي فلا يمكن تفكيكه لعاملين أكبر من 1 → NO.
144 = 12²، و12 = 2×6 (أو 3×4)، فيمكن كتابة 144 = 2²×6² → YES.
234 ليس مربعًا كاملًا أصلًا (15²=225 و16²=256) → NO مباشرة.

مختبر تفاعلي: تحقّق من كل رقم خطوة بخطوة

شغّل المحاكاة لمشاهدة الخوارزمية الحقيقية تُطبَّق على الأمثلة الثلاثة الرسمية بالتتابع: حساب الجذر التربيعي الصحيح، التأكّد من كونه دقيقًا، ثم قسمة تجريبية على جذر الجذر (z) للتحقق هل هو مركّب:

الأمثلة: 9, 144, 234

اضغط "الخطوة التالية" أو "تشغيل تلقائي" للبدء.

جرّب رقمك الخاص

أداة "جرّب رقمك الخاص" محدودة هنا بحوالي 10¹² فقط لأسباب دقة الأعداد العشرية في JavaScript، بينما الحل الحقيقي بلغة ++C (بالأسفل) يتعامل بأمان مع القيد الكامل 10¹⁸ لأنه يستخدم أعدادًا صحيحة (long long) بلا أي تقريب عشري.

كيف نفكّر في هذه المسألة؟

  • أعد صياغة المعادلة: A = x²·y² = (x·y)². لو سمّينا z = x·y، فإن A يجب أن يكون مربعًا كاملًا لعدد ما z.

  • لكن ليس أي مربع كامل يكفي: نحتاج تحديدًا أن يكون z = x·y بحيث x > 1 وy > 1 — أي أن z نفسه يجب أن يقبل التفكيك لعاملين أكبر من 1، وهذا بالضبط تعريف العدد المركّب (غير الأوّلي وغير 1).

  • اختبر بأمثلة صغيرة: z=4=2×2 ✓ مركّب، z=6=2×3 ✓ مركّب، لكن z=5 عدد أوّلي فتفكيكه الوحيد هو 1×5 — غير مقبول لأن أحد العاملين يساوي 1.

  • الخوارزمية إذن خطوتان فقط: (أ) احسب الجذر التربيعي الصحيح z لـA، وتحقّق أن z² = A بالضبط. (ب) إن كان كذلك، تحقّق هل z عدد مركّب عبر قسمة تجريبية حتى √z.

  • لاحظ الفخّ الشائع: السؤال ليس "هل A أوّلي؟" ولا "هل A مركّب؟" — بل "هل جذر A (بعد التأكد أنه مربع كامل) مركّب؟". هذا خلط سهل الوقوع فيه.

تحليل التعقيد — ولماذا لا نُفكّك A مباشرة

الفكرة الحاسمة في الكفاءة: نحن لا نحتاج أبدًا لتفكيك A نفسه (الذي قد يصل إلى 10¹⁸)، بل فقط جذره التربيعي z = √A، الذي لا يتجاوز 10⁹. القسمة التجريبية على z تحتاج فقط حتى √z ≈ 31,623.

الأسلوبالتعقيد لكل استعلامالزمن الكلي (N=1000)
تفكيك A مباشرة (خاطئ/بطيء)O(√A) ≈ 10⁹≈ 10¹² — بطيء جدًا
تفكيك z=√A فقط (الحل الصحيح)O(A¹⁄⁴) ≈ 31,623≈ 3.16×10⁷ — سريع جدًا

هذا مثال جميل على "قلّص المسألة قبل أن تحلّها": بدل أن تسأل سؤالًا صعبًا عن A الكبير، حوّلناه إلى سؤال أسهل بكثير عن z = √A الأصغر جذريًا.

الحل الكامل

product_of_squares.cpp
#include <iostream>
#include <cmath>
using namespace std;

// جذر تربيعي صحيح دقيق، مع تصحيح أخطاء التقريب العشري المحتملة
long long integerSqrt(long long A) {
    long long z = (long long)sqrtl((long double)A);
    while (z > 0 && z * z > A) z--;
    while ((z + 1) * (z + 1) <= A) z++;
    return z;
}

// هل z يقبل التفكيك لعاملين أكبر من 1؟ (أي: z مركّب)
bool isComposite(long long z) {
    if (z < 4) return false;  // 0،1: ليست حتى أعدادًا صالحة هنا / 2،3: أوليان
    for (long long d = 2; d * d <= z; d++) {
        if (z % d == 0) return true;
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    while (n--) {
        long long A;
        cin >> A;

        long long z = integerSqrt(A);
        if (z * z != A) {
            cout << "NO\n";
            continue;
        }

        cout << (isComposite(z) ? "YES" : "NO") << "\n";
    }
    return 0;
}

تحقّقنا يدويًا من الأمثلة الثلاثة: A=9 → z=3 (أوّلي) → NO. A=144 → z=12 (يقبل القسمة على 2) → YES. A=234 → z=15 لكن 15²=225 ≠ 234 → NO فورًا.

نقاط يجب الانتباه لها

دقة الجذر التربيعي العشري: دالة sqrt() أو sqrtl() قد تُعطي نتيجة أقل أو أكبر بمقدار 1 من القيمة الصحيحة الفعلية عند التعامل مع أعداد كبيرة جدًا (حتى 10¹⁸) بسبب التقريب العشري الداخلي. لهذا لا نثق بالنتيجة مباشرة أبدًا — نُصحّحها دائمًا بفحص z-1, z, z+1 كما في دالة integerSqrt أعلاه.

الأنواع العدديةA يصل إلى 10¹⁸، وهذا يتجاوز سعة int بكثير — يجب استخدام long long في كل مكان، بما في ذلك حساب z*z والمقارنات.
الحالات الصغيرة z < 4z=1 ليس له تفكيك صالح، وz=2, 3 عددان أوّليان — يجب أن يُرجع isComposite false لهذه الحالات الثلاث جميعًا (يضمنها الشرط z < 4).
الخلط بين فحص A وفحص zالقسمة التجريبية (وفحص الأوّلية) تُطبَّق على z = √A، وليس على A نفسه — تفكيك A مباشرة أبطأ بكثير وغير ضروري.
الشرط الصارم x,y > 1لا يكفي أن يكون A مربعًا كاملًا فقط — يجب أيضًا أن جذره قابل للتفكيك لعاملين، كلاهما أكبر من الواحد الصحيح.

هذه المسألة تجمع بين أداتين رأيناهما من قبل في المستوى الرابع (فحص كون عدد مربعًا كاملًا، والقسمة التجريبية بزمن O(√n) لفحص الأوّلية)، وتضيف لهما فكرة ذكية: طبّق الأداة الثانية على جذر المدخل بدلًا من المدخل نفسه، لتُصبح مسألة تبدو ثقيلة (A حتى 10¹⁸) سريعة الحل عمليًا.
