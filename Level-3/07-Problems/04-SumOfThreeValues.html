المسألة 4: Sum of Three Values (مجموع ثلاث قيم)

امتداد طبيعي لمسألة Sum of Two Values السابقة: بدلًا من خريطة تُجيب سؤال عضوية واحد، سنُثبّت عنصرين هذه المرة ونبحث عن الثالث بالبحث الثنائي داخل مصفوفة مُرتَّبة — لأن قيود هذه المسألة (n أصغر بكثير) تسمح بتعقيد أعلى قليلًا.

Medium CSES 1641 — Sorting and Searching

نص المسألة

لديك مصفوفة من n عددًا صحيحًا، ومطلوب منك إيجاد ثلاثة مواقع مختلفة يكون مجموع قيمها الثلاث يساوي عددًا مستهدفًا x مُعطى مسبقًا.

إذا وُجد أكثر من ثلاثيّة صحيحة، يمكنك طباعة أيٍّ منها. وإذا لم توجد أي ثلاثيّة تحقق الشرط، اطبع IMPOSSIBLE.

القيود

  • 1 ≤ n ≤ 5000

  • 1 ≤ x, aᵢ ≤ 10⁹

لاحظ الفرق عن المسألة السابقة: هنا n ≤ 5000 فقط (وليس 2·10⁵ كما في Sum of Two Values) — وهذا تلميح قوي بأن الحل المتوقّع تعقيده أعلى من O(n log n)، تحديدًا شيء قريب من O(n² log n).

الإدخال

السطر الأول: عددان صحيحان n وx — حجم المصفوفة والمجموع المستهدف.
السطر الثاني: n عددًا صحيحًا تمثّل قيم المصفوفة.

المخرجات

إمّا ثلاثة مواقع (1-indexed) بحيث يكون مجموع قيمها الثلاث يساوي x وكلّها مختلفة عن بعضها، أو الكلمة IMPOSSIBLE إن لم توجد أي ثلاثيّة صحيحة.

مثال

Input: 4 8 2 7 5 1 Output: 1 3 4

تحقّق: a[1] + a[3] + a[4] = 2 + 5 + 1 = 8. صحيح.

أي ترتيب مقبول: الحكم على CSES يتحقق فقط من صحة المجموع، وليس من مطابقة نفس الأرقام أو نفس الترتيب الموجود في المثال الرسمي — لذلك خوارزميتنا قد تُخرج ثلاثيّة صحيحة أخرى (أو بترتيب مختلف) وتُقبل بالمثل. سترى هذا فعليًا في المختبر أدناه.

مختبر تفاعلي: ثبّت عنصرين وابحث ثنائيًا عن الثالث

هذه هي نفس مصفوفة المثال الرسمي a = [2, 7, 5, 1] بعد ترتيبها حسب القيمة (مع الاحتفاظ بموقعها الأصلي 1-indexed تحت كل خلية). شغّل المحاكاة لمشاهدة الحلقتين المتداخلتين i, j والبحث الثنائي الحقيقي يعملان معًا خطوة بخطوة:

المصفوفة بعد الترتيب , x = 8

القيمة (والموقع الأصلي أسفلها)
اضغط "الخطوة التالية" أو "تشغيل تلقائي" لبدء البحث.

راقب كيف يبحث البحث الثنائي فقط ضمن الخلايا الواقعة بعد j — هذا وحده يضمن أن المواقع الثلاثة (بعد الترتيب) مختلفة دائمًا، تمامًا كما ضَمِن فحص الخريطة "قبل" الإدراج تفرّد الموقعين في المسألة السابقة.

كيف نبني على فكرة المسألة السابقة؟

  • الحل الساذج الأول: افحص كل ثلاثيّة ممكنة بثلاث حلقات متداخلة — تعقيد O(n³). مع n = 5000، هذا حوالي 1.25×10¹¹ عملية — بطيء جدًا.

  • لاحظ الشبه بالمسألة السابقة: إن ثبّتنا عنصرًا واحدًا a[i]، فإن المطلوب من الباقي يصبح بالضبط "أوجد زوجًا يجمع إلى x - a[i]" — وهذه بالضبط مسألة Sum of Two Values!

  • لكن الحل هنا يختار تثبيت عنصرَين لا عنصرًا واحدًا: بدلًا من إعادة استخدام خريطة لكل قيمة لـi (وهو ممكن أيضًا)، نُثبّت i وj معًا، ثم نبحث عن الثالث need = x - a[i] - a[j] ببحث ثنائي مباشر — وهذا يتطلّب ترتيب المصفوفة أولًا (مع حفظ المواقع الأصلية).

  • لماذا الترتيب يسمح بالبحث الثنائي؟ بعد الترتيب، القيم تصبح تصاعدية، فيمكننا التحقق من وجود قيمة معيّنة ضمن مجال معيّن بزمن O(log n) بدلًا من مسحه بالكامل.

  • لماذا نبحث فقط في [j+1, n-1]؟ لضمان أن العنصر الثالث يقع بعد j (في المصفوفة المرتّبة)، فتكون المواقع الثلاثة مختلفة دائمًا تلقائيًا، تمامًا كما فعلنا سابقًا بالبحث في الخريطة قبل الإدراج.

بونص — طريقة بديلة: يمكن أيضًا حل هذه المسألة بتثبيت عنصر واحد i فقط، ثم استخدام مؤشرين (Two Pointers) يتحركان من طرفي المجال [i+1, n-1] نحو بعضهما بزمن O(n) لكل i — فيصبح التعقيد الكلي O(n²)، أسرع من طريقة البحث الثنائي المشروحة هنا. كلا الأسلوبين صحيح ومقبول على الحكم.

تحليل التعقيد

  • الترتيب: O(n log n) مرة واحدة فقط في البداية.

  • الحلقتان المتداخلتان i, j: O(n²) زوج بحد أقصى.

  • لكل زوج، بحث ثنائي واحد: O(log n).

الزمن الكلي = O(n² log n)

لـn = 5000: تقريبًا 5000² × log&sub2;(5000) ≈ 25,000,000 × 13 ≈ 3.25×10⁸ عملية — مقبول بارتياح ضمن حد الثانية الواحدة. لاحظ جيدًا: لو كانت قيود هذه المسألة n ≤ 2·10⁵ (كما في Sum of Two Values)، لكانت هذه الطريقة بطيئة جدًا — القيد الصغير نسبيًا (5000) هو ما يسمح لنا أصلًا باستخدام تعقيد تربيعي.

الحل الكامل

sum_of_three_values.cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<pair<long long, int>> a(n);
    for (int i = 0; i < n; ++i) {
        long long v;
        cin >> v;
        a[i] = {v, i + 1};  // القيمة مع موقعها الأصلي (1-based)
    }

    sort(a.begin(), a.end());  // رتّب حسب القيمة

    // ثبّت عنصرين (i, j) وابحث ثنائيًا عن الثالث
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            long long need = x - a[i].first - a[j].first;

            int lo = j + 1, hi = n - 1;
            while (lo <= hi) {
                int mid = (lo + hi) / 2;
                if (a[mid].first == need) {
                    // وجدنا ثلاثيّة صحيحة
                    cout << a[i].second << " "
                        << a[j].second << " "
                        << a[mid].second << "\n";
                    return 0;
                } else if (a[mid].first < need) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
    }

    cout << "IMPOSSIBLE\n";
    return 0;
}

تحقّقنا يدويًا من هذا الكود على المثال الرسمي: بعد الترتيب تصبح المصفوفة [(1,4), (2,1), (5,3), (7,2)]، وأول ثلاثيّة يجدها الكود فعليًا هي i=0, j=1 (القيمتان 1 و2)، فيكون need = 8-1-2 = 5، والبحث الثنائي في [2,3] يجد القيمة 5 عند mid=2 — فيطبع الكود 4 1 3. هذا مختلف عن ناتج المثال الرسمي 1 3 4 شكليًا، لكنه صحيح بالمثل تمامًا (نفس الثلاثيّة، بترتيب مختلف) — وهذا متوقّع تمامًا حسب نص المسألة نفسه.

نقاط يجب الانتباه لها

فيضان الأعداد الصحيحة (Overflow) — خطر حقيقي هذه المرة: على عكس Sum of Two Values حيث لم يكن هناك خطر فيضان فعلي، هنا need = x - a[i] - a[j] يُطرح من قيمة قد تصل لـ10⁹ قيمتين قد تصل كل منهما لـ10⁹ أيضًا — والمجموع الكلي (لو حسبناه بشكل مختلف) قد يقترب من 3×10⁹، وهو ما يتجاوز سعة int (32-بت، الحد الأقصى تقريبًا 2.1×10⁹). لذلك استخدام long long لكل من x وقيم المصفوفة إلزامي هنا، وليس مجرد عادة أمان كما في المسألة السابقة.

تفرّد المواقع الثلاثةمضمون تلقائيًا لأن البحث الثنائي يقتصر دائمًا على المجال [j+1, n-1] — أي بعد j دائمًا، وبالتالي بعد i أيضًا.
حفظ الموقع الأصلي قبل الترتيبلا بد من تخزين كل قيمة مع فهرسها الأصلي (1-based) قبل الترتيب، وإلا ستفقد معرفة الموقع الحقيقي المطلوب طباعته.
حدود n المختلفة عن المسألة السابقةn ≤ 5000 هنا فقط، وليس 2·10⁵ — لا تفترض تلقائيًا نفس قيود المسألة السابقة في مسألة جديدة، ودائمًا اربط التعقيد المسموح بحجم n المُعطى.
عدم إيجاد أي حليجب إكمال فحص كل الأزواج الممكنة (والبحث الثنائي لكل منها) قبل الجزم بعدم وجود حل وطباعة IMPOSSIBLE.

لاحظ التدرّج الطبيعي عبر هذه السلسلة: Sum of Two Values عرّفتنا على فكرة "ثبّت واحدًا وابحث عن الباقي عبر هيكل بيانات سريع"، وSum of Three Values مدّت نفس الفكرة بمستوى تعشيش إضافي. لا يفاجئك إذن أن توجد مسألة "Sum of Four Values" تالية تبني على نفس الفلسفة، غالبًا بدمج فكرة الهاش من المسألة الأولى مع فكرة التثبيت المزدوج من هذه المسألة.
