المكونات المتصلة (Connected Components)

بعد أن تعلّمنا DFS كخوارزمية اجتياز، سنستخدمها الآن لحل مسألة كلاسيكية: كيف نعرف عدد "الجزر" المنفصلة في رسم بياني؟ هذا المفهوم أساس لعشرات المسائل التنافسية، بدءًا من توصيل المدن وحتى اكتشاف الأنماط داخل الرسم البياني.

المفاهيم الأساسية

تعريف المكوّن المتصل

في الرسم البياني غير الموجّه، يُقال إن الرأسين u وv ينتميان إلى نفس المكوّن المتصل (Connected Component) إذا كان هناك مسار يربط بينهما. إذا كان الرسم البياني يتكوّن من مكوّن واحد فقط، فإنه يُعتبر متصلاً بالكامل (Connected Graph).

فكرة جوهرية: عند تشغيل DFS من رأس غير مُزار، فإنها ستزور جميع الرؤوس القابلة للوصول منه — أي كل رؤوس مكوّنه المتصل بالضبط، ولن تتخطاه إلى أي رأس في مكوّن آخر. لذا، إذا مررنا على كل الرؤوس من 1 إلى N وشغّلنا DFS في كل مرة نجد فيها رأسًا غير مُزار، فإن عدد مرّات بدء DFS يساوي بالضبط عدد المكوّنات المتصلة.

تنبيه: هذه التقنية تعمل فقط على الرسوم البيانية غير الموجّهة. أما بالنسبة للرسوم الموجّهة، فهناك مفهوم مختلف تمامًا يُسمى "المكوّنات القوية الترابطية" (Strongly Connected Components - SCCs)، والذي يتطلّب خوارزميات مختلفة (مثل Kosaraju أو Tarjan) سنتعرّض لها لاحقًا في مستويات متقدّمة.

خطوات الخوارزمية

  1. قراءة الرسم البياني (الرؤوس والأحرف) وبناء قائمة الجوار adj[].

  2. إنشاء مصفوفة زيارة vis[] بقيم false.

  3. للمرور على جميع الرؤوس من 1 إلى N: إذا لم يُزَر الرأس i بعد، نشغّل DFS منه ونزيد عدّاد المكوّنات بمقدار 1.

  4. داخل DFS: نضع vis[u] = true ثم ندعو DFS لكل جار غير مُزار.

  5. نستخدم قيمة عدّاد المكوّنات النهائية للإجابة على متطلبات المسألة.

المحاكي التفاعلي للمكوّنات المتصلة

انقر على أي مكان فارغ في اللوحة لإضافة رأس جديد هناك، ثم اضغط على رأسين (بالترتيب) لتوصيلهما بحافة. اضغط "مثال جاهز" لتحميل رسم بياني جاهز فيه 3 مكوّنات، ثم شغّل DFS لترى كيف يكتشفها بألوان مختلفة.

الكود الأساسي لعدّ المكوّنات المتصلة

connected_components.cpp
const int maxN = 200001;

bool vis[maxN];
vector<int> adj[maxN];

void dfs(int u) {
    vis[u] = true;
    for (int v : adj[u])
        if (!vis[v])
            dfs(v);
}

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    int components = 0;
    for (int i = 1; i <= n; i++) {
        if (!vis[i]) {
            components++;
            dfs(i);
        }
    }

    cout << components;
}

لاحظ أن هذا الكود هو نفس كود DFS الأساسي من الدرس السابق، مع إضافة واحدة فقط: حلقة تمر على كل الرؤوس وتشغّل DFS من كل رأس غير مُزار، مع عدّاد يزداد في كل مرة نبدأ فيها DFS جديدة. هذا مثال ممتاز على كيف تُبنى الخوارزميات الأكثر تعقيدًا فوق أساسيات بسيطة تعلّمناها سابقًا.

مسألة: Building Roads

سهل — CSES 1666 ↗

يوجد n مدينة وm طريقًا بينها. مهمتك هي إيجاد الحد الأدنى من عدد الطرق التي يجب إضافتها بحيث يكون هناك مسار بين أي مدينتين، وتحديد أي الطرق يجب بناؤها.

الفكرة الرئيسية: إذا كان هناك k مكوّنًا متصلاً، فنحتاج بالضبط إلى k - 1 طريقًا لتوحيدها (تمامًا كما تحتاج لربط k جزيرة معًا بأقل عدد جسور: k-1 جسرًا يكفي دائمًا). الاستراتيجية: نختار رأسًا "مرجعيًا" (source) من كل مكوّن — وليكن أول رأس نكتشفه فيه — ثم نربط مرجع المكوّن الأول بمرجع كل مكوّن آخر.

الحل المشروح

نشغّل نفس خوارزمية عدّ المكوّنات، لكن بدلًا من الاكتفاء بعدّها، نحفظ في مصفوفة sources[] أول رأس نبدأ منه DFS في كل مكوّن (أي الرأس الذي دخل الشرط if (!vis[i])). في النهاية، عدد عناصر sources[] يساوي عدد المكوّنات k، والإجابة هي k - 1. لطباعة الطرق، نربط sources[0] بكل عنصر آخر في المصفوفة.

building_roads.cpp
const int maxN = 100001;
bool vis[maxN];
vector<int> adj[maxN];

void dfs(int u) {
    vis[u] = true;
    for (int v : adj[u])
        if (!vis[v])
            dfs(v);
}

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        adj[a].push_back(b);
        adj[b].push_back(a);
    }

    vector<int> sources;
    for (int i = 1; i <= n; i++) {
        if (!vis[i]) {
            sources.push_back(i);  // أول رأس في هذا المكوّن
            dfs(i);
        }
    }

    cout << sources.size() - 1 << "\n";
    for (int i = 1; i < (int)sources.size(); i++) {
        cout << sources[0] << " " << sources[i] << "\n";
    }
}

تتبّع مثال

لنأخذ n = 5 مع الطرق: (1,2) و(4,5) (والرأس 3 بلا أي طريق).

الخطوةماذا يحدث؟
i = 1غير مُزار → sources = [1] → dfs(1) يزور {1, 2}
i = 2مُزار بالفعل → تخطّ
i = 3غير مُزار → sources = [1, 3] → dfs(3) يزور {3} فقط
i = 4غير مُزار → sources = [1, 3, 4] → dfs(4) يزور {4, 5}
i = 5مُزار بالفعل → تخطّ
sources = [1, 3, 4] → k = 3 مكوّنات الإجابة: sources.size() - 1 = 2 الطرق المطلوبة: 1 3 1 4

تحقّق بنفسك في المحاكي أعلاه: ابنِ نفس هذا المثال (5 رؤوس، حافتان تفصلان الرؤوس إلى 3 مجموعات) وشغّل DFS لترى المكوّنات الثلاثة بألوان مختلفة — بالضبط كما تنبّأنا في هذا التتبّع.

مسألة: Cyclic Components

سهل — Codeforces 977E ↗

معطى رسم بياني غير موجّه، احسب عدد المكوّنات التي تُشكّل دورة (Cycle). المكوّن الذي يتكوّن من n رأسًا يُعتبر دورة إذا كان له بالضبط n حافة (أي أن كل رأس فيه درجته (degree) تساوي 2 بالضبط).

البرهان: إذا كان كل رأس في المكوّن مجاورًا لرأسين بالضبط (degree = 2)، فإن المكوّن يُشكّل دورة بسيطة واحدة. هذا شرط ضروري وكافٍ في الرسوم البيانية البسيطة غير الموجّهة (بدون حواف متعددة أو حلقات ذاتية).

الحل المشروح

نشغّل DFS من كل رأس غير مُزار، لكن هذه المرة تُرجع الدالة قيمة bool: صحيح (true) إذا كان المكوّن بأكمله يحقق شرط الدورة. نبدأ بافتراض أن الرأس الحالي يحقق الشرط (ret = degree[u] == 2)، ثم "نُضاعف" هذه النتيجة مع نتيجة كل جار باستخدام ret &= dfs(v) — بحيث تصبح ret صحيحة فقط إذا كان كل رأس في المكوّن (وليس رأسًا واحدًا فقط) يحقق شرط الدورة.

cyclic_components.cpp
const int maxN = 200001;
bool vis[maxN];
vector<int> adj[maxN];

bool dfs(int u) {
    vis[u] = true;
    bool ret = (adj[u].size() == 2);   // افتراض أولي: هل درجة u تساوي 2؟

    for (int v : adj[u]) {
        if (!vis[v]) {
            ret &= dfs(v);            // يجب أن يتحقق الشرط لكل الرؤوس، وليس فقط لآخر واحد
        }
    }
    return ret;
}

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        adj[a].push_back(b);
        adj[b].push_back(a);
    }

    int ans = 0;
    for (int i = 1; i <= n; i++) {
        if (!vis[i]) {
            if (dfs(i)) ans++;
        }
    }

    cout << ans;
}

فخّ مهم — الحلقات الذاتية (Self-loops): لو أن مكوّنًا يتكوّن من رأس واحد فقط مع حلقة ذاتية عليه (self-loop مثل edge(6, 6))، فإن الكود adj[6].push_back(6); adj[6].push_back(6); يجعل adj[6].size() == 2! هذا يعني أن الكود سيعتبر هذا الرأس المفرد "دورة" رغم أنه ليس كذلك منطقيًا. لحسن الحظ، مسألة Codeforces 977E تضمن صراحةً عدم وجود حلقات ذاتية أو حواف متكرّرة في المدخلات (رسم بياني بسيط)، لكن من المهم جدًا أن تنتبه لهذا الفخّ إذا واجهته في مسألة أخرى لا تضمن ذلك.

تتبّع مثال

لنأخذ n = 9 بثلاثة مكوّنات: مثلث {1,2,3} بالحواف (1,2),(2,3),(3,1)، وحافة واحدة {4,5} بالحافة (4,5)، ودورة رباعية {6,7,8,9} بالحواف (6,7),(7,8),(8,9),(9,6).

المكوّنعدد الرؤوسعدد الحوافهل كل الدرجات = 2؟دورة؟
{1, 2, 3}33نعمtrue ✓
{4, 5}21لا (كل رأس درجته 1)false ✗
{6, 7, 8, 9}44نعمtrue ✓
عدد المكوّنات الدورية (ans) = 2

لاحظ: المكوّن {4,5} يوضّح لماذا لا يمكن لأي مكوّن من رأسين فقط أن يكون دورة في رسم بياني بسيط — فهذا يتطلّب حافتين متكرّرتين بين نفس الرأسين (multi-edge)، وهو أمر غير مسموح به في الرسوم البسيطة. أصغر دورة ممكنة في رسم بياني بسيط تتكوّن من 3 رؤوس على الأقل.

قاموس المصطلحات

Connected Componentمكوّن متصل

مجموعة الرؤوس التي يوجد بينها مسار في كل الاتجاهات، ضمن رسم بياني غير موجّه.

Connected Graphرسم بياني متصل

رسم بياني يتكوّن من مكوّن متصل واحد فقط، أي يمكن الوصول من أي رأس إلى أي رأس آخر.

Source Vertexالرأس المرجعي

أول رأس يُكتشف في مكوّن معيّن أثناء المرور على الرؤوس؛ يُستخدم لتمثيل المكوّن بأكمله.

Degreeدرجة الرأس

عدد الحواف المتصلة برأس معيّن؛ يساوي adj[u].size().

Simple Graphرسم بياني بسيط

رسم بياني بدون حلقات ذاتية (self-loops) وبدون حواف متكرّرة (multi-edges) بين نفس الزوج من الرؤوس.

Self-loopحلقة ذاتية

حافة تربط رأسًا بنفسه؛ قد تُخلّ بشروط مثل "الدرجة = 2" إذا لم يُنتبه لها.

Strongly Connected Components (SCC)المكوّنات القوية الترابطية

المفهوم المكافئ للمكوّنات المتصلة، لكن في الرسوم البيانية الموجّهة؛ يتطلّب خوارزميات مختلفة.

Disjoint Set Union (DSU)مجموعات منفصلة متّحدة

هيكل بيانات بديل لإيجاد المكوّنات المتصلة، مفيد بشكل خاص عند تحديث الرسم البياني ديناميكيًا (إضافة حواف تباعًا).
