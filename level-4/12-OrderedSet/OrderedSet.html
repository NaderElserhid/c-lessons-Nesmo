ما هي ordered_set؟

ordered_set هي بنية بيانات متقدمة تعمل تمامًا مثل set العادي في C++ — لا تسمح بتكرار العناصر، ومرتبة تلقائيًا تصاعديًا — لكنها تُضيف عليه قدرتين استثنائيتين غير متوفرتين في set القياسي.

هي جزء من PBDS (Policy-Based Data Structures) التابعة لمكتبة GNU، وليست جزءًا من المعيار الرسمي لـ C++، لكنها مدعومة عمليًا في جميع منصات المسابقات البرمجية تقريبًا (Codeforces، CSES، وغيرها).

العمليةالوصفالتعقيد
find_by_order(k)تُرجع مؤشرًا (iterator) للعنصر ذي الترتيب k، بدءًا من 0، من الأصغر إلى الأكبر.O(log n)
order_of_key(x)تُرجع عدد العناصر الأصغر تمامًا من x الموجودة في المجموعة (سواء كان x موجودًا فيها أم لا).O(log n)

تنبيه مهم قبل المسابقة: هذا الكود يعمل مع GCC فقط ولن يعمل مع MSVC (Visual Studio) بدون تعديلات، لأن PBDS جزء من مكتبة libstdc++ وليست من المعيار الرسمي لـ C++.

💡 دقة تقنية إضافية: هل هي مرتبطة بالمترجم أم بالمكتبة؟

الأدق تقنيًا أن PBDS مرتبطة بمكتبة libstdc++ (مكتبة GNU القياسية) وليست حصرًا بمترجم GCC نفسه. هذا يعني عمليًا:

✅ تعمل مع GCC (يستخدم libstdc++ افتراضيًا).
✅ تعمل مع Clang إذا رُبط صراحة بـ libstdc++ (كما هو الحال على أغلب حكام الأونلاين مثل Codeforces).
❌ لا تعمل مع Clang + libc++ (المكتبة الافتراضية على macOS الحديثة).
❌ لا تعمل مع MSVC STL (مترجم Visual Studio) إطلاقًا.
القاعدة العملية في المسابقات: إذا كان الحكم يقبل GCC/G++ (وهذا شبه دائم في Codeforces وCSES)، فالكود سيعمل دون مشاكل.

الكود الأساسي (Template)

ordered_set.cpp — التعريف والاستخدام
// الملفات المطلوبة
#include <ext/pb_ds/assoc_container.hpp>
#include <ext/pb_ds/tree_policy.hpp>
using namespace __gnu_pbds;

// التعريف الكامل لـ ordered_set
template<typename T>
using ordered_set = tree<
    T,                                    // نوع العناصر
    null_type,                            // لا يوجد value (تمامًا كـ set)
    less<T>,                              // ترتيب تصاعدي
    rb_tree_tag,                          // شجرة حمراء-سوداء (Red-Black Tree)
    tree_order_statistics_node_update     // يتيح find_by_order و order_of_key
>;

// طريقة الاستخدام:
ordered_set<int> os;
os.insert(10);
os.insert(20);
os.insert(30);

// العنصر في الرتبة 0 (الأصغر): 10
auto it = os.find_by_order(0); // يشير إلى 10

// كم عنصر أصغر من 25؟ الجواب: 2 (وهما 10 و 20)
int cnt = os.order_of_key(25); // = 2

ملاحظة: لترتيب تنازلي (من الأكبر إلى الأصغر)، استبدل less<T> بـ greater<T> في تعريف الشجرة، ودلالة find_by_order/order_of_key تنعكس معه تلقائيًا.

💡 حل مشكلة التكرار — استخدام الأزواج

الـ ordered_set لا تقبل تكرار القيم تمامًا كـ set. الحل الذكي في مسائل مثل Sliding Window Median: نخزّن كل عنصر كزوج (قيمة, فهرس) بدلًا من مجرد القيمة!

  1. المشكلة: إذا كانت لدينا مصفوفة [3, 1, 3, 2] ونافذة تحتوي [3, 1, 3]، فلن نستطيع إدراج الرقم 3 مرتين في ordered_set<int> — العنصر الثاني سيُرفض بصمت!

  2. الحل: نحوّل كل عنصر a[i] إلى زوج (a[i], i). الآن (3,0) و (3,2) عنصران مختلفان تمامًا من منظور الشجرة.

  3. الترتيب محفوظ: الأزواج تُرتَّب افتراضيًا بالعنصر الأول (القيمة) ثم بالعنصر الثاني (الفهرس) عند التعادل، لذا ترتيبنا التصاعدي بالقيمة لا يتأثر إطلاقًا.

⚗️ مختبر: قارن بنفسك

أدخل مصفوفة تحتوي على قيم مكررة، وشاهد الفرق الحي بين محاولة إدراجها في ordered_set<int> مباشرة مقابل تحويلها إلى أزواج (قيمة, فهرس) أولًا.

📘 مسألة: Sliding Window Median

المسألة: لديك مصفوفة من n عنصر وقيمة k. اطبع الوسيط لكل مصفوفة جزئية (نافذة) بطول k، من أقصى اليسار إلى أقصى اليمين.

تعريف الوسيط: العنصر الأوسط بعد ترتيب النافذة. إذا كان k زوجيًا، فالوسيط هو القيمة الصغرى من العنصرين الأوسطين. مثال: [1, 2, 3, 4] ← الوسيط = 2.

مرجع خارجي موثّق
  • CSES 1076 — Sliding Window Median (قسم Sliding Window): نفس المسألة تمامًا بصيغتها القياسية على منصة CSES Problem Set.

⚗️ محاكاة النافذة المنزلقة (بأزواج حقيقية)

هذا المختبر يُشغّل بنية ordered_set<pair<int,int>> فعليًا: كل خطوة تحذف زوج العنصر الخارج من النافذة وتُدرج زوج العنصر الداخل، ثم تستخرج الوسيط عبر find_by_order — تمامًا كما في الكود الحقيقي.

الكود الكامل للحل

sliding_window_median.cpp
#include <iostream>
using namespace std;

#include <ext/pb_ds/assoc_container.hpp>
#include <ext/pb_ds/tree_policy.hpp>
using namespace __gnu_pbds;

template<typename T>
using ordered_set = tree<T, null_type, less<T>, rb_tree_tag, tree_order_statistics_node_update>;

int main() {
    int n, k;
    cin >> n >> k;

    pair<int, int> a[n];
    for (int i = 0; i < n; i++) {
        cin >> a[i].first;
        a[i].second = i;  // الفهرس يضمن عدم التكرار
    }

    ordered_set<pair<int, int>> os;

    // أدخل النافذة الأولى
    for (int i = 0; i < k; i++) {
        os.insert(a[i]);
    }

    // حساب موضع الوسيط
    int median = (k % 2 == 0) ? k/2 - 1 : k/2;

    // طباعة وسيط النافذة الأولى
    pair<int, int> ans = *os.find_by_order(median);
    cout << ans.first << ' ';

    // التحرك عبر جميع النوافذ المتبقية
    for (int i = 0; i < n - k; i++) {
        os.erase(a[i]);      // احذف أول عنصر في النافذة
        os.insert(a[i + k]); // أضف العنصر الجديد

        pair<int, int> ans2 = *os.find_by_order(median);
        cout << ans2.first << ' ';
    }
    return 0;
}
// التعقيد الزمني: O(n log n)
// التعقيد المكاني: O(k)
🧠 بديل محمول لكل المترجمات — الفينويك تري (Fenwick / BIT)

إن لم يقبل الحكم PBDS، يمكن محاكاة نفس الفكرة بشجرة Fenwick (BIT) بعد ضغط الإحداثيات (Coordinate Compression):

• order_of_key(x) ≈ مجموع بادئة (Prefix Sum) لعدد العناصر حتى القيمة المضغوطة لـ x.
• find_by_order(k) ≈ "المشي الثنائي" (Binary Lifting) على شجرة Fenwick: نبدأ من أعلى قوة للعدد 2 لا تتجاوز حجم المصفوفة، وننزل بها تدريجيًا، متحركين للأمام كلما بقي المجموع التراكمي أقل من أو يساوي k.
كلا الأسلوبين O(log n)، لكن Fenwick يعمل مع أي مترجم قياسي دون الحاجة لمكتبات GNU الخاصة — الثمن هو كتابة أكواد أطول قليلًا وضغط الإحداثيات يدويًا.
