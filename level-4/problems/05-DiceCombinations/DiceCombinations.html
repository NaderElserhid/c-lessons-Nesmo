CSES 1633 — Dice Combinations (Dynamic Programming) cses.fi/problemset/task/1633 ↗

Your task is to count the number of ways to construct sum n by throwing a dice one or more times. Each throw produces an outcome between 1 and 6.

For example, if n=3, there are 4 ways:

  • 1+1+1
  • 1+2
  • 2+1
  • 3
Input

The only input line has an integer n.

Output

Print the number of ways modulo 10^9+7.

Constraints

1 ≤ n ≤ 10^6

Example
Input:
3

Output:
4

🗣️ بالعربية — ماذا يعني هذا فعليًا؟

نرمي نرد سداسي الأوجه (نتيجة كل رمية من 1 إلى 6) مرة واحدة أو أكثر، ونجمع نتائج كل الرميات. المطلوب: كم عدد التسلسلات المختلفة من الرميات التي مجموعها يساوي n بالضبط؟ الترتيب مهم هنا: التسلسل 1+2 يُعدّ مختلفًا عن 2+1، رغم أن مجموعهما نفس القيمة (3) — وهذا هو سبب وجود أربع طرق (وليس أقل) للوصول إلى المجموع 3.

ترجمة المثال المعطى (n=3)

الطرق الأربع: 1+1+1 (ثلاث رميات)، 1+2 (رميتان)، 2+1 (رميتان، بترتيب معكوس)، 3 (رمية واحدة). لاحظ أن الناتج المطلوب هو باقي القسمة على 10^9+7، لأن العدد الحقيقي للطرق يكبر بسرعة هائلة كلما زاد n.

S — الحالة (State)

التعريف

dp[x] = عدد الطرق (مع اعتبار الترتيب) للوصول إلى المجموع x بالضبط. المطلوب في النهاية هو dp[n].

R — علاقة التكرار (Recurrence)

للوصول إلى المجموع x، آخر رمية للنرد كانت لا بد إحدى القيم 1 إلى 6. إن كانت آخر رمية تساوي k، فإن المجموع قبلها كان x - k. إذن كل طريقة للوصول إلى x تتكوّن من: طريقة للوصول إلى x - k، ثم رمية أخيرة بقيمة k:

dp[x] = Σ dp[x - k] for k = 1..6, only terms with x - k ≥ 0 (mod 10^9+7)

T — الانتقالات (Transitions)

من المجاميع الأصغر إلى الأكبر: لكل x، ننظر إلى ما يصل إلى 6 حالات سابقة: dp[x-1], dp[x-2], ..., dp[x-6] (نتجاهل أي منها يكون أصغر من صفر). هذه هي "الحواف" في رسم بياني للـDP لدينا.

B — الحالات الأساسية (Base cases)

ماذا عن x = 0؟ يوجد بالضبط طريقة واحدة للوصول إلى المجموع 0: عدم رمي النرد إطلاقًا (تسلسل فارغ). إذن:

  • dp[0] = 1

  • لأي x < 0، نعامل dp[x] = 0 (لا توجد طرق للوصول إلى مجموع سالب).

O — ترتيب الحساب (Order of computation)

يجب حساب dp[x] بترتيب تصاعدي في x، لأن dp[x] يعتمد فقط على مجاميع أصغر منه: نبدأ من dp[0]، ثم dp[1], dp[2], ..., dp[n] بالترتيب.

خلاصة الحدس: قسّم المسألة عند آخر رمية نرد. الحالة = "عدد الطرق للوصول إلى مجموع معيّن". كل حالة تعتمد على ما يصل إلى 6 مجاميع سابقة. نبني الإجابات تصاعديًا من 0 حتى n.

💻 الكود الكامل مع شرح كل جزء

C++ — الحل الكامل
#include <iostream>
#include <vector>
using namespace std;

const int MOD = 1'000'000'007;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    vector<int> dp(n + 1, 0);
    dp[0] = 1;  // طريقة واحدة للوصول لمجموع 0: تسلسل فارغ

    for (int x = 1; x <= n; x++) {
        long long ways = 0;
        for (int k = 1; k <= 6; k++) {
            if (x - k >= 0) {
                ways += dp[x - k];
                if (ways >= MOD) ways -= MOD;  // تفادي الفيضان (overflow)
            }
        }
        dp[x] = (int)ways;
    }

    cout << dp[n] << '\n';
    return 0;
}

⚗️ المختبر التفاعلي — بناء جدول dp خطوة بخطوة

اختر قيمة n، ثم شاهد مصفوفة dp تُبنى فعليًا خلية بخلية أمامك: الخلايا الصفراء هي المجاميع الستة السابقة (x-1 حتى x-6) التي تُجمع لحساب الخلية الزرقاء الحالية x.

القيد الحقيقي على المنصة يصل إلى n ≤ 10^6، ونفس بالضبط الحلقة O(n) تعمل بسرعة كبيرة عليه — نُحدّد هنا الحجم بحد أقصى 40 فقط لوضوح العرض التفاعلي البصري.

اضغط «الخطوة التالية» أو «تشغيل تلقائي» للبدء.

📊 تحليل التعقيد ونصائح الحل

الجانبالتعقيدلماذا
الزمنO(n)كل قيمة x من 1 إلى n تُحسب بعدد ثابت من العمليات (حتى 6 عمليات جمع)، أي O(6n) = O(n).
الذاكرةO(n)مصفوفة dp بحجم n+1 فقط.

⚠️ أخطاء شائعة عند الحل على المنصة

  1. نسيان تطبيق الباقي (modulo): إغفال أخذ باقي القسمة على 10^9+7 يجعل القيم تتجاوز حدود الأنواع العددية بسرعة كبيرة جدًا كلما كبر n (العدد الحقيقي للطرق ينمو أُسّيًا تقريبًا).

  2. الجمع بنوع int مباشرة: جمع قيمتين كل منهما أصغر من MOD (~10^9) قد يتجاوز سعة int (~2.1×10^9) قبل تطبيق الباقي — استخدم long long أثناء الجمع كما في الكود أعلاه.

  3. إهمال فحص x - k ≥ 0: عند x الصغيرة (مثل x=1 أو x=2)، بعض قيم k من 1 إلى 6 ستُنتج فهرسًا سالبًا في المصفوفة — يجب تجاهل هذه الحالات صراحة، لا افتراض أنها تساوي صفرًا تلقائيًا دون فحص.

  4. الخلط بين "المجموعات" و"التسلسلات": المسألة تعتبر الترتيب مهمًا (1+2 و2+1 طريقتان منفصلتان) — لو كانت المسألة تسأل عن التركيبات (combinations) بدل التبديلات (permutations)، لاختلف الحل جذريًا (كما في مسائل Coin Combinations اللاحقة في نفس القسم).

🚀 مسائل تالية من نفس قسم Dynamic Programming على CSES

بعد إتقان هذا النمط الأساسي (DP خطي بعدد ثابت من الانتقالات لكل حالة)، القسم نفسه يحتوي: Minimizing Coins (نفس البنية لكن نبحث عن أقل عدد رميات/عملات بدل عدد الطرق)، وCoin Combinations I (نفس المسألة تمامًا لكن بمجموعة قيم عامة بدل 1..6 فقط)، وCoin Combinations II (نفس الأخيرة، لكن الترتيب لا يهم هذه المرة — أي نطلب التركيبات لا التبديلات، وهذا يغيّر ترتيب الحلقات في الكود). مقارنة الحلول الأربعة معًا طريقة ممتازة لفهم كيف يُغيّر تفصيل صغير في نص المسألة بنية الحل بالكامل.
