Labyrinth — المتاهة

مسألة CSES 1193 من قسم Graph Algorithms — أوجد أقصر مسار داخل متاهة باستخدام البحث بالعرض أولاً (BFS)، ثم أعد بناء المسار نفسه خطوة بخطوة. هذه الصفحة تُجهّزك لفهم نص المسألة كما يظهر تمامًا على المنصة، وتشرح الحل سطرًا بسطر، وتضع بين يديك مختبرًا تفاعليًا حيًا لتجربة الخوارزمية بنفسك قبل حلّها فعليًا.

📄 نص المسألة كما يظهر على CSES

حين تفتح هذه المسألة على المنصة ستجدها باللغة الإنجليزية بالضبط كما هي أدناه — من المهم أن تتعوّد على قراءة نص المسألة الأصلي مباشرةً بدلًا من الاعتماد فقط على الترجمة، لأن التفاصيل الدقيقة (مثل صيغة الإخراج أو حالات خاصة) تُصاغ دائمًا بعناية في النص الإنجليزي.

CSES 1193 — Labyrinth (Graph Algorithms) cses.fi/problemset/task/1193 ↗

You are given a map of a labyrinth, and your task is to find a path from start to end. You can walk left, right, up and down.

Input

The first input line has two integers n and m: the height and width of the map.

Then there are n lines of m characters describing the labyrinth. Each character is . (floor), # (wall), A (start), or B (end). There is exactly one A and one B in the input.

Output

First print "YES", if there is a path, and "NO" otherwise.

If there is a path, print the length of the shortest such path and its description as a string consisting of characters L (left), R (right), U (up), and D (down). You can print any valid solution.

Constraints

1 ≤ n, m ≤ 1000

Example
Input:
5 8
########
#.A#...#
#.##.#B#
#......#
########

Output:
YES
9
LDDRRRRRU

🗣️ بالعربية — ماذا يعني هذا فعليًا؟

لديك شبكة (grid) من n صفًا و m عمودًا. كل خلية إمّا أرضية . يمكن المشي عليها، أو جدار # لا يمكن عبوره، أو نقطة البداية A، أو نقطة النهاية B (وكلتاهما تُعاملان كأرضية يمكن الوقوف عليها). تتحرك خطوة واحدة في كل مرة، في أحد الاتجاهات الأربعة فقط (لا حركة قطرية).

المطلوب بدقة

1) اطبع YES إذا وُجد مسار من A إلى B، وإلا اطبع NO فقط وتوقف.
2) إذا وُجد مسار، اطبع في السطر التالي طول أقصر مسار (عدد الخطوات)، ثم في السطر الذي يليه سلسلة من الحروف L/R/U/D تصف الحركات بالترتيب من A إلى B.
3) أي مسار بأقصر طول مقبول — لا يشترط أن يطابق مثال الحل تمامًا.

🔎 تتبّع المثال المعطى خطوة بخطوة

هذه هي نفس المتاهة من المثال، معروضة هنا بصريًا (A أخضر، B أحمر). المسار المُعطى في الحل LDDRRRRRU طوله 9 حركات — جرّب اتّباعه بإصبعك: يسار، أسفل، أسفل، يمين×5، أعلى، لتصل من A إلى B.

لاحظ أن الحكم (judge) على CSES يقبل أي مسار بنفس الطول الأقصر — إذا سلكت مسارًا مختلفًا لكنه أيضًا بطول 9، سيُقبل الحل. سنتحقق من هذا لاحقًا في تبويب «المختبر».

💡 لماذا BFS تحديدًا؟

حوّل المتاهة إلى رسم بياني (graph): كل خلية أرضية (أو A أو B) هي عقدة، وبين كل خليتين متجاورتين (يمين/يسار/أعلى/أسفل، كلاهما ليس جدارًا) حافة بوزن 1. المطلوب هو أقصر مسار بعدد الحواف من A إلى B — وهذا بالضبط ما يضمنه BFS في رسم بياني غير مُوزَّن (كل الحواف بنفس الوزن).

الخوارزميةهل تضمن أقصر مسار؟لماذا (أو لماذا لا)
BFSنعم ✓تستكشف العقد بترتيب تصاعدي صارم للمسافة من المصدر (طبقة تلو طبقة)، فأول مرة تصل فيها لعقدة تكون مسافتها هي الأقصر فعلًا.
DFSلا ✗تتعمّق في مسار واحد حتى نهايته قبل تجربة غيره، فقد تصل إلى B عبر مسار طويل وملتوٍ رغم وجود مسار أقصر لم تُجرّبه بعد.
Dijkstraنعم، لكنه مبالغةيعمل بشكل صحيح حتى مع أوزان مختلفة، لكنه هنا أبطأ من BFS بلا داعٍ (O((V+E)log V) بدلًا من O(V+E)) لأن كل الأوزان أصلًا متساوية.

🧭 خطة الحل الكاملة

  1. اقرأ الشبكة وحدّد موضعي A وB بمسح كل الخلايا.

  2. شغّل BFS من A، مع مصفوفتين إضافيتين لكل خلية: dist (المسافة من A، ‎-1‎ تعني لم تُزر بعد) وparDir (اتّجاه الحركة التي أوصلتنا إلى هذه الخلية من أبيها في شجرة BFS).

  3. إذا ظلّت dist[B] = -1 بعد انتهاء BFS، فلا يوجد مسار → اطبع NO.

  4. إذا وُجد مسار، اطبع YES ثم dist[B]، ثم أعد بناء المسار بالمشي من B إلى A عكسيًا باستخدام parDir، واعكس السلسلة الناتجة في النهاية لأنها بُنيت من B إلى A لا من A إلى B.

لماذا نُخزّن اتّجاه الحركة لا "الأب" مباشرةً؟ تخزين حرف واحد (U/D/L/R) بدلًا من إحداثيات الأب الكاملة يوفّر الذاكرة (char بدلًا من pair<int,int>) ويكفي تمامًا لإعادة بناء المسار، لأننا نعرف دائمًا كيف نعكس كل حركة (المعاكس لأعلى هو أسفل، والمعاكس لليمين هو اليسار).

🎯 نقطة دقيقة: أي مسار "أقصر" تجده BFS أولاً؟

عندما توجد عدة مسارات بنفس الطول الأقصر، فإن المسار الذي يُعاد بناؤه يعتمد على ترتيب فحص الاتجاهات الأربعة داخل حلقة BFS (في الكود المُعطى: U ثم D ثم L ثم R). لو بدّلنا هذا الترتيب، قد نحصل على سلسلة حروف مختلفة تمامًا لكن بنفس الطول — وكلاهما صحيح لأن المسألة تقبل «أي حل صحيح» صراحةً.

💻 الكود الكامل مع شرح كل جزء

C++ — الحل الكامل
#include <iostream>
#include <vector>
#include <string>
#include <queue>
#include <utility>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector<string> grid(n);
    for (int i = 0; i < n; i++) cin >> grid[i];

    pair<int, int> A {-1, -1}, B {-1, -1};
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            if (grid[i][j] == 'A') A = {i, j};
            if (grid[i][j] == 'B') B = {i, j};
        }
    }

    vector<vector<int>> dist(n, vector<int>(m, -1));
    vector<vector<char>> parDir(n, vector<char>(m, 0));

    queue<pair<int, int>> q;
    dist[A.first][A.second] = 0;
    q.push(A);

    // Directions: (dr, dc, moveChar)
    const int dr[4] = {-1, 1, 0, 0};
    const int dc[4] = {0, 0, -1, 1};
    const char mv[4] = {'U', 'D', 'L', 'R'};

    while (!q.empty()) {
        auto [r, c] = q.front(); q.pop();

        for (int k = 0; k < 4; k++) {
            int nr = r + dr[k];
            int nc = c + dc[k];

            if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;
            if (grid[nr][nc] == '#') continue;
            if (dist[nr][nc] != -1) continue;

            dist[nr][nc] = dist[r][c] + 1;
            parDir[nr][nc] = mv[k];
            q.push({nr, nc});
        }
    }

    if (dist[B.first][B.second] == -1) {
        cout << "NO\n";
        return 0;
    }

    cout << "YES\n";
    cout << dist[B.first][B.second] << "\n";

    // Reconstruct path from B back to A
    string path;
    int r = B.first, c = B.second;
    while (!(r == A.first && c == A.second)) {
        char d = parDir[r][c];
        path.push_back(d);

        // Move to parent (reverse the move)
        if (d == 'U') r += 1;
        else if (d == 'D') r -= 1;
        else if (d == 'L') c += 1;
        else if (d == 'R') c -= 1;
    }

    reverse(path.begin(), path.end());
    cout << path << "\n";
    return 0;
}

🧩 أهم جزء: كيف تعمل إعادة بناء المسار؟

هذا الجزء يُربك كثيرًا من الطلاب لأول وهلة، فلنُفكّكه بمثال حقيقي من المسألة نفسها. لدينا parDir[2][6] = 'U' عند B — ومعناها: «وصلنا إلى (2,6) عبر حركة للأعلى». إذن لكي نرجع للخلف من B نحو أبيها، يجب أن نتحرك بعكس الأعلى، أي للأسفل: r += 1. بهذا المنطق بالضبط يُبنى الشرط الكامل:

الحركة المُخزَّنة (كيف وصلنا للخلية)الحركة العكسية (للرجوع للأب)
U (تحرّكنا للأعلى)r += 1 (ننزل صفًا)
D (تحرّكنا للأسفل)r -= 1 (نصعد صفًا)
L (تحرّكنا لليسار)c += 1 (نرجع عمودًا لليمين)
R (تحرّكنا لليمين)c -= 1 (نرجع عمودًا لليسار)

تتبّع كامل مطابق للمثال: بدءًا من B=(2,6): U→(3,6)، R→(3,5)، R→(3,4)، R→(3,3)، R→(3,2)، R→(3,1)، D→(2,1)، D→(1,1)، L→(1,2)=A. السلسلة المُجمَّعة أثناء الرجوع هي U R R R R R D D L، وبعد عكسها (reverse) نحصل بالضبط على L D D R R R R R U — وهي إجابة المثال المُعطى حرفيًا! جرّب هذا التتبّع بنفسك في تبويب «المختبر».

⚗️ المختبر التفاعلي — حلّال المتاهة بالـ BFS

هذا المختبر يُشغّل نفس الخوارزمية بالضبط من الكود أعلاه (نفس ترتيب الاتجاهات U→D→L→R، ونفس منطق إعادة البناء بالعكس) على متاهة تختارها أنت. ارسم متاهتك الخاصة، أو استخدم مثال المسألة، أو ولّد متاهة عشوائية، ثم شاهد موجات BFS تتوسّع طبقةً بعد طبقة حتى الوصول إلى B، تليها إعادة بناء المسار الفعلي.

القيود الحقيقية على المنصة تصل إلى 1000×1000 خلية، لكن نُحدّد الحجم هنا (حتى 20×28) للحفاظ على وضوح الرسم والتفاعل السلس — الخوارزمية المُنفَّذة هي نفسها تمامًا بغض النظر عن الحجم.

اختر أداة الرسم ثم اضغط على أي خلية في الشبكة:

خلية زُارها BFS الموجة الحالية المسار النهائي
ارسم متاهتك (أو اختر «مثال المسألة») ثم اضغط «ابدأ BFS».

📊 تحليل التعقيد ونصائح الحل

الجانبالتعقيدلماذا
الزمنO(n × m)كل خلية تدخل قائمة الانتظار مرة واحدة فقط (بفضل فحص dist != -1)، وعند معالجتها نفحص جيرانها الأربعة في زمن ثابت O(1) — المجموع الكلي O(n×m).
الذاكرةO(n × m)مصفوفتا dist وparDir بحجم n×m، بالإضافة لقائمة الانتظار التي لا تتجاوز حجمها n×m في أسوأ الحالات.

لأقصى مدخل ممكن (1000×1000 = 1,000,000 خلية)، فإن O(n×m) تعني مليون عملية تقريبًا — أقل بكثير من حد الثانية الواحدة، حتى مع هامش أمان كبير.

⚠️ أخطاء شائعة عند الحل على المنصة

  1. استخدام DFS بدلًا من BFS: DFS قد يجد مسارًا صحيحًا لكن ليس بالضرورة الأقصر، وسيُرفض الحل حتى لو كانت "YES" صحيحة.

  2. قلب اتجاه العكس عند إعادة البناء: الخطأ الأكثر شيوعًا هو كتابة if (d=='U') r -= 1 (بدلًا من +=) بالخلط بين «الحركة التي وصلتنا للخلية» و«الحركة للرجوع منها» — راجع الجدول في تبويب «الكود» إن التبس عليك الأمر.

  3. نسيان طباعة "NO" فقط دون أسطر إضافية: إذا لم يوجد مسار، يجب أن يكون الإخراج بالكامل هو السطر "NO" ولا شيء غيره.

  4. القراءة البطيئة: مع شبكة قد تصل إلى مليون خلية، تجاهل ios::sync_with_stdio(false) قد يتسبّب بتجاوز حد الوقت (Time Limit Exceeded) رغم صحة الخوارزمية.

  5. إصدار المترجم: Structured Bindings (auto [r, c] = ...) تتطلب C++17 على الأقل — تأكد من اختيار C++17 أو أحدث عند الإرسال على CSES.

🚀 تحدٍّ إضافي: ماذا لو كان هناك أكثر من نقطة بداية أو نهاية؟

لو كانت المسألة تسمح بعدة نقاط بداية (متعدّدة المصادر)، يمكن تعميم نفس الفكرة بـ Multi-Source BFS: بدلًا من دفع A واحدة فقط في قائمة الانتظار في البداية، ندفع كل نقاط البداية معًا بمسافة 0. تبقى الخوارزمية صحيحة تمامًا لأن BFS لا يهتم من أي مصدر بدأت العقدة، طالما جميع المصادر تبدأ بنفس المسافة الأولية 0. هذا نمط شائع جدًا في مسائل الشبكات (مثل "أقرب نار تنتشر من عدة نقاط" أو "أقرب مستشفى" في مسائل أخرى).
