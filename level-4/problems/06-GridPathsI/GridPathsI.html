Grid Paths I — عدّ المسارات في شبكة بها فخاخ

مسألة CSES 1638 من قسم Dynamic Programming — نمتلك شبكة n×n قد تحتوي بعض المربعات على فخاخ لا يُسمح بالمرور عليها، والمطلوب حساب عدد المسارات من الزاوية العلوية اليسرى إلى الزاوية السفلية اليمنى، مع السماح بالحركة لليمين أو للأسفل فقط. امتداد طبيعي لفكرة Dice Combinations، لكن هذه المرة الحالة ثنائية الأبعاد (i, j) بدل بُعد واحد.

CSES 1638 — Grid Paths I (Dynamic Programming) cses.fi/problemset/task/1638 ↗

Consider an n × n grid whose squares may have traps. It is not allowed to move to a square with a trap.

Your task is to calculate the number of paths from the upper-left square to the lower-right square. You can only move right or down.

Input

The first input line has an integer n: the size of the grid.

After this, there are n lines that describe the grid. Each line has n characters: . denotes an empty cell, and * denotes a trap.

Output

Print the number of paths modulo 10^9+7.

Constraints

1 ≤ n ≤ 1000

Example
Input:
4
....
.*..
...*
*...

Output:
3

🗣️ بالعربية — ماذا يعني هذا فعليًا؟

لدينا شبكة مربعة بحجم n×n، بعض مربعاتها "فخاخ" (*) يُمنع المرور عليها إطلاقًا. نبدأ من الزاوية العلوية اليسرى، ويُسمح لنا فقط بالتحرّك خطوة واحدة إما لليمين أو للأسفل في كل مرة، والمطلوب: كم عدد المسارات المختلفة الممكنة للوصول إلى الزاوية السفلية اليمنى دون المرور بأي فخ؟

ترجمة المثال المعطى

في شبكة 4×4 المعطاة، توجد 3 مسارات صحيحة فقط تتجنّب كل الفخاخ الأربعة (عند المواقع (1,1)، (2,3)، (3,0) بترقيم يبدأ من صفر) وتصل من الزاوية (0,0) إلى الزاوية (3,3).

S — الحالة (State)

التعريف

dp[i][j] = عدد المسارات الصحيحة من الخلية (0,0) إلى الخلية (i,j)، مع الالتزام بالتحرّك يمينًا أو أسفل فقط، وعدم دخول أي فخ. المطلوب أخيرًا هو dp[n-1][n-1].

R — علاقة التكرار (Recurrence)

لخلية غير فخّ (grid[i][j] == '.'): أي مسار يصل إلى (i,j) لا بد أنه أتى إما من الأعلى (i-1,j) أو من اليسار (i,j-1)، لأن الحركة المسموحة فقط يمينًا أو أسفل — لا توجد طريقة أخرى للوصول:

dp[i][j] = dp[i-1][j] + dp[i][j-1] (mod 10^9+7, indices خارج الحدود = 0)

أما إذا كانت الخلية فخًّا (grid[i][j] == '*')، فلا يمكننا الوقوف عليها إطلاقًا: dp[i][j] = 0.

T — الانتقالات (Transitions)

transition.cpp
if (grid[i][j] == '*') dp[i][j] = 0;
else if (i == 0 && j == 0) dp[i][j] = 1;
else {
    long long from_up   = (i > 0 ? dp[i-1][j] : 0);
    long long from_left = (j > 0 ? dp[i][j-1] : 0);
    dp[i][j] = (from_up + from_left) % MOD;
}

B — الحالات الأساسية (Base cases)

  • خلية البداية (0,0): إذا كانت فخًّا، فلا يوجد أي مسار إطلاقًا (dp[0][0] = 0، ويُغطّى تلقائيًا بقاعدة الفخّ العامة). إذا كانت فارغة، فهناك طريقة واحدة بالضبط "للبدء" هناك: dp[0][0] = 1.

  • الصف الأول (i=0, j>0): لا يمكن الوصول إليه إلا من اليسار (لا يوجد صف أعلاه). العلاقة العامة مع dp[i-1][j]=0 تُعطي هذا تلقائيًا دون أي حالة خاصة إضافية.

  • العمود الأول (j=0, i>0): بالمثل، لا يمكن الوصول إليه إلا من الأعلى، وتُغطّيه العلاقة العامة مع dp[i][j-1]=0.

إذن كل الحالات الخاصة مُغطّاة تلقائيًا بالقاعدة العامة مع فحوصات الحدود، دون الحاجة لأي معالجة إضافية منفصلة للصف الأول أو العمود الأول.

O — ترتيب الحساب (Order of computation)

نمرّ على الخلايا بترتيب "صف أولًا" (row-major): حلقة خارجية i من 0 إلى n-1، وحلقة داخلية j من 0 إلى n-1. عند حساب dp[i][j]، نحتاج فقط إلى dp[i-1][j] (الصف السابق) وdp[i][j-1] (العمود السابق في نفس الصف) — وكلاهما محسوب بالفعل، لأن i-1 < i وj-1 < j.

مقارنة سريعة مع Dice Combinations: هناك كانت الحالة dp[x] تعتمد على حتى 6 قيم سابقة على محور واحد. هنا الحالة dp[i][j] تعتمد على قيمتين سابقتين فقط، لكن على محورين مختلفين (صف وعمود) — نفس فلسفة "ابنِ الإجابة من إجابات أصغر محسوبة مسبقًا"، فقط بأبعاد إضافية.

💻 الكود الكامل مع شرح كل جزء

C++ — الحل الكامل
#include <iostream>
#include <vector>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    vector<string> grid(n);
    for (int i = 0; i < n; ++i) {
        cin >> grid[i];
    }

    // dp[i][j] = عدد الطرق للوصول إلى (i, j)
    vector<vector<long long>> dp(n, vector<long long>(n, 0));

    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            if (grid[i][j] == '*') {
                dp[i][j] = 0;  // لا يمكن استخدام الفخاخ
                continue;
            }

            if (i == 0 && j == 0) {
                dp[i][j] = 1;  // خلية البداية (إن لم تكن فخًّا)
            } else {
                long long from_up   = (i > 0 ? dp[i - 1][j] : 0);
                long long from_left = (j > 0 ? dp[i][j - 1] : 0);
                dp[i][j] = (from_up + from_left) % MOD;
            }
        }
    }

    cout << dp[n - 1][n - 1] << "\n";
    return 0;
}

🔍 شرح مفصّل لكل جزء

vector<string> grid(n);نخزّن كل سطر من الشبكة كسلسلة نصية كاملة (بدل مصفوفة أحرف)، فيسهل الوصول لأي خلية عبر grid[i][j].
vector<vector<long long>> dp(n, ...)جدول ثنائي الأبعاد بحجم n×n، كل عناصره مُهيّأة بصفر ابتداءً — وهذا الصفر الافتراضي هو بالضبط ما نحتاجه لخلايا الفخاخ.
if (grid[i][j] == '*') { dp[i][j] = 0; continue; }قاعدة الفخّ: لا مسارات صحيحة تمرّ عبر هذه الخلية، وننتقل مباشرة للخلية التالية دون أي حساب إضافي.
if (i == 0 && j == 0) dp[i][j] = 1;الحالة الأساسية: خلية البداية (إن لم تكن فخًّا) تُهيَّأ بطريقة واحدة، تمامًا مثل dp[0] = 1 في Dice Combinations.
from_up و from_left مع فحص الحدودنتحقّق أن i > 0 قبل قراءة dp[i-1][j] (تفاديًا للخروج عن حدود المصفوفة)، وبالمثل لـj > 0. هذا التحقّق هو ما يجعل الصف الأول والعمود الأول يُحسبان بشكل صحيح تلقائيًا دون قواعد خاصة منفصلة.
(from_up + from_left) % MODتطبيق الباقي مباشرة بعد الجمع — تمامًا كما في Dice Combinations، لتفادي نمو القيم الحقيقية بلا حدود.

لماذا long long هنا مباشرة (وليس int مع تحويل لاحق)؟ بعكس Dice Combinations حيث استُخدم int للتخزين بعد التصحيح اليدوي للفيضان، هنا خُزِّن الجدول بالكامل كـvector<vector<long long>> منذ البداية — كلا الأسلوبين صحيح؛ المهم فقط أن أي عملية جمع بين قيمتين قريبتين من MOD يجب أن تتم بنوع يتّسع لضعف MOD تقريبًا قبل تطبيق الباقي.

⚗️ المختبر التفاعلي — بناء جدول dp خلية بخلية

اكتب شبكتك الخاصة بصيغة الإدخال على CSES بالضبط (n في السطر الأول، ثم n سطرًا كل منها n حرفًا من . أو *)، أو حمّل مثال المسألة، أو ولّد شبكة عشوائية — ثم شغّل الخوارزمية خطوة بخطوة. الخلايا الصفراء هي مصدرا القيمة (الأعلى واليسار) التي تُجمع لحساب الخلية الزرقاء الحالية.

القيد الحقيقي على المنصة يصل إلى n ≤ 1000، لكن نُحدّد الحجم هنا بحد أقصى 12×12 فقط لوضوح العرض التفاعلي البصري — نفس الخوارزمية الحقيقية بلا أي تغيير تعمل على أي حجم.

اضغط «الخطوة التالية» أو «تشغيل تلقائي» للبدء.

📊 تحليل التعقيد ونصائح الحل

الجانبالتعقيدلماذا
الزمنO(n²)يوجد n×n خلية، ولكل خلية عمل O(1) (نظرتان فقط للأعلى واليسار). لـn ≤ 1000، هذا حتى 10^6 عملية — سريع جدًا.
الذاكرةO(n²)جدول dp بحجم n×n بالكامل.

⚠️ أخطاء شائعة عند الحل على المنصة

  1. نسيان قاعدة الفخّ قبل أي حساب آخر: يجب التحقّق من grid[i][j] == '*' أولًا وتعيين dp[i][j] = 0 فورًا، قبل محاولة إضافة from_up وfrom_left — وإلا فقد يُحسب مسار وهمي يمرّ عبر فخّ.

  2. إغفال فخّ خلية البداية أو النهاية: إن كانت خلية البداية (0,0) نفسها فخًّا، فالإجابة صفر تلقائيًا (لا مسارات إطلاقًا) — قاعدة الفخّ العامة تتكفّل بهذا دون أي فحص خاص إضافي، لكن يجب عدم الخلط بينها وبين حالة "البداية فارغة" في الكود.

  3. قراءة الشبكة بترتيب خاطئ: السطر الأول من الشبكة (grid[0]) هو الصف العلوي (i=0)، والحرف الأول في كل سطر (grid[i][0]) هو العمود الأيسر (j=0) — عكس هذا الترتيب يُنتج شبكة مختلفة تمامًا عن المقصودة.

  4. تجاهل الباقي (modulo): كما في Dice Combinations، عدد المسارات الحقيقي في شبكة كبيرة يمكن أن يكبر بسرعة هائلة (يشبه نمو معاملات ذات الحدين)، فيجب تطبيق الباقي على 10^9+7 عند كل عملية جمع، وليس فقط في النهاية.

🚀 لماذا "Grid Paths I" وليس فقط "Grid Paths"؟

الرقم "I" في اسم المسألة يلمّح عادة إلى وجود نسخة "II" أصعب في نفس المجموعة على منصات أخرى (مثل نمط Coin Combinations I/II الذي رأيناه في Dice Combinations) — غالبًا بقيود أكبر تمنع الحل التربيعي البسيط O(n²) وتتطلّب تقنية أكثر تقدّمًا. الدرس العام: عندما ترى رقمًا في اسم مسألة، افترض أن هناك نسخة تالية تبني على نفس الفكرة الأساسية بقيد إضافي يكسر الحل الساذج.
