AtotheNmodM — هل M تقسم A^N؟

مسألة نظرية أعداد: بأعداد طبيعية A وN وM، حدّد هل العدد A^N (الذي قد يكون ضخمًا بشكل فلكي) قابل للقسمة على M بالتمام. المفتاح: لا نحسب A^N إطلاقًا — بل نحلّل M إلى عوامله الأوّلية ونقارن أُسّ كل عامل أوّلي في A^N (محسوبًا بالضرب لا بالحساب المباشر) بأُسّه المطلوب في M.

الصعوبةمتوسط
القيود1 ≤ A,N,M ≤ 10^9
التعقيدO(√M + log A)
مصدر المسألة (Mawhiba Booklets)
1

📄 نص المسألة

هذه المسألة ليست من CSES أو Codeforces، بل من دفاتر Mawhiba التدريبية (لا يوجد لها رابط حكم إلكتروني مباشر للإرسال) — لكننا وثّقناها هنا بنفس منهجية التحقّق المتّبعة في هذه السلسلة. هذا هو النص كما ورد:

AtotheNmodM (Mawhiba Booklets — Number Theory) mawhiba booklet ↗

Given natural numbers A, N, and M. Determine whether the number A^N is divisible by M.

Note: Pay attention that the number A^N can be extremely large - it is recommended to factorize numbers A and M and analyze their prime factors!

Input

The first and only line of standard input contains, in order, the natural numbers A, N, and M.

Output

Print "YES" if the number A^N is divisible by M, otherwise print "NO".

Constraints

1 ≤ A, N, M ≤ 10^9

If this task is too hard for you, try solving it when A and M are both powers of two. Or, if it's still too hard, try solving it when 1 ≤ N ≤ 2.

Example
Input:
10 2 50

Output:
YES

🗣️ بالعربية — ماذا يعني هذا فعليًا؟

نُعطى ثلاثة أعداد طبيعية A وN وM، والمطلوب فقط الإجابة بـ"نعم" أو "لا" عن سؤال واحد: هل M يقسم A^N بالتمام (بدون باقٍ)؟ التحدّي الحقيقي هنا ليس رياضيًا معقّدًا، بل حجميًا: A^N يمكن أن يكون رقمًا بمليارات الخانات (تخيّل A=10^9 وN=10^9) — لا يمكن تخزينه ولا حسابه مباشرة بأي نوع بيانات مهما كان، ولا حتى بمكتبات الأعداد الكبيرة ضمن حدود الوقت المعطاة.

ترجمة المثال المعطى

A=10, N=2, M=50: هنا A^N = 10^2 = 100، وهو رقم صغير يمكن حسابه مباشرة للتحقّق: 100 ÷ 50 = 2 بالضبط (بدون باقٍ) → YES. لكن هذا الحساب المباشر لن يعمل إطلاقًا لو كان N كبيرًا — وهنا يأتي دور تحليل الأعداد الأوّلية.

تدرّج في الصعوبة: تقترح المسألة نفسها حلّ نسخة أسهل أولًا: جرّب افتراض أن A وM كلاهما قوى للعدد 2 (فيصبح تحليلهما فوريًا)، ثم إن كانت لا تزال صعبة جرّب افتراض N ≤ 2 (فيصبح A^N صغيرًا نسبيًا لبعض الحالات). هذا نفس أسلوب "ابدأ بنسخة مبسّطة من القيود" الذي رأيناه في Product of Squares.

2

💡 فكرة الحل: قارن الأُسّ الأوّلي، لا الرقم نفسه

A^N قد يكون فلكيًا، لكن لا نحتاج لمعرفة قيمته الفعلية — نحتاج فقط لمعرفة: هل هو "مركّب بما يكفي" من عوامل M الأوّلية؟ وهذا سؤال عن الأُسس الأوّلية فقط، لا عن القيمة الكاملة.

الخطوة 1: حلّل M إلى عوامله الأوّلية

M = p1e1 × p2e2 × ... × pkek

الخطوة 2: احسب أُسّ كل عامل أوّلي داخل A

ليكن v_p(x) هو أُسّ العامل الأوّلي p داخل تحليل x (كم مرة يقسم p العدد x). المفتاح الرياضي: عندما نرفع A للقوة N، فإن أُسّ كل عامل أوّلي يُضرب في N ببساطة:

vp(AN) = N × vp(A)

هذا لأن A^N يعني ضرب A في نفسه N مرة، فكل عامل p موجود في A يتكرر N مرة أيضًا.

الخطوة 3: الشرط الكامل للقسمة

M تقسم A^N بالتمام إذا وفقط إذا كان أُسّ كل عامل أوّلي من عوامل M موجودًا بكمية كافية داخل A^N:

M | AN  ⇔  لكل i: N × vpi(A) ≥ ei

الخوارزمية النهائية

  1. إذا كان M = 1: الإجابة YES فورًا (أي عدد يقبل القسمة على 1).

  2. حلّل M إلى عوامل أوّلية p^e (بالقسمة التجريبية، تمامًا كما في فصل Prime Factorization).

  3. لكل عامل أوّلي p من عوامل M: احسب v = v_p(A). إن كان v = 0، فإن A^N لا يحتوي هذا العامل إطلاقًا → الإجابة NO فورًا.

  4. وإلا، تحقّق من الشرط N × v ≥ e. لتفادي ضرب N في v (قد يكون كبيرًا)، نُعيد كتابة الشرط كـN ≥ ⌈ e / v ⌉ — قسمة بدل ضرب، بلا أي خطر فيضان (overflow).

  5. إذا نجحت كل العوامل الأوّلية في الاختبار، الإجابة YES؛ وإلا NO عند أول فشل.

لماذا N ≥ ⌈e/v⌉ بدل N×v ≥ e مباشرة؟ رياضيًا الشرطان متكافئان تمامًا لو استخدمنا أعدادًا حقيقية، لكن N×v قد يكبر (حتى 10^9 × 30 ≈ 3×10^10) بينما ⌈e/v⌉ يبقى صغيرًا جدًا (أقل من 31 دائمًا، لأن e ≤ log₂(10^9) ≈ 30). إعادة كتابة الشرط بهذا الشكل ليست ضرورية هنا لتفادي فيضان فعلي (فـlong long يتّسع لذلك بسهولة)، لكنها عادة ممتازة: قسّم بدل أن تضرب كلما أمكن ذلك دون تغيير المعنى.

💻 الكود الكامل مع شرح كل جزء

C++ — الحل الكامل
#include <iostream>
using namespace std;

long long ceil_div(long long a, long long b) {
    // b > 0
    return (a + b - 1) / b;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long A, N, M;
    cin >> A >> N >> M;

    if (M == 1) {
        cout << "YES\n";
        return 0;
    }

    long long m = M;

    // حلّل M: m = حاصل ضرب p^e
    for (long long p = 2; p * p <= m; ++p) {
        if (m % p != 0)
            continue;

        long long e = 0;
        while (m % p == 0) {
            m /= p;
            e++;
        }

        // احسب v_p(A)
        long long v = 0;
        long long tempA = A;
        while (tempA % p == 0) {
            tempA /= p;
            v++;
        }

        if (v == 0) {
            cout << "NO\n";
            return 0;
        }

        // نحتاج N * v >= e  <=>  N >= ceil(e / v)
        long long need = ceil_div(e, v);
        if (N < need) {
            cout << "NO\n";
            return 0;
        }
    }

    // إن تبقّى m > 1، فهو عامل أوّلي بأُسّ 1
    if (m > 1) {
        long long p = m;
        long long e = 1;

        long long v = 0;
        long long tempA = A;
        while (tempA % p == 0) {
            tempA /= p;
            v++;
        }

        if (v == 0) {
            cout << "NO\n";
            return 0;
        }

        long long need = ceil_div(e, v);  // e=1 => need=1 دائمًا لو v>=1
        if (N < need) {
            cout << "NO\n";
            return 0;
        }
    }

    cout << "YES\n";
    return 0;
}

🔍 شرح مفصّل لكل جزء

ceil_div(a, b)تحسب ⌈a/b⌉ بأعداد صحيحة فقط دون أي أعداد عشرية، عبر الحيلة الكلاسيكية (a + b - 1) / b (تعمل بشرط b > 0، وهو محقَّق دائمًا هنا لأن v ≥ 1 عند هذه النقطة من الكود).
if (M == 1) { ... }حالة خاصة صريحة: أي عدد يقبل القسمة على 1، وحلقة تحليل M إلى عوامل ستفشل بلا معنى لو تركناها تعمل على m=1 (فلن يوجد أي p يقسمها).
for (long long p = 2; p * p <= m; ++p)القسمة التجريبية القياسية لتحليل m إلى عوامل أوّلية بتعقيد O(√M) — نفس الأسلوب تمامًا من فصل Prime Factorization، لكن مطبَّقًا هنا على M بدل عدد عام.
while (m % p == 0) { m /= p; e++; }نستخرج الأُسّ الكامل e لهذا العامل الأوّلي من M (وليس فقط التحقّق من وجوده)، تمامًا كما في التحليل الأوّلي الكامل.
حساب v بنفس الطريقة لكن على Aنفس منطق استخراج الأُسّ، لكن مطبَّق على tempA (نسخة من A) بدل m — نحرص على عدم تعديل A الأصلي لأننا سنحتاجه لكل عامل أوّلي لاحق.
if (v == 0) { NO }إن لم يقسم p العدد A إطلاقًا، فمهما رفعنا A للقوة N فلن يظهر p فيه أبدًا — النتيجة NO فورية دون أي حاجة لحساب N.
if (m > 1) { ... } بعد الحلقةالقسمة التجريبية تتوقف عند p*p > m؛ إن تبقّى m > 1 بعدها، فهذا يعني أن m نفسها عامل أوّلي واحد متبقٍّ بأُسّ 1 (نفس النمط المستخدم في فصل Prime Factorization بالضبط).

لماذا لا نحسب A^N مباشرة أبدًا؟ حتى لو استخدمنا long long أو أعدادًا كبيرة (big integers)، فإن A^N بقيم A,N حتى 10^9 قد يحتوي على مليارات الخانات العشرية — تخزين هذا الرقم وحده يحتاج ذاكرة تفوق أي حاسوب عادي بكثير، ناهيك عن الوقت اللازم لحسابه. هذا مثال جوهري على أهمية "إعادة صياغة المسألة رياضيًا" بدل محاولة الحساب المباشر (Brute Force) عندما تكون الأرقام المتوقّعة ضخمة بشكل غير عملي.

⚗️ المختبر التفاعلي — تحقّق خطوة بخطوة

أدخل A وN وM (حتى القيمة الحقيقية القصوى 10^9)، ثم شغّل الخوارزمية الحقيقية خطوة بخطوة لمشاهدة كل عامل أوّلي من عوامل M يُستخرَج، وحساب v وneed له، والتحقّق من الشرط — تمامًا مثل الكود أعلاه، دون حساب A^N إطلاقًا في أي لحظة.

اضغط «الخطوة التالية» أو «تشغيل تلقائي» للبدء.

لاحظ أن هذا المختبر يعمل بأمان على القيم القصوى الحقيقية (حتى 10^9) دون أي مشاكل أداء، لأن الخوارزمية بأكملها تعتمد على التحليل الأوّلي والقسمة فقط — ولا تحاول أبدًا حساب A^N الفعلي مهما كبرت القيم.

📊 تحليل التعقيد ونصائح الحل

الجزءالتعقيدلماذا
تحليل M إلى عوامل أوّليةO(√M)قسمة تجريبية قياسية حتى √M ≈ 31,623 عند M=10^9.
حساب v_p(A) لكل عاملO(log A)عدد مرات القسمة على p محدود بعدد عوامل p في A، وهو على الأكثر log₂(10^9) ≈ 30.
الإجماليO(√M + log A)سريع جدًا حتى للقيم القصوى — لا علاقة إطلاقًا بحجم N نفسه، رغم أنه يظهر في الشرط الرياضي.

⚠️ أخطاء شائعة عند الحل

  1. محاولة حساب A^N فعليًا (ولو جزئيًا): حتى تجربة حسابه بـlong long أو double ستفشل أو تُنتج نتائج غير دقيقة لقيم كبيرة نسبيًا من N — يجب الانتقال مباشرة لتحليل الأُسس الأوّلية دون أي محاولة حساب وسيطة للقيمة الفعلية.

  2. ضرب N×v مباشرة دون احتياط: رغم أن long long يتّسع لـ10^9 × 30 بأمان هنا، إلا أنه من العادات الجيدة استخدام ceil_div لتفادي أي مفاجآت في مسائل مشابهة بقيود أكبر.

  3. نسيان حالة M=1: إغفال هذه الحالة الخاصة يجعل حلقة تحليل M تبدأ بـm=1، فلن تجد أي عامل أوّلي يقسمها (لأن 1 ليس له عوامل أوّلية)، وسينتهي البرنامج بإجابة NO خاطئة تمامًا رغم أن الإجابة الصحيحة هي YES دائمًا.

  4. نسيان العامل الأوّلي المتبقّي بعد الحلقة: إذا كان لـM عامل أوّلي كبير (أكبر من √M الأصلي)، فلن تكتشفه حلقة القسمة التجريبية — يجب دائمًا فحص m > 1 بعد انتهاء الحلقة، تمامًا كما في التحليل الأوّلي القياسي.

🚀 لماذا هذه المسألة "متوسطة" رغم أن الكود قصير نسبيًا؟

طول الكود لا يعكس دائمًا صعوبة المسألة. الصعوبة الحقيقية هنا هي الملاحظة الرياضية نفسها: أن رفع عدد لقوة يُترجم إلى ضرب أُسّ كل عامل أوّلي فيه بنفس القوة (v_p(A^N) = N·v_p(A))، وأن هذا يحوّل سؤالًا عن عدد فلكي الحجم إلى مجرّد مقارنة بين أعداد صغيرة جدًا (الأُسس نفسها، التي لا تتجاوز 30 تقريبًا). إيجاد هذا التحويل هو ما يجعل المسألة "متوسطة" وليس مجرّد كتابة كود تحليل أوّلي عادي.
