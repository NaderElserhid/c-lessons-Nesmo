CSES 1130 — Tree Matching (Tree Algorithms) cses.fi/problemset/task/1130 ↗

You are given a tree consisting of n nodes.

A matching is a set of edges where each node is an endpoint of at most one edge. What is the maximum number of edges in a matching?

Input

The first input line contains an integer n: the number of nodes. The nodes are numbered 1,2,…,n.

Then there are n−1 lines describing the edges. Each line contains two integers a and b: there is an edge between nodes a and b.

Output

Print one integer: the maximum number of pairs.

Constraints

1 ≤ n ≤ 2·105
1 ≤ a, b ≤ n

Example
Input:
5
1 2
1 3
3 4
3 5

Output:
2

🗣️ بالعربية — ماذا يعني هذا فعليًا؟

لديك شجرة (tree): رسم بياني متصل بلا دورات، فيه n عقدة وn−1 حافة بالضبط. المطابقة (matching) هي مجموعة من الحواف بحيث لا تظهر أي عقدة كطرف لأكثر من حافة واحدة من هذه المجموعة — بمعنى آخر، إذا اخترت حافة (u,v) فلا يمكنك اختيار أي حافة أخرى تلمس u أو تلمس v. المطلوب هو أكبر عدد ممكن من الحواف في مثل هذه المجموعة.

ترجمة المثال المعطى

الشجرة: 1 متصلة بـ2 وبـ3، و3 متصلة أيضًا بـ4 وبـ5 (أي أن 3 عقدة مركزية بثلاثة جيران: 1، 4، 5). أكبر مطابقة ممكنة حجمها 2، وأحد الحلول الصحيحة هو اختيار الحافتين (1,2) و(3,4) — لاحظ أن العقدة 3 استُخدمت فقط في حافة واحدة (3,4)، رغم أن لها جارين آخرين (1 و5)، لأنها لا يمكن أن تكون طرفًا في أكثر من حافة مختارة واحدة.

💡 فكرة الحل: DP بحالتين على شجرة مُجذَّرة

نُجذّر الشجرة عند عقدة عشوائية (هنا نختار العقدة 1)، ثم لكل عقدة v نحسب حالتين ممكنتين، لأن التفاعل الوحيد بين شجرة فرعية والباقي يمر عبر حافة واحدة فقط: الحافة إلى الأب.

تعريف الحالتين

dp0[v] — أكبر مطابقة داخل الشجرة الفرعية لـ v عندما v غير مرتبطة بأبيها (حرة: قد تُطابق أحد أبنائها أو لا تُطابق أحدًا).
dp1[v] — أكبر مطابقة داخل الشجرة الفرعية لـ v عندما v مُطابَقة بالفعل مع أبيها (مشغولة، فلا يمكنها مطابقة أي ابن).

الإجابة النهائية هي dp0[الجذر] لأن الجذر لا أب له أصلًا.

🧮 علاقات الحساب (Recurrence)

الصيغ الرياضية
base   = مجموع dp0[child] لكل الأبناء المباشرين لـ v

dp1[v] = base                       (v مشغولة، لا يمكنها مطابقة أي ابن)

dp0[v] = max( base ,
              max عبر كل ابن u من:
                  base - dp0[u] + dp1[u] + 1 )

الفكرة في الحد الثاني: لو طابقنا v مع ابن معيّن u عبر الحافة (v,u)، فإننا نضيف حافة واحدة (+1)، ونُجبر u على الانتقال من حالته dp0[u] إلى حالته dp1[u] (لأنه أصبح مشغولًا بأبيه)، بينما بقية الأبناء يظلّون في حالة dp0 الحرة كما هم ضمن base — لذلك نطرح dp0[u] القديمة ونضيف dp1[u] الجديدة بدلًا عنها.

📐 إثبات SRTBOT الكامل

S — الحالةالحالتان dp0[v] وdp1[v] تغطيان كل الاحتمالات الممكنة، لأن التفاعل الوحيد بين شجرة v الفرعية وبقية الشجرة يمر حصرًا عبر حافة الأب — فإما أن هذه الحافة مُستخدمة في المطابقة أو غير مُستخدمة، ولا يوجد احتمال ثالث.
R — العلاقةإن كانت v مستخدَمة من أبيها (dp1[v]) فلا يمكنها أن تكون طرفًا لأي حافة أخرى، فتُجبر جميع أبنائها على البقاء في حالة dp0. أما إن كانت v حرة (dp0[v]) فأمامها خياران فقط: لا تُطابق أي ابن (base)، أو تُطابق ابنًا واحدًا بالضبط u (يحوّل حالته إلى dp1[u] ويضيف حافة واحدة). هذان الخياران متبادلا الاستبعاد وشاملان معًا لكل الحالات — وهذا يثبت أن الصيغ أعلاه ضرورية وكافية.
T — الانتقالنحسب أبناء كل عقدة أولًا عبر DFS، ثم: base = Σ dp0[child]، ثم dp1[v] = base، ثم dp0[v] = max(base, max(base - dp0[u] + dp1[u] + 1)).
B — الحالة الأساسيةلعقدة ورقة (leaf) لا أبناء لها: base = 0 (مجموع فارغ)، فتصبح dp1[v] = 0 (لا يوجد ابن لتطابقه أصلًا) وdp0[v] = 0 (لا يوجد ابن لتطابقه أيضًا). صحيح ومتّسق مع التعريف.
O — ترتيب الحسابDFS بترتيب post-order: نحسب DP لكل الأبناء قبل الأب. بما أن كل عقدة تعتمد فقط على قيم dp0/dp1 لأبنائها المباشرين، فإن هذا الترتيب يضمن توفر كل الاعتماديات وقت الحساب.
T — الوقت والذاكرةكل حافة تُعالَج عددًا ثابتًا من المرات أثناء DFS، لذلك الزمن O(n) والذاكرة O(n) لقوائم التجاور ومصفوفتي dp0/dp1 وعمق الاستدعاء.
🎯 بونص: أنماط DP مشابهة على الأشجار يجب ألا تخلط بينها

هذا النمط (حالتان: "حرة" و"مشغولة بالأب") يظهر في عائلة كاملة من مسائل DP على الأشجار، لكن كل مسألة تُعرّف "الحالة" بمعنى مختلف قليلًا:

Maximum Independent Set على شجرة يستخدم أيضًا حالتين dp[v][0] وdp[v][1]، لكن المعنى هناك هو "هل العقدة v نفسها مُختارة ضمن المجموعة المستقلة أم لا" — وهي مسألة مختلفة تمامًا عن المطابقة (matching)، رغم تشابه شكل الكود. لا تخلط بين الاثنين: في Independent Set نختار عُقَدًا (nodes) بحيث لا يتجاور أي اثنان منها، بينما في Tree Matching نختار حوافًا (edges) بحيث لا تشترك في عقدة.

Minimum Vertex Cover على شجرة مرتبطة رياضيًا بالـ Matching عبر نظرية كونيغ (König's theorem) في الأشجار والرسوم ثنائية التجزئة، حيث حجم أصغر تغطية رؤوس يساوي حجم أكبر مطابقة — تفصيل جميل يستحق الاستكشاف لاحقًا إن أردت الغوص أعمق في نظرية الرسوم البيانية.

💻 الكود الكامل مع شرح كل جزء

C++ — الحل الكامل
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

vector<vector<int>> g;
vector<long long> dp0, dp1;

void dfs(int v, int p) {
    long long base = 0;

    // أولًا: حلّ كل الأبناء أولًا (post-order)
    for (int to : g[v]) {
        if (to == p) continue;
        dfs(to, v);
        base += dp0[to];
    }

    // إن كانت v مطابَقة مع أبيها -> لا يمكنها مطابقة أي ابن
    dp1[v] = base;

    // إن كانت v غير مطابَقة مع أبيها -> إما لا تطابق أحدًا، أو تطابق ابنًا واحدًا بالضبط
    dp0[v] = base;

    for (int u : g[v]) {
        if (u == p) continue;
        long long candidate = base - dp0[u] + dp1[u] + 1;  // مطابقة الحافة (v,u)
        dp0[v] = max(dp0[v], candidate);
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    g.assign(n + 1, {});
    for (int i = 0; i < n - 1; i++) {
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);
    }

    dp0.assign(n + 1, 0);
    dp1.assign(n + 1, 0);

    int root = 1;
    dfs(root, -1);

    cout << dp0[root] << "\n";
    return 0;
}

🔍 شرح مفصّل لكل جزء

vector<vector<int>> g;قائمة تجاور (adjacency list) عالمية — g[v] تحتوي كل جيران العقدة v في الشجرة غير الموجّهة.
vector<long long> dp0, dp1;مصفوفتا DP. استُخدم long long هنا كعادة أمان في المسائل التنافسية أكثر منه ضرورة صارمة: أكبر مطابقة ممكنة في شجرة بحجم n هي على الأكثر n/2 ≤ 10^5، وهي قيمة تدخل بارتياح في int، لكن long long يتجنب أي مفاجأة لو أُعيد استخدام نفس الكود لاحقًا في مسألة بمجاميع أكبر.
dfs(int v, int p)v هي العقدة الحالية، وp هي أبوها (لتجنّب الرجوع إليها ضمن حلقة الجيران). يُستدعى الدالة recursively على كل الأبناء أولًا، مما يضمن ترتيب post-order المطلوب في إثبات SRTBOT.
حلقة for (int to : g[v]) { if (to==p) continue; dfs(to,v); base += dp0[to]; }تمرّ على كل جار، تتجاهل الأب، تحل الشجرة الفرعية للابن recursively، ثم تجمع قيم dp0 لكل الأبناء في base — وهذا هو "الأساس" الذي تُبنى عليه كل من dp1[v] وdp0[v].
dp1[v] = base;ترجمة مباشرة للصيغة الرياضية: إن كانت v مشغولة بأبيها، كل أبنائها يبقون أحرارًا (dp0)، فمجموع مساهماتهم هو base بالضبط.
حلقة for (int u : g[v]) { ... candidate = base - dp0[u] + dp1[u] + 1; dp0[v] = max(...); }تجرّب مطابقة v مع كل ابن u على حدة: تزيل مساهمة u القديمة (dp0[u]) من base، وتضيف مساهمته الجديدة كمُطابَق (dp1[u])، بالإضافة إلى +1 عن الحافة (v,u) نفسها، ثم تُبقي أفضل نتيجة رأتها عبر كل الأبناء (أو base نفسها إن لم يكن أي ابن يستحق ذلك).
g.assign(n + 1, {}); قراءة n−1 حافةتُضاف كل حافة في الاتجاهين (g[a].push_back(b) وg[b].push_back(a)) لأن الشجرة غير موجّهة، والقراءة تتوقف تلقائيًا عند n−1 حافة كما تنص المسألة تمامًا.
int root = 1; dfs(root, -1);تجذير الشجرة عند العقدة 1 اختياري بحت — حجم أكبر مطابقة في شجرة لا يعتمد إطلاقًا على أي عقدة اخترتها جذرًا، فقط يجب اختيار عقدة موجودة فعلًا (1 آمنة دائمًا لأن 1 ≤ n).
cout << dp0[root]الجذر ليس له أب بالتعريف، لذا فهو دائمًا في حالة "حرة" — والإجابة النهائية هي بالضبط dp0[root].

تنبيه مهم لعمق الاستدعاء: هذا الكود يستخدم DFS تكراريًا (recursive) عبر استدعاء الدالة نفسها لنفسها. مع n حتى 2×10^5، لو كانت الشجرة على شكل سلسلة طويلة (path) بدلًا من شجرة متفرّعة، فإن عمق الاستدعاء قد يصل إلى 2×10^5 مستوى متتاليًا — وهذا قد يتجاوز حجم المكدّس الافتراضي (stack) في بعض بيئات التصحيح المحلية ويُسبب Stack Overflow، رغم أنه غالبًا يعمل بأمان على خوادم الحكم مثل CSES التي تمنح حجم مكدّس أكبر. سنتوسّع في هذه النقطة وحلولها في تبويب «التحليل».

⚗️ المختبر التفاعلي — محلّل المطابقة على الشجرة

اكتب شجرتك الخاصة بنفس صيغة الإدخال على CSES بالضبط (n في السطر الأول، ثم n−1 سطرًا لكل حافة "a b")، أو حمّل مثال المسألة، أو ولّد شجرة عشوائية — ثم اضغط «حلّل الشجرة» لتشغيل خوارزمية DP الحقيقية (بترتيب post-order فعلي مبني تكراريًا وليس recursion، لتفادي مشكلة عمق الاستدعاء المذكورة في تبويب «الكود»)، ومشاهدة كل خطوة من خطوات الحساب، بالإضافة إلى إعادة بناء المطابقة القصوى فعليًا وتظليل حوافها على الرسم.

القيد الحقيقي على المنصة يصل إلى n ≤ 2×10^5، لكن نُحدّد الحجم هنا بحد أقصى 24 عقدة فقط للحفاظ على وضوح رسم الشجرة — الخوارزمية المُنفَّذة (بما فيها ترتيب post-order التكراري) هي نفسها تمامًا بغض النظر عن الحجم.

📊 تحليل التعقيد ونصائح الحل

الجانبالتعقيدلماذا
الزمنO(n)كل عقدة تُزار مرة واحدة، وكل حافة تُفحص مرتين بالضبط (مرة من كل طرف) عبر كل حلقات dfs، فالمجموع الكلي خطي في عدد العقد والحواف.
الذاكرةO(n)قائمة التجاور، ومصفوفتا dp0/dp1، وعمق مكدّس الاستدعاء (أو المكدّس اليدوي في نسخة تكرارية)، كلها خطية في n.

⚠️ أخطاء شائعة عند الحل على المنصة

  1. Stack Overflow على شجرة خطية (path): إن كانت الشجرة سلسلة طويلة (كل عقدة لها ابن واحد فقط) بحجم n=2×10^5، فقد يفشل DFS التكراري (recursive) بسبب تجاوز حجم مكدّس النداءات. الحلول الشائعة في المسابقات: (أ) تحويل DFS إلى نسخة تكرارية بمكدّس يدوي (Iterative DFS) كما فعلنا في المختبر أعلاه، أو (ب) زيادة حجم المكدّس صراحة (مثلًا عبر تشغيل الحل داخل thread بحجم مكدّس أكبر في ++C، أو رفع حد ulimit -s في بيئات Linux محلية).

  2. نسيان إضافة الحافة في الاتجاهين: بما أن الشجرة غير موجّهة، يجب استدعاء g[a].push_back(b) وg[b].push_back(a) معًا لكل حافة — نسيان أحدهما يكسر الاتصال بين العقد.

  3. الخلط بين Tree Matching وMaximum Independent Set: الكودان متشابهان شكليًا (حالتان لكل عقدة) لكن المعنى مختلف جذريًا — راجع البونص في تبويب «الفكرة والإثبات» لتفادي هذا الالتباس الشائع جدًا بين الطلاب.

  4. اختيار جذر غير موجود: تجذير الشجرة عند عقدة عشوائية أمر صحيح دائمًا طالما هذه العقدة موجودة فعليًا ضمن 1..n — العقدة 1 اختيار آمن ومضمون دائمًا لأن القيد يضمن 1 ≤ n.

  5. قراءة بطيئة: مع n حتى 2×10^5 حافة تقريبًا، نسيان ios::sync_with_stdio(false) قد يستهلك وقتًا غير ضروري من حد الثانية الواحدة.
