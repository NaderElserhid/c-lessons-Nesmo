CSES 1635 — Coin Combinations I (Dynamic Programming) cses.fi/problemset/task/1635 ↗

Consider a money system consisting of n coins. Each coin has a positive integer value. Your task is to calculate the number of distinct ways you can produce a money sum x using the available coins.

For example, if the coins are {2,3,5} and the desired sum is 9, there are 8 ways:

  • 2+2+5
  • 2+5+2
  • 5+2+2
  • 3+3+3
  • 2+2+2+3
  • 2+2+3+2
  • 2+3+2+2
  • 3+2+2+2
Input

The first input line has two integers n and x: the number of coins and the desired sum of money.

The second line has n distinct integers c_1,c_2,...,c_n: the value of each coin.

Output

Print one integer: the number of ways modulo 10^9+7.

Constraints

1 ≤ n ≤ 100
1 ≤ x ≤ 10^6
1 ≤ c_i ≤ 10^6

Example
Input:
3 9
2 3 5

Output:
8

🗣️ بالعربية — ماذا يعني هذا فعليًا؟

لدينا مجموعة من n عملة، كل عملة لها قيمة صحيحة موجبة. المطلوب: عدد التسلسلات المختلفة (وليس فقط المجموعات) من العملات التي مجموع قيمها يساوي x بالضبط. تمامًا كما في Dice Combinations، الترتيب مهم: 2+2+5 و2+5+2 و5+2+2 تُحسب كثلاث طرق منفصلة رغم أنها نفس مجموعة العملات {2,2,5}.

العلاقة مع Dice Combinations

هذه المسألة هي بالضبط Dice Combinations، لكن بدل قيم النرد الثابتة {1,2,3,4,5,6}، أصبحت قيم "العملات" عامة ويحدّدها الإدخال. نفس المنطق بالضبط ينطبق: نقسّم عند "آخر عملة استُخدمت" بدل "آخر رمية نرد".

S — الحالة (State)

التعريف

dp[s] = عدد الطرق (مع اعتبار الترتيب) لتكوين المبلغ s بالضبط باستخدام العملات المتاحة. المطلوب في النهاية هو dp[x].

R — علاقة التكرار (Recurrence)

لتكوين المبلغ s، آخر عملة مُستخدَمة كانت لا بد إحدى العملات c_1..c_n. إن كانت آخر عملة تساوي c_i، فإن المبلغ قبلها كان s - c_i:

dp[s] = Σ dp[s - c_i] لكل عملة c_i بحيث s - c_i ≥ 0 (mod 10^9+7)

T — الانتقالات (Transitions)

من المبالغ الأصغر إلى الأكبر: لكل s، ننظر إلى ما يصل إلى n حالة سابقة: dp[s-c_1], dp[s-c_2], ..., dp[s-c_n] (نتجاهل أي منها يكون أصغر من صفر). الفرق الوحيد عن Dice Combinations أن عدد الحالات السابقة هنا n (قد يصل إلى 100) بدل 6 ثابتة، والقيم c_i عامة بدل 1..6.

B — الحالات الأساسية (Base cases)

  • dp[0] = 1 — طريقة واحدة لتكوين المبلغ صفر: عدم استخدام أي عملة (تسلسل فارغ).

  • لأي s < 0، نعامل dp[s] = 0 (لا توجد طرق لمبلغ سالب) — تُغطّى تلقائيًا بفحص s - c_i ≥ 0.

O — ترتيب الحساب (Order of computation)

يجب حساب dp[s] بترتيب تصاعدي في s من 0 إلى x، لأن dp[s] يعتمد فقط على مبالغ أصغر منه.

T — التعقيد الزمني والمكاني

لكل مبلغ s من 1 إلى x، نمرّ على كل العملات الـn. الزمن الكلي: O(n·x). الذاكرة: O(x) لمصفوفة dp.

لماذا الحلقتان بهذا الترتيب تحديدًا (s في الخارج، ثم العملات في الداخل)؟ هذا الترتيب تحديدًا هو ما يجعل الترتيب "مهمًا" في العدّ (permutations). لو بدّلنا الحلقتين (العملات في الخارج، والمبلغ في الداخل)، لحصلنا على مسألة مختلفة تمامًا: عدّ التركيبات (combinations) حيث الترتيب لا يهم — وهذا بالضبط الفرق بين Coin Combinations I وCoin Combinations II.

💻 الكود الكامل مع شرح كل جزء

C++ — حل مقترح
#include <iostream>
#include <vector>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<long long> coins(n);
    for (int i = 0; i < n; i++) cin >> coins[i];

    vector<long long> dp(x + 1, 0);
    dp[0] = 1;  // طريقة واحدة لتكوين المبلغ صفر: لا شيء

    for (long long s = 1; s <= x; s++) {
        long long ways = 0;
        for (int i = 0; i < n; i++) {
            if (s - coins[i] >= 0) {
                ways += dp[s - coins[i]];
                if (ways >= MOD) ways -= MOD;  // تفادي الفيضان
            }
        }
        dp[s] = ways;
    }

    cout << dp[x] << "\n";
    return 0;
}

⚗️ المختبر التفاعلي — بناء جدول dp خطوة بخطوة

أدخل مجموعة العملات (مفصولة بمسافات) والمبلغ المطلوب x، ثم شاهد مصفوفة dp تُبنى فعليًا خلية بخلية أمامك: الخلايا الصفراء هي المبالغ السابقة s - c_i التي تُجمع لحساب الخلية الزرقاء الحالية s.

القيد الحقيقي على المنصة يصل إلى x ≤ 10^6 وn ≤ 100، ونفس بالضبط الخوارزمية O(n·x) تعمل عليه — نُحدّد هنا x بحد أقصى 40 فقط لوضوح العرض التفاعلي البصري.

اضغط «الخطوة التالية» أو «تشغيل تلقائي» للبدء.

⚠️ أخطاء شائعة عند الحل على المنصة

  1. الخلط بين Coin Combinations I وII: النسخة الأولى (هذه) تعدّ الترتيب (permutations)، وترتيب الحلقتين هو المبلغ في الخارج، العملات في الداخل. أما Coin Combinations II فتعدّ التركيبات فقط (لا يهم الترتيب)، ويتطلّب ذلك عكس ترتيب الحلقتين (العملات في الخارج، المبلغ في الداخل) — خطأ شائع جدًا هو استخدام نفس بنية الحلقات للمسألتين.

  2. نسيان تطبيق الباقي (modulo): بالضبط كما في Dice Combinations، عدد الطرق الحقيقي ينمو بسرعة كبيرة جدًا — يجب تطبيق الباقي على 10^9+7 بعد كل عملية جمع.

  3. افتراض أن العملات مرتّبة أو صغيرة: القيود تسمح بعملات تصل قيمتها إلى 10^6 (قد تكون أكبر من x نفسه) — يجب دائمًا فحص s - c_i ≥ 0 قبل الوصول إلى dp، وليس افتراض ترتيب معيّن للعملات.

  4. حجز مصفوفة dp بحجم n بدل x: خطأ سهل الوقوع فيه قادمًا من Dice Combinations حيث كان الحجمان متشابهين أحيانًا — الحجم الصحيح هنا هو x + 1، بغضّ النظر عن عدد العملات n.

🚀 الخطوة التالية: Coin Combinations II

بعد إتقان هذا النمط، الخطوة الطبيعية التالية هي Coin Combinations II من نفس قسم CSES: نفس المسألة تمامًا في الصياغة، لكن المطلوب عدّ التركيبات بدل التسلسلات (أي 2+2+5 و2+5+2 و5+2+2 تُحسب كطريقة واحدة فقط، لا ثلاث). الحل يحتاج فقط عكس ترتيب الحلقتين المتداخلتين (العملات في الخارج هذه المرة)، وهذا مثال ممتاز على كيف يُغيّر تفصيل بسيط جدًا في بنية الحلقات معنى الإجابة بالكامل رغم تطابق الكود شبه الكامل ظاهريًا.
