الدرس الثاني: البحث في العمق (Depth-First Search)

في الفصل السابق تعلّمنا كيف نخزّن الرسم البياني في الذاكرة. الآن حان وقت التحرك عليه فعليًا! DFS هي أول خوارزمية اجتياز (Traversal) نتعلّمها، وتُستخدم كأساس لحل عشرات المسائل التنافسية: من إيجاد المسارات إلى اكتشاف الدورات والتلوين الثنائي.

ما هو البحث في العمق؟

البحث في العمق (DFS) هو خوارزمية اجتياز على الرسوم البيانية (Graphs). تعمل بأسلوب المتاهة: تسير للأمام بأقصى عمق ممكن، فإذا وصلت إلى طريق مسدود (كل الجيران زُوروا) عادت خطوة للخلف (backtrack) وجرّبت مسارًا آخر لم تستكشفه بعد.

يُستخدم DFS في العديد من المسائل، مثل: إيجاد المسارات، اكتشاف الدورات (Cycle Detection)، التلوين الثنائي للرسوم البيانية (Bipartite Coloring)، وغيرها الكثير — وسنتعرّض لبعضها في الفصول القادمة.

التعقيد الزمني: O(V + E)

حيث V = عدد الرؤوس (Vertices)، وE = عدد الحواف (Edges).

نصيحة المدرب: فكّر في DFS كشخص يستكشف متاهة: يضع يده دائمًا على الجدار الأيمن ويمشي بدون توقف، فإذا اصطدم بطريق مسدود يرجع خطوة للوراء ويجرّب اتجاهًا آخر، حتى يزور كل ركن ممكن في المتاهة.

كيف يعمل DFS خطوة بخطوة؟

  1. ابدأ عند الرأس المصدر (Source) وضع عليه علامة "مُزار" (visited).

  2. انظر إلى جميع جيران الرأس الحالي. إذا وجدت جارًا لم يُزَر بعد، انتقل إليه (dfs بشكل تكراري) وكرّر العملية من جديد على هذا الجار.

  3. إذا تمت زيارة جميع جيران الرأس الحالي، ارجع (backtrack) إلى الرأس الذي جئت منه (الأب) واستمر في فحص بقية جيرانه.

  4. تنتهي الخوارزمية عندما تُزار جميع الرؤوس المتصلة بالمصدر (أي بعد أن يعود الاستدعاء الأول dfs(المصدر) بالكامل).

الكود الأساسي لـ DFS

الكود التالي يُنفّذ DFS باستخدام التعاود (Recursion)، وهو الأسلوب الأكثر وضوحًا:

dfs_basic.cpp
const int maxN = 200001;

bool vis[maxN];                    // مصفوفة الزيارة
vector<int> adj[maxN];            // قائمة التجاور

void dfs(int u) {
    vis[u] = true;               // ضع علامة على الرأس الحالي

    for (int v : adj[u]) {
        if (!vis[v])             // إذا لم يُزَر الجار
            dfs(v);             // زُره بشكل تكراري
    }
}

نقطة مهمة: مصفوفة vis[] ضرورية جدًا — بدونها ستدخل الخوارزمية في حلقة لا نهائية إذا كان الرسم البياني يحتوي على دورة (Cycle)، لأن الكود سيستمر في القفز بين نفس الرؤوس إلى الأبد. جرّب بنفسك في محاكي الأعلى: لاحظ كيف يمر DFS على الدورة 3-6-5-2 دون أن يعلق فيها، لأن كل رأس يُزار مرة واحدة فقط.

مسألة تطبيقية: إيجاد المسار (Path Finding)

سهل — معطى رسم بياني غير موجّه يتكوّن من N رأسًا مرقّمة من 1 إلى N، وM حافة. تحقّق مما إذا كان الرأس 1 يمكنه الوصول إلى الرأس N، واطبع مسارًا ممكنًا إذا وُجد.

فكرة الحل: نخزّن مصفوفة p[] حيث p[v] = الرأس الذي اكتشف v أثناء DFS (أي الرأس الذي استدعى dfs(v)). بعد انتهاء DFS من الرأس 1، نتتبّع المسار عكسيًا بدءًا من N صعودًا حتى نصل إلى 1 عبر p[].

path_finding.cpp
const int maxN = 200001;
int vis[maxN], p[maxN];        // vis = زيارة, p = الأب
vector<int> adj[maxN];

void dfs(int u) {
    vis[u] = true;
    for (int v : adj[u]) {
        if (!vis[v]) {
            p[v] = u;          // u أب v
            dfs(v);
        }
    }
}

int main() {
    int n, m;
    cin >> n >> m;

    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    dfs(1);

    if (!vis[n]) cout << "No";
    else {
        cout << "Yes\n";
        vector<int> pth;
        // تتبع المسار عكسياً
        for (int i = n; i != 1; i = p[i])
            pth.push_back(i);
        reverse(pth.begin(), pth.end());
        cout << 1 << ' ';
        for (int i : pth) cout << i << ' ';
    }
}

لاحظ: أب الرأس في p[] ليس بالضرورة "أقرب" رأس منطقيًا — فمثلًا في رسمنا التجريبي، الرأس 3 مرتبط مباشرة بالرأس 1 عبر حافة، لكن DFS يكتشفه فعليًا عبر المسار 1→2→5→6→3 قبل أن يصل دور فحص تلك الحافة المباشرة (لأن 3 يكون قد زِيرَ بالفعل). هذا طبيعي تمامًا في DFS، ولا يؤثر على صحة النتيجة.

نشاط: مراجعة سريعة لمفهوم DFS

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

التعقيد الزمني لـ DFS هو O(V + E).

DFS يزور جميع رؤوس الرسم البياني حتى لو كانت غير متصلة بالرأس المصدر.

بدون مصفوفة vis[]، قد تدخل الخوارزمية في حلقة لا نهائية إذا كان الرسم البياني يحتوي على دورة.

في مسألة Path Finding، الأب p[v] هو دائمًا الجار الأول لـ v في قائمة الجوار.

تمارين منزلية

1) تتبّع DFS يدويًا

لديك رسم بياني بالحواف التالية (adjacency مبني بترتيب push_back): 1-2, 1-3, 2-4, 3-4. اكتب ترتيب زيارة الرؤوس عند تنفيذ dfs(1).

adj[1]={2,3}, adj[2]={1,4}, adj[3]={1,4}, adj[4]={2,3}

ترتيب الزيارة: 1 → 2 → 4 → 3 (من 1 ننتقل إلى 2، ومن 2 إلى 4، ومن 4 نفحص جيرانه: 2 مُزار، 3 غير مُزار فننتقل إليه، ثم نعود بالكامل لأن كل الجيران زِيروا)

2) لماذا نحتاج vis[]؟

ماذا يحدث بالضبط إذا حذفنا شرط if (!vis[v]) من كود DFS الأساسي، وشغّلنا الخوارزمية على رسم بياني يحتوي على حافة واحدة فقط بين رأسين (1-2)؟

ستدخل الخوارزمية في حلقة لا نهائية: dfs(1) يستدعي dfs(2) (لأن 2 جار لـ 1)، وdfs(2) يستدعي dfs(1) مجددًا (لأن 1 جار لـ 2)، وهكذا إلى ما لا نهاية حتى ينهار البرنامج بخطأ Stack Overflow. هذا يوضح أن vis[] ليست مجرد تحسين أداء، بل شرط ضروري لصحة الخوارزمية.

3) مسألة Path Finding — حالة خاصة

ماذا يجب أن يطبع الكود إذا كان N = 1 (أي المصدر والهدف نفس الرأس)؟ تحقّق من أن الكود المعطى يتعامل مع هذه الحالة بشكل صحيح.

يجب أن يطبع Yes ثم المسار "1" فقط. بما أن dfs(1) يضع vis[1] = true فورًا، فإن الشرط !vis[n] يكون false عندما n=1، فينتقل الكود لطباعة "Yes"، وحلقة تتبع المسار for (int i = n; i != 1; i = p[i]) لا تُنفَّذ أي تكرار لأن الشرط i != 1 يفشل فورًا (لأن i يبدأ من n=1)، فتبقى pth فارغة، ويُطبع 1 فقط. تحققنا من هذا فعليًا بالتجربة: المدخل "1 0" ينتج "Yes" ثم "1".

قاموس المصطلحات

DFS (Depth-First Search)البحث في العمق

خوارزمية اجتياز تتوغّل بأقصى عمق ممكن قبل الرجوع للخلف.

Backtrackالرجوع للخلف

العودة إلى الرأس الأب بعد استنفاد كل جيران الرأس الحالي.

Visited Array (vis[])مصفوفة الزيارة

تمنع زيارة نفس الرأس أكثر من مرة، وضرورية لتجنب الحلقات اللانهائية عند وجود دورات.

Call Stackمكدس الاستدعاءات

سلسلة الاستدعاءات التكرارية النشطة حاليًا (من المصدر وحتى الرأس الحالي).

Recursionالتعاود

تقنية برمجية تستدعي فيها الدالة نفسها؛ الأسلوب الأكثر وضوحًا لتنفيذ DFS.

Parent Array (p[])مصفوفة الآباء

تخزّن الرأس الذي اكتشف كل رأس أثناء DFS؛ تُستخدم لإعادة بناء المسار.

Connected Componentالمكوّن المتصل

مجموعة الرؤوس التي يمكن الوصول إليها من رأس معيّن؛ DFS يزور مكوّنًا واحدًا فقط في كل استدعاء.

Cycleالدورة

مسار في الرسم البياني يعود إلى رأسه الأصلي؛ سبب الحاجة لمصفوفة الزيارة.
