ما هي نظرية الأعداد؟

نظرية الأعداد هي فرع من الرياضيات يُعنى بدراسة الأعداد الصحيحة (… , -2, -1, 0, 1, 2, …). لا كسور، لا أعداد عشرية، فقط أعداد نقية كاملة. في البرمجة التنافسية، تُعدّ من أكثر المواضيع شيوعاً في أسئلة الأولمبياد.


لماذا نهتم بها؟ تظهر نظرية الأعداد في مئات المسائل التنافسية: تبسيط الكسور، جدولة المواعيد المتكررة، التشفير، وتحليل الأعداد الأولية.

القاسم المشترك الأكبر (GCD)

تعريف
GCD(12, 18) = 6

أكبر عدد يقسم كلا العددين بدون باقٍ. قواسم 12: {1,2,3,4,6,12} وقواسم 18: {1,2,3,6,9,18} والمشترك الأكبر هو 6.

حالة خاصة
GCD(7, 13) = 1

حين يكون الناتج 1، نسمي العددين أوليّين نسبياً (Coprime). لا يشتركان في أي عامل سوى الواحد.

🐢 الطريقة الساذجة (البطيئة)

كرّر من 1 إلى min(a,b) وتحقق من كل عدد:

int gcd_naive(int a, int b) {
    int result = 1;
    for (int i = 1; i <= min(a, b); i++) {
        if (a % i == 0 && b % i == 0)
            result = i;
    }
    return result;
}
// التعقيد: O(min(a,b)) — بطيء جداً للأعداد الكبيرة!
تحذير: لا تستخدم هذه الطريقة في الأولمبياد! إذا كانت a و b بالمليارات، ستنتهي مهلة البرنامج. نحتاج لشيء أذكى.

خوارزمية إقليدس (الطريقة الذكية)

الفكرة الأساسية

اكتشف إقليدس قبل 2300 سنة: GCD(a, b) = GCD(b, a % b)

استمر في أخذ الباقي حتى يصبح صفراً، فالعدد الآخر هو الإجابة.

مثال خطوة بخطوة: GCD(48, 18)
GCD(48, 18) → 48 % 18 = 12 → GCD(18, 12)
GCD(18, 12) → 18 % 12 = 6 → GCD(12, 6)
GCD(12, 6) → 12 % 6 = 0 → GCD(6, 0) = 6 ✓ 
// الطريقة التعاودية (Recursive) — الأكثر شيوعاً
int gcd(int a, int b) {
    if (b == 0) return a;
    return gcd(b, a % b);
}

// الطريقة التكرارية (Iterative) — بدون تعاود
int gcd_iter(int a, int b) {
    while (b != 0) {
        int temp = b;
        b = a % b;
        a = temp;
    }
    return a;
}

// مدمجة في C++17 (الأسهل!)
// #include <numeric>
// std::gcd(a, b)  أو  __gcd(a, b) للإصدارات الأقدم
التعقيد الزمني: O(log(min(a,b))) — سريع جداً! يمكنه معالجة أعداد بالمليارات في ميكروثوانٍ.

المضاعف المشترك الأصغر (LCM)

الفكرة البصرية

LCM هو أول نقطة التقاء لمضاعفات عددين. فكّر في قطارين يغادران المحطة معاً — متى يلتقيان مجدداً؟

مضاعفات 4: 4، 8، 12، 16، 20، 24…
مضاعفات 6: 6، 12، 18، 24…
LCM(4, 6) = 12 ← أول لقاء!
// الصيغة: LCM(a,b) = (a × b) / GCD(a,b)
int lcm(int a, int b) {
    if (a == 0 || b == 0) return 0;
    return (a / gcd(a, b)) * b; // قسّم أولاً لتجنب الفيض!
}

// مدمجة في C++17
// std::lcm(a, b)
تنبيه الفيض (Overflow)! لا تكتب a * b / gcd(a,b) — إذا كانت a وb كبيرة، يمكن أن يفيض a*b قبل القسمة. اكتب دائماً (a / gcd(a,b)) * b.

ملخص الصيغ

الصيغة الوصف التعقيد
gcd(a, b) = gcd(b, a%b) خوارزمية إقليدس للـ GCD O(log min(a,b))
lcm(a,b) = (a/gcd)*b صيغة LCM باستخدام GCD O(log min(a,b))
gcd(a, 0) = a الحالة الأساسية للتعاود O(1)
gcd(a,b)*lcm(a,b) = a*b العلاقة بين GCD و LCM —

📌 مثال 1: تبسيط الكسور

معطى الكسر 18/24، أوجد أبسط صورة له.

18
24
قبل التبسيط
÷ GCD(18,24) = 6
3

أبسط صورة ✓
#include <iostream>
#include <numeric>
using namespace std;

int main() {
    int num = 18, den = 24;
    int common = std::gcd(num, den); // = 6
    num /= common; // 18/6 = 3
    den /= common; // 24/6 = 4
    cout << num << "/" << den; // Output: 3/4
}

📌 مثال 2: نقطة الالتقاء (مصباحان يوميضان)

مصباح A يومض كل 12 ثانية، ومصباح B كل 15 ثانية. لقد ومضا معاً الآن. متى يومضان معاً مرة أخرى؟

الحل: نبحث عن أصغر وقت هو مضاعف لكلا الرقمين. هذا بالضبط هو LCM(12, 15) = 60 ثانية.
#include <iostream>
#include <numeric>
using namespace std;

int main() {
    int a = 12, b = 15;
    cout << "يومضان معاً بعد: " << std::lcm(a, b) << " ثانية";
    // Output: يومضان معاً بعد: 60 ثانية
}

🎯 تلميح متقدم: GCD لأكثر من عددين

يمكن تطبيق GCD على مصفوفة كاملة! الخاصية: GCD(a, b, c) = GCD(GCD(a, b), c)

// GCD لمصفوفة كاملة
int arr[] = {12, 18, 24, 36};
int result = arr[0];
for (int x : arr)
    result = gcd(result, x);
// result = 6

سؤال 1 — سهل
ما هو GCD(8, 12)؟
○ 2
○ 4
○ 6
○ 8
قواسم 8: {1,2,4,8} وقواسم 12: {1,2,3,4,6,12}. المشترك الأكبر هو 4. بإقليدس: GCD(12,8)→GCD(8,4)→GCD(4,0)=4 ✓
سؤال 2 — سهل
ما هو LCM(3, 5)؟
○ 8
○ 15
○ 30
○ 1
3 و5 أوليّان نسبياً (GCD=1)، لذا LCM(3,5)=3×5/1=15. مضاعفات 3: 3,6,9,12,15... مضاعفات 5: 5,10,15... ← أول لقاء: 15 ✓
سؤال 3 — سهل
في خوارزمية إقليدس، ما هي الحالة الأساسية للتوقف؟
○ عندما يصبح a يساوي 0
○ عندما يصبح b يساوي 0
○ عندما يصبح a = b
○ عندما يصبح a يساوي 1
في gcd(a,b): إذا b==0 نرجع a. وهذا هو تعريف إقليدس: gcd(a,0)=a لأن كل عدد يقسم الصفر.
سؤال 4 — سهل
ما الفرق بين GCD وLCM بشكل مبسّط؟
○ GCD هو الأكبر، LCM هو الأصغر
○ GCD يقسم العددين، LCM ينقسم عليهما
○ GCD يُضاعف، LCM يُقسّم
○ لا فرق بينهما
GCD(a,b) يقسم كلاً من a وb (عامل مشترك). أما LCM(a,b) فكلٌّ من a وb يقسمانه (مضاعف مشترك). الاتجاه معكوس!
سؤال 5 — سهل
ما ناتج تبسيط الكسر 14/21؟
○ 1/2
○ 2/3
○ 7/14
○ 3/4
GCD(14,21)=7. 14÷7=2, 21÷7=3. الكسر المبسّط هو 2/3. يمكن التحقق: 2×21=42=3×14 ✓
سؤال 6 — متوسط
ثلاثة حافلات تغادر المحطة معاً. الحافلة A كل 6 دقائق، B كل 9 دقائق، C كل 12 دقيقة. بعد كم دقيقة تجتمع الثلاثة معاً؟
○ 18 دقيقة
○ 36 دقيقة
○ 27 دقيقة
○ 54 دقيقة
LCM(6,9,12): أولاً LCM(6,9)=18 لأن GCD(6,9)=3 فـ LCM=18. ثم LCM(18,12): GCD(18,12)=6 فـ LCM=36. الإجابة: 36 دقيقة ✓
سؤال 7 — متوسط
ما تعقيد خوارزمية إقليدس الزمني؟ ولماذا هي أفضل من الطريقة الساذجة؟
○ O(n) — لأنها أقصر في الكود
○ O(log min(a,b)) — لأن الباقي يتناقص بسرعة أسية
○ O(n²) — لأنها تستخدم حلقتين
○ O(1) — لأنها ثابتة دائماً
كل خطوة في إقليدس تُقلّل المسألة بعامل على الأقل 2 (يمكن إثبات أن a%b ≤ a/2 دائماً). لذا عدد الخطوات ≤ 2log₂(min(a,b))، مما يعطي O(log min(a,b)).
سؤال 8 — متوسط
إذا كان GCD(a, b) = 1، ماذا يُسمى هذان العددان، وما قيمة LCM(a, b)؟
○ أوليّان، وLCM = a + b
○ متساويان، وLCM = a
○ أوليّان نسبياً (Coprime)، وLCM = a × b
○ أوليّان مطلقان، وLCM = 1
حين GCD(a,b)=1 يُسمّيان Coprime أو أوليّان نسبياً. ومن الصيغة: LCM = (a/GCD)*b = (a/1)*b = a×b. مثال: LCM(7,13)=91=7×13.
سؤال 9 — متوسط
لماذا نكتب (a / gcd(a,b)) * b بدلاً من (a * b) / gcd(a,b)؟
○ لأن القسمة أسرع من الضرب
○ لتجنب فيض الأعداد (Integer Overflow)
○ لأن الناتجين مختلفان رياضياً
○ لا فرق، كلاهما صحيح دائماً
مثال: a=10⁹, b=10⁹. a*b = 10¹⁸ وهو أكبر من حد int (≈2×10⁹). لكن (a/gcd)*b يُقلّل a أولاً قبل الضرب، مما يتجنب الفيض. هذا فرق حرج في الأولمبياد!
سؤال 10 — متوسط
ما قيمة GCD(a, b) × LCM(a, b) دائماً؟
○ a + b
○ a × b
○ GCD²
○ LCM²
علاقة أساسية: GCD(a,b) × LCM(a,b) = a × b. إثبات: LCM = a*b/GCD، إذن GCD*LCM = GCD*(a*b/GCD) = a*b. مثال: GCD(4,6)=2, LCM=12, 2×12=24=4×6 ✓
سؤال 11 — صعب
ما الناتج الصحيح لـ gcd(0, 7) وgcd(7, 0) باستخدام خوارزمية إقليدس؟
○ كلاهما 0
○ gcd(0,7)=0 و gcd(7,0)=7
○ كلاهما 7
○ خطأ في التنفيذ
gcd(7,0): b=0 فنرجع a=7 ✓. gcd(0,7): نستدعي gcd(7, 0%7)=gcd(7,0)=7 ✓. إذن كلاهما يُعيد 7. الصفر يُعتبر من مضاعفات كل الأعداد رياضياً.
سؤال 12 — صعب
عندك مستطيل 252 × 105 سم. تريد تبليطه بمربعات متطابقة (بدون كسر). ما أكبر حجم ممكن للمربع؟ وكم مربعاً تحتاج؟
○ مربع 21 سم، 60 مربعاً
○ مربع 21 سم، 60 مربعاً ← هذا هو الصحيح
○ مربع 7 سم، 540 مربعاً
○ مربع 42 سم، 15 مربعاً
حجم المربع = GCD(252, 105). بإقليدس: GCD(252,105)→GCD(105,42)→GCD(42,21)→GCD(21,0)=21. عدد المربعات = (252/21)×(105/21) = 12×5 = 60 مربعاً ✓
سؤال 13 — صعب
في البرنامج التالي، ما القيمة المُطبعة؟
int a=36, b=24; cout << (a*b)/gcd(a,b);
مع العلم أن GCD(36,24)=12.
○ 48
○ 72
○ 864
○ 12
LCM(36,24) = (36×24)/GCD = 864/12 = 72. تحقق: 72÷36=2 ✓, 72÷24=3 ✓. ملاحظة: هنا a*b=864 لا يُسبب فيضاً لأن الأعداد صغيرة، لكن في أعداد كبيرة استخدم (a/gcd)*b.
سؤال 14 — صعب
إذا كانت a وb عددين موجبَين وكان GCD(a,b)=d، فما الصحيح دائماً؟
○ d يساوي a أو b دائماً
○ d أكبر من a وb
○ GCD(a/d, b/d) يساوي d أيضاً
○ GCD(a/d, b/d) = 1 (أوليّان نسبياً)
مهم جداً! بعد قسمة a وb على GCD المشترك d، يصبح العددان الجديدان a/d وb/d أوليّان نسبياً دائماً (GCD=1). هذه هي فكرة تبسيط الكسور: بعد التبسيط بالـ GCD، البسط والمقام لا يشتركان في عوامل.
سؤال 15 — صعب
كم خطوة تعاودية تحتاج خوارزمية إقليدس لحساب GCD(Fib(n+1), Fib(n)) حيث Fib هي أعداد فيبوناتشي؟ وما النتيجة دائماً؟
○ n خطوة والنتيجة Fib(n)
○ n/2 خطوة والنتيجة 2
○ n خطوة والنتيجة دائماً 1
○ log(n) خطوة والنتيجة Fib(2)
هذا هو الحالة الأسوأ لإقليدس! GCD(Fib(n+1), Fib(n)) يحتاج بالضبط n خطوة لأن Fib(n+1) = Fib(n) + Fib(n-1) فالباقي هو Fib(n-1). والنتيجة دائماً 1 لأن أعداد فيبوناتشي المتتالية هي دائماً أوليّة نسبياً. لذا فيبوناتشي هو الحالة الأسوأ لإقليدس!
