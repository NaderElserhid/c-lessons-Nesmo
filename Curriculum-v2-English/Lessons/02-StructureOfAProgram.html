What Is Inside a C++ Program?

Almost every simple program is made of four ordered layers: files we borrow from, then general declarations, then the main function, then the statements inside it. In this small program you will find everything in its place, so click the lines to understand the role of each one:

The main Function: The Starting Point

When you run your program, the system looks for a function named main and starts execution from it, and from nowhere else. That is why:

The rules
  • A program must contain exactly one main
  • Its return type is int
  • Its body is enclosed between { and }
  • The statements inside it run in order from top to bottom
Not allowed
  • Changing the name to Main or start
  • Defining two functions named main
  • Calling main from inside the program

The two accepted forms of main

FormWhen to use it
int main() { ... }A program that needs no command-line arguments (our case for now)
int main(int argc, char* argv[]) { ... }A program that receives arguments when it is launched from the terminal

What does return 0; mean?

The value that main returns goes to the operating system and is called the exit code. The value 0 means everything succeeded, and any other value usually signals a problem. A special feature of main is that if you forget to write return 0; at its end, C++ adds it for you implicitly.

Even so, we write return 0; explicitly in our lessons, because it makes the author's intention clear, and because this implicit behavior belongs to main alone among all functions.

Header Files (#include)

C++ is small at its core, and all of its ready-made tools come in libraries. We borrow a tool by writing the line #include followed by the name of the header file between < >. Before compilation, the preprocessor replaces this line with the entire contents of that file.

HeaderWhat it gives usExamples
<iostream>Input and outputcin, cout
<string>Working with textstring
<cmath>Math functionssqrt, pow
<vector>Resizable arraysvector
<algorithm>Ready-made algorithmssort, max

What is using namespace std?

All the names of the standard library live inside a "neighborhood" called std. We can either write the neighborhood's name every time (std::cout), or announce once that we will use the names of this neighborhood directly with the line using namespace std;. In contests and short exercises we prefer the second way because it is shorter.

You will find some programmers writing #include <bits/stdc++.h> to include all the libraries at once. This header is specific to the GCC compiler and is not part of the standard, so it may not work in other compilers. In our lessons we include each header by name so that we learn what we actually need.

Spacing and Formatting: For Humans, Not Machines

The compiler does not care about the number of spaces, blank lines or indentation outside of texts. The two programs below do exactly the same job:

Formatted and readable
#include <iostream>
using namespace std;

int main() {
    int a = 2;
    int b = 5;
    cout << a + b;
    return 0;
}
Works, but hard to read
#include <iostream>
using namespace std;
int main(){int a=2;int b=5;
cout<<a+b;
        return 0;}

The output of each one is:

7

We compiled and ran both versions, and the output is identical. The difference shows up when you come back to the code after a week or when a teammate reads it: the first is clear at first glance, and the second needs decoding.

A few simple formatting rules are enough for now: one statement per line, four spaces (or one tab) in front of every line inside { }, and a blank line between the logical parts of the program.

One important exception: lines that start with # are each written on their own line, because the preprocessor works line by line.

From a Text File to a Program: What Does g++ Do?

When you type the compile command, your file goes through three stages in a row:

1

Preprocessing

The # lines are carried out: the contents of header files are pasted in place of #include, and comments are removed.

2

Compilation

The compiler checks the rules and converts each file into partial machine code. This is where errors such as a forgotten ; show up.

3

Linking

The pieces are joined with the code of the standard libraries into a single executable file. One of the errors of this stage is that the compiler cannot find the main function.

The usual commands in the terminal:

terminal
# compile trip.cpp into an executable named trip
g++ -std=c++17 trip.cpp -o trip

# run it
./trip

The option -std=c++17 selects the version of the language, and -o trip sets the name of the resulting executable. On Windows the result is usually trip.exe.

Put the Recipe in Order

Medium

This program prints the steps for making tea, but the programmer wrote the steps in the wrong order. The program runs and compiles, yet its output makes no sense. Fix it without changing the text of any step:

tea_jumbled.cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Serve the tea" << endl;
    cout << "Add the tea leaves" << endl;
    cout << "Wait three minutes" << endl;
    cout << "Boil the water" << endl;
    cout << "Pour the water" << endl;
    return 0;
}

Requirements
  • Reorder the cout lines so that the steps appear in the logical order shown in the expected output.
  • Do not change the text of the steps and do not delete any of them.
  • Add a comment at the top of the file with the name of the recipe.
Expected output
Boil the water Add the tea leaves Pour the water Wait three minutes Serve the tea
Hints
  • Remember that the computer runs the statements from top to bottom in the order you wrote them.
  • Start by deciding the first logical step, then arrange the rest behind it.
Sample solution (after you try)
tea.cpp
// Tea recipe
#include <iostream>
using namespace std;

int main() {
    cout << "Boil the water" << endl;
    cout << "Add the tea leaves" << endl;
    cout << "Pour the water" << endl;
    cout << "Wait three minutes" << endl;
    cout << "Serve the tea" << endl;
    return 0;
}

Quick summary

  • #include brings in the tools we need, and using namespace std; saves us from typing std::.
  • The main function is the starting point, and return 0; means the program finished successfully.
  • Spaces and blank lines are for the reader, not the compiler, so format your code to make it easy to understand.
  • A program goes through three stages: preprocessing, compilation, then linking.
  • Common structure mistakes: forgetting a ;, a brace or a header.

Glossary

The most important terms in this lesson:

Function

A named group of statements that performs a specific task.

main

The function where the execution of the program starts.

Preprocessor

A stage that comes before compilation and carries out the lines that start with #.

Directive

A line that starts with #, such as #include, and talks to the preprocessor.

Header file

A file that holds the definitions of ready-made tools that we add to our program.

Namespace

A neighborhood that groups related names to avoid clashes between them, such as std.

Block

A group of statements enclosed between { and }.

Return value

The value a function hands back to whoever called it.

Exit code

The number a program passes to the operating system when it ends; 0 means success.

Linking

The stage that joins the parts of a program and its libraries into one executable file.

Indentation

Shifting lines inside blocks to make the structure of the program clear.

Standard library

A library of ready-made tools that comes with the language, including iostream and string.
