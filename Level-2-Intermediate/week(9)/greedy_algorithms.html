الخوارزميات الجشعة (Greedy Algorithms)

فن اختيار الأفضل "الآن" دون التفكير في الغد!
🍪 مقدمة لذيذة:
تخيل أنه تم وضع طبق مليء بأنواع مختلفة من البسكويت أمامك، وقيل لك اختر ما تشاء. الاستراتيجية الفطرية لديك ستكون: البحث عن أكبر قطعة بسكويت وأخذها أولاً!
أنت هنا لم تضع خطة معقدة للمستقبل، ولم تحسب السعرات الحرارية الإجمالية، أنت فقط نظرت للوضع الحالي، واخترت الخيار الذي يبدو الأفضل في هذه اللحظة.
هذا بالضبط هو مبدأ الخوارزمية الجشعة (Greedy) في البرمجة.

ماذا يعني Greedy (جشع) برمجياً؟

الخوارزمية الجشعة تبني الحل خطوة بخطوة. كلمة "جشع" تعني البحث عن "الحل الأمثل محلياً" (Locally Optimal) — أي أنك في كل خطوة تختار القرار الذي يبدو الأفضل في اللحظة الحالية فقط، ولا تعود لتعديل قراراتك السابقة أبداً.

الهدف من هذا الجشع اللحظي هو الأمل في أن تقودنا هذه الخطوات المتتالية إلى "الحل الأمثل عالمياً" (Globally Optimal) للمشكلة بأكملها.

النمط العام للخوارزمية الجشعة:

while (المشكلة لم تُحل بعد) {
    // 1. اختر أفضل خيار متاح في الوقت الحالي
    Item best_choice = select_best_now();
    
    // 2. أضفه إلى الحل النهائي
    solution.add(best_choice);
    
    // 3. حدّث حالة المشكلة (المتبقي منها)
    update_problem_state();
}

مثال 1: إرجاع الباقي (Coin Change)

معك فئات عملات: (25، 10، 5، 1). تريد إرجاع مبلغ معين (مثلاً 63) للعميل باستخدام أقل عدد ممكن من العملات.

💡 الفكرة الجشعة: دائماً ابدأ بأخذ أكبر عملة ممكنة لا تتجاوز المبلغ المتبقي!

🤖 محاكي الجشع: إرجاع العملات

العملات المتاحة: 25, 10, 5, 1

#include <iostream>
#include <vector>
using namespace std;

int main() {
    int amount = 63;
    // العملات مرتبة من الأكبر للأصغر (شرط أساسي للجشع)
    vector<int> coins = {25, 10, 5, 1}; 
    
    int count = 0;
    
    for (int c : coins) {
        // كم مرة يمكننا استخدام هذه العملة؟
        count += amount / c; 
        // تحديث المبلغ المتبقي عبر باقي القسمة
        amount %= c;         
    }
    
    cout << count << endl; // النتيجة: 6 عملات
    return 0;
}

تحليل الخطوات למبلغ 63:

  • الخوارزمية تأخذ 25 مرتين (المجموع 50، المتبقي 13).
  • تأخذ 10 مرة واحدة (المجموع 60، المتبقي 3).
  • الـ 5 أكبر من 3، فتتجاوزها.
  • تأخذ 1 ثلاث مرات (المجموع 63، المتبقي 0).
النتيجة: 25 + 25 + 10 + 1 + 1 + 1 = 6 عملات. (هذه الطريقة تنجح دائماً في أنظمة العملات الحقيقية).

🚨 متى تفشل الخوارزمية الجشعة؟ (الأهم)

الجشع ليس سحراً! ينجح الجشع فقط عندما يضمن الاختيار المحلي الأفضل الوصول للحل العام الأفضل. إذا لم تكن المسألة تمتلك هذه الخاصية، فإن الجشع سيقودك لفخ ويمنعك من رؤية حلول أفضل.

مثال الفشل الشهير (تغيير نظام العملات):
تخيل أن نظام العملات في دولتك هو: {1, 3, 4}، والمبلغ المطلوب هو 6.

❌ الخوارزمية الجشعة ستفكر هكذا:
ستأخذ أكبر عملة (4). المتبقي 2. ستأخذ (1) ثم (1).
النتيجة الجشعة = 3 عملات (4 + 1 + 1).

✅ لكن الحل الأمثل الحقيقي هو:
أخذ عملتين من فئة (3).
النتيجة المثلى = عملتان فقط! (3 + 3).

هنا، أدى "الطمع" في أخذ العملة الكبيرة (4) إلى حرماننا من الحل الأمثل. (في هذه الحالات الصعبة نلجأ لخوارزميات أخرى مثل البرمجة الديناميكية Dynamic Programming).

مثال 2: اختيار النشاطات (Activity Selection)

معك مجموعة من النشاطات، كل نشاط له (وقت بداية) و (وقت نهاية). لا يمكنك القيام إلا بنشاط واحد في نفس الوقت. المطلوب: ما هو أكبر عدد من النشاطات يمكنك إنهاؤها؟

💡 الفكرة الجشعة السحرية: دائماً اختر النشاط الذي ينتهي أولاً!
لماذا؟ لأن النشاط الذي ينتهي مبكراً يترك لك أكبر مساحة ممكنة من الوقت المتبقي لاختيار نشاطات أخرى. 
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    // كل زوج يمثل: {البداية، النهاية}
    vector<pair<int, int>> act = {{1, 3}, {2, 5}, {4, 6}, {6, 8}, {5, 7}};
    
    // الخطوة الذهبية: الترتيب تصاعدياً حسب "وقت النهاية" (العنصر الثاني في الزوج)
    sort(act.begin(), act.end(), [](auto &a, auto &b){ 
        return a.second < b.second; 
    });
    
    int count = 0;
    int current_end_time = 0;
    
    for (auto &p : act) {
        // إذا كان وقت بداية النشاط الحالي يأتي بعد أو مع نهاية نشاطنا السابق
        if (p.first >= current_end_time) {
            count++;                 // نقوم باختياره
            current_end_time = p.second; // نحدث وقت النهاية
        }
    }
    
    cout << count << endl; // النتيجة: 3 نشاطات
    return 0;
}

خطوات تصميم خوارزمية جشعة ناجحة:

معظم مسائل الجشع تعتمد على نمط ثابت: الفرز ثم الاختيار (Sort & Select).
  1. الفرز (Sorting): قم بترتيب العناصر بناءً على قاعدة معينة (مثل الأكبر قيمة، أو الأقل وقتاً). وغالباً ما نستخدم std::sort.
  2. المرور (Iterating): مرّ على العناصر بالترتيب.
  3. الاختيار (Selection): اختر أفضل خيار صالح في كل مرة وحدّث الحالة.

✅ مميزات الخوارزميات الجشعة

  • سريعة جداً وبسيطة: غالباً ما يكون تعقيدها الزمني $O(N \log N)$ (بسبب عملية الترتيب Sort)، وهو ممتاز للمسابقات.
  • سهلة الفهم والبرمجة: الكود يكون عادة قصيراً ومباشراً.
  • مثالية للجدولة: تعمل بشكل رائع في مشاكل الرسوم البيانية (Graphs)، الجدولة، وتوزيع الموارد.

❌ عيوبها ومخاطرها

  • لا تعطي دائماً الحل الأمثل: كما رأينا في مثال العملات.
  • قِصر النظر: القرارات الجشعة المبكرة قد تدمر وتمنع الوصول لحل أفضل لاحقاً (لأنها لا تنظر للمستقبل).
  • صعوبة الإثبات: إثبات أن خوارزمية جشعة معينة ستعمل بشكل صحيح بنسبة 100% قد يتطلب براهين رياضية معقدة.
💡 نصيحة ذهبية: قبل أن تبرمج حلاً جشعاً، اسأل نفسك دائماً: "هل هذا الاختيار الذي سأقوم به الآن، قد يمنعني من أخذ شيء أفضل لاحقاً؟" حاول بناء (مثال مضاد - Counter Example) في عقلك أو على الورق لاختبار فكرتك قبل برمجتها!
