دليل التعقيد الزمني والمكاني (Time & Space Complexity)

التعقيد الزمني (Time Complexity): عندما نكتب برامج، بعض الحلول تعمل أسرع من غيرها. التعقيد الزمني هو طريقة لـ قياس مدى سرعة نمو الخوارزمية كلما كبر حجم المدخلات ($n$).
لا نقيسه بالثواني، بل نقيسه بعدد الخطوات التي تزداد عند زيادة حجم المدخلات. التعقيد الزمني يساعدك على مقارنة الخوارزميات بدون تشغيلها فعليًا.

مثال أساسي على قياس الخطوات

لنفترض أن لدينا هذا الكود:

for (int i = 0; i < n; i++) {
    cout << i << " ";
}
إذا كان $n = 10$، يطبع البرنامج 10 أرقام. وإذا كان $n = 1000$، يطبع 1000 رقم. إذا تضاعف $n$، فإن عدد الخطوات أيضًا يتضاعف. نقول إن هذا الكود يعمل في $O(n)$ زمن، لأنه يحتوي على $n$ خطوة/عملية. هذا يعني أن الوقت ينمو خطيًا مع حجم المدخلات.

ما معنى الرمز الكبير (Big O)؟

الرمز الكبير $O$ (Big O) يوضح كيف ينمو عدد الخطوات مع زيادة $n$. نهتم فقط بالنمو الرئيسي، وليس بالثوابت أو التفاصيل الصغيرة.

الرمز (Big O) الاسم المثال الوصف
$O(1)$ وقت ثابت x = a + b; يعمل فورًا بغض النظر عن حجم $n$.
$O(\log n)$ لوغاريتمي set::insert كل خطوة تقلل المشكلة للنصف.
$O(n)$ وقت خطي حلقة على مصفوفة الوقت ينمو خطيًّا.
$O(n \log n)$ شبه خطي ترتيب (Sorting) أبطأ قليلًا من $O(n)$، ولكن أسرع بكثير من $O(n^2)$.
$O(n^2)$ وقت تربيعي حلقات متداخلة الوقت ينمو بسرعة كبيرة عند زيادة $n$.
$O(2^n)$ أسي تجربة جميع التركيبات ينمو بشكل هائل بسرعة.

كلما كان التعقيد أصغر، كان النمو أسرع.

1. وقت ثابت – $O(1)$

مثال: زيادة الرقم

معطى لك رقم $x$. قم بزيادة $x$ بمقدار 1، ثم اطبعه.

#include <iostream>
using namespace std;

int main() {
    int x;
    cin >> x;
    x += 1;
    cout << x << '\n';
}
هنا، قمنا بثلاثة أشياء: قراءة عدد صحيح، زيادته بمقدار واحد، وإخراجه. كلها عمليات بسيطة. لكننا لا نقول إن هذا تعقيد $O(3)$، لأننا لا نهتم بالثوابت؛ نهتم فقط بالنمو الرئيسي. إذن هذا $O(1)$.

2. وقت خطي – $O(n)$

مثال: مجموع المال

معطى لك $n$ أوراق نقدية قيمتها $a_1$ ريال، $a_2$ ريال، …، $a_n$ ريال. كم مجموع الريالات لديك؟

#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    int arr[n];
    
    for (int i = 0; i < n; i++)
        cin >> arr[i];
        
    long long sum = 0;
    for (int i = 0; i < n; i++)
        sum += arr[i];
        
    cout << sum << '\n';
}
الحلقة تعمل مرة لكل عنصر. إذا تضاعفت المصفوفة، يتضاعف الوقت أيضًا. لاحظ أننا أنشأنا مصفوفة وأدخلنا العناصر، ثم جمعناها. بالمجموع: $O(2n)$. لكننا لا نهتم بالثوابت، إذن التعقيد $O(n)$ - خوارزمية زمنها خطي.

3. وقت تربيعي – $O(n^2)$

مثال: النسخ

معطى لك $n$ أوراق نقدية. لكل يوم من الـ $n$ أيام، قم بزيادة قيمة كل ورقة بمقدار واحد. اطبع قيم كل الأوراق لكل يوم من الأيام.

#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    int arr[n];
    for (int i = 0; i < n; i++)
        cin >> arr[i];

    for (int days = 1; days <= n; days++) {
        for (int i = 0; i < n; i++) {
            cout << arr[i] + days << ' ';
        }
        cout << '\n';
    }
}
هناك $n$ أيام و $n$ أوراق في كل يوم يجب زيادتها. بالمجموع، نقوم بـ $n \times n$ عملية. إذا كان $n = 1000$، فإن الخطوات = مليون. لهذا يمكن أن تصبح خوارزميات $O(n^2)$ بطيئة جدًا بسرعة.

مقارنة معدلات النمو

لنرى كيف ينمو عدد الخطوات مع زيادة $n$. حتى لو بدت الفروقات صغيرة عند $n$ صغير، فإنها تتضخم جدًا عند $n$ كبير.

$n$ $O(1)$ $O(\log n)$ $O(n)$ $O(n^2)$
10 1 $\approx 3$ 10 100
100 1 $\approx 6$ 100 10,000
1,000 1 $\approx 9$ 1000 1,000,000

قاعدة سريعة لتخمين الحل المقبول

هذا يساعدك على تخمين نوع الحل المناسب لحجم مدخلات معين في المسابقات:

حجم $n$ التعقيد الأقصى المقبول
$n \le 10^4$ عادة $O(n^2)$ مقبول
$n \le 10^5$ عادة $O(n \log n)$ أو أفضل
$n \le 10^7$ $O(n)$ أو أفضل
$n \ge 10^9$ فقط $O(1)$ أو $O(\log n)$

تحسين الحلول

أحيانًا ليس واضحًا، لكن يمكنك جعل البرنامج أسرع بالتفكير في حلول أذكى.

المجموع البسيط

معطى لك رقم $n$. أوجد مجموع الأرقام من $-n$ إلى $n$.

حل بسيط خطيًا $O(n)$: 
#include <iostream>
using namespace std;
int main() {
    int n;
    cin >> n;
    long long sum = 0;
    for (int i = -n; i <= n; i++)
        sum += i;
    cout << sum << '\n';
}
الحل الأفضل $O(1)$:
يمكننا عمل أفضل من ذلك. كل عدد يظهر مرة موجبة ومرة سالبة. إذن في النهاية، كل الأعداد تلغي بعضها البعض ويبقى فقط صفر. هذا الحل وقت ثابت وأسرع بكثير. دائمًا حاول التفكير في أسرع حل ممكن. 
#include <iostream>
using namespace std;
int main() {
    int n;
    cin >> n;
    cout << 0 << '\n';
}

التعقيد المكاني (Space Complexity)

أحيانًا نهتم أيضًا بـ كمية الذاكرة التي يستخدمها البرنامج. هذا ما يسمى التعقيد المكاني. الفكرة نفسها: كيف ينمو استخدام الذاكرة مع زيادة حجم المدخلات. 
int arr[n];  // يستهلك مساحة تتناسب مع n، إذن المساحة O(n)
int x;       // يستهلك مساحة ثابتة، إذن المساحة O(1)
