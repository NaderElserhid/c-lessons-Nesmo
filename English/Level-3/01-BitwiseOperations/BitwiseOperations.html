Bitwise Operations

In this chapter you will drop down to the deepest layer of the numbers your programs work with: individual bits. You will learn how positive and negative numbers are actually stored inside the computer, and how operators like AND, OR, XOR, and shifting work on each individual bit. These tools are essential for optimization tricks, and they will be the foundation for an upcoming chapter on generating all subsets using a binary representation called a Bitmask.

Why Learn Bitwise Operations?

Bitwise operations let you work with the individual bits inside an integer directly, instead of treating the number as a single block. These operations are very powerful for manipulating bits, optimization tricks, and things like generating all the subsets of a given set — which you will see in detail in an upcoming chapter.

Binary Numbers

Computers store integers in binary form — using only 0 and 1. We say a bit is set if its value is 1. Each position (bit) represents a power of 2:

Bit position76543210
Value1286432168421

To get the value of a binary number, we sum the powers of 2 at the positions where the bit equals 1. For example:

00000110 = 4 + 2 = 6 00001010 = 8 + 2 = 10 00001100 = 8 + 4 = 12 00000001 = 1 = 1 00000000 = 0 = 0

So when we perform bitwise operations (&, |, ^, etc.), we're actually combining or modifying these individual bits.

Two's Complement and Negative Numbers

So far we've only talked about non-negative numbers. But in C++ (and in most modern processors), signed integers are stored in a format called two's complement.

The idea: use the highest bit (the most significant bit) as a sign bit. Suppose we have signed integers made of 8 bits:

Bit position76543210
Value-1286432168421

The range of signed 8-bit numbers is: -128 ... +127

The Shape of Positive Numbers

Positive numbers (and zero) look exactly like in ordinary binary:

00000101 = 5 00000000 = 0 00001010 = 10

How Negative Numbers Are Stored (Two's Complement)

To get -x in two's complement:

  1. Write x in binary.

  2. Flip all the bits (0 -> 1, 1 -> 0).

  3. Add 1.

Example: representing -5 on 8 bits:

+5 = 00000101 flip = 11111010 + 1 = 11111011 = -5

Checking -1:

+1 = 00000001 flip = 11111110 + 1 = 11111111 = -1

So: 11111111 = -1, 11111011 = -5, 10000000 = -128.

Why Is This Method Useful?

By using two's complement:

  • Ordinary binary addition also works with negative numbers unchanged.

  • There is only a single representation for zero.

  • Subtraction can simply be performed as a + (-b).

Right Shifting Negative Numbers

For unsigned types, >> always shifts bits to the right while inserting 0 bits from the left.

For signed types, most compilers perform an arithmetic right shift: the sign bit (the highest bit) is copied, so negative numbers stay negative during the shift.

Example (assuming an arithmetic shift):

x = -4 -> 11111100 (8-bit view) x >> 1 -> 11111110 (still negative: -2)

For this reason, when we only care about the raw bits, it's often safer to use unsigned types like uint32_t and unsigned long long, etc. — to avoid surprises from arithmetic shifting with negative numbers.

The Main Bitwise Operators

All these operators work on integer types (int, long long, etc.):

OperatorNameWhat It Does Bit by Bit
&ANDequals 1 if both bits are 1, otherwise 0
|ORequals 1 if at least one of the bits is 1, otherwise 0
^XORequals 1 if the two bits differ, otherwise 0
~NOT / complementflips every bit (1 → 0, 0 → 1)
<<Left shiftshifts bits to the left (like multiplying by powers of 2)
>>Right shiftshifts bits to the right (like dividing by powers of 2)

Seeing Bitwise Operations in Binary Form

Let's use small numbers and assume they are made of 8 bits for extra clarity:

a = 6 -> 00000110 b = 10 -> 00001010

The AND Operator &

a & b -> 00000110 00001010 -------- 00000010 = 2

The OR Operator |

a | b -> 00000110 00001010 -------- 00001110 = 14

The XOR Operator ^

a ^ b -> 00000110 00001010 -------- 00001100 = 12 (bits that are different become 1)

The NOT Operator ~

~a -> 11111001 (in 8 bits, but in real C++ the operation applies to the type's full width)

Shifts

a << 1 -> 00001100 = 12 (6 * 2) a << 2 -> 00011000 = 24 (6 * 4) b >> 1 -> 00000101 = 5 (10 / 2) b >> 2 -> 00000010 = 2 (10 / 4, integer division)

A Full C++ Example

bitwise_demo.cpp
#include <iostream>
using namespace std;

void printBits(int x) {
    for (int i = 7; i >= 0; i--) {
        cout << ((x >> i) & 1);
    }
}

int main() {
    int a = 6;   // 00000110
    int b = 10;  // 00001010

    cout << "a = "; printBits(a); cout << " (" << a << ")\n";
    cout << "b = "; printBits(b); cout << " (" << b << ")\n\n";

    cout << "a & b = "; printBits(a & b); cout << " (" << (a & b) << ")\n";
    cout << "a | b = "; printBits(a | b); cout << " (" << (a | b) << ")\n";
    cout << "a ^ b = "; printBits(a ^ b); cout << " (" << (a ^ b) << ")\n";
    cout << "~a    = "; printBits((unsigned char)~a); cout << " (only low 8 bits)\n";
    cout << "a << 1 = "; printBits(a << 1); cout << " (" << (a << 1) << ")\n";
    cout << "b >> 1 = "; printBits(b >> 1); cout << " (" << (b >> 1) << ")\n";
}

The printBits function loops over every bit position i (from 7 down to 0), and performs x >> i, which shifts the value of x right by i places. This moves the bit at position i all the way to the rightmost position. Then we take & 1, which performs an AND with 00000001, keeping only the rightmost bit and clearing all the others. So the combination (x >> i) & 1 extracts the bit at position i and prints it to the screen.

a = 00000110 (6) b = 00001010 (10) a & b = 00000010 (2) a | b = 00001110 (14) a ^ b = 00001100 (12) ~a = 11111001 (only low 8 bits) a << 1 = 00001100 (12) b >> 1 = 00000101 (5)

This output was actually verified by compiling and running the code above — it matches exactly all the manual calculations we saw in this chapter.

Common Mistakes and Tips

  • Don't confuse & (bitwise AND) with && (logical AND), or | with || — this is one of the most common mistakes beginners make.

  • Remember that right-shifting negative signed numbers can differ from ordinary division when working with raw bits — use unsigned types if you need consistently predictable behavior.

  • ~x operates on the type's full width (usually 32 bits for int), not just 8 bits — that's why we used (unsigned char)~a in the example to show only the last 8 bits.

  • Shifting by a negative amount, or by an amount greater than or equal to the type's bit width, is undefined behavior in C++ — always avoid it.

Quick Summary

Every integer is stored as a sequence of bits, and each bit represents a power of 2.
Negative numbers are stored using two's complement: flip the bits, then add 1.
The AND, OR, XOR, and NOT operators work bit by bit, and shifts behave like multiplying or dividing by powers of 2.
Right-shifting negative signed numbers usually preserves the sign (arithmetic shift) — use unsigned to avoid surprises.

3) Bitwise Operators on Two New Numbers

For the numbers a = 13 and b = 21, compute a & b, a | b, a ^ b, and ~a (on 8 bits). Then compute the value of (-10) >> 2 assuming an 8-bit arithmetic shift.

a = 13: 00001101 b = 21: 00010101 a & b = 00000101 = 5 a | b = 00011101 = 29 a ^ b = 00011000 = 24 ~a (8-bit) = 11110010 -10 (8-bit) = 11110110 (-10) >> 2 = 11111101 = -3

Notice that the arithmetic shift copied the sign bit (1) three times from the left, preserving the negativity of the result.
