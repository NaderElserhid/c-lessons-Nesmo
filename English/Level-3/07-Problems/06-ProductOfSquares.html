Product of Squares

A number-theory problem that's simple to state but hides an elegant idea behind it: the question "can A be written as a product of two squares x² and y² with x,y > 1?" reduces exactly to just two sequential questions: is A itself a perfect square? And if so, is its square root a composite (non-prime) number?

Easy

Problem Statement

You're given positive integers, and for each number A you must determine whether it can be written in the form:

A = x² · y² where x > 1 and y > 1

Constraints

  • 1 ≤ N ≤ 1000 (number of queries)

  • 1 ≤ A ≤ 10¹⁸

Ease into the difficulty: the problem itself suggests solving an easier version first if you run into trouble: try first assuming 1 ≤ A ≤ 10⁵, and if it's still hard, try 1 ≤ A ≤ 10⁴. This is an excellent technique for any hard problem: start with a smaller version of the constraints, make sure your solution is correct on it, then extend it to handle the full constraint.

Input

First line: an integer N. Then N lines, each containing an integer A to check.

Output

For each number A, print YES if it satisfies the condition, or NO if it doesn't.

Example

Input: 3 9 144 234 Output: NO YES NO

9 = 3² is the only option, but 3 is prime so it can't be split into two factors greater than 1 → NO.
144 = 12², and 12 = 2×6 (or 3×4), so 144 = 2²×6² can be written → YES.
234 isn't a perfect square at all (15²=225 and 16²=256) → NO immediately.

Try Your Own Number

The "Try Your Own Number" tool here is limited to about 10¹² only, due to floating-point precision limits in JavaScript, while the real C++ solution (below) safely handles the full constraint 10¹⁸ because it uses integers (long long) with no floating-point rounding at all.

How Do We Think About This Problem?

  • Rewrite the equation: A = x²·y² = (x·y)². If we call z = x·y, then A must be a perfect square of some number z.

  • But not just any perfect square is enough: we specifically need z = x·y with x > 1 and y > 1 — meaning z itself must accept being split into two factors greater than 1, which is exactly the definition of a composite number (not prime and not 1).

  • Test with small examples: z=4=2×2 ✓ composite, z=6=2×3 ✓ composite, but z=5 is prime, so its only factorization is 1×5 — not acceptable since one factor equals 1.

  • So the algorithm is just two steps: (a) compute the integer square root z of A, and verify that z² = A exactly. (b) if so, check whether z is composite via trial division up to √z.

  • Watch out for the common trap: the question isn't "is A prime?" nor "is A composite?" — it's "is the square root of A (after confirming it's a perfect square) composite?" This is an easy mix-up to fall into.

Complexity Analysis — and Why We Don't Factor A Directly

The key efficiency insight: we never need to factor A itself (which can reach 10¹⁸), only its square root z = √A, which doesn't exceed 10⁹. Trial division on z only needs to go up to √z ≈ 31,623.

ApproachComplexity per queryTotal time (N=1000)
Factoring A directly (wrong/slow)O(√A) ≈ 10⁹≈ 10¹² — far too slow
Factoring z=√A only (the correct solution)O(A¹⁄⁴) ≈ 31,623≈ 3.16×10⁷ — very fast

This is a beautiful example of "shrink the problem before you solve it": instead of asking a hard question about the large A, we transformed it into a much easier question about the much smaller z = √A.

The Full Solution

product_of_squares.cpp
#include <iostream>
#include <cmath>
using namespace std;

// exact integer square root, correcting for possible floating-point rounding errors
long long integerSqrt(long long A) {
    long long z = (long long)sqrtl((long double)A);
    while (z > 0 && z * z > A) z--;
    while ((z + 1) * (z + 1) <= A) z++;
    return z;
}

// does z accept being split into two factors greater than 1? (i.e.: is z composite)
bool isComposite(long long z) {
    if (z < 4) return false;  // 0,1: not even valid values here / 2,3: prime
    for (long long d = 2; d * d <= z; d++) {
        if (z % d == 0) return true;
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    while (n--) {
        long long A;
        cin >> A;

        long long z = integerSqrt(A);
        if (z * z != A) {
            cout << "NO\n";
            continue;
        }

        cout << (isComposite(z) ? "YES" : "NO") << "\n";
    }
    return 0;
}

We verified this manually against the three examples: A=9 → z=3 (prime) → NO. A=144 → z=12 (divisible by 2) → YES. A=234 → z=15 but 15²=225 ≠ 234 → NO immediately.

Points Worth Watching

Floating-point square root precision: the sqrt() or sqrtl() function may give a result off by 1 (too low or too high) from the actual correct value when dealing with very large numbers (up to 10¹⁸) due to internal floating-point rounding. That's why we never trust the result directly — we always correct it by checking z-1, z, z+1 as in the integerSqrt function above.

Numeric typesA reaches 10¹⁸, far exceeding int capacity — long long must be used everywhere, including computing z*z and the comparisons.
Small cases z < 4z=1 has no valid factorization, and z=2, 3 are both prime — isComposite must return false for all three of these cases (guaranteed by the condition z < 4).
Confusing checking A with checking zThe trial division (and primality check) is applied to z = √A, not to A itself — factoring A directly is far slower and unnecessary.
The strict condition x,y > 1It's not enough for A to just be a perfect square — its root must also be splittable into two factors, both greater than one.

This problem combines two tools we've seen before in Level Four (checking whether a number is a perfect square, and trial division in O(√n) time to check primality), and adds a clever twist: apply the second tool to the root of the input instead of the input itself, turning a problem that looks heavy (A up to 10¹⁸) into one that's fast to solve in practice.
