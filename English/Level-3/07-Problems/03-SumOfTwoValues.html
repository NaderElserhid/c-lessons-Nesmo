Sum of Two Values

This problem is your first real introduction to the "Complement" pattern that will show up in dozens of problems later on: instead of checking every possible pair, at each element we ask exactly one question — "have I seen the value that completes the required sum before?" — using the std::map we learned about in Level Two.

Easy CSES 1640 — Sorting and Searching

Problem Statement

You're given an array of n integers, and you need to find two different positions i and j (i.e. i ≠ j) such that the sum of their values equals a target number x given beforehand.

If more than one valid pair exists, you may print any of them. If no pair satisfies the condition, print IMPOSSIBLE.

Constraints

  • 1 ≤ n ≤ 2·10⁵

  • 1 ≤ x, aᵢ ≤ 10⁹

Input

First line: two integers n and x — the array size and the target sum.
Second line: n integers representing the array values.

Output

Either two positions (1-indexed) i j such that a[i] + a[j] = x and i ≠ j, or the word IMPOSSIBLE if no valid pair exists.

Example

Input: 4 8 2 7 5 1 Output: 2 4

One correct solution is positions 2 and 4 (1-indexed), because a[2] + a[4] = 7 + 1 = 8.

A note on indexing: we'll handle the array internally using zero-based indexing (a[0], a[1], ..., a[n-1]) as in the code, but the output required on CSES must use 1-based positions — so we always print index + 1.

Notice that at every step we check the map before adding the current element to it — this is exactly what guarantees the two resulting positions are always different (i ≠ j), with no extra check needed.

How Do We Think About This Problem?

  • Understand the problem: we want any pair of different positions whose values sum to exactly x — we don't care which specific pair, just that one valid pair exists.

  • Try the naive solution first: check every possible pair (i, j) with two nested loops, and verify whether a[i] + a[j] = x.

  • Estimate the cost of this solution: the number of possible pairs is roughly n²/2. With n up to 2·10⁵, that's about 2×10¹⁰ operations — far slower than the one-second time limit allows.

  • Look for information that can be reused: at each element a[i], the only real question is: "has the value x - a[i] appeared before?" — this is a membership question, not an exhaustive search.

  • Choose the right data structure: std::map<long long, int> answers the membership question and stores a new value, both in O(log n) time.

  • Implement the algorithm in a single pass: scan the array just once, updating the map as you go, instead of scanning it fully for every element.

  • Check the edge cases: what if no pair exists at all? What if the same value repeats more than once in the array?

The Core Idea: The Complement

For each element a[i] we pass over, we compute the value that "completes it" to reach the sum x:

need = x - a[i]

If need already exists in the map of "values we've seen before", we've found a valid pair immediately. Otherwise, we store a[i] itself in the map (along with its index) so it's available as a potential complement for a later element, and continue scanning.

This transformation — from "check every pair" to "for each element, ask one membership question" — is the exact same pattern that will recur in many other problems later, such as Sum of Three Values (where we fix one element and apply the same "find a pair" idea to the rest).

The Full Solution

sum_of_two_values.cpp
#include <iostream>
#include <map>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<long long> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    // value -> index (1-based)
    map<long long, int> pos;

    for (int i = 0; i < n; i++) {
        long long need = x - a[i];

        auto it = pos.find(need);
        if (it != pos.end()) {
            // found a pair: a[i] + need = x
            cout << it->second << " " << (i + 1) << "\n";
            return 0;
        }

        // store the current value along with its index (1-based)
        pos[a[i]] = i + 1;
    }

    cout << "IMPOSSIBLE\n";
    return 0;
}

We verified this code manually against the official example step by step (it matched 2 4 exactly), and against a case with no valid pair (it prints IMPOSSIBLE after fully scanning the array without finding a match).

Points Worth Watching

The two different positions (i ≠ j)Guaranteed automatically because we search the map before adding the current element to it, so an element can never match itself.
Searching for the wrong elementA very common mistake is writing pos.find(a[i]) instead of pos.find(need) — remember: we're searching for the complement, not the current value itself.
1-based indexingDon't forget to print i + 1, not i — CSES expects positions starting from 1.
Repeated valuesIf the same value repeats in the array, the map will keep the last index it appeared at — this is perfectly fine since the problem accepts any valid solution.
Data typeThe values x and aᵢ can reach 10⁹, which comfortably fits in an int on its own, and need = x - a[i] itself also stays roughly within the same range — there's no real overflow risk here, but using long long as in the code above is a safety habit that costs nothing, especially if you reuse the same template later in a problem that actually requires summing values.
Finding no solutionYou must complete the full scan of the array before concluding there's no solution — don't stop early.

Time complexity: std::map is built on a balanced red-black tree, so each search or insert operation costs O(log n), giving a total time of O(n log n) — entirely sufficient here. If you want it faster, std::unordered_map gives O(n) on average, but it doesn't preserve any ordering of the values and isn't directly suitable if you later need order-based queries (finding the nearest value, for example).

This is the famous Two-Sum pattern — one of the most recurring patterns in both competitive programming and technical job interviews alike. Whenever you meet a problem asking to "find two elements/pairs satisfying a sum condition," think immediately: can it be transformed into "for each element, look for its complement in a set of what you've seen before?"
