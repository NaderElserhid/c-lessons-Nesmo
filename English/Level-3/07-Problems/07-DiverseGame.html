Diverse Game

A constructive problem straight out of the constructive problems chapter: we have a complete matrix (containing every number from 1 to n·m), and we need to build another matrix with the same property, but differing from the first in every single cell without exception. The exact same idea we saw with Anti-Identity Permutation, but this time applied to a two-dimensional matrix instead of a one-dimensional array.

Easy Codeforces 1994A

Problem Statement

You have a matrix a of size n × m, containing every integer from 1 to n·m, each exactly once. Build a matrix b of the same size, which also contains every number from 1 to n·m exactly once, such that for every cell (i, j): a[i][j] ≠ b[i][j]. If this is impossible, print -1.

Constraints

  • Number of test cases 1 ≤ t ≤ 1000

  • 1 ≤ n, m ≤ 10 per case

  • The sum of n·m over all test cases doesn't exceed 5×10⁴

Example

Input: 5 1 1 1 2 1 2 1 1 5 2 4 5 3 1 Output: -1 1 2 4 5 3 1 2

In the first case (n=m=1), there's only one possible value (1), which necessarily matches a's own value → impossible. In the second case, b=[1, 2] satisfies 1≠2 and 2≠1.

Important note: the problem accepts any valid matrix b, not necessarily the same one shown in the official example. In the third case above for instance, the official output given is 4 5 3 1 2, but our solution on this page will produce a matrix that looks different from it (and is equally correct) — exactly as happened earlier with the Sum of Three Values problem.

The Solution Idea: Shift by One

  • This problem is a matrix version of Anti-Identity Permutation: instead of rotating a single array, we rotate every value in the two-dimensional matrix by one within the range 1..n·m.

  • For each cell: b[i][j] = a[i][j] + 1, unless a[i][j] = n·m (the largest value), in which case b[i][j] = 1 (we wrap back to the start of the range).

  • Why does this always work (almost)? Because shifting by one keeps all the values distinct from each other (it's still a full permutation of 1..n·m), while at the same time every value becomes different from its original value — except in one unique case.

  • The one exception: if n·m = 1 (i.e. n=m=1), then the rotation maps the single value back to itself (1 → 1), exactly as we saw with n=1 in Anti-Identity Permutation. This is the only impossible case.

This is a beautiful example of how a single constructive idea (shifting by one to avoid fixed points) can be reused in more than one form: a one-dimensional array, a two-dimensional matrix, or any other data structure that needs "every element must change."

The Full Solution

diverse_game.cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;

    while (t--) {
        int n, m;
        cin >> n >> m;

        int a[n][m], b[n][m];

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                cin >> a[i][j];

                if (a[i][j] == n * m) b[i][j] = 1;
                else b[i][j] = a[i][j] + 1;
            }
        }

        if (n == 1 && m == 1) {
            cout << -1 << "\n";
            continue;
        }

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                cout << b[i][j] << ' ';
            }
            cout << "\n";
        }
    }
}

Portability note: the declaration int a[n][m] with non-constant dimensions (a VLA — Variable Length Array) is accepted by compilers such as GCC (used by most online judges), but it is officially not part of the standard C++ specification. The always-safe and portable alternative is to use vector<vector<int>> a(n, vector<int>(m));.

Points Worth Watching

Order of checkingCompute b fully while reading, then check the n=m=1 case before printing — if you print b before confirming impossibility, you'll print a wrong answer for that exact case.
Don't forget a newline after each caseEach test case must be printed on separate line(s); failing to add "\n" after each row can mix up the output of consecutive test cases.
The printed value isn't uniqueThere's no "one correct solution" — any matrix b that satisfies both conditions (a full permutation + differing from a in every cell) is accepted by the judge.

The exact same lesson as Anti-Identity Permutation, but on a different data structure: "cyclically shift every value by one" automatically builds a permutation with no fixed points, and the one impossible case only shows up when there's just a single element in the entire structure.
