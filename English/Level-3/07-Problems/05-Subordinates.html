Subordinates

In every dynamic programming problem we've solved so far (Frog 1, Knapsack 1), the state dp[i] was tied to a position in an array we moved through in a clear linear order from start to end. This problem shows that the same "build the solution from smaller solutions" idea also works on top of a tree — only the "order of computation" changes from a linear sequence to a post-order traversal via DFS: compute all children first, then the parent.

Easy CSES 1674 — Tree Algorithms

Problem Statement

A company has n employees numbered from 1 to n. Employee number 1 is the general manager. For each employee from 2 to n, the identity of their direct boss is given — this builds a hierarchical structure (a tree) for the company, where a boss may have multiple direct children.

Required: for each employee from 1 to n, compute their total number of subordinates (direct and indirect combined).

Constraints

  • 1 ≤ n ≤ 2·10⁵

Input

First line: an integer n.
Second line: n-1 integers p2 p3 ... pn, where pi is the direct boss of employee i.

Output

Print n integers: for each employee from 1 to n, their total number of subordinates.

Example

Input: 5 1 1 2 3 Output: 4 1 1 0 0

Employee 2's boss is 1, employee 3's boss is 1, employee 4's boss is 2, employee 5's boss is 3. Manager 1 has 4 subordinates (everyone), 2 has 1 (only 4), 3 has 1 (only 5), and 4, 5 are leaves with no subordinates.

Notice the order in which nodes are processed isn't necessarily 1, 2, 3, 4, 5 — the only thing that matters is that every node is processed after all of its direct children, regardless of its number.

How Do We Build On the DP Idea We Already Know?

  • Define the state: size[v] = the number of employees in the subtree rooted at v, including v itself.

  • The recurrence: size[v] = 1 + sum of size[child] for every direct child of v — in exactly the same spirit as dp[i] = combine(dp[previous states]) that we saw in Frog 1, except "the previous states" here are the children in the tree, not i-1 and i-2.

  • Base case: leaves (employees with no direct subordinates) have size[v] = 1 (just themselves).

  • Order of computation: since computing size[v] needs every child's value ready first, the tree must be processed in post-order (DFS processes children before the parent) — there's no "left to right" here as in an array, but the same principle applies: never compute a state before every state it depends on is ready.

  • Final answer: the number of subordinates of v = size[v] - 1 (we subtract v itself, since it isn't its own subordinate).

Complexity Analysis

Each employee is processed exactly once in the DFS, and each edge (boss←child) is used once when building the children list.

Time = O(n) , Memory = O(n)

The Full Solution

subordinates.cpp
#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> children;
vector<long long> subCount;

void dfs(int v) {
    long long total = 0;

    // compute all children first (post-order)
    for (int c : children[v]) {
        dfs(c);
        total += subCount[c] + 1;   // the child itself + all of its subordinates
    }

    subCount[v] = total;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    children.assign(n + 1, {});
    for (int i = 2; i <= n; i++) {
        int p;
        cin >> p;
        children[p].push_back(i);
    }

    subCount.assign(n + 1, 0);
    dfs(1);

    for (int i = 1; i <= n; i++) {
        cout << subCount[i] << (i < n ? ' ' : '\n');
    }
    return 0;
}

We verified this code manually against the full official example: dfs(1) calls dfs(2) which returns 1 (since 2 has one child, 4), and dfs(3) similarly returns 1, so subCount[1] = (1+1) + (1+1) = 4 — matching exactly the official output 4 1 1 0 0.

Points Worth Watching

Recursion depthIf the company is one long chain (each employee is the boss of exactly one other), the recursive dfs could reach a depth of 2·10⁵ levels — the same issue we discussed in Frog 1, but at a much larger scale here. The safest fix if you run into this in practice: an iterative DFS with a manual stack instead of self-recursion.
Printing all n valuesYou must print the subordinate count for every employee from 1 to n, including the general manager and the leaves (whose value is 0) — not just those who actually have subordinates.
long long isn't strictly necessaryThe largest possible result value is n-1 ≤ 2·10⁵-1, which fits comfortably in an int. long long was used in the code above purely as a safety habit.
The order of children doesn't matterThe operation is a pure cumulative sum (commutative), so it doesn't matter in what order we process the children inside the loop.

This is the simplest possible form of what's called Tree DP: a single state per node, computed cumulatively from its children. Whenever you meet a problem asking for information tied to "everything below this node in a tree" (size, sum, leaf count...), think immediately in the same template: define the state, write its relation to the children, and compute it in post-order via DFS.
