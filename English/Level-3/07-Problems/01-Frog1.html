Frog 1 (Frog Jumps)

This problem is a direct application of the "minimum cost to reach the end" idea we learned in the Dynamic Programming chapter, except the transition cost now depends on the actual values instead of being a fixed cost per position. Apply SRTBOT to it step by step and you'll find it quite familiar.

Easy AtCoder DP Contest — A

Problem Statement

You're given an array containing n elements (representing the heights of n stones). You start at the first element, and must reach the last element, using one of the following two moves each time:

  • Move from position i to position i + 1 at a cost of |a[i] - a[i+1]|.

  • Move from position i to position i + 2 at a cost of |a[i] - a[i+2]|.

Required: find the minimum total cost of moving from the first element to the last element.

Important note on indexing: in this problem we'll assume everything is zero-indexed — i.e. all array positions are numbered 0, 1, ..., n-1. Note that the original AtCoder statement numbers the stones from 1 to n, so "stone 1" in the statement corresponds to a[0] in the code, and "stone n" corresponds to a[n-1].

Constraints

  • 2 ≤ n ≤ 10⁵

  • 1 ≤ a_i ≤ 10⁴

Input

First line: an integer n.
Second line: n integers representing the stone heights.

Output

A single integer: the minimum total cost of reaching the last stone from the first stone.

Example 1

Input: 4 10 30 40 20 Output: 30

Optimal path: stone 1 → 2 → 4, at a cost of |10-30| + |30-20| = 20 + 10 = 30.

Example 2

Input: 6 30 10 60 10 60 50 Output: 40

Optimal path: stone 1 → 3 → 5 → 6, at a cost of |30-60| + |60-60| + |60-50| = 30 + 0 + 10 = 40.

Solution Methodology: How Do We Think About This Problem?

  • Understand the problem: we want the minimum total cost to move from position 0 to position n-1, using jumps of one or two steps, at a cost equal to the absolute difference between the heights of the two positions.

  • Try small examples by hand: trace the first example manually: is jumping directly cheaper than passing through every position?

  • Look for a recursive pattern: to reach position i, you must have come either from i-1 or from i-2 — there's no third option.

  • Think about efficiency: the naive recursive solution (without memoization) explores the same positions repeatedly, exactly like the Fibonacci problem — the time becomes exponential.

  • Write the code and verify: define dp[i], write the recurrence, add memoization, and check it against all the official examples.

  • Check the edge cases: what happens when n = 2? And what about the array size for large n?

Step 1: Why Not Try Every Path?

We can write a naive recursive solution: define solve(i) = minimum cost to reach position i. Then solve(i) = min(solve(i-1) + |a[i]-a[i-1]|, solve(i-2) + |a[i]-a[i-2]|).

But this solution re-explores the same positions many times (exactly like Fibonacci: solve(5) calls solve(4) and solve(3), and solve(4) in turn calls solve(3) again). The time becomes roughly O(2ⁿ) — completely impractical once n reaches 10⁵.

Step 2: Applying the SRTBOT Framework

S — State: we define dp[i] = the minimum cost to reach position i starting from position 0.

R — Recurrence: there are two ways to reach position i: from i-1 or from i-2. Since we don't know which is better, we take the minimum of the two options:

dp[i] = min( dp[i-1] + |a[i]-a[i-1]| , dp[i-2] + |a[i]-a[i-2]| )

T — Transitions: from state i, the two states we depend on are only i-1 and i-2.

B — Base cases: dp[0] = 0 (we start here, so there's no cost yet), and dp[1] = |a[1]-a[0]| (the only way to reach position 1 is the direct jump from 0).

O — Order of computation: we compute from smallest to largest: 0 ← 1 ← 2 ← ... ← n-1, so that dp[i-1] and dp[i-2] are ready before computing dp[i].

T — Time/space complexity: time O(n) (each state is computed once), and memory O(n) to store dp[].

Step 3: The Full Solution (Top-Down with Memoization)

frog1.cpp
#include <iostream>
using namespace std;

int a[200000];
int dp[200000];

int f(int i) {
    // base cases
    if (i == 0) {
        return 0;
    }
    if (i == 1) {
        return abs(a[1] - a[0]);
    }

    // if the solution has already been computed
    if (dp[i] != -1) {
        return dp[i];
    }

    dp[i] = min(
        f(i - 1) + abs(a[i] - a[i - 1]),
        f(i - 2) + abs(a[i] - a[i - 2])
    );

    return dp[i];
}

int main() {
    // assign -1 to every element to indicate we don't know the solution to any state yet
    for (int i = 0; i < 200000; i++) {
        dp[i] = -1;
    }

    int n;
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    cout << f(n - 1) << "\n";
}
Example 1: 4 / 10 30 40 20 → 30 Example 2: 2 / 10 10 → 0 Example 3: 6 / 30 10 60 10 60 50 → 40

We verified the code against all three official examples, along with a random test of size n = 100,000 (the largest possible input), and compared it against an independent Bottom-Up solution — the results matched exactly.

Step 4: Points Worth Watching

Smallest possible case: when n = 2, the answer is simply f(1) = |a[1]-a[0]|, and no two-step jump is needed at all.

Numeric type limits: the maximum possible cost is roughly (n-1) × 10⁴ ≈ 10⁵, which comfortably fits inside an int (which holds up to about 2.1 × 10⁵) — unlike other problems we've seen before that needed long long, here int is entirely sufficient. The rule: always check the actual bounds of the problem, and don't assume automatically.

Watch out for recursion depth: since n can reach 10⁵, this recursive solution can reach a call depth of around 100,000 nested calls. This runs smoothly on most systems, but in environments with a very limited stack size it could cause a Stack Overflow error. If you run into this in similar problems, the safest fix is to convert to a Bottom-Up version (an iterative loop instead of recursive calls).

This problem is exactly the "minimum cost to reach the end" pattern from the Dynamic Programming chapter, but with a variable transition cost instead of a fixed cost at each position. Whenever you meet a "minimum number of steps" or "minimum cost" problem with limited jumps (one or two steps), think directly in the same template: dp[i] = transition cost + min(dp[predecessors of i]).
