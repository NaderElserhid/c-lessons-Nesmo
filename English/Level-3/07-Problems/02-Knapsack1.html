Knapsack 1 (The Knapsack Problem)

Learn how to pick the best set of items so you get the highest possible value without exceeding the knapsack's capacity. This is the first problem where we see a DP state with two dimensions instead of one — but the core idea (take or don't take) is entirely familiar from the Dynamic Programming chapter.

Medium AtCoder DP Contest — D

Problem Statement

You have a knapsack with capacity W kilograms, and N items. Each item i has a weight wᵢ (how much it weighs) and a value vᵢ (how much it's worth).

Goal: choose a subset of the items such that:

sum of weights ≤ W  &  sum of values → as large as possible

Each item can be taken at most once (which is why this version is called 0/1 Knapsack) — unlike some other versions of this problem that allow taking the same item multiple times.

Constraints

  • 1 ≤ N ≤ 100

  • 1 ≤ W ≤ 100,000

  • 1 ≤ wᵢ ≤ W

  • 1 ≤ vᵢ ≤ 10⁹

Input

First line: two integers N and W. Then N lines, each containing wᵢ and vᵢ for item i.

Example 1

Input: 3 8 3 30 4 50 5 60 Output: 90

We choose items 1 and 3: weight 3+5=8, value 30+60=90.

Example 2 — Watch Out for Overflow!

Input: 5 5 1 1000000000 1 1000000000 1 1000000000 1 1000000000 1 1000000000 Output: 5000000000

The answer here is 5,000,000,000 — which far exceeds the largest value an int (32-bit) can store! This official AtCoder example exists specifically to remind you to use long long.

How Do We Think About the Solution? (SRTBOT)

S — State Definition

dp[i][j] = the largest possible value considering items 0 through i, with capacity j

That is: what if we only had the first i+1 items, and our knapsack had capacity j? Notice the state here needs two dimensions (i and j) instead of one as in Fibonacci or Frog 1 — because the decision at each item depends on how much capacity is actually left, not just on "where we are".

R — Recurrence (the Transition)

When considering item i, we have exactly two options:

  • Don't take item i: dp[i][j] = dp[i-1][j] — the value equals exactly what we got from the previous items with the same capacity.

  • Take item i (only if j ≥ wᵢ): dp[i][j] = dp[i-1][j-wᵢ] + vᵢ — we add its value, and subtract its weight from the capacity before looking at the previous items.

We take the larger of the two options:

dp[i][j] = max( dp[i-1][j] , dp[i-1][j-wᵢ] + vᵢ )

B — Base Case

Conceptually: dp[-1][j] = 0 for every j (before considering any item, the value is always zero). Since arrays in C++ don't accept a negative index, we handle the first item (i=0) as a separate special case in the code, rather than actually relying on a row i=-1.

O — Order of Computation

We compute an entire row (all values of j) for item i before moving to item i+1, because every cell in row i depends only on cells in row i-1 (the one directly before it), not on cells in the same row.

T — Time and Space Complexity

  • Time: the number of states is N × W, and each state is computed in O(1) time → total O(N × W).

  • Memory: we store a table of size N × W → O(N × W).

Steps to Build the Solution

  • Define the dp array: we define dp[i][j] as the largest value achievable using the first i+1 items and capacity j.

  • Initialize the array with -1: we use -1 as a default value to distinguish computed from uncomputed cells (memoization).

  • Handle the base case (i = 0): if the capacity is enough to take the first item, we return its value, otherwise we return zero.

  • Apply the main transition: for each item i and capacity j: we compute both cases (take / don't take) and pick the larger.

  • Extract the result: the answer is f(n-1, W) — the best value using all items and the full capacity.

Walking Through the Code Piece by Piece

Global Variables

knapsack.cpp
long long dp[200][200000];
int v[200], w[200];

  • dp[i][j] — a two-dimensional array storing the best value for items 0 through i with capacity j.

  • We use long long because the values can reach N × 10⁹ = 10¹¹, which far exceeds a regular int.

  • v[] and w[] store the value and weight of each item.

The Main Function (Recursive + Memoization)

knapsack.cpp
long long f(int i, int capacity) {
    // base case: the first item only
    if (i == 0) {
        if (capacity < w[i]) return 0;
        else                 return v[i];
    }
    // if this state has already been computed, return it directly
    if (dp[i][capacity] != -1) return dp[i][capacity];

    // don't take item i
    dp[i][capacity] = f(i - 1, capacity);

    // take item i (if its weight doesn't exceed the capacity)
    if (capacity >= w[i]) {
        dp[i][capacity] = max(dp[i][capacity],
                              f(i - 1, capacity - w[i]) + v[i]);
    }
    return dp[i][capacity];
}

How does the function work?

  • Base case: if we've reached the first item, we check whether it can be taken or not.

  • Memoization: if we've already computed dp[i][capacity] before, we return it directly instead of recomputing — this is what saves time!

  • Transition: we compute the "don't take" case first, then if the weight allows, we compute the "take" case and pick the larger.

The main Function

knapsack.cpp
int main() {
    // initialize every cell with -1 (not yet computed)
    for (int i = 0; i < 200; i++)
        for (int j = 0; j < 200000; j++)
            dp[i][j] = -1;

    int n, weight;
    cin >> n >> weight;

    for (int i = 0; i < n; i++)
        cin >> w[i] >> v[i];

    // request the answer: all items, maximum capacity
    cout << f(n - 1, weight) << endl;
}

  • We start by initializing every dp cell with -1 so we know which cells haven't been computed yet.

  • We read the input: N (number of items) and W (knapsack capacity), then the weight and value of each item.

  • We call f(n-1, weight) because the array starts at 0, and n-1 is the last item.

The Full Code

knapsack_full.cpp
#include <iostream>
using namespace std;

long long dp[200][200000];
int v[200], w[200];

long long f(int i, int capacity) {
    if (i == 0) {
        if (capacity < w[i]) return 0;
        else                 return v[i];
    }
    if (dp[i][capacity] != -1) return dp[i][capacity];

    // i in the case where the item is excluded
    dp[i][capacity] = f(i - 1, capacity);

    // i in the case where the item is taken
    if (capacity >= w[i]) {
        dp[i][capacity] = max(dp[i][capacity],
                              f(i - 1, capacity - w[i]) + v[i]);
    }
    return dp[i][capacity];
}

int main() {
    for (int i = 0; i < 200; i++)
        for (int j = 0; j < 200000; j++)
            dp[i][j] = -1;

    int n, weight;
    cin >> n >> weight;

    for (int i = 0; i < n; i++)
        cin >> w[i] >> v[i];

    cout << f(n - 1, weight) << endl;
}

We verified the code against all three official examples, along with a random test at the maximum possible size (N=100, W=100,000), and compared it against an independent Bottom-Up solution — the results matched exactly (and both gave the same correct answer that exceeds int limits).

Points Worth Watching

Overflow: as we saw in the second official example, the total value can reach N × 10⁹ = 100 × 10⁹ = 10¹¹. This number is far larger than the maximum int value (about 2.1 × 10⁹), so using long long for the dp array isn't optional here — it's necessary.

Memory size: the array dp[200][200000] of type long long (8 bytes per cell) consumes roughly 200 × 200,000 × 8 ≈ 305 megabytes — this fits within this problem's official memory limit (1024 megabytes), but is far more than what we actually need (since N ≤ 100 and W ≤ 100,000, roughly dp[101][100001] would suffice, about only 80 megabytes). It's good practice to size arrays close to the problem's actual limits, especially in problems with a tighter memory limit.

Recursion depth: since N ≤ 100 only, the call depth here is very small (unlike Frog 1 where the depth could reach 100,000) — there's no need to worry about a Stack Overflow in this particular problem.

This pattern — "for each item: take or don't take, while tracking a limited resource (capacity)" — is the foundation for dozens of other classic problems (Subset Sum, Coin Change, Partition Equal Subset Sum, and others). Once you master the two-dimensional state here (item + remaining capacity), you'll find that many harder DP problems are simply variations on the same idea.
