Bit Strings

A very simple counting problem at its mathematical core (the rule of product), but it teaches us a far more important lesson: how to handle a numerical answer of gigantic size through step-by-step modular arithmetic, instead of trying to compute an astronomically large number directly.

Easy CSES 1617

Problem Statement

You need to compute the number of bit strings of length n. A bit string is a sequence of n symbols, each either 0 or 1.

For example, if n = 3, the possible bit strings are: 000, 001, 010, 011, 100, 101, 110, 111 — that is, 8 strings.

Constraints

  • 1 ≤ n ≤ 10⁶

Input and Output

One line containing n. Print the result modulo 10⁹+7 (since the actual result may be far too large to fit in any regular data type).

Example

Input: 3 Output: 8

The Solution Idea: The Rule of Product

  • At each of the n positions in the string, there are two choices completely independent of every other position: 0 or 1.

  • By the Rule of Product in counting: if you have n independent decisions, each with a fixed number of choices, the total number of combinations is the product of the number of choices at each decision.

  • Here: 2 × 2 × ... × 2 (repeated n times) = 2ⁿ.

  • The problem: 2¹₀₀₀₀₀₀ is an enormous number (far larger than any regular integer type could ever hold). The fix: we take the remainder modulo 10⁹+7 at every step of the multiplication, instead of computing the full number and taking the remainder at the end.

This is the principle of Modular Arithmetic we saw before: (a × b) mod M = ((a mod M) × (b mod M)) mod M. That's why we can apply mod M after every small multiplication without changing the final result.

Even with n = 10⁶, the loop performs only a million multiplication-and-remainder operations — extremely fast for any modern computer (complexity O(n)), unlike trying to store the actual number 2ⁿ, which would need hundreds of thousands of decimal digits.

The Full Solution

bit_strings.cpp
#include <iostream>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> n;

    long long ans = 1;
    for (long long i = 0; i < n; i++) {
        ans = (ans * 2) % MOD;
    }

    cout << ans << "\n";
    return 0;
}

A note for the future: an O(n) loop is entirely sufficient here because n ≤ 10⁶. But if the problem allowed n up to 10¹⁸, say, a loop of a billion billion iterations would be impossible in the time given; in that case you'd need Fast (Binary) Exponentiation to compute 2ⁿ mod M in O(log n) time instead of O(n).

The most important lesson here isn't "how do we compute 2ⁿ" — it's: whenever you see a request to output a result "modulo a large number", that's a clear signal that the true result is too large to store in any data type, and you must apply the modulo after every intermediate computation, not just at the very end.
