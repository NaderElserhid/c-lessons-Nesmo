Backtracking

In the fourth chapter we generated every subset by looping through numbers from 0 to 2ⁿ-1. Now we'll see another, more general and more powerful approach: Backtracking — we build the solution decision by decision, and backtrack (undo the decision) whenever we've explored every possibility in a given direction. This technique will become your core tool for solving problems far bigger than just generating subsets.

What Is Backtracking?

Backtracking is a technique that explores all possible solutions to a given problem. Backtracking builds solutions step by step, and backtracks over the steps whenever it finishes exploring a given direction.

How Does It Work?

A backtracking algorithm starts with an empty solution. At each step, the algorithm tries every possible way forward. After exploring all the ways, the algorithm backtracks to the previous step by undoing the last step. The algorithm can be summarized as follows:

  • Start with an empty solution.

  • Extend the solution step by step.

  • Recursively explore every different way the solution could be built.

  • Backtrack over the last step taken.

Notice that this description is very general — Backtracking is not one specific algorithm, but a general framework we apply in different ways depending on the problem. We'll see two different examples in this chapter.

Generating Subsets via Backtracking

To generate all subsets of an array using Backtracking, start with an empty solution. At each step, you have a position i; try both possibilities: adding a[i] to the subset or excluding it. After exploring each way, backtrack over the last change. When i goes beyond the array (i == n), print the current subset.

subsets_backtracking.cpp
#include <iostream>
#include <vector>
using namespace std;

int n = 3;
int a[3] = {5, 3, 1};
vector<int> v;

void backtracking(int i) {

    // If i == n, we've gone through every element, print the current subset
    if (i == n) {
        cout << "subset: ";
        for (int j = 0; j < v.size(); j++) {
            cout << v[j] << ' ';
        }
        cout << "\n";
        return;
    }

    // Try adding a[i] to the subset
    v.push_back(a[i]);   // add it to v
    backtracking(i + 1); // try every solution where a[i] is present in v

    // Try excluding a[i] from the subset
    v.pop_back();        // undo adding a[i]
    backtracking(i + 1); // try every solution where a[i] is not present in v

    // no undo needed here since we didn't change anything in the last step
}

int main() {
    backtracking(0);
}
subset: 5 3 1 subset: 5 3 subset: 5 1 subset: 5 subset: 3 1 subset: 3 subset: 1 subset:

Notice this is the same eight subsets we saw in the previous chapter using bitmasks — but here we arrived at them in a completely different order, because Backtracking explores them through a recursive decision tree instead of direct numeric counting from 0 to 2ⁿ-1.

Example Problem: Apple Division

CSES 1623 — you have an array p of n apples with known weights. You want to split the apples into two groups so that the difference between each group's total weight is as small as possible. You need to print the smallest possible difference.

ConstraintRange
Number of apples n1 ≤ n ≤ 20
Weight of each apple p_i1 ≤ p_i ≤ 10⁹

Example (from the official site)

input
5
3 2 7 4 1
1

Explanation: the first group has weights 2, 3, 4 (sum 9), and the second group has weights 1, 7 (sum 8). Difference = |9 - 8| = 1, which is the smallest possible difference.

The Solution

We'll use Backtracking to try every possible split: at each apple i, we try putting it in the first group, then try putting it in the second group. When we finish all the apples (i == n), we compare the current difference against the best difference found so far.

apple_division.cpp
#include <iostream>
using namespace std;

int n;
int a[20];
long long sum1 = 0;         // total of the first group
long long sum2 = 0;         // total of the second group
long long ans = 2000000000; // the answer, a very large number initially

void backtracking(int i) {
    // If i == n, update the current answer
    if (i == n) {
        ans = min(ans, abs(sum1 - sum2));
        return;
    }
    // try every possible choice

    // try adding a[i] to the first group
    sum1 += a[i];
    backtracking(i + 1);
    sum1 -= a[i];

    // try adding a[i] to the second group
    sum2 += a[i];
    backtracking(i + 1);
    sum2 -= a[i];
}

int main() {
    cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    backtracking(0);

    cout << ans << "\n";
}
1

Notice the use of long long for the totals, not int. Since each weight can reach up to 10⁹ and there can be up to 20 apples, the largest possible total reaches around 2×10¹⁰ — which far exceeds the limit of int (about 2.1×10⁹).

Common Mistakes

1) Forgetting the Undo Step

Look at this modified subset-generation code — its author forgot the line v.pop_back();:

missing_undo.cpp
void backtracking(int i) {
    if (i == n) {
        cout << "subset: ";
        for (int j = 0; j < (int)v.size(); j++) cout << v[j] << ' ';
        cout << "\n";
        return;
    }
    v.push_back(a[i]);
    backtracking(i + 1);

    // !! we forgot v.pop_back(); here !!
    backtracking(i + 1);
}
subset: 5 3 1 subset: 5 3 1 subset: 5 3 1 1 subset: 5 3 1 1 subset: 5 3 1 1 3 1 subset: 5 3 1 1 3 1 subset: 5 3 1 1 3 1 1 subset: 5 3 1 1 3 1 1

Without the undo, elements keep piling up in v forever, giving you wrong, bloated subsets instead of 8 correct, distinct ones. Every step that changes shared state (such as v or sum) must be undone after exploring that direction — this is the essence of "backtracking" in Backtracking.

2) Using int Instead of long long for Large Totals

In the Apple Division problem, if you used int instead of long long to store sum1 and sum2, a silent overflow could happen when the weights are large:

1500000000 + 1500000000 as int = -1294967296 (wrong!) 1500000000 + 1500000000 as long long = 3000000000 (correct)

3) Exploring Only One Direction

If you forget one of the two branches (for example only exploring "add the element" without "excluding it"), the algorithm won't explore every possible solution, and you may miss the correct answer entirely.

Quick Summary

Backtracking builds the solution step by step, recursively explores every possibility, then backtracks after each exploration.
To generate subsets: at each element, try including it then excluding it, and undo between the two attempts.
In Apple Division: at each apple, try putting it in the first group then the second, and update the best difference once a split is complete.
Never forget the undo step, and use the appropriate type (long long) to avoid overflow.

3) Find the Bug

A classmate modified the Apple Division code so it explores only one branch per apple (placing it in the first group only):

find_error4.cpp
void backtracking(int i) {
    if (i == n) {
        ans = min(ans, abs(sum1 - sum2));
        return;
    }
    sum1 += a[i];
    backtracking(i + 1);
    sum1 -= a[i];
    // !! completely forgot the "add a[i] to the second group" branch !!
}

What's wrong with this code? And what will it always print?

The code explores only one branch (every apple always goes into the first group), and never tries putting any apple in the second group. Since sum2 always stays 0, the result will always be |sum of all weights - 0|, i.e. the sum of all weights — nearly the worst possible answer, not the optimal one.

The fix: add the second branch (sum2 += a[i]; backtracking(i+1); sum2 -= a[i];) to explore both possibilities.

Glossary

BacktrackingBacktracking

A technique for exploring every possible solution by gradually building the solution and backtracking after each exploration.

RecursionRecursion

A function calling itself to solve a smaller instance of the same problem.

Base CaseBase Case

The condition that stops the recursive call (such as i == n), preventing the function from calling itself forever.

Undo StepUndo Step

Reverting the last change to shared state (such as pop_back or subtracting a value) after exploring a given direction.

Call StackCall Stack

The structure the language uses to remember the currently active chain of recursive calls.

Brute ForceBrute Force

Solving a problem by trying every possible option without clever shortcuts.

State SpaceState Space

The total of all partial and complete solutions the algorithm might explore.

OverflowOverflow

A value exceeding the limit a data type can store, producing an incorrect result without a compile error.
