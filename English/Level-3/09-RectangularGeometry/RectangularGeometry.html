Rectangular Geometry (Axis-Aligned Rectangles)

This chapter covers rectangles whose sides are parallel to the coordinate axes (axis-aligned). We'll learn how to represent points and rectangles with simple structs, how to compute area, how to check whether two rectangles intersect and compute the intersection region itself — then we'll see that all these ideas have a simpler one-dimensional counterpart (intervals on a number line), and finish with a real USACO problem that applies this one-dimensional idea directly.

Axis-Aligned Rectangle Geometry

Axis-aligned rectangle geometry deals with rectangles whose sides are parallel to the coordinate axes. This section covers the basic operations used with this type of rectangle.

Note: throughout this chapter we assume the positive x-axis points right, and the positive y-axis points up — exactly like the usual mathematical coordinate system.

Representing Points and Rectangles

A point contains a pair of coordinates: an x coordinate and a y coordinate. We can group them together in a struct:

point.cpp
struct Point {
    int x;
    int y;
};

An axis-aligned rectangle can be represented by two of its points: the bottom-left point and the top-right point. We group these two points into another struct:

rectangle.cpp
struct Rectangle {
    Point bottom_left;
    Point top_right;
};

Throughout this section, we assume every rectangle is normalized, meaning:

  • bottom_left.x ≤ top_right.x
  • bottom_left.y ≤ top_right.y

Width, Height, and Area

Width is the horizontal distance between the two sides: width = r.top_right.x - r.bottom_left.x

Height is the vertical distance between the two sides: height = r.top_right.y - r.bottom_left.y

Area is the product of the width and height: area = width * height

area.cpp
int area(Rectangle r) {
    int width = r.top_right.x - r.bottom_left.x;
    int height = r.top_right.y - r.bottom_left.y;
    return width * height;
}

Checking for Intersection

Two rectangles intersect with a positive area only when their ranges overlap on the x axis and the y axis together. It's easier to check the opposite case (no intersection).

Two rectangles are separated horizontally if one of them ends at or before the other begins. Similarly, they are separated vertically according to the matching condition on the y axis. If either separation holds, the rectangles do not intersect.

rectangles_intersect.cpp
bool rectangles_intersect(Rectangle a, Rectangle b) {
    bool separated_x = a.top_right.x <= b.bottom_left.x ||
        b.top_right.x <= a.bottom_left.x;
    bool separated_y = a.top_right.y <= b.bottom_left.y ||
        b.top_right.y <= a.bottom_left.y;

    return !separated_x && !separated_y;
}

Note: if two rectangles only touch at an edge or a corner, their shared area equals zero, so we don't consider them intersecting — this is why we use <= (not <) in the separation condition above.

Finding the Intersection

If rectangles a and b intersect, their intersection is another rectangle. Its bottom-left point uses the larger coordinate between the two lower bounds on each axis, while its top-right point uses the smaller coordinate between the two upper bounds.

rectangle_intersection.cpp
#include <algorithm>
using namespace std;

Rectangle rectangle_intersection(Rectangle a, Rectangle b) {
    Rectangle c;
    c.bottom_left.x = max(a.bottom_left.x, b.bottom_left.x);
    c.bottom_left.y = max(a.bottom_left.y, b.bottom_left.y);
    c.top_right.x = min(a.top_right.x, b.top_right.x);
    c.top_right.y = min(a.top_right.y, b.top_right.y);
    return c;
}

Only call rectangle_intersection after rectangles_intersect has confirmed an actual intersection exists. Calling it on two non-intersecting rectangles will produce a "rectangle" with negative width or height — meaningless data.

One-Dimensional Geometry

The same ideas apply in one dimension, where we work with intervals instead of rectangles. An interval contains a left endpoint and a right endpoint:

interval.cpp
struct Interval {
    int left;
    int right;
};

We assume every interval is normalized, i.e. left ≤ right.

Length

The length of an interval is: length = segment.right - segment.left

length.cpp
int length(Interval segment) {
    return segment.right - segment.left;
}

Checking for Intersection

Two intervals intersect with a positive length unless one of them ends at or before the other begins:

intervals_intersect.cpp
bool intervals_intersect(Interval a, Interval b) {
    return a.right > b.left && b.right > a.left;
}

Just as with rectangles, two intervals that share only a single endpoint have zero overlap and are not considered intersecting.

Finding the Intersection

If intervals a and b intersect, their intersection begins at the larger left endpoint and ends at the smaller right endpoint:

interval_intersection.cpp
#include <algorithm>
using namespace std;

Interval interval_intersection(Interval a, Interval b) {
    Interval c;
    c.left = max(a.left, b.left);
    c.right = min(a.right, b.right);
    return c;
}

Notice the exact symmetry between rectangles and intervals: max on the lower/left bounds, and min on the upper/right bounds — exactly the same idea, just with one axis instead of two.

Applied Problem: Fence Painting

USACO 2015 December Contest, Bronze — Problem 1

We treat the fence as a one-dimensional number line. Farmer John paints the interval from x=a to x=b. Bessie paints the interval from x=c to x=d, which might partially or fully overlap with Farmer John's interval. We need to compute the total length of the fence now painted (regardless of overlap).

Constraints

  • a < b and c < d

  • All values a, b, c, d are within the range 0 .. 100

Example

Input (paint.in): 7 10 4 8 Output (paint.out): 6

Here, 6 units of fence are covered by paint, from x=4 to x=10.

The Solution

We add up the lengths of the two intervals, then subtract the length they share (the overlap). If the two intervals don't overlap, the shared length equals zero:

total = length(a) + length(b) - overlap_length(a, b)
paint.cpp
#include <algorithm>
#include <cstdio>
#include <iostream>
using namespace std;

struct Interval {
    int left;
    int right;
};

int length(Interval segment) {
    return segment.right - segment.left;
}

int overlap_length(Interval a, Interval b) {
    int left = max(a.left, b.left);
    int right = min(a.right, b.right);
    return max(0, right - left);
}

int main() {
    freopen("paint.in", "r", stdin);
    freopen("paint.out", "w", stdout);

    Interval a, b;
    cin >> a.left >> a.right >> b.left >> b.right;

    int total = length(a) + length(b) - overlap_length(a, b);
    cout << total << "\n";
}

A manual check matching the official example: length(a)=10-7=3, length(b)=8-4=4, the overlap: left=max(7,4)=7, right=min(10,8)=8, so overlap=max(0,8-7)=1. Total: 3+4-1=6 ✓ exactly matches the official output.

Why is max(0, right-left) clever? If the two intervals don't overlap at all, right - left will be negative (since right < left) — and max(0, ...) automatically turns this negative value into zero, without needing a separate if check. This is cleaner than calling intervals_intersect first and then branching.

A note on input/output: USACO problems usually require reading from a file and writing to a file (freopen("paint.in", "r", stdin) and freopen("paint.out", "w", stdout)) instead of direct standard input/output — always double-check the required input/output format before submitting your solution.

Points Worth Watching

Touching is not intersectingUsing <= in the separation condition (not <) ensures that rectangles/intervals that only touch at a single edge are considered non-intersecting, since their shared area/length is already zero.
Don't call the intersection function without checking firstrectangle_intersection and interval_intersection assume an intersection already exists — calling them on non-intersecting shapes produces meaningless results (negative width or length).
Assuming normalizationEvery function in this chapter assumes bottom_left ≤ top_right (or left ≤ right) beforehand; if your data isn't normalized, normalize it first (by comparing/swapping coordinates) before using these functions.
overlap_length with max(0, ...)In the Fence Painting solution specifically, using max(0, right-left) makes the code always work correctly without needing to check for intersection separately first.

Quick Summary

An axis-aligned rectangle is represented by its bottom-left and top-right points, always assuming normalization.
Area = width × height.
Checking for no intersection is easier than checking for intersection: a single separation (horizontal or vertical) is enough to prove no intersection.
The intersection rectangle: max on the lower bounds, min on the upper bounds — provided you've first confirmed an intersection exists.
The same ideas apply to intervals in one dimension, and are used to compute "total covered length" via: length(a)+length(b)-overlap(a,b).

Homework

1) Intersect Two Rectangles by Hand

Rectangle A: bottom_left=(0,0), top_right=(6,6). Rectangle B: bottom_left=(4,2), top_right=(10,5). Do they intersect? If yes, compute the intersection rectangle and its area.

separated_x: 6≤4? No, 10≤0? No → not separated horizontally. separated_y: 6≤2? No, 5≤0? No → not separated vertically. So they do intersect.

bottom_left = (max(0,4), max(0,2)) = (4, 2) top_right = (min(6,10), min(6,5)) = (6, 5) width = 2, height = 3 area = 6

2) Two Rectangles That Only Touch

Rectangle A: (0,0)-(5,5). Rectangle B: (5,0)-(9,5). Do they intersect under this chapter's definition? Explain why.

They don't intersect. separated_x = (a.top_right.x=5 ≤ b.bottom_left.x=5) → true (5≤5), so separated_x = true regardless of separated_y. The two rectangles touch exactly at the vertical edge x=5 only, and their shared area is zero, so they are not considered intersecting.

3) Total Coverage Length for Three Interval Cases

Compute the total covered length (using the same Fence Painting logic) for the following cases: (a) a=[0,5], b=[10,15] (completely separate). (b) a=[0,10], b=[3,7] (interval B entirely inside A). (c) a=[2,6], b=[6,9] (touching at exactly one point).

(a) length=5+5, overlap=max(0, min(5,15)-max(0,10))=max(0,-5)=0 → total = 10 (b) length=10+4, overlap=max(0, min(10,7)-max(0,3))=max(0,4)=4 → total = 10 (B is entirely inside A, so it adds nothing) (c) length=4+3, overlap=max(0, min(6,9)-max(2,6))=max(0,0)=0 → total = 7

Case (b) shows why the general formula (not just "simple addition") is necessary: an interval entirely contained within another adds no new length to the coverage.

Glossary

Axis-alignedAxis-aligned

A geometric shape (a rectangle here) whose sides are exactly parallel to the coordinate axes, with no tilt or rotation.

NormalizedNormalized

The assumption that the lower point actually comes before the upper point on each coordinate (bottom_left ≤ top_right, or left ≤ right for intervals).

Bounding BoxBounding Box

A common term for an axis-aligned rectangle used to represent a shape's boundaries (appears often in graphics and collision detection).

IntervalInterval

The one-dimensional counterpart of a rectangle: a range defined by a left endpoint and a right endpoint on a number line.

Overlap / IntersectionOverlap / Intersection

The shared region (or interval) between two shapes, computed by taking max on the lower bounds and min on the upper bounds.

Union Length / CoverageUnion Length / Coverage

The total length (or area) covered by at least one of several shapes, computed using the inclusion-exclusion principle.

freopenfreopen

A C++ function that redirects standard input/output to/from a file, commonly used in USACO problems.
