Problems with Subproblems — Partial Scoring and Solving the Iso-celestial Problem

What Are Problems With Subproblems?

On the Codeforces platform, a problem is either solved completely or not solved at all — there are no partial points. On other platforms, and in most national and international olympiads, a single problem is split into several Subtasks that differ in the constraints placed on the input, and the competitor is given points independently for each subtask they manage to solve.

Usually, the earlier subtasks are easier (smaller constraints that allow slower solutions), while the later subtasks require a complete, fast solution that works within the problem's original constraints. The final verdict shows the sum of points from every subtask that succeeded, not a single verdict alone.

This gives you an important strategy: if you can't reach the optimal full solution, first write a simpler (even if slower) solution that solves the earlier subtasks with small constraints, to guarantee partial points instead of zero.

The Iso-celestial Problem

Codeforces

You are given a number of points N on the two-dimensional coordinate plane, where N ≤ 3000. You need to compute the number of triples of points that form an isosceles triangle (meaning at least two of its three sides are equal in length).

Scoring System

The problem consists of three subtasks that differ only in the constraints placed on N:

SubtaskConstraintsPoints
1 N = 3 33
2 N ≤ 100 33
3 No additional constraints 34

Note: in the third subtask there are no additional constraints, meaning the only constraints that apply are the ones stated in the original problem text. For N, this means 1 ≤ N ≤ 3000.

Solution to Subtask 1

In this subtask we have only N = 3 points, so they either form an isosceles triangle or they don't. To check this, we can simply test whether two of the three points' sides are equal in length.

subtask1.cpp
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

int n;

long long x[3001], y[3001];

long double dist(int i, int j) {
    long double dy = y[i] - y[j];
    long double dx = x[i] - x[j];

    return sqrtl(dy * dy + dx * dx);
}

bool f(int a, int b, int c) {
    long double ab = dist(a, b);
    long double ac = dist(a, c);
    long double bc = dist(b, c);

    return (ab == ac || ab == bc || ac == bc);
}

int main() {
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> x[i] >> y[i];
    }

    cout << f(0, 1, 2);
}
Input: 0 0 / 2 0 / 0 2 → Output: 1 (two equal legs: length 2) Input: 0 0 / 1 0 / 0 5 → Output: 0 (no two sides are equal)

Solution to Subtask 2

Since N ≤ 100 in this subtask, we can iterate over every possible triple of points, and test each one using the check function f from the previous solution.

subtask2.cpp
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

int n;

long long x[3001], y[3001];

long double dist(int i, int j);  // same as before
bool f(int a, int b, int c);     // same as before

int main() {
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> x[i] >> y[i];
    }

    int counter = 0;

    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            for (int k = j + 1; k < n; k++) {
                if (f(i, j, k)) counter++;
            }
        }
    }

    cout << counter;
}
Number of checks ≈ N³ / 6

This approach performs about O(N³) checks, which is fast enough when N ≤ 100 (about a million checks), but far too slow for the full problem where N ≤ 3000, since the number of operations would reach about 27,000,000,000 — much slower than the time limit usually allowed in contests (just one or two seconds).

Solution to Subtask 3 (the Full Solution)

At this stage, we need to think differently and use geometric observations to reach a faster solution. Suppose we have a single point P, and we compute the distance between it and every other point.

We can notice that if there are two points X and Y at the same distance from point P, then the triangle (P, X, Y) is isosceles (the two equal legs are PX and PY). And if there are K points all at the same distance from P, then any pair of these points, combined with P, forms an isosceles triangle.

This is exactly the "choosing two elements from a set" idea we learned in the Basic Counting unit! The number of possible pairs from a set of size K is C(K, 2) = K(K-1)/2.

From this observation, we get an algorithm that performs O(N²) operations: for each point P, we go through all the other points Q and count how many times each distinct distance appears. Then, we go through all the distinct distances, and if the count of repetitions for that distance is C, we add C · (C-1) / 2 to the answer.

Interactive Lab: Watch the Points Group Around the Apex P

subtask3.cpp
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

int n;

long long x[3001], y[3001];

long double dist(int i, int j);  // same as before

int main() {
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> x[i] >> y[i];
    }

    int counter = 0;

    for (int i = 0; i < n; i++) {
        long double all[n];

        for (int j = 0; j < n; j++) {
            all[j] = dist(i, j);
        }

        sort(all, all + n);

        int cnt = 1;

        for (int j = 1; j < n; j++) {
            if (all[j] != all[j-1]) {
                counter += cnt * (cnt - 1) / 2;
                cnt = 0;
            }
            cnt++;
        }

        counter += cnt * (cnt - 1) / 2;
    }

    cout << counter;
}
For the points in the simulation above: total count = 4

We go through the distinct distances in their sorted order, then move through them in ascending order, only taking action when the current distance changes from the previous one. To simplify the code, we take advantage of the fact that the distance from a point to itself will end up at index 0 in the sorted array (since it's zero, the smallest possible value), which lets us start the loop directly from index 1 without any special handling.

Notice that the solution to subtask 3 is completely general and also works on the inputs of subtasks 1 and 2 (it's correct for any N). In contests, competitors sometimes go straight to writing the full solution if they can, but solving the easier subtasks first is a safe strategy for guaranteeing partial points.

Glossary of Terms

SubtaskSub-problem

A part of the problem with different constraints and independent points, common in olympiads.

Partial ScorePartial credit

Points awarded to a solution that passes only some subtasks, without solving the whole problem.

Brute ForceTry everything

Trying every possibility directly without optimization, usually slow but easy to write.
