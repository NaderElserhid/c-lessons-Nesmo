Greedy Algorithms

In the casework chapter you learned to split a problem into different situations. Now we'll learn a completely different solving strategy: instead of trying every possibility, at each step you pick whichever option looks best right now, never going back. This approach — greedy algorithms — is fast and simple, but it's a double-edged sword: sometimes it gives you the exact optimal solution, and sometimes it leads you into a trap. The most important part of this chapter is learning how to tell the two cases apart.

What Does "Greedy" Mean?

A greedy algorithm builds the solution step by step, and at each step it chooses the best option currently available, without thinking about future consequences.

Imagine you always take the biggest cookie first — hoping that will lead you to the best possible outcome in the end.

The word "Greedy" means locally optimal — that is, at each step you choose the decision that looks best at the current moment. Sometimes this reaches the optimal solution (the best possible solution), and sometimes it fails. The secret is knowing when the greedy strategy works and when it doesn't — and that's exactly what this chapter is about.

The General Idea

  • You have a goal (like minimizing cost or maximizing value).

  • At each step you take the option that looks best right now.

  • You continue until the solution is complete.

The golden rule: never go back and revise your earlier decisions in a greedy algorithm.

The general pattern:

pattern.txt
while (problem is not solved) {
    pick the best option available right now;
    update the state of the problem;
}

Example: Coin Change

You have coins: 1, 5, 10, 25. Find the minimum number of coins to make the amount 63.

The greedy idea: always take the largest possible coin.

coin_change.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int amount = 63;
    vector<int> coins = {25, 10, 5, 1};
    int count = 0;

    for (int c : coins) {
        count += amount / c;
        amount %= c;
    }
    cout << count; // 6 coins
}

The choices: 25 + 25 + 10 + 1 + 1 + 1 = 63. Result = 6 coins.

Example: Activity Selection

You have a set of activities, each with a start time and an end time, and you can only do one activity at a time. What's the maximum number of activities you can finish?

The greedy idea: choose the activity that finishes first.

activity_selection.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    vector<pair<int, int>> act = {{1, 3}, {2, 5}, {4, 6}, {6, 8}, {5, 7}};
    sort(act.begin(), act.end(), [](auto &a, auto &b){ return a.second < b.second; });

    int count = 0, end = 0;
    for (auto &p : act) {
        if (p.first >= end) {
            count++;
            end = p.second;
        }
    }
    cout << count; // 3
}

We always choose the activity that finishes earliest — because it leaves the largest possible room for other activities.

When Do Greedy Algorithms Succeed?

They succeed when the best local choice always leads to the best global solution. This happens when the problem has:

  • The Greedy Choice Property.

  • Optimal Substructure.

You don't need to memorize these terms precisely — just practically test whether the greedy strategy works in every case before relying on it.

Examples where greedy works:

  • A coin system (1, 2, 5) → taking the largest first always gives the minimum count.

  • Scheduling the shortest tasks first — lets you finish the largest number of them.

  • Choosing the largest values when certain limits exist.

Examples Where Greedy Fails

The coins {1, 3, 4} and the amount 6:

StrategyChoiceNumber of Coins
Greedy (largest first)4 + 1 + 13
Actually best3 + 32

Greedy fails here! Because taking the larger coin (4) first prevents us from reaching the better solution (3+3). This is a classic example showing that greedy is not a guarantee — its success depends on the nature of the specific coin system.

Another example: sorting large items first when trying to fill a bag (the Knapsack problem) — this can rule out better solutions, because a large item might occupy space that could have been filled with smaller items worth a higher total value.

Steps for Designing a Greedy Algorithm

  • Sort something (by value, time, ratio, ...).

  • Go through the elements in order.

  • Choose the best valid option each time.

  • Update the state (remaining time, remaining capacity, ...).

A common pattern:

greedy_pattern.cpp
sort(items.begin(), items.end(), rule);
for (auto &item : items) {
    if (can_take(item)) take(item);
}

Pros and Cons

Pros: very fast and simple. Often easy to understand and implement. Suitable for scheduling and selection problems.

Cons: doesn't always give the optimal solution. Early decisions can ruin the solution later on. Must be carefully tested or proven before relying on it.

Tips

  • Always ask: could this choice prevent better solutions later?

  • Try building counterexamples to test the strategy.

  • Many greedy problems rely on a "sort + select" pattern.

Quick Summary

Greedy = choosing the best local decision at each step.
It only works when these decisions guarantee the globally optimal solution.
Common in scheduling, graphs, and resource allocation.
Simple and fast to implement and code.

3) Discovering Where Greedy Fails for Coins {1, 3, 4}

Using coins {1, 3, 4}, try the amounts from 1 to 30 and compare the greedy strategy's result with the true optimal solution (which can be computed with simple dynamic programming). How many amounts does greedy fail on?

hw3_stress.cpp
int greedyCoins(int amount, vector<int> coins) {
    int count = 0;
    for (int c : coins) {
        count += amount / c;
        amount %= c;
    }
    return count;
}

int optimalCoins(int amount, vector<int>& coins) {
    vector<int> dp(amount+1, INT_MAX);
    dp[0] = 0;
    for (int i = 1; i <= amount; i++)
        for (int c : coins)
            if (c <= i && dp[i-c] != INT_MAX)
                dp[i] = min(dp[i], dp[i-c]+1);
    return dp[amount];
}
Greedy fails at the amounts: 6, 10, 14, 18, 22, 26, 30 (7 failing cases out of 30 amounts tested)

Notice the pattern: all the failing cases are numbers increasing by 4 starting from 6 (that is, amounts congruent to 2 mod 4). In all these cases, greedy uses one extra coin of 4 that it shouldn't, instead of replacing it with two coins of 3 — exactly the kind of "testing with counterexamples" this chapter's tips recommended.

Glossary

Greedy AlgorithmGreedy Algorithm

A strategy that builds the solution step by step, choosing the best local option each time with no backtracking.

Local OptimumLocal Optimum

The best option available at the current moment, which may not be the best for the problem as a whole.

Global OptimumGlobal Optimum

The best possible solution for the entire problem, which is what we're actually trying to reach.

Greedy Choice PropertyGreedy Choice Property

A property guaranteeing that the best local choice always leads to the globally optimal solution.

Optimal SubstructureOptimal Substructure

A property meaning the optimal solution to the big problem is made up of optimal solutions to smaller subproblems.

CounterexampleCounterexample

A specific test case that shows a given greedy strategy fails and doesn't give the optimal solution.
