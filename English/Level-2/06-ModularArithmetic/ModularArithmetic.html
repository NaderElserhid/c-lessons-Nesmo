Modular Arithmetic

Throughout this level you've worked with arrays, sorted them, and searched them quickly. But what happens when the numbers in a problem become so huge that they don't even fit in a long long variable? In this chapter you'll learn "modular arithmetic" — an essential tool in competitive programming that keeps numbers small and manageable by always taking the remainder when dividing by a certain number, exactly like the hands of a clock cycling every 12 or 24 hours.

What Does mod Mean?

Modular Arithmetic is a way of doing arithmetic where numbers "wrap around" after reaching a certain value called the modulus.

Think of it like a clock: after 24 hours pass, the clock returns to the same time again. That's exactly the operation mod 24!

When we say a mod m, we mean the remainder when dividing a by m.

ExpressionMeaningResult
7 mod 37 ÷ 3 → remainder1
10 mod 410 ÷ 4 → remainder2
15 mod 615 ÷ 6 → remainder3
12 mod 1212 ÷ 12 → remainder0

In C++ we use the % operator to compute the remainder:

basic_mod.cpp
#include <iostream>
using namespace std;

int main() {
    cout << 7 % 3 << endl;    // 1
    cout << 10 % 4 << endl;   // 2
    cout << 10 % 5 << endl;   // 0
}
1 2 0

Why Do We Use Modular Arithmetic in Programming?

When dealing with very large numbers (for example, in combinatorics or cryptography), results can become too big to fit in regular data types, or even in long long. The solution: we take the remainder (mod) after every operation to keep the numbers small the whole time.

A common modulus in competitive programming:

constant.cpp
const int MOD = 1'000'000'007; // a large prime number

Why do we specifically use this value?

  • It fits safely within 64-bit numbers (it doesn't cause overflow when multiplying two numbers smaller than it).

  • It avoids overflow during repeated addition or multiplication.

  • Because it's prime, it has useful mathematical properties (such as making it possible to compute a modular inverse, as we'll see later).

Example: Adding Large Numbers

big_sum.cpp
#include <iostream>
using namespace std;

int main() {
    const int MOD = 1'000'000'007;
    long long a = 1e12, b = 1e12;
    cout << (a + b) % MOD << endl;
}
999986007

Without taking mod, the result would have been 2,000,000,000,000 — an enormous number that could cause problems in later operations. By taking mod, we kept the result within a small, safe range.

Basic Rules

Addition

(a + b) % m = (a % m + b % m) % m

Subtraction

(a - b) % m = ((a % m - b % m) + m) % m

We add + m to guarantee we don't get a negative result (we'll see why in more detail shortly).

Multiplication

(a * b) % m = (a % m * b % m) % m

Example

rules_example.cpp
int a = 7, b = 5, m = 3;
cout << (a + b) % m << endl;   // 0
cout << (a * b) % m << endl;   // 2
0 2

Handling Negative Numbers

In C++, the % operator can give a negative result when one of the operands is negative:

negative_mod.cpp
cout << (-5) % 3; // -2
-2

This contradicts the usual mathematical definition of mod, which assumes the result is always between 0 and m-1. This can cause subtle bugs when using the result as an array index, for example.

To fix this problem, we add m and then take mod again:

((a % m) + m) % m

fixed_negative_mod.cpp
int a = -5, m = 3;
cout << ((a % m) + m) % m; // 1
1

Modular Exponentiation

To quickly compute (a^b) mod m, we don't multiply a by itself b times (that would be O(b) complexity and far too slow for large numbers). Instead, we use Fast/Binary Exponentiation:

  • If b is even: a^b = (a^(b/2))²

  • If b is odd: a^b = (a^(b/2))² × a

modpow.cpp
long long modpow(long long a, long long b, long long m) {
    if (b == 0) return 1;
    long long half = modpow(a, b / 2, m);
    long long res = (half * half) % m;
    if (b % 2 == 1)
        res = (res * (a % m)) % m;

    return res;
}

Since b is halved every time the recursion is called, the total number of recursive calls is roughly log₂(b) — exactly like the doubling loop we studied in the time complexity chapter. So this function's complexity is O(log b).

modpow(2, 10, 1000) → 24

Modular Inverse

When we need to perform a division operation under a modulus, we can't just write (a / b) % m — regular division doesn't align with the properties of modular arithmetic. Instead, we use the modular inverse.

If MOD is a prime number, the inverse of a is computed with:

modular_inverse.cpp
long long inverse = modpow(a, MOD - 2, MOD);

So the division a / b mod m becomes:

modular_division.cpp
(a * modpow(b, MOD - 2, MOD)) % MOD

Verification example: the inverse of 5 with respect to MOD = 1,000,000,007 is 400,000,003. We can confirm this is correct because:

(5 * 400000003) % 1000000007 = 1

And that's exactly the definition of a modular inverse: a number that, when multiplied by the original number under the same modulus, gives 1.

This method (using modpow(a, MOD-2, MOD)) relies on a small theorem called "Fermat's Little Theorem", and works only when MOD is a prime number and a is not divisible by MOD.

Quick Summary

% gives the remainder of division.
Use (a + b) % MOD, (a * b) % MOD, and ((a - b) % MOD + MOD) % MOD.
For large exponents, use fast exponentiation (modular exponentiation) with O(log b) complexity.
For division, use the modular inverse if the modulus is a prime number.

Homework Exercises

1) Safe Subtraction Under a Modulus

You have a = 3, b = 8, m = 7. Compute (a - b) % m the regular way, then compute it the safe way that never gives a negative result.

hw1.cpp
int a = 3, b = 8, m = 7;
cout << (a - b) % m << endl;             // -5
cout << ((a - b) % m + m) % m << endl;    // 2
-5 2

The regular way gives -5 because 3 - 8 = -5, and the result is already negative. By adding m before taking mod a second time, we get the correct result, 2.

2) Using Fast Exponentiation

Compute 3^13 mod 17 using the modpow function.

hw2.cpp
cout << modpow(3, 13, 17) << endl;
12

You can check this by hand: 3^13 = 1,594,323, and 1,594,323 mod 17 = 12. Fast exponentiation reaches the same result in far fewer steps (roughly log₂(13) ≈ 4 calls only, instead of 13 multiplications).

3) Division Using the Modular Inverse

Compute (10 / 3) mod 1,000,000,007 using the modular inverse.

hw3.cpp
long long MOD = 1000000007;
long long a = 10, b = 3;
long long result = (a % MOD * modpow(b, MOD - 2, MOD)) % MOD;
cout << result << endl;
333333339

To verify: (333,333,339 * 3) % 1,000,000,007 = 10 — meaning the division correctly returned to the original number, exactly as you'd expect from a proper division.
