Simulation

By now you've learned some powerful tools: sets, maps, sorting, binary search, and modular arithmetic. But not every problem needs a clever algorithm — sometimes all you need to do is "simulate" what actually happens, step by step, exactly as if you were running a small program inside your program. In this chapter you'll learn how to turn a long problem description into a simple loop that follows the rules literally.

What is Simulation?

Simulation problems are about mimicking a real or logical process step by step. You're asked to "simulate" what happens — exactly like running a small program inside your program!

In competitive programming, simulation means carefully following the problem's rules and executing every step exactly as described. You don't need a complicated algorithm — just repeat what normally happens using loops.

Example: The Collatz Conjecture

Consider the following process: start with a certain number n. At each step:

  • If n is even, replace it with n / 2.

  • If n is odd, replace it with 3n + 1.

Print the number of steps the process took before n becomes equal to 1.

You might wonder: does this process always reach 1? Actually, no one has a definitive answer to that — it's a famous unsolved mathematical problem! But we can simply simulate it and see what happens for any number we try.

collatz.cpp
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    int steps = 0;
    while (n != 1) {
        if (n % 2 == 0) {
            n /= 2;
        } else {
            n = 3*n + 1;
        }
        steps++;
    }
    cout << steps << "\n";
    return 0;
}

So the answer is 7.

When Do We Use Simulation?

Simulation is excellent when:

  • The problem gives you a detailed list of steps or actions.

  • There's no obvious mathematical shortcut.

  • You can just follow the process directly.

Common examples:

  • Games (like tic-tac-toe, snake, and others).

  • Movement on a grid (robots, cars, people walking).

  • Text transformations (editing text, rotation).

  • Managing elements (queues, stacks, or tasks over time).

The General Simulation Pattern

Most simulation problems follow the same pattern:

pattern.txt
initialize variables
while (there are still actions left) {
    read next action
    update variables according to rules
}
print final result

You're basically "running" the rules step by step.

Example: A Robot on a Grid

A robot starts at (0, 0). It receives a sequence of moves made up of the letters N, S, E, W. Print its final coordinates.

robot.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string moves;
    cin >> moves;
    int x = 0, y = 0;
    for (char c : moves) {
        if (c == 'N') y++;
        else if (c == 'S') y--;
        else if (c == 'E') x++;
        else if (c == 'W') x--;
    }
    cout << x << " " << y;
}

If the input is NNEEWS, the robot ends up at (1, 1).

Example: Simulating a Game

There are several heroes in a game, each with their own strength. Every second, the weakest hero A deals damage to the strongest hero B, reducing B's strength by A's strength. The game ends when a hero's strength reaches 0. Print the number of seconds the game lasted.

game_simulation.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n; cin >> n;
    vector<int> strength(n);
    for (int &x : strength) cin >> x;

    int seconds = 0;
    while (true) {
        sort(strength.begin(), strength.end());
        if (strength[0] == 0) break;
        strength[n-1] -= strength[0];
        seconds++;
    }
    cout << seconds;
}

This simulates the entire process exactly as described. For example, if we start with the strengths [1, 2, 4, 8]:

12

Tips for Simulation Problems

  • Follow the rules literally. Don't overthink it — just execute exactly what the problem says.

  • Use loops and conditionals to handle the different cases.

  • Print the intermediate steps while debugging to make sure your logic matches the description.

  • Be careful with boundaries (like going off the grid or using wrong indices).

  • Use small cases to test your code by hand.

  • Simulate the program with pen and paper to understand what's actually happening before coding it step by step.

Performance Tip

Sometimes, a simulation can be very slow if the process takes billions of steps. In these cases, you need to find patterns or shortcuts:

  • If the process repeats after a certain number of steps, use math to skip over the cycles (like modular arithmetic).

  • If the output stops changing after a while, stop early.

Pros and Cons

Pros: very direct — no need for complicated algorithms. Easy to implement and understand. Works with almost any process based on rules.

Cons: can be slow for large inputs. Easy to make small mistakes when following many steps. Debugging can take a while if intermediate results aren't printed.

Homework Exercises

1) Speeding Up the Game Simulation (For Just Two Heroes)

When there are only two heroes with strengths a and b, the process "the weaker one hits the stronger one by its own strength" is exactly the same as the Euclidean Algorithm using repeated subtraction to find the greatest common divisor! Instead of subtracting one at a time (slow), use integer division and % to speed up the process.

hw1_fast_game.cpp
#include <iostream>
using namespace std;

long long fastSeconds(long long a, long long b) {
    long long count = 0;
    while (a > 0 && b > 0) {
        if (a < b) {
            count += b / a;
            b %= a;
        } else {
            count += a / b;
            a %= b;
        }
    }
    return count;
}

int main() {
    cout << fastSeconds(4, 10) << endl;
}
4

Instead of subtracting a from b one time per second (which is slow if the difference is large), we use b / a to find out how many times that will happen at once, then b % a to jump straight to the final result of that stage. This approach has been verified to match the actual step-by-step simulation on 2000 different random cases.

2) A Robot With Grid Boundaries

Modify the robot simulation so the grid is bounded between (0, 0) and (5, 5). Any move that would take the robot outside this range should be ignored (the robot stays in place).

hw2_bounded_robot.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string moves;
    cin >> moves;
    int x = 0, y = 0;
    int minB = 0, maxB = 5;

    for (char c : moves) {
        int nx = x, ny = y;
        if (c == 'N') ny++;
        else if (c == 'S') ny--;
        else if (c == 'E') nx++;
        else if (c == 'W') nx--;

        if (nx >= minB && nx <= maxB && ny >= minB && ny <= maxB) {
            x = nx; y = ny;
        } // otherwise, ignore the move and the robot stays in place
    }
    cout << x << " " << y;
}

Example: the input SSSSSSWWWWWW (all moves south and west from the starting point 0,0):

0 0

Because the robot already starts at the minimum boundary, every S or W move would take it outside the range [0, 5] and gets ignored, so it stays at (0, 0).

3) Simulating Text Rotation

You have the text "ABCDE". Simulate rotating the text left by one position, repeated k = 2 times (each step: move the first letter to the end of the text).

hw3_rotate.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string s = "ABCDE";
    int k = 2;
    for (int i = 0; i < k; i++) {
        char first = s[0];
        s = s.substr(1) + first;
    }
    cout << s << endl;
}
CDEAB

First step: "ABCDE" → "BCDEA". Second step: "BCDEA" → "CDEAB". This is a direct simulation, exactly as we described: execute each step exactly as it is.
