Digit Queries

An infinite sequence made of every positive integer glued together, and you must find the digit at a position that can reach 10¹⁸ — without building the sequence itself, of course! The solution relies on grouping numbers by their digit count and jumping between the blocks directly.

Medium CSES 2431

Problem Statement

Consider the infinite sequence formed by gluing together all positive integers in order:

1234567891011121314151617181920212223...

We have q queries. In each query, you are given a position k (1-indexed) inside this infinite sequence. Your task is to print the digit located at position k.

Constraints

  • 1 ≤ q ≤ 1000

  • 1 ≤ k ≤ 10¹⁸

Example

Input:
3
7
19
12
Output:
7
4
1

Solving Methodology: How Do We Think About This Problem?

  • Understand the problem: we want digit number k in an infinite sequence without actually building the sequence.

  • Try small examples by hand: compute the digit at k=7, k=19, and k=12 by hand and check against the example.

  • Look for a pattern: group the numbers by their digit count (one digit, two digits, three...) and you'll find each group contributes a fixed number of digits.

  • Break into cases: use this grouping to jump directly to the correct block instead of scanning digit by digit.

  • Write the code and verify: test it against the problem's three examples.

  • Check the edge cases: what happens at the largest possible value of k? Could any variable overflow?

Step 1: Why Can't We Actually Build the Sequence?

Since k can reach 10¹⁸, building the sequence up to that position would require enormous time and space — we couldn't even store a prefix that long. We need a mathematical approach that computes the requested digit directly, without scanning every number before it.

Step 2: Grouping Numbers by Digit Count

Notice that the numbers naturally split into blocks based on their digit count:

Digit CountRangeCount of NumbersTotal Digits
11 – 999
210 – 9990180
3100 – 9999002700

In general, for the block of numbers with d digits: the first number in it is base = 10^(d-1), it contains 9 × base numbers, and it contributes a total of 9 × base × d digits.

For any position k: we start with d=1 and base=1, and compute the current block's length. If k is greater than the block length, we subtract it and move to the next block (d++, base *= 10). We stop once k falls inside the current block.

After finding the right block, we number within it starting from zero: k0 = k - 1, so index_of_number = k0 / d (which number inside the block) and index_in_number = k0 % d (which digit inside that number), and the actual number is num = base + index_of_number.

Step 3: The Full Solution

digit_queries.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int q;
    cin >> q;

    while (q--) {
        long long k;
        cin >> k;

        long long d = 1;       // current digit length
        long long base = 1;    // 10^(d-1)

        // Step 1: find the block (digit length d) that contains position k
        while (true) {
            long long count_numbers = 9 * base;
            long long block_len = count_numbers * d;

            if (k > block_len) {
                k -= block_len;
                d++;
                base *= 10;
            } else {
                break;
            }
        }

        // Step 2: find the exact number and digit within this d-digit block
        long long k0 = k - 1;
        long long index_of_number = k0 / d;
        long long index_in_number = k0 % d;

        long long num = base + index_of_number;

        string s = to_string(num);
        char answer_digit = s[index_in_number];

        cout << answer_digit << endl;
    }

    return 0;
}
Input: 3 / 7 19 12 → Output: 7, 4, 1

For each query, the block-search loop is very short: d will not exceed roughly 18, since k ≤ 10¹⁸. So each query's runtime is close to constant, and the total complexity is O(q log k).

Step 4: Watch Out for Overflow

Use long long for k, base, and block_len, since these values can reach into the quintillions with k up to 10¹⁸.

Within these constraints, d will not exceed roughly 18, so the product 9 * base * d stays within the long long type's limits without any overflow.

Always try the largest possible value (k = 10¹⁸) as a key edge case — the solution above gives the answer 3 for it.

This pattern — splitting a large problem into "blocks" with uniform properties, then jumping between them instead of scanning element by element — shows up often in problems dealing with a huge range of numbers. Remember this idea whenever you see a massive constraint like 10¹⁸.
