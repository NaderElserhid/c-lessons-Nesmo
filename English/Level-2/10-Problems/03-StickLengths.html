Stick Lengths

A famous CSES problem whose statement is very simple, but reaching the optimal solution requires a clever mathematical observation. We'll use the sorting technique you learned in chapter four to discover that the ideal value is always the array's median.

Medium CSES 1074

Problem Statement

You are given n sticks with certain lengths. You want to make all the sticks the same length.

You can increase or decrease the length of each stick. Changing a stick's length from x to y costs |x - y|.

Task: find the minimum possible total cost to make all the sticks the same length.

Constraints

  • 1 ≤ n ≤ 2 × 10⁵

  • 1 ≤ each stick's length ≤ 10⁹

Input

First line: an integer n — the number of sticks.
Second line: n integers — the lengths of the sticks.

Output

A single integer — the minimum possible total cost.

Example

Input:
5
2 3 1 5 2
Output:
5

Solving Methodology: How Do We Think About This Problem?

  • Understand the problem: we want to choose a single target length that minimizes the sum of |stick length - target| over all sticks.

  • Try small examples by hand: take 3 or 4 sticks and compute the cost for every possible target yourself.

  • Look for a pattern: where does the value that always gives the minimum cost lie?

  • Why does this hold true? think of the sticks as pairs (the smallest value with the largest value) and what happens to the cost as the target moves.

  • Write the code and verify: sort the array, take the middle element (the median), and compute the cost.

  • Check the edge cases: what happens when n=1? What if n is even? And could the sum overflow the int type?

Step 1: Try Small Examples by Hand

Let's take a very small example: sticks with lengths 1, 2, 3. Let's compute the total cost for every possible target:

TargetCost per StickTotal
1|1-1|+|2-1|+|3-1| = 0+1+23
2|1-2|+|2-2|+|3-2| = 1+0+12
3|1-3|+|2-3|+|3-3| = 2+1+03

The minimum cost happened at target 2 — which is exactly the middle element (the median) after sorting! Try the same thing on the original example 1, 2, 2, 3, 5 in the lab above and you'll notice the minimum cost (5) also occurs at the median 2.

Step 2: Why Is the Optimal Solution the Median?

After sorting the sticks in ascending order, picture them as pairs: the smallest stick with the largest, the second smallest with the second largest, and so on:

For any target t that falls between the two ends of a pair (min, max), the cost from that pair is always |min - t| + |max - t| = max - min — meaning it's fixed and doesn't change as long as t stays between the two ends! But as soon as t steps outside that range (becomes smaller or larger than both ends), the cost starts to increase.

So: the best target is the value that falls inside all the overlapping pairs at once — and that is exactly the median of the sorted array. If n is odd, that's precisely the middle element; if it's even, any value between the two middle elements (including either one) gives the same optimal cost.

This is exactly the idea you saw in the interactive lab above: the cost drops the closer the target gets to the middle, and starts rising again as soon as it passes it.

Step 3: The Full Solution (Sort + Median)

The algorithm is simple now that we understand why it works: sort the array (using the sorting algorithms from chapter four), take the middle element as the target, then sum the absolute distances between it and every stick:

stick_lengths.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;

    sort(a.begin(), a.end());
    long long median = a[n / 2];

    long long cost = 0;
    for (long long x : a) cost += abs(x - median);

    cout << cost << "\n";
    return 0;
}

After sorting, the array becomes 1, 2, 2, 3, 5, and the median is a[5/2] = a[2] = 2. Total cost: |1-2|+|2-2|+|2-2|+|3-2|+|5-2| = 1+0+0+1+3 = 5.

Input: 5 / 2 3 1 5 2 → Output: 5

The running time here is O(n log n) because of the sorting step — fast enough even with n up to 2 × 10⁵.

Step 4: Check the Edge Cases

A single stick (n=1): the median is the stick itself, so the cost is 0 with no need to change anything.

All sticks the same length: every difference equals zero, so the total cost is 0 — the solution handles this automatically with no special case.

n is even: there are two elements in the middle instead of one. Try 1, 2, 3, 4: at target 2 the cost is 1+0+1+2=4, and at target 3 the cost is 2+1+0+1=4 — exactly the same result! So choosing either of the two middle elements is correct.

Watch out for a common trap: stick lengths can go up to 10⁹, and there can be up to 2 × 10⁵ of them, so the total cost sum could reach roughly 2 × 10¹⁴ — which far exceeds the range of the int type! That's why we used long long for both the lengths and the sum in the code above.

Notice how everything you've learned comes together here: sorting from chapter four gave us a fast way to find the median, while a simple mathematical observation about overlapping pairs turned a problem that looked complicated into a two-line solution. This pattern — "sort, then use the median" — will show up often in problems about minimizing absolute distances.
