Domino Piling

A classic easy problem from Codeforces that directly applies the "casework" approach we learned: we split the problem based on the parity of the grid's dimensions, and solve each case separately before merging them into one simple, fast piece of code.

Easy Codeforces 50A

Problem Statement

There is a two-dimensional grid made of N rows and M columns. You have an unlimited number of dominoes of size 2 × 1, and you want to place as many of these pieces as possible on the grid such that:

  • Each piece covers two full cells.

  • No pieces overlap.

  • All pieces stay entirely within the grid.

Solving Methodology: How Do We Think About This Problem?

Before looking at the solution, let's follow the same methodology we use for every competitive programming problem:

  • Understand the problem: we want the largest number of 2×1 pieces we can place on an N×M grid without overlapping or going out of bounds.

  • Try small examples by hand: what if the grid is 1×1? Or 2×2? Or 2×3?

  • Look for a pattern: compare the results and try to relate them to the total number of cells N × M.

  • Split into cases: does the pattern change depending on whether N or M is even?

  • Write the code and verify: try the code on all the examples.

  • Check the edge cases: what happens when N=1 and M=1?

We notice a pattern: the answer is very close to (N × M) / 2 — but what if N × M is odd (as in the 1×1 case)? Then the number of pieces can't be a fraction, so we need to round down, and this is exactly where the reason for splitting the problem into cases shows up.

Step 2: Analysis Using Casework

In this problem we have 3 cases, and we analyze them using the "casework" approach we learned earlier:

  • If N is an even number (N % 2 == 0): we can cover the entire grid by placing the pieces vertically. The number of pieces used will be (N × M) / 2, because the grid has N × M cells, and each piece covers two cells.

  • If M is an even number (M % 2 == 0): we can cover the entire grid by placing the pieces horizontally. The number of pieces will also be (N × M) / 2.

  • If both N and M are odd numbers: first we place pieces vertically starting from the first row, which leaves one full row uncovered (because N is odd). In that row we place pieces horizontally, leaving exactly one cell uncovered (because M is odd). So the number of pieces used will be (N × M - 1) / 2.

domino_piling.cpp
#include <iostream>
using namespace std;

int main() {
    int N, M;
    cin >> N >> M;

    if (N % 2 == 0) {
        cout << (N * M) / 2 << endl;
    }
    else if (M % 2 == 0) {
        cout << (N * M) / 2 << endl;
    }
    else {
        cout << (N * M - 1) / 2 << endl;
    }
}

Notice that the first and second formulas are identical ((N × M) / 2) — the first two cases could actually be merged into a single case, "if N × M is even", but analyzing them separately (vertical or horizontal) helps you understand why the formula works, not just memorize it.

Step 3: Check the Edge Cases

What happens at the smallest possible value? If N = 1 and M = 1, the code enters the third case (both odd), computing (1 × 1 - 1) / 2 = 0 — which is exactly correct, since a single cell isn't enough for any piece. This confirms that our solution correctly handles the smallest possible cases without needing any extra special handling.
