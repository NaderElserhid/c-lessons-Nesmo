Sum of Three Values

A natural extension of "Sum of Two Values": we fix two elements and use binary search to find the third quickly, turning an O(n³) solution into an O(n² log n) one.

Medium CSES 1641

Problem Statement

You are given an array of n integers, and your task is to find three values at distinct positions i, j, k whose sum is x.

Constraints

  • 1 ≤ n ≤ 5000

  • 1 ≤ x, a_i ≤ 10⁹

Input

First line: two integers n and x — the array size and the required sum.
Second line: n integers — the array values.

Output

Print three integers: the positions of the chosen values (1-indexed). If more than one valid triple exists, you can print any of them. If no triple satisfies the condition, print IMPOSSIBLE.

Example

Input:
4 8
2 7 5 1
Output:
1 3 4

Solving Methodology: How Do We Think About This Problem?

  • Understand the problem: we want three distinct positions whose values sum to exactly x.

  • Connect it to an easier problem: this resembles "Sum of Two Values" but with one extra element — how can we build on that?

  • Think about complexity: the naive solution with three nested loops runs in O(n³) — far too slow here.

  • Fix one or two: if we fix two elements, only one element with a specific value remains to be found — and that can be done with binary search if the array is sorted.

  • Write the code and verify: sort while keeping the original positions, then fix a pair and search for the third.

  • Check the edge cases: could the sum of three large values overflow the int type?

Step 1: Why Not Try Every Triple?

The fully brute-force solution checks every possible triple using three nested loops, in O(n³) time. But since n can reach 5000, n³ becomes 125 × 10⁹ operations — far more than can run within one second.

Step 2: Fix Two Elements and Binary Search for the Third

Sort while keeping original positions: we store each element along with its original position as a pair (value, index), then sort by value. This lets us binary search over the values while still being able to recover the original positions when printing.

Fixing two elements and searching for the third: we iterate over all pairs (i, j) such that i < j. For each pair, we compute need = x - a[i] - a[j], and binary search for need only within the range [j+1, n-1]. If we find it at position k, we print the three original positions.

Since we always search only in positions greater than j, the three positions i, j, k will automatically be distinct with no extra check needed.

Complexity: sorting is O(n log n), and the double loop is O(n²) with one binary search per pair costing O(log n) → total O(n² log n), which is fast enough for n ≤ 5000.

Step 3: The Full Solution

sum_of_three_values.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<pair<long long,int>> a(n);
    for (int i = 0; i < n; ++i) {
        long long v;
        cin >> v;
        a[i] = {v, i + 1}; // store value and original 1-based index
    }

    sort(a.begin(), a.end()); // sort by value

    // Fix two indices (i, j) and binary search for the third
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            long long need = x - a[i].first - a[j].first;

            int lo = j + 1, hi = n - 1;
            while (lo <= hi) {
                int mid = (lo + hi) / 2;
                if (a[mid].first == need) {
                    cout << a[i].second << " "
                         << a[j].second << " "
                         << a[mid].second << "\n";
                    return 0;
                } else if (a[mid].first < need) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
    }

    cout << "IMPOSSIBLE\n";
    return 0;
}
Input: 4 8 / 2 7 5 1 → Output: 4 1 3 (another valid triple: a[4]+a[1]+a[3] = 1+2+5 = 8)
Input: 6 14 / 9 2 6 3 8 1 → Output: 2 4 1

Step 4: Watch Out for Overflow

Use long long for the values and for x, since x and a_i can reach 10⁹, and the sum of three values can reach 3 × 10⁹ — which exceeds the int type's limits (about 2.1 × 10⁹).

Always make sure the binary search range is [j+1, n-1] only (not [0, n-1]) to guarantee the three positions are automatically distinct.

If no valid triple exists, make sure the program prints IMPOSSIBLE only after trying every possible pair (i, j) without exception.

Notice the recurring pattern: "fix one or more elements, and use a faster search for the rest" is a very common way to turn slow solutions into practical ones. Here we used it to turn O(n³) into O(n² log n) just by adding sorting and binary search.
