Bit Strings

A classic CSES problem that combines the multiplication principle you learned in counting back in Level 1 with the modular arithmetic you just learned in this level — a massive power (2 raised to a huge exponent) that must be computed safely under a remainder modulo a large prime.

Easy CSES 1617

Problem Statement

Your task is to count the number of bit strings of length n. A bit string is a sequence of length n, where each position is either 0 or 1.

For example, if n = 3, the bit strings are [000, 001, 010, 011, 100, 101, 110, 111], so there are 8 of them.

Input

A single integer n.

Output

Print the total number of bit strings of length n, modulo 10⁹ + 7.

Example

Solving Methodology: How Do We Think About This Problem?

  • Understand the problem: we want the count of all possible sequences of length n made up of only 0s and 1s.

  • Try small examples by hand: what if n=1? Or n=2? Count them yourself.

  • Look for a pattern: how many choices does each position have? How does that relate to the total count?

  • Pay attention to the output: the answer is required modulo a large number — why?

  • Write the code and verify: try the code on the given example (n=3 → 8).

  • Check the edge cases: what happens when n is very large? Is your solution fast enough?

Step 1: Try Small Examples

Let's count bit strings by hand for very small lengths:

Did you notice the pattern? Every time we increase the length by one position, the number of strings doubles! That's because every previous string can end with either 0 or 1, producing twice as many new strings.

Step 2: The General Formula — the Multiplication Principle

Each position in a string of length n has two independent choices: 0 or 1. So, by the multiplication principle we studied in the counting fundamentals back in Level 1, the number of bit strings equals:

2 × 2 × ... × 2 (n times) = 2ⁿ

We need to print this value modulo 10⁹ + 7.

Step 3: Why Do We Need mod? And a Simple Iterative Solution

The value 2ⁿ can become enormous — far larger than even long long can hold. That's why the problem asks for the answer modulo the common modulus 10⁹ + 7 that we studied in the modular arithmetic chapter.

We can compute 2ⁿ mod M iteratively using a simple loop, doubling the result and taking mod at each step (exactly like the doubling loop from the time complexity chapter):

bit_strings.cpp
#include <iostream>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> n;

    long long ans = 1;
    for (long long i = 0; i < n; ++i) {
        ans = (ans * 2) % MOD;
    }

    cout << ans << "\n";
    return 0;
}

We start with ans = 1 (representing 2⁰ = 1, the empty string). At each iteration, we double ans and take the remainder, exactly matching how the number of strings doubles when a new position is added. After n iterations, ans equals 2ⁿ mod M.

Input: 3 → Output: 8

A Note on Fast Exponentiation (an Alternative for Very Large n)

In this problem, an O(n) loop is fast enough because n isn't too large. But in other problems, n might be enormous (say, up to 10¹⁸), and we can't afford to repeat the loop n times — that would take far too long.

In those cases, we use the fast exponentiation (modpow) function we built in the modular arithmetic chapter, which computes aᵉ mod m in O(log n) instead of O(n):

bit_strings_fast.cpp
long long modpow(long long a, long long b, long long m) {
    if (b == 0) return 1;
    long long half = modpow(a, b / 2, m);
    long long res = (half * half) % m;
    if (b % 2 == 1)
        res = (res * (a % m)) % m;
    return res;
}

int main() {
    long long n;
    cin >> n;
    cout << modpow(2, n, 1000000007LL) << "\n";
}

Both methods give exactly the same result (we verified this on many examples), but at n = 1,000,000, the simple loop needs a million steps while fast exponentiation needs only about 20 steps — an enormous difference that becomes decisive as the constraints in a problem get larger.
