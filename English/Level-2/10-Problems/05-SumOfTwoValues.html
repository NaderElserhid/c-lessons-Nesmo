Sum of Two Values

A classic CSES problem that teaches you how to use a map to turn a slow O(n²) search into a fast O(n log n) search that scans the array only once.

Easy CSES 1640

Problem Statement

You are given an array of n integers, and your task is to find two distinct positions i and j such that a[i] + a[j] = x.

If several valid pairs exist, you can print any one of them. If no pair satisfies the condition, print IMPOSSIBLE.

Constraints

  • 1 ≤ n ≤ 2 × 10⁵

  • 1 ≤ x, a_i ≤ 10⁹

Input

First line: two integers n and x — the array size and the required sum.
Second line: n integers — the array values.

Output

Either two (1-based) positions in the form i j such that a[i] + a[j] = x and i ≠ j, or IMPOSSIBLE if no pair satisfies the condition.

Example

Input:
4 8
2 7 5 1
Output:
2 4

(One valid pair is a[2] + a[4] = 7 + 1 = 8)

Solving Methodology: How Do We Think About This Problem?

  • Understand the problem: we want two distinct positions whose values sum to exactly x.

  • Try small examples by hand: take an array of 3-4 elements and search for the pair yourself.

  • Look for a pattern: for each element a[i], what we actually need to know is whether we have already seen the value x - a[i].

  • Think about efficiency: the naive solution with two nested loops checks every pair, but it is far too slow when n is large.

  • Write the code and verify: use a map to record every value you have seen along with its position, and look up the complement during that same scan.

  • Check the edge cases: what if no solution exists? What if values repeat?

Step 1: Why Not Try Every Pair?

The simplest solution is to check every possible pair of positions (i, j) and see whether a[i] + a[j] = x, using two nested loops. This runs in O(n²) time.

But since n can reach 2 × 10⁵, n² becomes about 4 × 10¹⁰ operations — far more than can run within one second. We need a faster approach that scans the array only once.

Step 2: The Map Idea (Pairing During the Scan)

We scan the array's elements from left to right. At each position i:

  1. We define need = x - a[i] — the value we need to complete the sum.

  2. If need already exists in the map at some earlier position j, we have found the solution: a[i] + a[j] = x.

  3. Otherwise, we store a[i] with its position i in the map, and move on to the next element.

Since every element is processed once, and each map operation costs roughly O(log n), the whole algorithm runs in O(n log n) time — fast enough even for the largest possible inputs.

Step 3: The Full Solution

sum_of_two_values.cpp
#include <iostream>
#include <map>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<long long> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    // value -> index (1-based)
    map<long long, int> pos;

    for (int i = 0; i < n; i++) {
        long long need = x - a[i];

        auto it = pos.find(need);
        if (it != pos.end()) {
            // found a pair: a[i] + need = x
            cout << it->second << " " << (i + 1) << "\n";
            return 0;
        }

        // store current value with its 1-based index
        pos[a[i]] = i + 1;
    }

    cout << "IMPOSSIBLE\n";
    return 0;
}
Input: 4 8 / 2 7 5 1 → Output: 2 4

Step 4: Points to Watch Out For

Distinct positions: using a map of only earlier values (not the current value) automatically guarantees i ≠ j.

1-based indices: CSES expects positions starting at 1, so we must print i + 1, not i.

Repeated values: if a value repeats, the map keeps only its most recently recorded position — this causes no problem since any valid pair is accepted.

No solution: if the loop finishes without finding a pair, the answer is IMPOSSIBLE.

Although x and a_i only reach 10⁹ (which fits comfortably in an int), we used long long in the code as a general safety habit when dealing with sums or differences that could approach a type's limits — to avoid any surprises later if the constraints change.

This pattern — "a map built during a single scan" — shows up in many competitive programming problems whenever you need to look up a value mathematically related to the current element (like the complement here). Remember it well; it is far faster than any solution using two nested loops.
