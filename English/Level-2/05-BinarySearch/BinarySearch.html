Binary Search

In the last chapter you learned how to sort data using the sort function with O(n log n) complexity. Now we'll put that sorted data to work for us: instead of checking every element one by one, we'll learn how to "guess smartly" and reach the answer in very few steps — even if the data has a million elements. This is the idea behind binary search, one of the most important tools in competitive programming.

Linear Search

Imagine you have a list of numbers and want to check whether a specific number exists in it. The simplest way is to go through the list element by element:

linear_search.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {4, 8, 15, 16, 23, 42};
    int target = 15;

    for (int i = 0; i < arr.size(); i++) {
        if (arr[i] == target) {
            cout << "Found at index " << i;
            return 0;
        }
    }
    cout << "Not found";
}
Found at index 2

This is called Linear Search because you move through the list linearly, element after element. It always works correctly, but it can be slow if the list is long — you might need to check every single element.

If there are a million numbers, that means up to a million checks in the worst case. Recall from the third chapter that this means a time complexity of O(n).

Now imagine you're looking for a name in a printed phone book. You wouldn't start from page one and read name by name. You'd open the book to the middle, check whether you're in the right alphabetical section, and then discard half the pages at once. This is exactly what Binary Search does.

The Idea Behind Binary Search

Binary search is like a "guess the number" game. Each time you pick the middle value and ask:

  • Is this value too small?

  • Is it too large?

  • Or is it exactly right?

Based on the answer, the search space is cut in half every time. This makes the search much faster than linear search — but it only works if the data is already sorted (which is exactly why we studied sorting in the last chapter first!).

Classic Binary Search

Example: We have the sorted array [1, 3, 5, 6, 7, 9, 11]. Search for the number 7 and print its position if found.

Step-by-Step Solution

We start with the full range, then gradually narrow the search.

First, we find the middle element, which is 6. We ask: is 7 smaller or larger than 6? It's larger, and since the array is sorted, this means 7 will be after 6. We can discard the entire first half.

The logically remaining array is [7, 9, 11]. The middle element is 9. The number 7 is smaller than 9, meaning it comes before it. We discard 9 and everything after it.

Finally, only [7] remains. The middle element is exactly 7 — that's what we were looking for!

We only did three comparisons: we compared 6 with 7, then 9 with 7, then 7 with 7.

binary_search.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {1, 3, 5, 6, 7, 9, 11};
    int target = 7;
    int left = 0, right = arr.size() - 1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] == target) {
            cout << "Found at index " << mid;
            return 0;
        } else if (arr[mid] < target)
            left = mid + 1;
        else
            right = mid - 1;
    }

    cout << "Not found";
}
Found at index 4

Time Complexity

Each step cuts the range in half. If there are n elements, binary search needs only about log₂(n) steps — that is, O(log n) complexity. Even with a million numbers, that means only about 20 checks instead of a million checks with linear search!

The complexity of binary search is O(log n), while the complexity of linear search is O(n).

Finding the First Element Greater Than or Equal to X

Binary search can do more than just find a specific number — it can also be used to find positions or boundaries in a sorted array.

Example: You have the array [2, 4, 6, 8, 10]. Find the first element greater than or equal to 7.

first_geq.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {2, 4, 6, 8, 10};
    int x = 7;

    int left = 0, right = arr.size() - 1;
    int ans = -1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] >= x) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    if (ans == -1) cout << "No element found";
    else cout << "First element >= " << x << " is at index " << ans;
}
First element >= 7 is at index 3

That is, arr[3] = 8 is the first element greater than or equal to 7. Notice the difference from classic search: instead of stopping as soon as we find a valid value, we save it in ans and then keep searching to the left (right = mid - 1) in case we find a better candidate (a smaller index).

The General Algorithm

  • Start with two pointers, left and right.

  • Compute the middle of the range, mid.

  • If the middle value is the answer (or a candidate for it), record it.

  • If it's too small, move left to mid + 1.

  • If it's too large (or a candidate that could be improved), move right to mid - 1.

  • Repeat until left > right.

In the "first element ≥ X" problem, when arr[mid] ≥ X, we save mid as a candidate and keep searching in the left half for a smaller index.

Binary search can only be used to find an exact matching value, and cannot be used to find positions or boundaries.

Linear Search vs. Binary Search

Let's compare the number of operations each search needs to reach the answer, as the array size n increases:

nLinear Search O(n)Binary Search O(log n)
10≤ 10≤ 4
1,000≤ 1,000≤ 10
1,000,000≤ 1,000,000≤ 20

With a million elements, binary search needs only about 20 checks compared to a million for linear search — an enormous difference, thanks to cutting the range in half every step. But it always requires the data to be sorted first (which is exactly why we studied sorting right before this chapter).

Homework Exercises

1) Trace Through Binary Search

You have the sorted array [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91] (11 elements, indices 0 to 10). Apply classic binary search to look for the target 72. Determine the final index and the number of comparisons.

First comparison: left=0, right=10 → mid=5 → arr[5]=23. Since 23 < 72, we move right: left = 6.

Second comparison: left=6, right=10 → mid=8 → arr[8]=56. Since 56 < 72, we move right: left = 9.

Third comparison: left=9, right=10 → mid=9 → arr[9]=72. Match! We stop.

Found at index 9 after 3 comparisons

2) First Element Strictly Greater Than X

Modify the "first element ≥ X" algorithm to become "first element strictly greater (>) than X". Apply it to the array [2, 4, 6, 8, 10] to find the first element greater than 6.

hw2.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {2, 4, 6, 8, 10};
    int x = 6;

    int left = 0, right = arr.size() - 1;
    int ans = -1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] > x) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    if (ans == -1) cout << "No element found";
    else cout << "First element > " << x << " is at index " << ans;
}
First element > 6 is at index 3

The only difference from "first element ≥ X" is using > instead of >= in the condition.

3) Count Elements Smaller Than X

You have the sorted array [1, 3, 5, 7, 9, 11]. Use binary search to compute the number of elements smaller than 6 (without going through every element).

hw3.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {1, 3, 5, 7, 9, 11};
    int x = 6;
    int n = arr.size();

    int left = 0, right = n - 1;
    int ans = n; // if we never find an element >= x, all elements are smaller than x

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] >= x) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    cout << "Count of elements less than " << x << " = " << ans;
}
Count of elements less than 6 = 3

The clever idea: the index of the first element ≥ x is exactly equal to the number of elements smaller than x (because everything before it in a sorted array is smaller than it). The elements 1, 3, 5 are smaller than 6, and there are 3 of them — exactly what the algorithm gave us!
