Constructive Algorithms

In earlier chapters our goal was always to compute a value: the shortest path, the largest profit, the smallest difference. This chapter is entirely different in nature: the task is to build an actual object that satisfies certain conditions — an array, a permutation, or even a way to cover a board — or to prove that such an object does not exist at all. There is no ready-made algorithm here like Dijkstra that we apply mechanically; the real tool here is logic and observation.

What Are Constructive Algorithms?

A Constructive Problem asks you to build a specific example that satisfies a set of rules, or to prove that no such example exists.

Unlike ordinary algorithmic problems where you compute a numeric value (shortest path, maximum profit...), constructive problems ask for the object itself — such as "print an array such that..." — rather than a single number describing some property of it.

Let's look at three examples right away to see how this type of problem works in practice, then extract from them general strategies applicable to any new constructive problem.

Example 1: Zero Sum Array

Given an integer n, print n integers, all distinct from each other, such that their sum equals 0.

Construction Idea

Instead of randomly searching for numbers, we build the answer directly with a fixed pattern. We know that for any number i: i + (-i) = 0. So we can print pairs of a positive and a negative number. If n is odd, we add 0 to the mix to complete the required number of elements while keeping the sum at zero.

nOutput
10
21 -1
31 -1 0
51 -1 2 -2 0
zero_sum_array.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    for (int i = 1; i <= n / 2; i++) {
        cout << i << " " << -i << " ";
    }

    if (n % 2 != 0) cout << 0;
    cout << endl;
}

Check the count: the loop prints two elements per iteration and repeats n/2 times (integer division), giving 2 × (n/2) elements, and then only one extra element is added if n is odd — so the total count is always exactly n, regardless of whether n is even or odd.

Example 2: Anti-Identity Permutation

Build a permutation of length n (1-indexed) such that p[i] ≠ i for every position i. For example, if n=3, then [1, 2, 3] is invalid because 1 is at position 1, but [2, 3, 1] is valid.

Construction Idea

If we rotate the array by just one position, no number will remain in its original place. The formula: p[i] = i + 1 for every i < n, and p[n] = 1.

Note: at n=1 there is no solution. The number 1 cannot be placed anywhere other than position 1, because the only possible permutation of length 1 is [1] itself. This is an early example of how part of solving a constructive problem is recognizing when no solution exists at all.

Example 3: Chessboard Domineering

You have a standard chessboard (8×8) with two opposite corners removed (leaving 62 squares). Can the board be fully covered with domino pieces (each piece covering two adjacent squares)?

We tricked you! Sometimes the "construction" required is proving that the task is impossible.

The Coloring Argument

A standard chessboard has 32 black squares and 32 white squares. Opposite corners are always the same color. If we remove two opposite corners (both white, say), we're left with 32 black and only 30 white squares. Every domino piece covers exactly one black square and one white square. To cover the whole board, we need an equal number of black and white squares. Conclusion: this is impossible.

This is not the usual approach, but it happens from time to time. The lesson here: sometimes solving a problem with pen, paper, and out-of-the-box thinking is far easier than trying to write code for it directly.

How Do You Solve Constructive Problems?

Unlike graph theory or dynamic programming, there's no ready-made algorithm here like Dijkstra — instead you use logic and observation. Here are five practical strategies used again and again:

1) Try Small N

This is by far the most important strategy. If the problem asks for a solution for general n, don't guess the complex formula right away. Take pen and paper and solve it for n=1, 2, 3 by hand. Many constructive problems are solved by noticing a pattern in the small cases.

2) Parity (Odd vs Even)

Many constructions rely on the properties of even and odd numbers (odd + odd = even). Example: if a problem asks "can these two numbers be made equal by repeatedly adding 2 to one of them?", check parity first. If one is odd and the other even, they will never be equal, because adding 2 never changes a number's parity.

3) The Pigeonhole Principle

If you have n+1 elements distributed among n boxes, then at least one box must contain two elements. This principle is used often to prove the existence of a solution (or its impossibility).

4) Construction by Induction

Ask yourself: "if I have a correct solution for n, can I easily add one element to make it correct for n+1?" This lets you build the answer gradually instead of searching for it all at once.

5) Check the Worst Case (or the Trivial Solution)

Sometimes the answer is very simple. Before overthinking, check whether the answer is simply:

  • The array sorted in ascending order 1, 2, 3, ...
  • The array sorted in descending order n, n-1, n-2, ...
  • All elements zero, or all elements one

Quick Summary

Constructive problems ask for an actual object satisfying certain conditions, or a proof of non-existence.
Zero Sum Array: balanced pairs (i, -i), with an extra zero when n is odd.
Anti-Identity Permutation: rotating by one position guarantees every element moves away from its place, except at n=1.
Chessboard Domineering: sometimes the solution is proving impossibility, via a simple coloring argument.
The five strategies (small n, parity, pigeonhole, induction, worst case) are general thinking tools suited to any new constructive problem.

Homework

1) Extend Zero Sum Array by Hand

Using the same construction idea, work out by hand what the code would print for n = 6 and n = 7.

n=6: 1 -1 2 -2 3 -3 n=7: 1 -1 2 -2 3 -3 0

At n=6 (even): 3 pairs with no extra zero. At n=7 (odd): 3 pairs then one extra zero, completing the count to 7 elements.

2) Why Doesn't Always Adding a Zero Work in Zero Sum Array?

If we added 0 to the array even when n is even (without adjusting the number of pairs), what would go wrong?

If we added an extra zero without reducing the number of pairs, the total element count would become n+1 instead of n — which explicitly violates the problem's requirement to print exactly n elements, even though the sum would still be zero. The condition on the element count matters just as much as the condition on the sum.

3) Design a Different Construction for Anti-Identity Permutation

Rotating by one position is not the only solution. Try proposing a completely different construction (hint: what if you swapped each element with its counterpart from the opposite end when n is even?).

A valid alternative example (for even n only): swap each pair of neighboring elements, i.e. p = [2, 1, 4, 3, 6, 5, ...]. Check: p[1]=2≠1, p[2]=1≠2, and so on for every pair. This construction doesn't work directly when n is odd (a last element is left without a partner), so rotating by one position remains the more general solution that works for every n ≥ 2.

Glossary

Constructive AlgorithmConstructive Algorithm

An approach that asks you to build an actual object satisfying certain conditions, or to prove that it does not exist.

PermutationPermutation

An arrangement of all the numbers from 1 to n, with each number appearing exactly once.

DerangementDerangement

A permutation in which no element remains in its original position — that is, p[i] ≠ i for every i.

ParityParity

Whether a number is even or odd; a property unchanged by adding or subtracting an even number.

Pigeonhole PrinciplePigeonhole Principle

If more elements are distributed than there are boxes, at least one box must contain two elements.

InductionInduction

Building a solution for a larger case starting from a known solution for a smaller case, by adding a simple modification.

InvariantInvariant

A property that always remains true no matter how the state changes during execution (such as the sum staying zero after every pair in Zero Sum Array).

Existence ProofExistence Proof

A logical argument proving that a solution exists (often by actually constructing it) or that it does not exist at all (like the coloring argument in the chessboard example).
