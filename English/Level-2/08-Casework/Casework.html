Casework

In the simulation chapter you learned to follow rules step by step. Sometimes, though, not all inputs behave the same way — some are even and some are odd, some are positive and some are negative. In this chapter you'll learn "casework": a way of thinking (not a new algorithm) that teaches you how to split a complicated problem into simpler situations, solve each one separately, then combine the results.

What is Casework?

Casework problems are ones whose solution is found by splitting the problem into different cases, solving each one separately, then merging the results.

In many problems you might try to write a single formula or a single loop that covers everything. But in casework problems, you notice that different situations behave differently. So instead of one general rule, you say:

  • If case A happens, do this.

  • If case B happens, do that.

  • And maybe also case C, case D, and so on.

Then you either combine the answers from all the cases together, or pick the best one among them.

Why Do We Use Casework?

  • It lets you handle special cases clearly (when simple logic isn't enough).

  • It helps you break a hard problem into manageable pieces.

  • It shows up a lot in counting problems or problems with multiple outcomes.

How to Do Casework

  • Read the problem carefully and look for places where something changes (like small/large, positive/negative, even/odd).

  • Identify all the different cases that cover every possibility without overlap.

  • For each case, figure out how to compute the result.

  • Combine the results if needed (either by adding them, or by taking the smallest/largest).

  • Make sure you haven't missed any case, and haven't counted anything twice.

Example: Even or Odd Sum

You have two numbers a and b. Compute the number of pairs (i, j) such that 1 ≤ i ≤ a and 1 ≤ j ≤ b and i + j is even.

Observation: i + j is even if both are even or both are odd. So there are two cases:

  • Case 1: i is even and j is even.

  • Case 2: i is odd and j is odd.

We compute each case separately, then add them together.

even_odd_sum.cpp
#include <iostream>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;

    int evenA = a / 2;
    int oddA = a - evenA;
    int evenB = b / 2;
    int oddB = b - evenB;

    int pairs = evenA * evenB + oddA * oddB;
    cout << pairs;
}

Example: if a = 5 and b = 4, the numbers from 1 to 5 contain 2 even and 3 odd numbers, and the numbers from 1 to 4 contain 2 even and 2 odd numbers. So: pairs = 2×2 + 3×2 = 4 + 6 = 10.

Example: Triangle Validity

You are given three side lengths a, b, c. Determine whether they can form a triangle.

We can test each case by checking that the sum of any two sides is greater than the third side:

  • b + c > a

  • a + c > b

  • a + b > c

If all these inequalities hold, forming a triangle is possible. We check each of these inequalities, and if any one fails, the answer is "NO"; otherwise the answer is "YES".

triangle.cpp
#include <iostream>
using namespace std;

int main() {
    int a, b, c;
    cin >> a >> b >> c;

    bool ok = true;
    if (b + c <= a) ok = false;
    if (a + c <= b) ok = false;
    if (a + b <= c) ok = false;

    cout << (ok ? "YES" : "NO");
}

This checks each case independently — a direct example of casework.

Example: Coordinate Quadrant

You are given the coordinates of a point (x, y). Print which quadrant it belongs to.

CaseQuadrant
x > 0 and y > 0Quadrant I
x < 0 and y > 0Quadrant II
x < 0 and y < 0Quadrant III
x > 0 and y < 0Quadrant IV
x = 0 or y = 0On one of the axes
quadrant.cpp
#include <iostream>
using namespace std;

int main() {
    int x, y;
    cin >> x >> y;

    if (x > 0 && y > 0) cout << "Quadrant I";
    else if (x < 0 && y > 0) cout << "Quadrant II";
    else if (x < 0 && y < 0) cout << "Quadrant III";
    else if (x > 0 && y < 0) cout << "Quadrant IV";
    else cout << "On an axis";
}

Notice that the final case (else) catches every point that doesn't explicitly fall in any of the four quadrants — that is, when x = 0 or y = 0. This is a good example of the "watch the boundaries" tip we mentioned in the simulation tips.

Tips for Casework

  • Make sure your cases don't overlap.

  • Make sure every possibility is covered.

  • Watch out for boundaries (like 0 or exact equality).

  • Keep the logic clear and simple.

Quick Summary

Casework means splitting a problem into simpler situations.
Solve each case independently, then merge the results.
It's a way of thinking, not a special algorithm.
Excellent for the early stages of solving problems.

Tip: when you're not sure where to start, ask yourself: "What are the possible cases?" — that's the beginning of casework.

Homework Exercises

1) Counting Pairs With an Odd Sum

Using the same idea as "even or odd sum", modify the code to compute the number of pairs (i, j) whose sum is odd instead of even (for the same a=5, b=4).

hw1_odd_sum.cpp
int evenA = a / 2, oddA = a - evenA;
int evenB = b / 2, oddB = b - evenB;
int oddPairs = evenA * oddB + oddA * evenB; // case: even with odd, or odd with even
cout << oddPairs;
10

i + j is odd when one of them is even and the other is odd — two new cases, just like the original example. Notice that 10 (even) + 10 (odd) = 20 = a × b, which is a good sanity check because every possible pair has either an even sum or an odd sum, with no overlap and none missing — exactly what "covering every possibility without overlap" means.

2) Classifying Triangle Type

Extend the triangle validity code to also determine the type of the triangle if it's valid: Equilateral if all sides are equal, Isosceles if exactly two sides are equal, or Scalene if all sides are different.

hw2_triangle_type.cpp
string classify(int a, int b, int c) {
    bool valid = (a+b>c) && (b+c>a) && (a+c>b);
    if (!valid) return "Not a triangle";
    if (a==b && b==c) return "Equilateral";
    if (a==b || b==c || a==c) return "Isosceles";
    return "Scalene";
}
classify(5, 5, 5) → Equilateral classify(3, 4, 5) → Scalene classify(5, 5, 8) → Isosceles classify(1, 1, 5) → Not a triangle

Notice the order of the cases: we first check validity (otherwise the classification is meaningless), then we check the most specific case (all three equal) before the less specific case (only two sides equal) — ordering cases from most specific to most general matters a great deal here to avoid mistakenly classifying an equilateral triangle as merely isosceles.

3) Adding the Origin Point Case

Extend the coordinate quadrant code to distinguish a special case: if the point is exactly at the origin (0, 0), print "Origin" instead of "On an axis".

hw3_origin.cpp
string classify(int x, int y) {
    if (x==0 && y==0) return "Origin";
    if (x==0 || y==0) return "On an axis";
    if (x>0 && y>0) return "Quadrant I";
    if (x<0 && y>0) return "Quadrant II";
    if (x<0 && y<0) return "Quadrant III";
    return "Quadrant IV";
}
classify(0, 0) → Origin classify(0, 5) → On an axis classify(3, 5) → Quadrant I

This is an excellent example of "don't miss any case" — the origin point is a special case inside the "on an axis" case, so it must be checked first (most specific before most general), otherwise the condition x==0 || y==0 would catch it before reaching the more precise condition.
