Depth First Search

Go as deep as possible, then come back

What will you learn in this lesson?

  • Understand the idea of DFS: going as far as possible before turning back
  • Write it with recursion and with an explicit stack
  • Use the visited array and the parent to avoid loops
  • Record depth and entry and exit times
  • Solve reachability and cycle-detection problems

An adventure in a maze

Imagine you are inside a maze, holding a piece of chalk. You walk down a corridor, and at every junction you take the first branch you have not tried, marking every room you enter. When you reach a dead end or a room you already marked, you step back and try the next branch. This is Depth First Search (DFS).

The idea: go as far as you can before turning back. It helps with questions like: can we get from one vertex to another? How many vertices can be reached? Is there a cycle in the graph? And it is the basis of more advanced algorithms.

The chalk is the visited array, and keeping track of the way back is the call stack that the computer builds for us whenever a function calls itself.

DFS with recursion

The easiest way to write it is a function that calls itself on every neighbor we have not visited:

dfs.cpp
#include <iostream>#include <vector>using namespace std; vector<vector<int>> adj;vector<bool> visited; void dfs(int v) {    visited[v] = true;    cout << v << " ";    for (int u : adj[v]) {        if (!visited[u]) {            dfs(u);        }    }} int main() {    int n = 8;    int edges[8][2] = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {3, 7}, {5, 8}, {6, 8}};    adj.assign(n + 1, {});    visited.assign(n + 1, false);    for (auto& e : edges) {        adj[e[0]].push_back(e[1]);        adj[e[1]].push_back(e[0]);    }     cout << "DFS order from 1: ";    dfs(1);    cout << endl;    return 0;}
Click any highlighted line of code to read its explanation here...
DFS order from 1: 1 2 4 5 8 6 3 7

Follow the order on the graph: we started at 1, went down to 2 (its first neighbor), and from there to 4, where we hit a dead end, so we returned and continued from 5, then 8, then 6, then 3, then 7. Notice that 6 came to us from 8, and 3 came from 6, not from 1 directly, because depth has priority.

Without the visited array the program would go around forever in any graph that has a cycle (from 1 to 2 to 5 to 8 to 6 to 3 then 1 then 2...). In almost every graph problem, mark the vertex as soon as you enter it, before you look at its neighbors.

What is the running time of DFS? Each vertex is entered once, and each edge is examined twice (from each end), so the time is O(n + m).

Parent, depth, and entry and exit times

DFS can record useful information about each vertex: its parent (the one we came from), its depth, when we entered it (tin) and when we finished with it (tout). An example on a tree:

dfs_times.cpp
#include <iostream>#include <vector>using namespace std; vector<vector<int>> adj;vector<int> parent, depth, tin, tout;int timer = 0; void dfs(int v, int p) {    parent[v] = p;    tin[v] = ++timer;    for (int u : adj[v]) {        if (u != p) {            depth[u] = depth[v] + 1;            dfs(u, v);        }    }    tout[v] = ++timer;} int main() {    int n = 7;    int edges[6][2] = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {3, 7}};    adj.assign(n + 1, {});    parent.assign(n + 1, 0);    depth.assign(n + 1, 0);    tin.assign(n + 1, 0);    tout.assign(n + 1, 0);    for (auto& e : edges) {        adj[e[0]].push_back(e[1]);        adj[e[1]].push_back(e[0]);    }     dfs(1, 0);    cout << "v parent depth in out" << endl;    for (int v = 1; v <= n; v++) {        cout << v << "     " << parent[v] << "      " << depth[v] << "    " << tin[v] << "  " << tout[v] << endl;    }    return 0;}

Vertex 2 has the interval [2, 7], which contains the intervals of its children 4 and 5 ([3, 4] and [5, 6]). This rule means that u is in the subtree of v if and only if its interval lies inside the interval of v. It is used a lot in tree problems.

DFS with a stack, no recursion

Recursion uses call-stack memory, which can run out in a very deep graph (such as a path of hundreds of thousands of vertices). The alternative is to build the stack ourselves:

dfs_iterative.cpp
int n = 8;int edges[8][2] = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {3, 7}, {5, 8}, {6, 8}};vector<vector<int>> adj(n + 1);for (auto& e : edges) {    adj[e[0]].push_back(e[1]);    adj[e[1]].push_back(e[0]);} vector<bool> seen(n + 1, false);stack<int> st;st.push(1);cout << "iterative DFS: ";while (!st.empty()) {    int v = st.top();    st.pop();    if (seen[v]) {        continue;    }    seen[v] = true;    cout << v << " ";    for (int i = (int)adj[v].size() - 1; i >= 0; i--) {        if (!seen[adj[v][i]]) {            st.push(adj[v][i]);        }    }}cout << endl;
Click any highlighted line of code to read its explanation here...
iterative DFS: 1 2 4 5 8 6 3 7

A stack gives back the last element that went in (last in, first out), which is exactly what the recursive function does internally.

What do we use DFS for?

First: is there a path? We start a DFS from vertex a and see whether it visited b:

Second: is there a cycle? In an undirected graph, if we meet a visited neighbor other than the parent, we reached it by two routes, so there is a cycle:

find_cycle.cpp
auto hasCycle = [](int n, vector<pair<int, int>> edges) {    vector<vector<int>> adj(n + 1);    for (auto& e : edges) {        adj[e.first].push_back(e.second);        adj[e.second].push_back(e.first);    }    vector<bool> seen(n + 1, false);    bool found = false;    function<void(int, int)> dfs = [&](int v, int parent) {        seen[v] = true;        for (int u : adj[v]) {            if (u == parent) {                continue;            }            if (seen[u]) {                found = true;            } else {                dfs(u, v);            }        }    };    for (int v = 1; v <= n; v++) {        if (!seen[v]) {            dfs(v, 0);        }    }    return found;}; cout << "square with a diagonal: " << (hasCycle(4, {{1, 2}, {2, 3}, {3, 4}, {4, 1}, {1, 3}}) ? "has a cycle" : "no cycle") << endl;cout << "a path of four: " << (hasCycle(4, {{1, 2}, {2, 3}, {3, 4}}) ? "has a cycle" : "no cycle") << endl;cout << "two separate edges: " << (hasCycle(4, {{1, 2}, {3, 4}}) ? "has a cycle" : "no cycle") << endl;
Click any highlighted line of code to read its explanation here...
square with a diagonal: has a cycle a path of four: no cycle two separate edges: no cycle

Notice that we ignore the parent, because the edge we came along is not a cycle. And for a graph made of several parts we start a DFS from every vertex we have not visited, which is how connected components are found.

Lesson project: can I get there?

We answer reachability questions in a transport network.

The idea

A city has several bus lines linking stations. Passengers ask: "can I go from station a to station b (even by changing buses)?". You also want to know how many stations someone starting at station 1 can reach.

What you need to do
  1. Read n and m and then m edges, then q questions.
  2. For each question a b run a DFS from a after resetting the visited array, and print YES if it visited b, otherwise NO.
  3. At the end run a DFS from 1 and print Reachable from 1: and the number of visited vertices.
Two sample runs

First run (a graph with three parts):

9 7 1 2 2 3 1 3 4 5 5 6 5 7 8 9 4 1 3 1 5 6 7 8 3
YES NO YES NO Reachable from 1: 3

Second run (a single path):

5 4 1 2 2 3 3 4 4 5 2 1 5 5 1
YES YES Reachable from 1: 5

Check it in your head: in the first run, vertices 1, 2 and 3 form a separate triangle, so we cannot get from 1 to 5, nor from 8 to 3. But 6 and 7 are both connected to 5.

After you try it yourself: show the solution
can_i_reach.cpp
#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> adj;
vector<bool> seen;

void dfs(int v) {
    seen[v] = true;
    for (int u : adj[v]) {
        if (!seen[u]) {
            dfs(u);
        }
    }
}

int main() {
    int n, m;
    cin >> n >> m;
    adj.assign(n + 1, {});
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        adj[a].push_back(b);
        adj[b].push_back(a);
    }

    int q;
    cin >> q;
    for (int i = 0; i < q; i++) {
        int a, b;
        cin >> a >> b;
        seen.assign(n + 1, false);
        dfs(a);
        cout << (seen[b] ? "YES" : "NO") << endl;
    }

    seen.assign(n + 1, false);
    dfs(1);
    int count = 0;
    for (int v = 1; v <= n; v++) {
        if (seen[v]) {
            count++;
        }
    }
    cout << "Reachable from 1: " << count << endl;
    return 0;
}

1

Is there a cycle?

Medium

Read an undirected graph (it may have several parts) and print YES if it contains a cycle, otherwise NO.

Requirements
  • Build the adjacency list.
  • Run a DFS from every vertex that has not been visited, passing the parent along.
  • If you find a visited neighbor that is not the parent, record that a cycle exists.
  • Print the result.
Example input and expected output
5 5 1 2 2 3 3 4 4 2 4 5
YES
Hints
  • The edge a - b must not count as a cycle when you step back to your parent.
  • In the example 1-2-3-4-2 and then 4-5: the vertices 2, 3 and 4 form a cycle, so the answer is YES.
Sample solution (after you try)
has_cycle.cpp
// Challenge 1: is there a cycle?
#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> adj;
vector<bool> seen;
bool found = false;

void dfs(int v, int parent) {
    seen[v] = true;
    for (int u : adj[v]) {
        if (u == parent) {
            continue;
        }
        if (seen[u]) {
            found = true;
        } else {
            dfs(u, v);
        }
    }
}

int main() {
    int n, m;
    cin >> n >> m;
    adj.assign(n + 1, {});
    seen.assign(n + 1, false);
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        adj[a].push_back(b);
        adj[b].push_back(a);
    }
    for (int v = 1; v <= n; v++) {
        if (!seen[v]) {
            dfs(v, 0);
        }
    }
    cout << (found ? "YES" : "NO") << endl;
    return 0;
}
2

The reach list

Medium

Read n, m and s, then m edges. Print the number of vertices reachable from s (including s), then a colon, then their numbers in ascending order.

Requirements
  • Build the list and run a DFS from s.
  • Count the visited vertices.
  • Print the count, then :, then the numbers separated by spaces in ascending order.
Example input and expected output
9 7 5 1 2 2 3 1 3 4 5 5 6 5 7 8 9
4: 4 5 6 7
Hints
  • The ascending order comes from walking over v from 1 to n, not from the DFS order.
  • With the graph from the example and s = 5 the answer is 4: 4 5 6 7.
Sample solution (after you try)
reach_list.cpp
// Challenge 2: list everything reachable from a vertex
#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> adj;
vector<bool> seen;

void dfs(int v) {
    seen[v] = true;
    for (int u : adj[v]) {
        if (!seen[u]) {
            dfs(u);
        }
    }
}

int main() {
    int n, m, s;
    cin >> n >> m >> s;
    adj.assign(n + 1, {});
    seen.assign(n + 1, false);
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        adj[a].push_back(b);
        adj[b].push_back(a);
    }
    dfs(s);
    int count = 0;
    for (int v = 1; v <= n; v++) {
        if (seen[v]) {
            count++;
        }
    }
    cout << count << ":";
    for (int v = 1; v <= n; v++) {
        if (seen[v]) {
            cout << " " << v;
        }
    }
    cout << endl;
    return 0;
}

Quick summary

  • DFS goes as far as it can before turning back, and marks visited vertices so it never repeats them.
  • We implement it with a recursive function or an explicit stack. Its time is O(n + m).
  • We mark a vertex as visited as soon as we enter it, before looking at its neighbors.
  • We pass the parent to avoid stepping back; a visited neighbor other than the parent means a cycle.
  • The times tin and tout make the interval of a vertex contain the intervals of its descendants.
  • The neighbor order changes the visiting order but not the set of vertices reached.
  • In very deep large graphs we may prefer an explicit stack to avoid exceeding the recursion limit.

Glossary

The most important terms in this lesson:

DFS

Depth first search: goes as deep as possible, then returns.

Visited

A vertex we marked so we do not return to it.

Recursion

A function that calls itself.

Call stack

Memory that keeps the open calls in order.

Stack

A last-in, first-out structure.

Parent

The vertex DFS came from to reach the current vertex.

Depth

The number of edges between the root and the vertex.

Entry time

A number given to a vertex the moment we enter it.

Exit time

A number given to a vertex after all its descendants are done.

Reachable

There is a path to it from the starting vertex.

Back edge

An edge to a visited vertex that is not the parent; it shows a cycle.

Lambda

A nameless function written inside another function.
