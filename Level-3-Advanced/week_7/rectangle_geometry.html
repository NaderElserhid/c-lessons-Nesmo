هندسة المستطيلات 📐

التعامل مع المستطيلات المحاذية للمحاور (Axis-Aligned Rectangles) في البرمجة التنافسية

تتعامل هندسة المستطيلات في هذا السياق مع المستطيلات التي تكون أضلاعها موازية (محاذية) لمحاور الإحداثيات $X$ و $Y$. في البرمجة التنافسية، تعتبر هذه الأشكال من أهم المفاهيم الأساسية وتستخدم بكثرة في مسائل التقاطعات والمساحات.

💡 ملحوظة هامة: في نظامنا الإحداثي القياسي، نفترض أن المحور الموجب للسينات $X$ يشير لليمين، والمحور الموجب للصادات $Y$ يشير للأعلى.

1. تمثيل المستطيلات وحساب المساحة

يمكن تمثيل أي مستطيل محاذٍ للمحاور بواسطة نقطتين فقط في المستوى الإحداثي: نقطة الزاوية السفلى اليسرى (Bottom-Left) ونقطة الزاوية العليا اليمنى (Top-Right).

  • إحداثيات النقطة السفلى اليسرى: $(bl\_x, bl\_y)$
  • إحداثيات النقطة العليا اليمنى: $(tr\_x, tr\_y)$

لحساب الأبعاد والمساحة، نستخدم المعادلات التالية:

  • العرض (Width): $tr\_x - bl\_x$
  • الطول/الارتفاع (Height): $tr\_y - bl\_y$
  • المساحة (Area): $\text{Width} \times \text{Height}$
int area(int bl_x, int bl_y, int tr_x, int tr_y) {
  int width = tr_x - bl_x;
  int height = tr_y - bl_y;
  return width * height;
}

2. التحقق من تقاطع مستطيلين (Intersection)

إذا كان لدينا مستطيلان $A$ و $B$، فمتى يتقاطعان؟ لكي يتقاطع المستطيلان، يجب أن يتداخلا في البعدين معاً (في محور $X$ ومحور $Y$).

برمجياً، من الأسهل والأسرع أن نتحقق من متى لا يتقاطعان. لا يتقاطع المستطيلان إذا كان أحدهما يقع بالكامل يمين، يسار، أعلى، أو أسفل الآخر:

  • في محور X: $A$ يقع بالكامل يسار $B$ إذا كان $(a\_tr\_x \le b\_bl\_x)$، أو $A$ يقع يمين $B$ إذا كان $(b\_tr\_x \le a\_bl\_x)$.
  • في محور Y: $A$ يقع بالكامل أسفل $B$ إذا كان $(a\_tr\_y \le b\_bl\_y)$، أو $A$ يقع أعلى $B$ إذا كان $(b\_tr\_y \le a\_bl\_y)$.
bool are_intersected(int a_tr_x, int a_tr_y, int a_bl_x, int a_bl_y, 
                     int b_tr_x, int b_tr_y, int b_bl_x, int b_bl_y) {
  // إذا تحقق أي من شروط الانفصال، فإنهما لا يتقاطعان
  if (a_tr_y <= b_bl_y || b_tr_y <= a_bl_y || a_tr_x <= b_bl_x || b_tr_x <= a_bl_x) {
    return false;
  } else {
    return true;
  }
}

إيجاد مستطيل التقاطع

إذا كانا يتقاطعان، فإن منطقة التقاطع تشكل مستطيلاً جديداً $C$. يمكننا إيجاد إحداثياته عبر أخذ الماكس (Max) لنقاط البداية، والميني (Min) لنقاط النهاية:

  • $c\_bl\_x = \max(a\_bl\_x, b\_bl\_x)$
  • $c\_bl\_y = \max(a\_bl\_y, b\_bl\_y)$
  • $c\_tr\_x = \min(a\_tr\_x, b\_tr\_x)$
  • $c\_tr\_y = \min(a\_tr\_y, b\_tr\_y)$

3. المعادلات أحادية البعد (1D Intervals)

تنطبق أفكار هندسة المستطيلات على البعد الواحد، حيث نتعامل مع مجالات (Intervals) على خط الأعداد بدلاً من المستطيلات في المستوى. يُمثل المجال برقمين: بداية $l$ ونهاية $r$.

  • طول المجال: $r - l$
⚠️ تصحيح برمجي ومنطقي: للتأكد من أن مجالين $[a\_l, a\_r]$ و $[b\_l, b\_r]$ لا يتقاطعان، يجب أن يكون أحدهما بالكامل على يسار أو يمين الآخر. الشرط الصحيح لعدم التقاطع هو b_l >= a_r أو a_l >= b_r. 
bool are_intersected_1d(int a_l, int a_r, int b_l, int b_r) {
  // إذا كانت بداية الثاني بعد نهاية الأول، أو بداية الأول بعد نهاية الثاني
  if (b_l >= a_r || a_l >= b_r) {
    return false; // لا يوجد تقاطع
  } else {
    return true;  // يوجد تقاطع
  }
}

إذا كان المجالين يتقاطعان، فإن منطقة التقاطع هي مجال جديد يبدأ من $\max(a\_l, b\_l)$ وينتهي عند $\min(a\_r, b\_r)$.

4. تطبيق عملي: مسألة USACO (Fence Painting)

في هذه المسألة، لدينا فلاح قام بطلاء سياج خشبي على فترتين (مجالين) $[a\_l, a\_r]$ و $[b\_l, b\_r]$. المطلوب حساب المساحة الإجمالية (Total Length) المغطاة بالطلاء.

طريقة الحل: إذا لم يتقاطع المجالان، فالمساحة هي ببساطة مجموع طول كل مجال. أما إذا تقاطعا، فسنقوم بجمع طوليهما ولكن يجب أن نطرح "منطقة التقاطع" لأننا قمنا بحسابها مرتين!

#include <iostream>
#include <algorithm>
using namespace std;

int main() {
  // توجيه المدخلات والمخرجات لملفات (مطلوب في منصة USACO)
  freopen("paint.in", "r", stdin);
  freopen("paint.out", "w", stdout);
  
  int a_l, a_r, b_l, b_r;    
  cin >> a_l >> a_r >> b_l >> b_r;
  
  // حساب طول كل مجال بشكل منفصل
  int total = (a_r - a_l) + (b_r - b_l);
  
  // حساب إحداثيات منطقة التقاطع المحتملة
  int c_l = max(a_l, b_l);
  int c_r = min(a_r, b_r);
  
  // التحقق من وجود تقاطع: إذا كانت البداية أصغر من النهاية فهناك تداخل
  if (c_l < c_r) {
    int intersection = (c_r - c_l);
    cout << total - intersection << "\n";
  } else {
    // لا يوجد تقاطع، نطبع المجموع الكلي فقط
    cout << total << "\n";
  }
  
  return 0;
}
💡 سر برمجي: لاحظ في الكود أعلاه أننا استخدمنا شرط c_l < c_r للتحقق من التقاطع بدلاً من كتابة الشروط الطويلة. هذه حيلة رياضية أنيقة تعتمد على أنه إذا كانت منطقة التقاطع المحسوبة $(c\_r - c\_l)$ رقمًا موجبًا، إذن فهما يتقاطعان حتماً!
