البرمجة الديناميكية

Dynamic Programming — احفظ الإجابات ولا تحسبها مرتين

ماذا ستتعلم في هذا الدرس؟

  • تفهم لماذا يكرر الحل الذاتي البسيط حساباته، وكيف يعالج الدفتر هذه المشكلة
  • تكتب الحل من الأعلى (دفتر) ومن الأسفل (جدول)
  • تستعمل أسئلة SRTBOT لبناء الحالة والعلاقة والحالات الأساسية والترتيب
  • تحسب زمن الحل من عدد الحالات والعمل لكل حالة
  • تحل مسائل الأفضل (min) ومسائل العدّ (الجمع) وتسترجع الطريق نفسه

لا تحل المسألة نفسها مرتين

تخيل أن المعلم يسألك: «كم يساوي 17 + 25؟» فتحسب وتجيب 42. وبعد دقيقة يعيد عليك السؤال نفسه. هل تحسب من جديد؟ بالطبع لا: تكتب الجواب في ورقة وتنظر إليها. هذه هي فكرة البرمجة الديناميكية (Dynamic Programming) باختصار: احفظ إجابات المسائل الصغيرة حتى لا تحسبها مرتين.

تنفع البرمجة الديناميكية حين يتحقق شرطان: (1) جواب المسألة الكبيرة يُبنى من أجوبة مسائل أصغر منها، و(2) نفس المسائل الصغيرة تتكرر كثيرًا أثناء الحساب. عندها نكتب كل جواب في «دفتر» أو «جدول» ونعود إليه عند الحاجة.

لنبدأ بمثال مشهور: أعداد فيبوناتشي. نعرّفها هكذا: fib(0) = 0 وfib(1) = 1، وبعد ذلك كل عدد هو مجموع العددين قبله: fib(n) = fib(n-1) + fib(n-2). فتكون السلسلة: 0، 1، 1، 2، 3، 5، 8، 13، 21، ...

الحل البطيء: أن تنسى كل شيء

التعريف السابق يكاد يتحول إلى كود حرفيًا. لكن لاحظ كم مرة تُستدعى الدالة عندما نطلب fib(25) فقط:

fib_slow.cpp
#include <iostream>using namespace std; long long calls = 0; long long fib(int n) {    calls++;    if (n < 2) {        return n;    }    return fib(n - 1) + fib(n - 2);} int main() {    cout << fib(25) << endl;    cout << calls << " calls" << endl;    return 0;}
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
75025 242785 calls

الجواب 75025 صحيح، لكننا استدعينا الدالة نحو 243 ألف مرة من أجل رقم صغير كهذا! السبب أن fib(25) يحتاج fib(24) وfib(23)، وfib(24) يحتاج fib(23) مرة أخرى، وهكذا تتكرر الحسابات نفسها آلاف المرات. ويتضخم العمل بسرعة (يتضاعف تقريبًا مرة ونصف مع كل زيادة في n)، وهذا نمو أسّي.

مختبر تفاعلي: شجرة الاستدعاءات المتكررة

اختر n وشاهد شجرة الاستدعاءات. الدوائر الحمراء هي أرقام أعدنا حسابها بعد أن حسبناها سابقًا. ثم فعّل «الدفتر» وانظر كيف تتحول الاستدعاءات المكررة إلى دوائر خضراء نكتفي بقراءة جوابها، فتختفي الأغصان تحتها.

عدد الاستدعاءات: 0 استدعاءات مكررة: 0

التحسين الأول: الدفتر (Memoization)

الحل بسيط: نضيف مصفوفة memo نحفظ فيها كل جواب نحسبه. قبل أن نحسب أي شيء نسأل: هل الجواب موجود؟ هذه الطريقة تسمى من الأعلى إلى الأسفل (top-down) لأننا نبدأ من السؤال الكبير وننزل إلى الصغار، وتسمى أيضًا (memoization). اضغط على الأسطر المضيئة لتقرأ شرحها:

fib_memo.cpp
#include <iostream>#include <vector>using namespace std; vector<long long> memo;long long calls = 0; long long fib(int n) {    calls++;    if (n < 2) {        return n;    }    if (memo[n] != -1) {        return memo[n];    }    memo[n] = fib(n - 1) + fib(n - 2);    return memo[n];} int main() {    int n = 50;    memo.assign(n + 1, -1);    cout << fib(n) << endl;    cout << calls << " calls" << endl;    return 0;}
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
12586269025 99 calls

طلبنا fib(50) وهو رقم ضخم (12,586,269,025) وانتهى البرنامج بـ 99 استدعاءً فقط! بدون الدفتر كان سيحتاج إلى ما يقارب 40 مليار استدعاء. كل رقم من 2 إلى 50 حُسب مرة واحدة، وما عدا ذلك قراءة سريعة من الدفتر. لاحظ أننا استعملنا long long لأن القيمة تتجاوز حدود int (الذي يتسع حتى نحو 2.1 مليار).

التحسين الثاني: الجدول (من الأسفل إلى الأعلى)

بدل أن ننزل من السؤال الكبير بالنداء الذاتي، نبدأ من الأسفل: نملأ الحالات الأساسية، ثم نصعد خانة خانة حتى نبلغ المطلوب. هذه طريقة من الأسفل إلى الأعلى (bottom-up)، ولا تحتاج إلى نداء ذاتي ولا إلى مكدس استدعاءات:

طريقة التفكير: SRTBOT

لا تحتاج أن تحفظ الحلول؛ تحتاج أن تتعلم كيف تفكر. هذه الأسئلة الست تقودك في أي مسألة برمجة ديناميكية، واختصارها SRTBOT:

الحرفالسؤالفي فيبوناتشي
S — الحالة (State)ماذا يعني dp[i] بالضبط؟dp[i] = fib(i)
R — العلاقة (Recurrence)كيف نبني حالة كبيرة من حالات أصغر؟dp[i] = dp[i-1] + dp[i-2]
T — الانتقالات (Transitions)من أي حالات نصل إلى هذه الحالة؟من i-1 ومن i-2
B — الحالات الأساسية (Base cases)ما الحالات التي نعرف جوابها دون حساب؟dp[0] = 0 وdp[1] = 1
O — الترتيب (Order)بأي ترتيب نملأ حتى يكون ما نحتاجه جاهزًا؟من 2 إلى n تصاعديًا
T — التعقيد (Time)كم حالة؟ وكم عمل لكل حالة؟n حالة × عمل ثابت = O(n)

قاعدة التعقيد: الزمن = (عدد الحالات) × (العمل لكل حالة). في فيبوناتشي لدينا n حالة وكل حالة جمع واحد، فالزمن O(n) بدل O(2n).

مسألة جديدة: عبور الأحجار برسوم

على نهر صف من الأحجار المرقمة من 0. أنت تقف على الحجر 0، وتريد أن تصل إلى آخر حجر. في كل مرة تقفز إلى الحجر التالي أو الذي بعده، وتدفع رسم الحجر الذي هبطت عليه (لا رسم على الحجر 0). ما أقل مجموع رسوم للوصول إلى آخر حجر؟

طبّق الأسئلة الست:

الحرفجوابنا
Sdp[i] = أقل رسوم للوصول إلى الحجر i
Rdp[i] = toll[i] + min(dp[i-1], dp[i-2])
Tنصل إلى i من i-1 أو من i-2
Bdp[0] = 0 وdp[1] = toll[1]
Oi من 2 إلى n-1 تصاعديًا
Tn حالة × عمل ثابت = O(n)

ولنرَ أن الدفتر ينفع هنا أيضًا، نقارن الحل الذاتي بدونه ومعه على 25 حجرًا:

toll_compare.cpp
#include <iostream>#include <vector>#include <algorithm>using namespace std; int n = 25;vector<int> toll;vector<int> memo;long long calls = 0; int best(int i, bool useMemo) {    calls++;    if (i == 0) {        return 0;    }    if (i == 1) {        return toll[1];    }    if (useMemo && memo[i] != -1) {        return memo[i];    }    int r = toll[i] + min(best(i - 1, useMemo), best(i - 2, useMemo));    memo[i] = r;    return r;} int main() {    toll.assign(n, 0);    for (int i = 1; i < n; i++) {        toll[i] = (i * 7) % 10 + 1;    }     memo.assign(n, -1);    calls = 0;    int a = best(n - 1, false);    cout << "plain recursion: " << a << " (" << calls << " calls)" << endl;     memo.assign(n, -1);    calls = 0;    int b = best(n - 1, true);    cout << "with memo:       " << b << " (" << calls << " calls)" << endl;    return 0;}

مختبر تفاعلي: املأ الجدول بنفسك

غيّر رسوم الأحجار كما تشاء، ثم اضغط «الخطوة التالية» لملء الجدول خانة خانة. سترى القيمتين اللتين يختار البرنامج الأصغر بينهما. بعد اكتمال الجدول اضغط «أظهر الطريق» لتعرف أي أحجار مرّ عليها الحل الأرخص.

نكهة أخرى: العدّ بدل الاختيار الأفضل

بدل أن نسأل «ما أرخص طريق؟» نسأل «كم طريقًا يوجد؟». التغيير في العلاقة صغير جدًا: نستعمل الجمع بدل min. مثال: كم طريقة لصعود سلم من n درجة إذا كانت كل خطوة تصعد 1 أو 2 أو 3 درجات؟

count_ways.cpp
int n = 10;vector<long long> ways(n + 1, 0);ways[0] = 1;for (int i = 1; i <= n; i++) {    for (int step = 1; step <= 3; step++) {        if (i - step >= 0) {            ways[i] += ways[i - step];        }    }}for (int i = 0; i <= n; i++) {    cout << ways[i] << " ";}cout << endl;
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
1 1 2 4 7 13 24 44 81 149 274

الجدول يقول إن لـ 10 درجات توجد 274 طريقة. وراجع الحالة الأساسية: ways[0] = 1، أي طريقة واحدة للبقاء في الأسفل. لو وضعناها صفرًا لصار كل جدول بأصفار.

حين نعدّ الطرق تكبر الأرقام بسرعة هائلة. لذلك استعملنا long long، وفي كثير من المسائل يطلب النص أن تطبع الجواب «باقي القسمة على عدد معين» حتى لا يطغى حجم الأرقام.

أخطاء شائعة وكيف تتجنبها

الخطأالعلاج

كيف أعرف أن المسألة تحتاج إلى برمجة ديناميكية؟ اسأل: هل أستطيع أن أصف الحل بمعادلة تعتمد على حلول أصغر؟ هل أكتب حلًا ذاتيًا بطيئًا يكرر حسابات؟ فإن كانت الإجابة نعم فالدفتر أو الجدول هما الحل.

مشروع الدرس: أرخص طريق عبر النهر

نجد أقل رسوم، ونطبع الأحجار التي نقفز عليها.

الفكرة

أكمل مسألة الأحجار: لا يكفي أن تعرف أقل رسوم، بل تريد أن تعرف الطريق نفسه. الحيلة أن نسجل في كل حجر «من أي حجر أتينا إلى هنا في أرخص طريق»، ثم نمشي إلى الوراء من آخر حجر حتى البداية ونعكس القائمة.

المطلوب منك
  1. اقرأ n ثم رسوم الأحجار (رسم الحجر 0 صفر).
  2. املأ dp كما في الدرس، وسجّل في المصفوفة from[i] أي الحجرين (i-1 أو i-2) كان الأرخص. عند التساوي اختر i-1.
  3. ابدأ من آخر حجر وتتبّع from إلى الخلف، ثم اعكس القائمة.
  4. اطبع Minimum toll: ثم الرسوم، وبعده سطرًا يبدأ بـ Path: وبعده أرقام الأحجار بالترتيب.
مثالان على التشغيل

التشغيل الأول:

7 0 3 8 2 6 4 1
Minimum toll: 10 Path: 0 1 3 5 6

التشغيل الثاني (حجران فقط):

2 0 5
Minimum toll: 5 Path: 0 1

تحقق ذهنيًا: في التشغيل الأول الطريق 0 → 1 → 3 → 5 → 6 يدفع 3 + 2 + 4 + 1 = 10. أما الطريق 0 → 2 → 4 → 6 فيدفع 8 + 6 + 1 = 15، وهو أغلى.

بعد أن تجرّب بنفسك: اعرض الحل
toll_path.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> toll(n);
    for (int i = 0; i < n; i++) {
        cin >> toll[i];
    }

    vector<int> dp(n, 0), from(n, -1);
    if (n > 1) {
        dp[1] = toll[1];
        from[1] = 0;
    }
    for (int i = 2; i < n; i++) {
        if (dp[i - 1] <= dp[i - 2]) {
            from[i] = i - 1;
        } else {
            from[i] = i - 2;
        }
        dp[i] = toll[i] + dp[from[i]];
    }

    vector<int> path;
    for (int at = n - 1; at != -1; at = from[at]) {
        path.push_back(at);
    }
    reverse(path.begin(), path.end());

    cout << "Minimum toll: " << dp[n - 1] << endl;
    cout << "Path:";
    for (int stone : path) {
        cout << " " << stone;
    }
    cout << endl;
    return 0;
}

أقل عدد من العملات

متوسط

لديك k فئات من العملات (يمكنك استعمال كل فئة أي عدد من المرات). اقرأ k وamount ثم قيم الفئات. اطبع أقل عدد من العملات مجموعها amount بالضبط، أو -1 إن كان ذلك مستحيلًا.

المطلوب
  • عرّف dp[x] = أقل عدد من العملات لتكوين المبلغ x.
  • الحالة الأساسية dp[0] = 0، وباقي الخانات تبدأ بقيمة كبيرة جدًا (غير ممكن).
  • لكل مبلغ x جرّب كل فئة c لا تتجاوز x، وحدّث dp[x] = min(dp[x], dp[x - c] + 1).
  • اطبع dp[amount] أو -1.
مثال على الإدخال والناتج المتوقع
3 11 1 5 7
3
تلميحات
  • انتبه ألا تستعمل dp[x - c] إذا كانت قيمته «غير ممكن»، وإلا أضفت 1 إلى قيمة كبيرة.
  • في المثال (الفئات 1 و5 و7 والمبلغ 11) أفضل حل هو 5 + 5 + 1، أي 3 عملات.
نموذج الحل (بعد المحاولة)
fewest_coins.cpp
// Challenge 1: the fewest coins
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int k, amount;
    cin >> k >> amount;
    vector<int> coin(k);
    for (int i = 0; i < k; i++) {
        cin >> coin[i];
    }

    const int INF = 1000000000;
    vector<int> dp(amount + 1, INF);
    dp[0] = 0;
    for (int x = 1; x <= amount; x++) {
        for (int c : coin) {
            if (c <= x && dp[x - c] != INF) {
                dp[x] = min(dp[x], dp[x - c] + 1);
            }
        }
    }

    if (dp[amount] == INF) {
        cout << -1 << endl;
    } else {
        cout << dp[amount] << endl;
    }
    return 0;
}

نموذج الحل (بعد المحاولة)
tiling.cpp
// Challenge 2: tiling a 2 x n strip
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> ways(n + 1, 0);
    ways[0] = 1;
    ways[1] = 1;
    for (int i = 2; i <= n; i++) {
        ways[i] = ways[i - 1] + ways[i - 2];
    }
    cout << ways[n] << endl;
    return 0;
}

ملخص سريع

  • البرمجة الديناميكية تحفظ إجابات المسائل الصغيرة حتى لا تحسبها مرتين.
  • تنفع حين يُبنى الجواب من أجوبة أصغر وتتكرر المسائل الصغيرة نفسها.
  • من الأعلى (دفتر): دالة ذاتية تحفظ النتيجة وتقرأها إن وُجدت. من الأسفل (جدول): حلقة تملأ الخانات بالترتيب.
  • اسأل SRTBOT: الحالة، العلاقة، الانتقالات، الحالات الأساسية، الترتيب، التعقيد.
  • زمن الحل = عدد الحالات × العمل لكل حالة.
  • نبدّل min بـ + لتتحول مسألة «الأفضل» إلى مسألة «العدّ».
  • لاسترجاع الطريق نحفظ مع كل خانة مصدرها ثم نمشي إلى الخلف.

قاموس المصطلحات

المصطلحات الإنجليزية الأهم في هذا الدرس ومقابلها بالعربية:

Dynamic programmingبرمجة ديناميكية

حل مسألة كبيرة بحفظ أجوبة المسائل الصغيرة وإعادة استعمالها.

Subproblemمسألة جزئية

نسخة أصغر من المسألة يُبنى منها الجواب.

Stateحالة

وصف مسألة جزئية واحدة، مثل dp[i].

Recurrenceعلاقة تكرار

معادلة تعرّف جواب حالة بدلالة حالات أصغر.

Base caseحالة أساسية

حالة نعرف جوابها دون حساب.

Memoizationحفظ النتائج

تخزين الجواب بعد أول حساب وقراءته لاحقًا.

Top-downمن الأعلى

نبدأ من المسألة الكبيرة وننزل بنداء ذاتي مع الدفتر.

Bottom-upمن الأسفل

نملأ الجدول من الحالات الصغيرة إلى المطلوبة.

Overlapping subproblemsمسائل متداخلة

مسائل جزئية تتكرر نفسها أثناء الحل.

Transitionانتقال

الانتقال من حالة إلى حالة أخرى في العلاقة.

Tableجدول

المصفوفة التي تحفظ أجوبة الحالات.

Fibonacciفيبوناتشي

سلسلة كل عدد فيها مجموع العددين قبله.

عشرة أسئلة بين السهلة والمتوسطة. اختر إجابة واحدة لكل سؤال.
