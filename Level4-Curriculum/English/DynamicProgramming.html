Dynamic Programming

Save the answers and never compute them twice

What will you learn in this lesson?

  • Understand why simple recursion repeats its work, and how a notebook fixes that
  • Write the top-down (notebook) and the bottom-up (table) solutions
  • Use the SRTBOT questions to build the state, recurrence, base cases and order
  • Compute the time of a solution from the number of states and the work per state
  • Solve "best" problems (min) and counting problems (addition), and recover the route itself

Do not solve the same thing twice

Imagine the teacher asks you: "What is 17 + 25?" You work it out and answer 42. A minute later the teacher asks the very same question. Do you calculate again? Of course not: you wrote the answer on a sheet of paper and you look at it. That is the idea of Dynamic Programming in a nutshell: save the answers to small problems so you never compute them twice.

Dynamic programming works when two conditions hold: (1) the answer to the big problem is built from answers to smaller problems, and (2) the same small problems keep repeating while we compute. Then we write each answer in a "notebook" or a "table" and come back to it when needed.

Let us start with a famous example: the Fibonacci numbers. We define them like this: fib(0) = 0 and fib(1) = 1, and after that each number is the sum of the two before it: fib(n) = fib(n-1) + fib(n-2). So the sequence is 0, 1, 1, 2, 3, 5, 8, 13, 21, ...

The slow solution: forgetting everything

The definition above turns into code almost word for word. But look how many times the function is called when we ask for fib(25) only:

fib_slow.cpp
#include <iostream>using namespace std; long long calls = 0; long long fib(int n) {    calls++;    if (n < 2) {        return n;    }    return fib(n - 1) + fib(n - 2);} int main() {    cout << fib(25) << endl;    cout << calls << " calls" << endl;    return 0;}
Click any highlighted line of code to read its explanation here...
75025 242785 calls

The answer 75025 is correct, but we called the function about 243 thousand times for such a small number! The reason: fib(25) needs fib(24) and fib(23), and fib(24) needs fib(23) again, and so the same computations repeat thousands of times. The work blows up fast (it multiplies by about one and a half with every increase in n), which is exponential growth.

The first improvement: the notebook (memoization)

The fix is simple: we add an array memo in which we save every answer we compute. Before computing anything we ask: is the answer already there? This approach is called top-down because we start from the big question and go down to the small ones, and it is also called memoization. Click the highlighted lines to read their explanations:

fib_memo.cpp
#include <iostream>#include <vector>using namespace std; vector<long long> memo;long long calls = 0; long long fib(int n) {    calls++;    if (n < 2) {        return n;    }    if (memo[n] != -1) {        return memo[n];    }    memo[n] = fib(n - 1) + fib(n - 2);    return memo[n];} int main() {    int n = 50;    memo.assign(n + 1, -1);    cout << fib(n) << endl;    cout << calls << " calls" << endl;    return 0;}
Click any highlighted line of code to read its explanation here...
12586269025 99 calls

We asked for fib(50), a huge number (12,586,269,025), and the program finished with only 99 calls! Without the notebook it would have needed about 40 billion calls. Every number from 2 to 50 was computed once, and everything else was a quick read from the notebook. Notice that we used long long, because the value exceeds the range of int (which holds up to about 2.1 billion).

The second improvement: the table (bottom-up)

Instead of going down from the big question with recursion, we start from the bottom: we fill in the base cases, then climb cell by cell until we reach what we want. This is the bottom-up way, and it needs no recursion and no call stack:

fib_table.cpp
int n = 10;vector<long long> dp(n + 1);dp[0] = 0;dp[1] = 1;for (int i = 2; i <= n; i++) {    dp[i] = dp[i - 1] + dp[i - 2];}for (int i = 0; i <= n; i++) {    cout << dp[i] << " ";}cout << endl;

The way of thinking: SRTBOT

You do not need to memorize solutions; you need to learn how to think. These six questions guide you through any dynamic programming problem, and their acronym is SRTBOT:

LetterThe questionIn Fibonacci
S — StateWhat exactly does dp[i] mean?dp[i] = fib(i)
R — RecurrenceHow do we build a big state from smaller ones?dp[i] = dp[i-1] + dp[i-2]
T — TransitionsFrom which states do we arrive at this state?from i-1 and from i-2
B — Base casesWhich states do we answer without computing?dp[0] = 0 and dp[1] = 1
O — OrderIn which order do we fill so that what we need is ready?from 2 to n, ascending
T — TimeHow many states? How much work per state?n states × constant work = O(n)

The complexity rule: time = (number of states) × (work per state). In Fibonacci we have n states and each one is a single addition, so the time is O(n) instead of O(2n).

A new problem: crossing stones with tolls

On a river there is a row of stones numbered from 0. You stand on stone 0 and want to reach the last stone. Each time you jump to the next stone or to the one after it, and you pay the toll of the stone you land on (stone 0 has no toll). What is the smallest total toll to reach the last stone?

Apply the six questions:

LetterOur answer
Sdp[i] = the smallest toll to reach stone i
Rdp[i] = toll[i] + min(dp[i-1], dp[i-2])
Twe reach i from i-1 or from i-2
Bdp[0] = 0 and dp[1] = toll[1]
Oi from 2 to n-1, ascending
Tn states × constant work = O(n)

To see that the notebook helps here too, we compare the plain recursive solution with and without it on 25 stones:

toll_compare.cpp
#include <iostream>#include <vector>#include <algorithm>using namespace std; int n = 25;vector<int> toll;vector<int> memo;long long calls = 0; int best(int i, bool useMemo) {    calls++;    if (i == 0) {        return 0;    }    if (i == 1) {        return toll[1];    }    if (useMemo && memo[i] != -1) {        return memo[i];    }    int r = toll[i] + min(best(i - 1, useMemo), best(i - 2, useMemo));    memo[i] = r;    return r;} int main() {    toll.assign(n, 0);    for (int i = 1; i < n; i++) {        toll[i] = (i * 7) % 10 + 1;    }     memo.assign(n, -1);    calls = 0;    int a = best(n - 1, false);    cout << "plain recursion: " << a << " (" << calls << " calls)" << endl;     memo.assign(n, -1);    calls = 0;    int b = best(n - 1, true);    cout << "with memo:       " << b << " (" << calls << " calls)" << endl;    return 0;}

Another flavor: counting instead of choosing the best

Instead of asking "what is the cheapest route?" we ask "how many routes are there?". The change in the relation is tiny: we use addition instead of min. Example: how many ways are there to climb a staircase of n steps if each move climbs 1, 2 or 3 steps?

count_ways.cpp
int n = 10;vector<long long> ways(n + 1, 0);ways[0] = 1;for (int i = 1; i <= n; i++) {    for (int step = 1; step <= 3; step++) {        if (i - step >= 0) {            ways[i] += ways[i - step];        }    }}for (int i = 0; i <= n; i++) {    cout << ways[i] << " ";}cout << endl;
Click any highlighted line of code to read its explanation here...
1 1 2 4 7 13 24 44 81 149 274

The table says that for 10 steps there are 274 ways. And check the base case: ways[0] = 1, one way to stay at the bottom. If we set it to zero, the whole table would be zeros.

When we count ways, the numbers grow enormously fast. That is why we used long long, and in many problems the statement asks you to print the answer "modulo some number" so that the size of the numbers does not explode.

Common mistakes and how to avoid them

The mistakeThe remedy
A missing or wrong base case (such as forgetting dp[0])Write the base cases first and test them by hand on the smallest input
A wrong filling order (reading a cell that is not filled yet)Make sure everything a cell depends on comes before it in the loop
Forgetting to initialize the notebook with -1 or another "not computed" valueChoose a value that cannot be a real answer
Overflowing int when countingUse long long or a modulus
Mixing up the meaning of dp[i] while writingWrite the definition of the state as a comment above the array

How do I know a problem needs dynamic programming? Ask: can I describe the solution with an equation that depends on smaller solutions? Can I write a slow recursive solution that repeats computations? If the answer is yes, then a notebook or a table is the way.

Lesson project: the cheapest path across the river

We find the smallest toll, and print the stones we jump on.

The idea

Complete the stones problem: knowing the smallest toll is not enough, you want to know the route itself. The trick is to record at every stone "which stone we came from in the cheapest route to here", then walk backwards from the last stone to the start and reverse the list.

What you need to do
  1. Read n and then the tolls of the stones (the toll of stone 0 is zero).
  2. Fill dp as in the lesson, and record in the array from[i] which of the two stones (i-1 or i-2) was the cheaper. In a tie choose i-1.
  3. Start at the last stone and follow from backwards, then reverse the list.
  4. Print Minimum toll: and the toll, and after it a line that starts with Path: followed by the stone numbers in order.
Two sample runs

First run:

7 0 3 8 2 6 4 1
Minimum toll: 10 Path: 0 1 3 5 6

Second run (only two stones):

2 0 5
Minimum toll: 5 Path: 0 1

Check it in your head: in the first run the route 0 → 1 → 3 → 5 → 6 pays 3 + 2 + 4 + 1 = 10. The route 0 → 2 → 4 → 6 pays 8 + 6 + 1 = 15, which is more expensive.

After you try it yourself: show the solution
toll_path.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> toll(n);
    for (int i = 0; i < n; i++) {
        cin >> toll[i];
    }

    vector<int> dp(n, 0), from(n, -1);
    if (n > 1) {
        dp[1] = toll[1];
        from[1] = 0;
    }
    for (int i = 2; i < n; i++) {
        if (dp[i - 1] <= dp[i - 2]) {
            from[i] = i - 1;
        } else {
            from[i] = i - 2;
        }
        dp[i] = toll[i] + dp[from[i]];
    }

    vector<int> path;
    for (int at = n - 1; at != -1; at = from[at]) {
        path.push_back(at);
    }
    reverse(path.begin(), path.end());

    cout << "Minimum toll: " << dp[n - 1] << endl;
    cout << "Path:";
    for (int stone : path) {
        cout << " " << stone;
    }
    cout << endl;
    return 0;
}

1

The fewest coins

Medium

You have k coin denominations (you may use each denomination any number of times). Read k and amount, then the denominations. Print the smallest number of coins whose total is exactly amount, or -1 if that is impossible.

Requirements
  • Define dp[x] = the fewest coins to make the amount x.
  • The base case is dp[0] = 0, and all other cells start with a very large value (impossible).
  • For every amount x try every denomination c that does not exceed x, and update dp[x] = min(dp[x], dp[x - c] + 1).
  • Print dp[amount] or -1.
Example input and expected output
3 11 1 5 7
3
Hints
  • Be careful not to use dp[x - c] when its value is "impossible", or you would add 1 to a huge value.
  • In the example (denominations 1, 5 and 7 and the amount 11) the best solution is 5 + 5 + 1, which is 3 coins.
Sample solution (after you try)
fewest_coins.cpp
// Challenge 1: the fewest coins
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int k, amount;
    cin >> k >> amount;
    vector<int> coin(k);
    for (int i = 0; i < k; i++) {
        cin >> coin[i];
    }

    const int INF = 1000000000;
    vector<int> dp(amount + 1, INF);
    dp[0] = 0;
    for (int x = 1; x <= amount; x++) {
        for (int c : coin) {
            if (c <= x && dp[x - c] != INF) {
                dp[x] = min(dp[x], dp[x - c] + 1);
            }
        }
    }

    if (dp[amount] == INF) {
        cout << -1 << endl;
    } else {
        cout << dp[amount] << endl;
    }
    return 0;
}
2

Tiling a strip with dominoes

Easy

A strip has width 2 and length n (up to 60). You have 1 × 2 dominoes that can be placed horizontally or vertically. In how many ways can the strip be covered completely, with no gaps and no overlaps?

Requirements
  • Think about the last column: either one vertical domino covers it, leaving n-1, or two horizontal dominoes cover the last two columns, leaving n-2.
  • Write the recurrence and its two base cases (n = 0 and n = 1).
  • Use long long.
  • Print the number.
Example input and expected output
5
8
Hints
  • You will find that the relation is the Fibonacci relation again.
  • With n = 5 the answer is 8.
Sample solution (after you try)
tiling.cpp
// Challenge 2: tiling a 2 x n strip
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> ways(n + 1, 0);
    ways[0] = 1;
    ways[1] = 1;
    for (int i = 2; i <= n; i++) {
        ways[i] = ways[i - 1] + ways[i - 2];
    }
    cout << ways[n] << endl;
    return 0;
}

Quick summary

  • Dynamic programming saves the answers of small problems so they are never computed twice.
  • It works when the answer is built from smaller answers and the same small problems repeat.
  • Top-down (notebook): a recursive function that saves its result and reads it if it exists. Bottom-up (table): a loop that fills the cells in order.
  • Ask SRTBOT: state, recurrence, transitions, base cases, order, time.
  • Time of the solution = number of states × work per state.
  • Replace min by + and a "best" problem becomes a "counting" problem.
  • To recover the route we store the source of every cell and walk backwards.

Glossary

The most important terms in this lesson:

Dynamic programming

Solving a big problem by saving the answers of small problems and reusing them.

Subproblem

A smaller version of the problem from which the answer is built.

State

The description of one subproblem, such as dp[i].

Recurrence

An equation that defines the answer of a state using smaller states.

Base case

A state whose answer we know without computing.

Memoization

Storing the answer after the first computation and reading it later.

Top-down

We start from the big problem and go down with recursion and a notebook.

Bottom-up

We fill the table from the small states up to the one we need.

Overlapping subproblems

Subproblems that repeat while solving.

Transition

The move from one state to another in the recurrence.

Table

The array that stores the answers of the states.

Fibonacci

A sequence where each number is the sum of the two before it.
