Number Theory

The greatest common divisor (GCD) and the least common multiple (LCM)

What will you learn in this lesson?

  • Understand the gcd and lcm with examples from everyday life
  • Write Euclid's algorithm and understand why it is fast
  • Use the ready-made gcd and lcm and compute the lcm without overflow
  • Apply the two tools to fractions, periodic events and tiling
  • Extend the idea to more than two numbers with a running result

Fair sharing and a repeating meeting

You have 12 chocolates and 18 biscuits, and you want to make identical bags, each with the same number of chocolates and the same number of biscuits, with nothing left over. What is the largest number of bags you can make? The answer is 6 bags (each with two chocolates and three biscuits). The number 6 is the GCD, the greatest common divisor of 12 and 18.

In another example, two lights blink: the first every 4 seconds and the second every 6 seconds, and they just blinked together. When will they blink together again? After 12 seconds, the smallest number divisible by both 4 and 6. That is the LCM, the least common multiple.

Number theory is a big name for a simple game: playing with whole numbers, division and remainders. The gcd answers "what is the largest thing that divides both?", and the lcm answers "where do their multiples first meet?".

The naive way and its cost

The simplest way to find the gcd is to try every number from 1 up to the smaller of the two numbers, and keep the last number that divided both:

gcd_brute.cpp
#include <iostream>#include <algorithm>using namespace std; int main() {    int a = 36, b = 60;    int tries = 0;    int best = 1;    for (int d = 1; d <= min(a, b); d++) {        tries++;        if (a % d == 0 && b % d == 0) {            best = d;        }    }    cout << "gcd = " << best << " after " << tries << " tries" << endl;    return 0;}

gcd = 12 after 36 tries

The method is correct, but it needs as many tries as the smaller number. For small numbers there is no problem, but if the two numbers are around a billion we would try a billion numbers! We need a smarter idea.

Euclid's algorithm: a trick over two thousand years old

Euclid noticed that any number that divides both a and b also divides a - b (and so, by repeated subtraction, a % b). That is, the common divisors do not change when we replace the larger number with its remainder after dividing by the smaller:

gcd(a, b) = gcd(b, a % b), and when the second becomes zero the first is the answer: gcd(a, 0) = a.

euclid.cpp
#include <iostream>using namespace std; int gcd2(int a, int b) {    cout << "gcd(" << a << ", " << b << ")" << endl;    if (b == 0) {        return a;    }    return gcd2(b, a % b);} int main() {    int g = gcd2(252, 105);    cout << "answer " << g << endl;    return 0;}
Click any highlighted line of code to read its explanation here...
gcd(252, 105) gcd(105, 42) gcd(42, 21) gcd(21, 0) answer 21

See how fast the numbers collapsed: from 252 and 105 to 105 and 42, then 42 and 21, then 21 and 0. Only four steps. And the best part is that the number of steps stays small even for huge numbers:

euclid_steps.cpp
long long pairs[3][2] = {{832040, 514229}, {1000000000, 640000000}, {1000000000, 1}};for (auto& p : pairs) {    long long a = p[0], b = p[1];    int steps = 0;    while (b != 0) {        a %= b;        swap(a, b);        steps++;    }    cout << p[0] << " and " << p[1] << ": steps = " << steps << endl;}
Click any highlighted line of code to read its explanation here...
832040 and 514229: steps = 28 1000000000 and 640000000: steps = 5 1000000000 and 1: steps = 1

With two numbers near a billion we needed only a few steps. The worst case is consecutive Fibonacci numbers (like the first case: 28 steps), and even there the number of steps is about log n. That is why we say the algorithm runs in O(log min(a, b)).

Interactive lab (1): Euclid with squares

There is a beautiful geometric picture of Euclid: take a rectangle of length a and width b and cut out as many squares as possible whose side is the shorter side. A smaller strip remains, so cut squares from it the same way, and repeat until nothing is left. The side of the last square is the gcd! Type two numbers (up to 99) and press "Next step".

The ready-made gcd and lcm

Normally we do not need to write Euclid ourselves: since C++17 the functions gcd and lcm exist in the header <numeric>. (In old compilers use __gcd(a, b), which provides only the gcd.)

builtin_gcd.cpp
#include <iostream>#include <numeric>using namespace std; int main() {    cout << gcd(84, 36) << endl;    cout << lcm(4, 6) << endl;    cout << gcd(0, 5) << endl;    cout << gcd(17, 5) << endl;    return 0;}

Watch out for the types of the numbers: if you pass an int together with a long long to gcd, the program may not compile or may give an unexpected type. Make both types identical, and prefer long long when the numbers are large.

The lcm and its relation to the gcd

We do not need a loop to find the least common multiple: the gcd is enough, because gcd(a, b) × lcm(a, b) = a × b. From it:

lcm(a, b) = a / gcd(a, b) * b — we divide first and then multiply, so the intermediate result does not grow and exceed the type's limit.

lcm_demo.cpp
#include <iostream>#include <numeric>using namespace std; long long lcm2(long long a, long long b) {    return a / gcd(a, b) * b;} int main() {    long long all = 1;    for (int k = 1; k <= 10; k++) {        all = lcm2(all, k);    }    cout << "lcm of 1..10 = " << all << endl;    cout << "gcd * lcm = " << gcd(12, 18) * lcm2(12, 18) << ", a * b = " << 12 * 18 << endl;    cout << "lights meet after " << lcm2(lcm2(12, 15), 20) << " seconds" << endl;    return 0;}
Click any highlighted line of code to read its explanation here...
lcm of 1..10 = 2520 gcd * lcm = 216, a * b = 216 lights meet after 60 seconds

For three or more numbers we apply the function to the running result: lcm(lcm(12, 15), 20) = lcm(60, 20) = 60. The same goes for the gcd: gcd(a, b, c) = gcd(gcd(a, b), c).

Uses in life and in contests

The two most famous uses are reducing fractions (divide the numerator and denominator by the gcd) and adding fractions (use the lcm of the denominators):

Lesson project: floor tiles

We choose the largest square tile that covers the floor with no cutting.

The idea

The school will tile the floor of a rectangular hall with identical square tiles. You want the largest tile possible that covers the whole floor without cutting any tile, and then you want to know how many tiles are needed.

What you need to do
  1. Read the width and length of the hall (whole numbers in centimeters).
  2. The side of the largest square that fills the rectangle with no remainder is the gcd of the two dimensions.
  3. The number of tiles = (width ÷ side) × (length ÷ side).
  4. Print Tile side: and the side, and on a second line Tiles: and the count.
Two sample runs

First run:

360 240
Tile side: 120 Tiles: 6

Second run (two coprime dimensions):

7 13
Tile side: 1 Tiles: 91

Check it in your head: 360 and 240 are both divisible by 120, so a 120 × 120 tile covers the floor with three tiles along the length (360÷120) and two along the width (240÷120), which is 6 tiles. But 7 and 13 are divisible only by 1, so the tile is 1 × 1 and there are 91 of them.

After you try it yourself: show the solution
tiles.cpp
#include <iostream>
#include <numeric>
using namespace std;

int main() {
    long long width, length;
    cin >> width >> length;

    long long side = gcd(width, length);
    long long tiles = (width / side) * (length / side);

    cout << "Tile side: " << side << endl;
    cout << "Tiles: " << tiles << endl;
    return 0;
}

1

Adding two fractions

Medium

Read two fractions p1/q1 and p2/q2 (positive numbers, denominators up to 1000). Print their sum reduced, in the form numerator/denominator.

Requirements
  • Compute the smallest common denominator as the lcm of the two denominators.
  • Convert each numerator to the new denominator and add them.
  • Reduce the result by dividing by the gcd of the numerator and denominator.
  • Print the resulting fraction.
Example input and expected output
1 6 3 10
7/15
Hints
  • Use long long to be safe from overflow.
  • With the example 1/6 + 3/10 the denominator is 30 and the numerator is 5 + 9 = 14, so the result is 14/30 = 7/15.
Sample solution (after you try)
add_fractions.cpp
// Challenge 1: add two fractions
#include <iostream>
#include <numeric>
using namespace std;

int main() {
    long long p1, q1, p2, q2;
    cin >> p1 >> q1 >> p2 >> q2;

    long long den = lcm(q1, q2);
    long long num = p1 * (den / q1) + p2 * (den / q2);
    long long g = gcd(num, den);

    cout << num / g << "/" << den / g << endl;
    return 0;
}
2

The alarms

Medium

You set n alarms (up to 10); the cycle of each alarm is p minutes (from 1 to 100). They all rang together just now. After how many minutes will they all ring together again?

Requirements
  • Read n and then the cycles.
  • Keep a running result that starts at 1, and update it with each cycle using the lcm.
  • Use the formula that divides before multiplying.
  • Print the result.
Example input and expected output
3 12 15 20
60
Hints
  • The answer may exceed int, so use long long.
  • With the example (12, 15 and 20) the answer is 60.
Sample solution (after you try)
alarms.cpp
// Challenge 2: when do all the alarms ring together?
#include <iostream>
#include <numeric>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long all = 1;
    for (int i = 0; i < n; i++) {
        long long period;
        cin >> period;
        all = all / gcd(all, period) * period;
    }
    cout << all << endl;
    return 0;
}

Quick summary

  • The gcd gcd(a, b) is the largest number dividing both numbers, and the lcm lcm(a, b) is the smallest number divisible by both.
  • The naive way tries every number, and its cost is the size of the smaller number.
  • Euclid's rule: gcd(a, b) = gcd(b, a % b) and gcd(a, 0) = a, and its time is O(log n).
  • Since C++17 gcd and lcm are available in <numeric> (before that, __gcd).
  • lcm(a, b) = a / gcd(a, b) * b: we divide first so the intermediate result does not exceed the limit.
  • gcd(a, b) × lcm(a, b) = a × b.
  • For several numbers we apply the function to the running result.

Glossary

The most important terms in this lesson:

GCD

The largest number that divides two numbers with no remainder.

LCM

The smallest positive number divisible by both numbers.

Divisor

A number that divides another number with no remainder.

Multiple

The product of a number with any whole number.

Remainder

What is left after division, computed with the operator %.

Euclidean algorithm

A fast method for the gcd based on the remainder.

Coprime

Two numbers whose greatest common divisor is 1.

Number theory

The study of the properties of whole numbers.

Overflow

A result larger than the largest value the type can hold.

Fraction

A numerator over a denominator.

Common denominator

One denominator for two fractions; the smallest is the lcm.

Running result

A result we update with every new element.
