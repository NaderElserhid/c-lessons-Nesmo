Sieve of Eratosthenes

All the primes at once

What will you learn in this lesson?

  • Understand the idea of the sieve: crossing out the multiples of every prime
  • Write the sieve with vector<bool> and explain why we start from i * i
  • Compare its cost with trial division and know that it is O(N log log N)
  • Use prefix sums to answer how many primes are in any range
  • Know when the sieve fits and when to prefer trial division

A sieve for sorting numbers

Imagine you want a list of all the primes up to a million, or you will be asked a thousand times "is this number prime?". We saw that testing one number takes up to √n tries, so if we test every number one after another we waste a lot of time on repeated work.

Eratosthenes invented a smarter trick more than two thousand years ago: we do not ask every number "are you prime?". Instead we take the smallest number that is not crossed out and cross out all its multiples in one go. What remains uncrossed is the primes. The method is called the Sieve because it lets the unwanted numbers fall through and keeps the primes, like a sieve that keeps the big pebbles.

Write the numbers from 2 to 30. The number 2 is not crossed out, so it is prime: cross out all its multiples, 4, 6, 8... The number 3 is not crossed out, so it is prime: cross out its multiples, 9, 12, 15... The number 4 is crossed out, so skip it. The number 5 is prime, so cross out 25... and so on. Whatever is left untouched at the end is prime.

From paper to code

We represent "crossed out / not crossed out" with an array of true or false. This is the complete function, and we will test it on small numbers and on a million:

sieve.cpp
#include <iostream>#include <vector>using namespace std; vector<bool> sieve(int n) {    vector<bool> is_prime(n + 1, true);    is_prime[0] = false;    if (n >= 1) {        is_prime[1] = false;    }    for (int i = 2; i * i <= n; i++) {        if (is_prime[i]) {            for (int j = i * i; j <= n; j += i) {                is_prime[j] = false;            }        }    }    return is_prime;} int main() {    vector<bool> p = sieve(50);    cout << "primes up to 50:";    for (int i = 2; i <= 50; i++) {        if (p[i]) {            cout << " " << i;        }    }    cout << endl;     vector<bool> big = sieve(1000000);    int count = 0;    for (int i = 2; i <= 1000000; i++) {        if (big[i]) {            count++;        }    }    cout << "primes up to one million: " << count << endl;    return 0;}

In a fraction of a second the computer found that between 1 and a million there are 78498 primes.

Why j = i * i ? The multiple 2i was crossed out by 2, the multiple 3i was crossed out by 3, and so on: every multiple k × i with k < i was crossed out by a smaller prime from the start. The first truly new multiple is i × i. And since the outer loop stops when i * i > n, every composite number has been crossed out before that.

Common mistakes: forgetting to set 0 and 1 to false, reserving an array of size n instead of n + 1 (so cell n does not exist), and asking for a huge limit (memory is limited: ten million bool cells fit in ten megabytes, but a billion does not).

How much do we really gain?

Let us count the work precisely for N = 100000: the trial-division tests for every number, against the crossing operations of the sieve, once starting from 2i and once starting from i * i:

sieve_cost.cpp
const int N = 100000; long long trial = 0;for (int n = 2; n <= N; n++) {    for (int d = 2; d * d <= n; d++) {        trial++;        if (n % d == 0) {            break;        }    }} vector<bool> a(N + 1, true);long long from2i = 0;for (int i = 2; i <= N; i++) {    if (a[i]) {        for (int j = 2 * i; j <= N; j += i) {            a[j] = false;            from2i++;        }    }} vector<bool> b(N + 1, true);long long fromSq = 0;for (int i = 2; i * i <= N; i++) {    if (b[i]) {        for (int j = i * i; j <= N; j += i) {            b[j] = false;            fromSq++;        }    }} cout << "trial division tests: " << trial << endl;cout << "sieve, start at 2i:   " << from2i << endl;cout << "sieve, start at i*i:  " << fromSq << endl;
Click any highlighted line of code to read its explanation here...
trial division tests: 2745694 sieve, start at 2i: 256808 sieve, start at i*i: 193078

The sieve is more than ten times faster here, and the gap grows as N grows. Starting at i * i instead of 2i saves about a quarter of the crossings (193 thousand instead of 257 thousand) and lets us stop at the root. The running time of the full sieve is about O(N log log N), very close to O(N), because log log N does not exceed 4 or 5 even for huge numbers. Trial division for every number costs O(N √N).

The sieve with prefix sums

The best use of the sieve: we build it once, then answer thousands of questions "how many primes are between a and b?" with one subtraction, thanks to prefix sums:

sieve_prefix.cpp
const int N = 1000;vector<bool> p(N + 1, true);p[0] = p[1] = false;for (int i = 2; i * i <= N; i++) {    if (p[i]) {        for (int j = i * i; j <= N; j += i) {            p[j] = false;        }    }} vector<int> pref(N + 1, 0);for (int i = 1; i <= N; i++) {    pref[i] = pref[i - 1] + (p[i] ? 1 : 0);} cout << "primes up to 100: " << pref[100] << endl;cout << "primes in [10, 100]: " << pref[100] - pref[9] << endl;cout << "primes in [500, 600]: " << pref[600] - pref[499] << endl; int last = N;while (!p[last]) {    last--;}cout << "largest prime up to " << N << ": " << last << endl;

Lesson project: the prime census

We build a sieve and extract a short report from it.

The idea

The math club counts primes the way a census counts people: "how many primes are there up to this limit? Which is the largest? What is their sum?". We want a program that answers this for any limit up to a million.

What you need to do
  1. Read the limit n (up to 1000000).
  2. Build the sieve up to n.
  3. Walk over the numbers from 2 to n, count the primes, remember the largest prime, and add them up in a long long.
  4. Print the lines: Count:, Largest: and Sum:.
Two sample runs

First run:

Second run:

Check it in your head: the first hundred numbers contain 25 primes and the largest is 97. The first thousand contain 168 primes and the largest is 997. And if you give the program the number 1 it should print Count: 0 and Largest: -1.

After you try it yourself: show the solution
prime_census.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;

    vector<bool> is_prime(n + 1, true);
    is_prime[0] = false;
    if (n >= 1) {
        is_prime[1] = false;
    }
    for (int i = 2; i * i <= n; i++) {
        if (is_prime[i]) {
            for (int j = i * i; j <= n; j += i) {
                is_prime[j] = false;
            }
        }
    }

    int count = 0, largest = -1;
    long long sum = 0;
    for (int i = 2; i <= n; i++) {
        if (is_prime[i]) {
            count++;
            largest = i;
            sum += i;
        }
    }

    cout << "Count: " << count << endl;
    cout << "Largest: " << largest << endl;
    cout << "Sum: " << sum << endl;
    return 0;
}

1

Sum of two primes

Medium

Read an even number n (from 4 up to 1000000). Print the smallest prime p together with n - p such that both are prime, separated by a space. (Mathematicians believe this is always possible and call it the Goldbach conjecture.)

Requirements
  • Build the sieve up to n.
  • Walk over p from 2 to n / 2.
  • At the first p where p and n - p are both prime, print them and stop.
  • Use return 0 after printing to end the program.
Example input and expected output
28
5 23
Hints
  • Take the example n = 28: 2 does not work because 26 is not prime, 3 does not work (25), but 5 works (23).
  • The answer for the example is 5 23.
Sample solution (after you try)
goldbach.cpp
// Challenge 1: two primes that add up to an even number
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;

    vector<bool> is_prime(n + 1, true);
    is_prime[0] = false;
    is_prime[1] = false;
    for (int i = 2; i * i <= n; i++) {
        if (is_prime[i]) {
            for (int j = i * i; j <= n; j += i) {
                is_prime[j] = false;
            }
        }
    }

    for (int p = 2; p <= n / 2; p++) {
        if (is_prime[p] && is_prime[n - p]) {
            cout << p << " " << n - p << endl;
            return 0;
        }
    }
    cout << "none" << endl;
    return 0;
}
2

Primes in ranges

Medium

Read the number of questions q (up to 100000), then q pairs a b (1 ≤ a ≤ b ≤ 1000000). For each pair print the number of primes in the range [a, b].

Requirements
  • Build the sieve up to a million only once.
  • Build the prefix-sum array pref.
  • Answer each question with pref[b] - pref[a - 1].
  • Print each answer on its own line.
Example input and expected output
3 10 100 1 1 90 100
21 0 1
Hints
  • If you rebuilt the sieve for every question you would exceed the time limit.
  • With the input 10 100, 1 1 and 90 100 the answers are 21, 0 and 1.
Sample solution (after you try)
prime_ranges.cpp
// Challenge 2: how many primes in each range?
#include <iostream>
#include <vector>
using namespace std;

int main() {
    const int N = 1000000;
    vector<bool> is_prime(N + 1, true);
    is_prime[0] = false;
    is_prime[1] = false;
    for (int i = 2; i * i <= N; i++) {
        if (is_prime[i]) {
            for (int j = i * i; j <= N; j += i) {
                is_prime[j] = false;
            }
        }
    }

    vector<int> pref(N + 1, 0);
    for (int i = 1; i <= N; i++) {
        pref[i] = pref[i - 1] + (is_prime[i] ? 1 : 0);
    }

    int q;
    cin >> q;
    for (int k = 0; k < q; k++) {
        int a, b;
        cin >> a >> b;
        cout << pref[b] - pref[a - 1] << endl;
    }
    return 0;
}

Quick summary

  • The sieve crosses out the multiples of every prime and leaves the primes untouched.
  • We start with an array of true, and set 0 and 1 to false.
  • The outer loop needs only i * i <= n, and crossing starts from i * i because the smaller multiples were crossed earlier.
  • Time is O(N log log N) and memory is O(N), far faster than testing every number by trial division.
  • vector<bool> reserves one bit per cell.
  • With prefix sums we answer "how many primes in [a, b]" with pref[b] - pref[a - 1].
  • For one very large number use trial division up to the root; for many small numbers use the sieve.

Glossary

The most important terms in this lesson:

Sieve

An algorithm that crosses out what we do not want and leaves the primes.

Eratosthenes

An ancient Greek scholar who invented this method.

Prime

A number with exactly two divisors: 1 and itself.

Composite

A number with more than two divisors.

Multiple

The product of a number with a whole number.

Cross out

Marking a cell as not prime.

Prefix sums

An array that stores the sum of everything before each position.

Bit

The smallest unit of information, with value 0 or 1.

log log N

A function that grows extremely slowly and stays under 5 for practical numbers.

Memory limit

The most memory a program is allowed to use.

Range

The numbers between two limits [a, b].

Goldbach conjecture

Every even number greater than 2 is a sum of two primes; it has not been proven.
