المسائل ذات المسائل الفرعية

Problems with Subproblems — النقاط الجزئية وحل مسألة Iso-celestial

ما هي المسائل ذات المسائل الفرعية؟

في منصة Codeforces، تكون المسألة إما محلولة بالكامل أو غير محلولة إطلاقًا — لا توجد نقاط جزئية. أما في المنصّات الأخرى وفي معظم الأولمبيادات الوطنية والدولية، فتُقسّم المسألة الواحدة إلى عدة مسائل فرعية (Subtasks) تختلف في القيود المفروضة على المدخلات، ويُمنح المشارك نقاطًا مستقلة عن كل مسألة فرعية ينجح في حلّها.

عادةً، تكون المسائل الفرعية الأولى أسهل (قيود أصغر تسمح بحلول أبطأ)، بينما تتطلب المسائل الفرعية الأخيرة حلًّا كاملًا وسريعًا يعمل ضمن القيود الأصلية للمسألة. الحكم النهائي (verdict) يُظهر مجموع النقاط من كل المسائل الفرعية التي نجحت، لا حكمًا واحدًا فقط.

هذا يمنحك استراتيجية مهمة: إذا لم تستطع الوصول إلى الحل الكامل الأمثل، اكتب أولًا حلًّا أبسط (وإن كان أبطأ) يحل المسائل الفرعية الأولى ذات القيود الصغيرة، لضمان نقاط جزئية بدلًا من صفر.

مسألة Iso-celestial

Codeforces

يُعطى لك عدد من النقاط N على المستوى الإحداثي ثنائي الأبعاد، حيث N ≤ 3000. المطلوب هو حساب عدد المجموعات الثلاثية من النقاط التي تُشكّل مثلثًا متساوي الساقين (أي أنّ ضلعين من أضلاعه الثلاثة متساويان في الطول على الأقل).

نظام التقييم

تتكوّن المسألة من ثلاث مسائل فرعية تختلف فقط في القيود المفروضة على N:

المسألة الفرعيةالقيودالنقاط
1 N = 3 33
2 N ≤ 100 33
3 لا توجد قيود إضافية 34

ملاحظة: في المسألة الفرعية الثالثة لا توجد قيود إضافية، أي أن القيود الوحيدة المطبَّقة هي تلك الواردة في نص المسألة الأصلي. بالنسبة إلى N، يعني ذلك أنّ 1 ≤ N ≤ 3000.

الحل للمسألة الفرعية 1

في هذه المسألة الفرعية لدينا N = 3 نقاط فقط، وبالتالي إمّا أنّها تُشكّل مثلثًا متساوي الساقين أو لا. للتحقّق من ذلك، يمكننا ببساطة فحص ما إذا كان هناك ضلعان متساويان في الطول بين النقاط الثلاث.

subtask1.cpp
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

int n;

long long x[3001], y[3001];

long double dist(int i, int j) {
    long double dy = y[i] - y[j];
    long double dx = x[i] - x[j];

    return sqrtl(dy * dy + dx * dx);
}

bool f(int a, int b, int c) {
    long double ab = dist(a, b);
    long double ac = dist(a, c);
    long double bc = dist(b, c);

    return (ab == ac || ab == bc || ac == bc);
}

int main() {
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> x[i] >> y[i];
    }

    cout << f(0, 1, 2);
}
Input: 0 0 / 2 0 / 0 2 → Output: 1 (ساقان متساويان: طول 2) Input: 0 0 / 1 0 / 0 5 → Output: 0 (لا يوجد أي ضلعين متساويين)

الحل للمسألة الفرعية 2

بما أنّ N ≤ 100 في هذه المسألة الفرعية، يمكننا المرور على جميع المجموعات الثلاثية الممكنة من النقاط، واختبار كل واحدة منها باستخدام دالة الفحص f من الحل السابق.

subtask2.cpp
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

int n;

long long x[3001], y[3001];

long double dist(int i, int j);  // كما في السابق
bool f(int a, int b, int c);     // كما في السابق

int main() {
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> x[i] >> y[i];
    }

    int counter = 0;

    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            for (int k = j + 1; k < n; k++) {
                if (f(i, j, k)) counter++;
            }
        }
    }

    cout << counter;
}
عدد الفحوصات ≈ N³ / 6

هذه الطريقة تُجري عددًا من الفحوصات قدره O(N³)، وهي سريعة كفاية عندما N ≤ 100 (حوالي مليون فحص)، لكنها بطيئة جدًا بالنسبة للمسألة الكاملة التي يكون فيها N ≤ 3000، إذ سيصل عدد العمليات إلى نحو 27,000,000,000 عملية — أبطأ بكثير من الحد الزمني المسموح به عادةً في المسابقات (ثانية أو ثانيتان فقط).

الحل للمسألة الفرعية 3 (الحل الكامل)

في هذه المرحلة، نحتاج إلى التفكير بطريقة مختلفة واستخدام الملاحظات الهندسية للوصول إلى حل أسرع. لنفترض وجود نقطة واحدة P، ونحسب المسافة بينها وبين كل نقطة أخرى.

يمكننا ملاحظة أنّه إذا كانت هناك نقطتان X وY على نفس المسافة من النقطة P، فإنّ المثلث (P, X, Y) سيكون متساوي الساقين (الساقان هما PX وPY). وإذا وُجدت K نقطة جميعها على نفس المسافة من P، فإنّ أي زوج من هذه النقاط عند جمعه مع P يُشكّل مثلثًا متساوي الساقين.

هذه بالضبط فكرة "اختيار عنصرين من مجموعة" التي تعلّمناها في وحدة مبادئ العدّ! عدد الأزواج الممكنة من مجموعة حجمها K هو C(K, 2) = K(K-1)/2.

من هذه الملاحظة، نحصل على خوارزمية تُجري O(N²) عملية: لكل نقطة P، نمرّ على جميع النقاط الأخرى Q ونحصي عدد المرات التي تظهر فيها كل مسافة مميزة. بعد ذلك، نمرّ على جميع المسافات المميزة، ولنفرض أنّ عدد التكرارات لتلك المسافة هو C، فنضيف C · (C-1) / 2 إلى الجواب.

المختبر التفاعلي: راقب التجميع حول نقطة الرأس P

subtask3.cpp
#include <algorithm>
#include <cmath>
#include <iostream>
using namespace std;

int n;

long long x[3001], y[3001];

long double dist(int i, int j);  // كما في السابق

int main() {
    cin >> n;

    for (int i = 0; i < n; i++) {
        cin >> x[i] >> y[i];
    }

    int counter = 0;

    for (int i = 0; i < n; i++) {
        long double all[n];

        for (int j = 0; j < n; j++) {
            all[j] = dist(i, j);
        }

        sort(all, all + n);

        int cnt = 1;

        for (int j = 1; j < n; j++) {
            if (all[j] != all[j-1]) {
                counter += cnt * (cnt - 1) / 2;
                cnt = 0;
            }
            cnt++;
        }

        counter += cnt * (cnt - 1) / 2;
    }

    cout << counter;
}
للنقاط في المحاكاة أعلاه: العدد الكلي = 4

يتم المرور على المسافات المختلفة بترتيبها بعد الفرز، ثم المرور عليها تصاعديًا مع اتخاذ إجراء فقط عند تغيّر المسافة الحالية عن السابقة. ولتبسيط الكود، نستفيد من حقيقة أنّ المسافة بين النقطة ونفسها ستكون عند الفهرس 0 في المصفوفة المرتّبة (لأنها صفر، وهي أصغر قيمة ممكنة)، مما يسمح لنا ببدء الحلقة من الفهرس 1 مباشرة دون معالجة خاصة.

لاحظ أنّ حل المسألة الفرعية 3 عام تمامًا ويعمل أيضًا على مدخلات المسألتين الفرعيتين 1 و2 (فهو صحيح لأي N). في المسابقات، يكتفي المتسابقون أحيانًا بكتابة الحل الكامل مباشرة إن استطاعوا، لكن حل المسائل الفرعية الأسهل أولًا استراتيجية آمنة لضمان نقاط جزئية.

تحقق من فهمك

١. ما الفرق الرئيسي بين نظام تقييم Codeforces ومعظم الأولمبيادات؟

Codeforces يعطي حكمًا واحدًا (محلولة/غير محلولة)، بينما الأولمبيادات تقسّم المسألة إلى مسائل فرعية بنقاط مستقلة
لا يوجد أي فرق بينهما
Codeforces يمنح نقاطًا جزئية دائمًا، والأولمبيادات لا تفعل

٢. لماذا حل المسألة الفرعية 2 (O(N³)) غير كافٍ للحصول على النقاط الكاملة؟

لأنه بطيء جدًا عندما N ≤ 3000 (حوالي 27 مليار عملية)
لأنه يعطي نتيجة خاطئة دائمًا
لأنه لا يُترجَم (compile)

٣. في حل المسألة الفرعية 3، ماذا يعني وجود K نقطة على نفس المسافة من النقطة P؟

أنّ أي زوج من هذه النقاط مع P يُشكّل مثلثًا متساوي الساقين، وعدد هذه الأزواج هو C(K,2)
أنّ جميع هذه النقاط متطابقة الإحداثيات
أنّها لا تُشكّل أي مثلثات إطلاقًا

٤. لماذا يمكن أن تبدأ الحلقة الداخلية في حل المسألة الفرعية 3 من الفهرس 1 دون معالجة خاصة؟

لأنّ مسافة النقطة إلى نفسها تساوي صفرًا، وهي أصغر قيمة، فتستقر عند الفهرس 0 بعد الفرز
لأنّ الفهرس 0 محجوز دائمًا للنقطة الأولى في الإدخال
لا يوجد سبب، وهذا اختيار عشوائي في الكود

٥. ما التعقيد الزمني لحل المسألة الفرعية 3 الكامل؟

O(N²) تقريبًا (بسبب الفرز داخل حلقة تمر على كل نقطة)
O(N) فقط
O(N³) نفس تعقيد الحل السابق

٦. ما الاستراتيجية الأفضل عند مواجهة مسألة ذات مسائل فرعية وأنت غير متأكد من الحل الكامل؟

اكتب أولًا حلًّا أبسط يحل المسائل الفرعية الأسهل، لضمان نقاط جزئية
لا تُرسل أي حل إلا إذا كان يحل جميع المسائل الفرعية دفعة واحدة
أرسل كودًا فارغًا للحصول على نقاط المحاولة
