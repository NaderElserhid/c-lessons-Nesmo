Greedy Algorithms — خذ أفضل خيار الآن

ماذا ستتعلم في هذا الدرس؟

  • تفهم فكرة الخوارزمية الطماعة ولماذا هي سريعة وقصيرة
  • تعرف أن الطمع ليس صحيحًا دائمًا وتكسره بمثال مضاد
  • تطبّق قالب «رتّب ثم امسح» على الميزانية والانتظار والأنشطة
  • تحلّ مسألة اختيار الأنشطة بالترتيب بحسب النهاية
  • تتحقق من صحة الطمع بحجة الاستبدال والاختبار المقارن

خذ الأفضل الآن

في بوفيه مفتوح لديك صحن واحد. الخوارزمية الطماعة (Greedy) تقول: خذ في كل خطوة أفضل ما أمامك الآن، ولا تفكر بالمستقبل ولا تتراجع. بائع يعيد لك الباقي يفعل ذلك: يعطيك أكبر عملة تدخل في المبلغ، ثم أكبر عملة في الباقي، وهكذا.

تخيّل أنك تتسلق جبلًا في الضباب، وتتخذ كل خطوة نحو الأعلى حيث تقف. قد تصل إلى القمة الحقيقية، وقد تعلق على تلة صغيرة لا تؤدي لشيء. الخوارزميات الطماعة سريعة وبسيطة، لكنها لا تنجح إلا إذا كانت المسألة من النوع الذي يصل فيه التسلق الأعمى إلى القمة.

التحدي الحقيقي في الطمع ليس كتابة الكود (فهو قصير جدًا)، بل معرفة هل الطمع صحيح في هذه المسألة. وسنتعلم كيف نفكّر في ذلك.

المثال الأول: إعادة الباقي

لدينا عملات بقيم 25 و10 و5 و1، ونريد دفع 63 بأقل عدد ممكن من العملات. نأخذ الأكبر ما أمكن:

make_change.cpp
int coins[] = {25, 10, 5, 1};int amount = 63, count = 0; for (int c : coins) {    while (amount >= c) {        amount -= c;        count++;        cout << c << " ";    }}cout << "=> " << count << " coins" << endl;
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
25 25 10 1 1 1 => 6 coins

ستة عملات، ولا يمكن أفضل من ذلك. لكن هل الطمع يعمل دائمًا مع العملات؟ جرّب مجموعة عملات مختلفة: 4 و3 و1، والمبلغ 6:

greedy_fails.cpp
int coins[] = {4, 3, 1};int amount = 6; int greedy = 0, rest = amount;for (int c : coins) {    greedy += rest / c;    rest %= c;} vector<int> best(amount + 1, 1000000);best[0] = 0;for (int a = 1; a <= amount; a++) {    for (int c : coins) {        if (a >= c) {            best[a] = min(best[a], best[a - c] + 1);        }    }}cout << "greedy = " << greedy << ", optimal = " << best[amount] << endl;
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
greedy = 3, optimal = 2

الطمع أعطانا ثلاث عملات (4 + 1 + 1) بينما الأمثل عملتان (3 + 3). الطمع ليس صحيحًا دائمًا! مع العملات الأمريكية (25 و10 و5 و1) يعمل، لكن مع بعض الأنظمة الأخرى يفشل. فلا تستعمل الطمع قبل أن تتأكد من صحته.

مختبر تفاعلي (1): متى ينجح الطمع مع العملات؟

اختر نظام عملات (أو اكتب نظامك بأعداد تفصل بينها فواصل) والمبلغ. سترى حل الطمع وحل الأمثل (الذي يجرّب كل الاحتمالات) وهل اتفقا. جرّب الأنظمة المختلفة وابحث عن مبلغ يفشل فيه الطمع!

طمع صحيح: اشترِ الأرخص أولًا

معك ميزانية، وتريد شراء أكبر عدد ممكن من الأشياء. هنا الطمع يعمل: ابدأ بالأرخص دائمًا. لماذا؟ لأن أي بديل أغلى يستهلك ميزانية أكثر فيترك لك عددًا أقل:

shopping_budget.cpp
vector<int> price = {40, 10, 25, 5, 30};int budget = 70, spent = 0, items = 0; sort(price.begin(), price.end());for (int p : price) {    if (spent + p > budget) {        break;    }    spent += p;    items++;}cout << "bought " << items << " items, spent " << spent << endl;
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
bought 4 items, spent 70

هذا هو القالب الأشهر للطمع: رتّب ثم امسح. تحتاج الخطوتان O(n log n) (للترتيب) وO(n) (للمسح) فالمجموع سريع جدًا. وأغلب مسائل الطمع تتكون من اختيار «معيار الترتيب» الصحيح.

تقليل الانتظار: الأقصر أولًا

في طابور خدمة، لو بدأنا بالزبون الأطول تأخّر كل من بعده. فإن بدأنا بالأقصر قلّ مجموع الانتظار:

waiting_time.cpp
vector<int> t = {5, 2, 8, 3}; auto totalWait = [](const vector<int>& v) {    int wait = 0, sum = 0;    for (int x : v) {        sum += wait;        wait += x;    }    return sum;}; cout << "as given: " << totalWait(t) << endl;sort(t.begin(), t.end());cout << "shortest first: " << totalWait(t) << endl;
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
as given: 27 shortest first: 17

اختيار الأنشطة: أشهر مثال للطمع

لديك n نشاطًا، لكل منها وقت بداية ونهاية، ولا يمكنك حضور نشاطين متداخلين. أي عدد أكبر يمكنك حضوره؟ هناك عدة أفكار للطمع: الأبكر بداية؟ الأقصر مدة؟ الأبكر نهاية؟ المختبر التالي يجرّب الثلاثة أمامك:

مختبر تفاعلي (2): أي معيار طمع هو الصحيح؟

الأشرطة هي الأنشطة على خط الزمن. اضغط على كل معيار ولاحظ عدد الأنشطة التي حصلت عليها. اضغط «أنشطة عشوائية» وأعد التجربة عدة مرات: أي معيار لا يخسر أبدًا؟

لماذا ينجح «الأبكر نهاية»؟

الفكرة بالحدس: النشاط الذي ينتهي أبكر يترك أطول وقت متبقٍّ لبقية الأنشطة. لا يوجد اختيار أول أفضل منه: لو كان في الحل الأمثل نشاط أول آخر ينتهي لاحقًا، نستطيع استبداله بالنشاط الأبكر نهاية دون أن نخسر شيئًا (لأنه ينتهي قبله فلا يتداخل مع أي نشاط يليه). هذه الحجة تسمى حجة الاستبدال (exchange argument) وهي الطريقة الأشهر لإثبات صحة الطمع. التنفيذ: رتّب بحسب النهاية، ثم امسح الأنشطة واختر كل نشاط يبدأ بعد نهاية آخر نشاط اخترته:

activity_scan.cpp
vector<pair<int, int>> a = {{1, 3}, {2, 4}, {3, 5}, {4, 6}};
int last = 0, count = 0;
for (auto& p : a) {
    if (p.first >= last) {
        count++;
        last = p.second;
    }
}
cout << count << endl;

ماذا سيطبع هذا الكود؟ (الأنشطة مرتّبة بحسب النهاية)

3 8

النشاط (1,4) يُختار فتصبح آخر نهاية 4. النشاط (2,5) يتداخل فيُرفض. النشاط (4,6) يبدأ عند 4 فيُختار وآخر نهاية 6. والنشاط (6,8) يُختار وآخر نهاية 8. المجموع 3 وآخر نهاية 8.

انتبه للشرط p.first >= last (أكبر أو يساوي). نشاط يبدأ لحظة انتهاء السابق تمامًا مسموح غالبًا، لكن اقرأ نص المسألة لتعرف هل التلامس يعدّ تداخلًا.

كيف أعرف أن الطمع يصلح؟

  1. اجتهد في الحدس: ما «أفضل» اختيار في كل خطوة؟ جرّب عدة معايير للترتيب.
  2. جرّب أمثلة صغيرة بيدك، وحاول أن تكسر فكرتك بمثال مضاد (كما فعلنا مع العملات 4 و3 و1).
  3. اسأل عن حجة الاستبدال: هل يمكن تحويل أي حل أمثل ليبدأ بقراري الطماع دون خسارة؟
  4. تحقق برمجيًا: قارن حلّك الطماع بحل القوة الغاشمة على كل المدخلات الصغيرة (مثلما تعلّمنا في درس تحليل الحالات).

الاختبار المقارن هو صديقك الأوفى: كتابة حل بطيء (يجرّب كل الاحتمالات) وحل طماع ومقارنتهما على آلاف المدخلات العشوائية الصغيرة تكشف أي فكرة طماعة خاطئة خلال ثوانٍ.

مشروع الدرس: معرض الأنشطة المدرسي

برنامج يختار أكبر عدد من الأنشطة المتتالية دون تداخل.

الفكرة

في يوم المعرض المدرسي تقام ورش كثيرة، لكل ورشة وقت بداية ونهاية، والطالب لا يستطيع حضور ورشتين متداخلتين. تريد برنامجًا يخبره بأقصى عدد من الورش يمكنه حضورها، ويطبع جدوله.

المطلوب منك
  1. اقرأ n ثم n ورشة، لكل منها s البداية وe النهاية.
  2. خزّن كل ورشة في pair بحيث تأتي النهاية أولًا ثم البداية (لتُرتَّب بحسب النهاية تلقائيًا).
  3. رتّب بـ sort ثم امسح: اختر الورشة إن كانت بدايتها ≥ نهاية آخر ورشة مختارة.
  4. اطبع Max activities: k ثم كل ورشة مختارة في سطر بالشكل 9-10.
مثالان على التشغيل

التشغيل الأول:

7 9 10 10 12 9 11 11 13 12 14 13 15 10 11
Max activities: 4 9-10 10-11 11-13 13-15

التشغيل الثاني (الكل متداخل):

3 1 5 2 6 3 7
Max activities: 1 1-5

تحقق ذهنيًا: في الأول بعد الترتيب بالنهاية: نختار 9-10، ثم 10-11 (يبدأ عند 10 تمامًا)، ثم 11-13، ثم 13-15. أما 9-11 و10-12 و12-14 فتتداخل مع المختار فنرفضها.

بعد أن تجرّب بنفسك: اعرض الحل
activity_fair.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> byEnd;
    for (int i = 0; i < n; i++) {
        int s, e;
        cin >> s >> e;
        byEnd.push_back({e, s});
    }
    sort(byEnd.begin(), byEnd.end());

    int lastEnd = -1, count = 0;
    vector<pair<int, int>> chosen;
    for (const auto& p : byEnd) {
        int s = p.second, e = p.first;
        if (s >= lastEnd) {
            count++;
            lastEnd = e;
            chosen.push_back({s, e});
        }
    }

    cout << "Max activities: " << count << endl;
    for (const auto& c : chosen) {
        cout << c.first << "-" << c.second << endl;
    }
    return 0;
}

واجبات بعد الدرس

تحديان بسيطان تحلّهما بنفسك بعد انتهاء الدرس. اكتب الحل في ملف .cpp، ثم ترجمه وشغّله وقارن ناتجك بالناتج المتوقع. جرّب أولًا، ثم افتح التلميح إن علقت، ولا تفتح نموذج الحل إلا بعد المحاولة الجادة.

1

أكبر عدد من الكتب

سهل

اقرأ n وbudget ثم أسعار n كتابًا. اطبع أكبر عدد من الكتب يمكنك شراؤها دون تجاوز الميزانية (كل كتاب يُشترى مرة واحدة).

المطلوب
  • خزّن الأسعار في vector<int> ورتّبها تصاعديًا.
  • اشترِ الأرخص فالأرخص ما دام المجموع لا يتجاوز الميزانية.
  • اطبع عدد الكتب فقط.
مثال على الإدخال والناتج المتوقع
6 50 20 10 15 30 5 25
4
تلميحات
  • توقف عند أول كتاب لا تستطيع شراءه (break)، فكل ما بعده أغلى.
  • مع الأسعار 5 10 15 20 25 30 والميزانية 50 نشتري 5 و10 و15 و20 أي 4 كتب.
نموذج الحل (بعد المحاولة)
books_budget.cpp
// Challenge 1: buy as many books as possible
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n, budget;
    cin >> n >> budget;
    vector<int> price(n);
    for (int i = 0; i < n; i++) {
        cin >> price[i];
    }
    sort(price.begin(), price.end());

    int spent = 0, count = 0;
    for (int p : price) {
        if (spent + p > budget) {
            break;
        }
        spent += p;
        count++;
    }
    cout << count << endl;
    return 0;
}
2

قوارب الإنقاذ

متوسط

يريد n أشخاص عبور نهر، وزن كل شخص معروف، وكل قارب يتسع لشخصين على الأكثر بشرط ألا يزيد مجموع وزنيهما عن limit (وكل شخص وحده يتسع بالتأكيد). اطبع أقل عدد من القوارب.

المطلوب
  • رتّب الأوزان.
  • استخدم مؤشرين: i للأخف وj للأثقل.
  • الأثقل يركب دائمًا، وإن كان يتسع معه الأخف فيركب الاثنان، ثم تحرّك المؤشرات.
مثال على الإدخال والناتج المتوقع
5 10 2 9 5 5 8
3
تلميحات
  • في كل قارب: j--، وإن وُجد مكان للأخف فزد i++. زد عدّاد القوارب.
  • مع الأوزان 2 9 5 5 8 والحد 10 نحتاج 3 قوارب: الـ9 وحده، و(2,8)، و(5,5).
نموذج الحل (بعد المحاولة)
rescue_boats.cpp
// Challenge 2: rescue boats (at most two people per boat)
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n, limit;
    cin >> n >> limit;
    vector<int> w(n);
    for (int i = 0; i < n; i++) {
        cin >> w[i];
    }
    sort(w.begin(), w.end());

    int i = 0, j = n - 1, boats = 0;
    while (i <= j) {
        if (i < j && w[i] + w[j] <= limit) {
            i++;
        }
        j--;
        boats++;
    }
    cout << boats << endl;
    return 0;
}

ملخص سريع

  • الخوارزمية الطماعة تختار في كل خطوة أفضل خيار محلي ولا تتراجع، وهي سريعة وقصيرة غالبًا.
  • الطمع **ليس صحيحًا دائمًا**: عملات {4, 3, 1} والمبلغ 6 يعطيان 3 عملات بدل 2.
  • القالب الأشهر: **رتّب ثم امسح**، ومفتاح الحل هو اختيار معيار الترتيب الصحيح.
  • لشراء أكبر عدد بميزانية: الأرخص أولًا. ولتقليل الانتظار: الأقصر أولًا.
  • لاختيار أكبر عدد من الأنشطة غير المتداخلة: رتّب بحسب **النهاية** واختر ما يبدأ بعد آخر نهاية مختارة.
  • نبرهن صحة الطمع بحجة الاستبدال أو نكسره بمثال مضاد صغير.
  • تحقق دائمًا بمقارنة حلّك الطماع بحل القوة الغاشمة على مدخلات صغيرة كثيرة.

تحقق من فهمك

اقرأ كل عبارة ثم اختر صحيح أو خطأ. سيظهر التفسير مباشرة بعد إجابتك.

قاموس المصطلحات

المصطلحات الإنجليزية الأهم في هذا الدرس ومقابلها بالعربية:

Greedyطماع

خوارزمية تختار أفضل خيار محلي في كل خطوة دون تراجع.

Local optimumأمثل محلي

أفضل خيار ممكن في الخطوة الحالية فقط.

Global optimumأمثل شامل

أفضل حل ممكن للمسألة كلها.

Counterexampleمثال مضاد

حالة واحدة تكسر الفكرة وتثبت أنها خاطئة.

Exchange argumentحجة الاستبدال

إثبات أن أي حل أمثل يمكن تحويله ليوافق قرار الطمع.

Intervalفترة

مدة زمنية لها بداية ونهاية.

Overlapتداخل

اشتراك فترتين في جزء من الزمن.

Activity selectionاختيار الأنشطة

مسألة إيجاد أكبر عدد من الفترات غير المتداخلة.

Sort then scanرتّب ثم امسح

نمط حل طماع شائع: ترتيب ثم مرور واحد.

Two pointersمؤشران

Canonical coin systemنظام عملات يعمل معه الطمع

Brute forceالقوة الغاشمة
