تحليل التعقيد

Time Complexity — كيف نعرف أن حلّنا سينجح قبل كتابته

ماذا ستتعلم في هذا الدرس؟

  • تفهم لماذا نعدّ العمليات ولا نقيس الثواني
  • تحسب تعقيد الحلقات الواحدة والمتداخلة وحلقة القسمة على 2
  • تقرأ رمز O الكبير وتطبّق قاعدتي إهمال الثوابت والاحتفاظ بالحد الأكبر
  • تقدّر هل ينجح حلّك بمعرفة حدود المسألة وقاعدة 10⁸ عملية
  • تتعرف إلى تكلفة عمليات الحاويات الشائعة وتقدّر استهلاك الذاكرة

لماذا يتأخر برنامجي؟

كتبت حلًّا صحيحًا لمسألة، جرّبته على الأمثلة الصغيرة فنجح، ثم أرسلته فجاءك الحكم: Time Limit Exceeded (تجاوز الزمن). السبب ليس خطأ في المنطق، بل أن برنامجك يعمل بطريقة لا تتحمل الأحجام الكبيرة. علم تحليل التعقيد (Time Complexity) يعلّمك أن تعرف ذلك قبل أن تكتب سطرًا واحدًا.

تخيّل أنك تبحث عن اسم في دليل هاتف من ألف صفحة. الطريقة الأولى أن تقلّب صفحة صفحة (ألف خطوة في الأسوأ). والثانية أن تفتح من المنتصف وتحذف نصف الدفتر في كل مرة (عشر خطوات فقط!). كلا الطريقتين صحيح، لكن الفرق بينهما يتضخم مع كبر الدفتر.

لا نقيس الزمن بالثواني لأن الثواني تتغير بحسب جهازك. بدل ذلك نعدّ عدد العمليات الأساسية كدالة في حجم المدخلات n. هذا ما يخبرنا كيف يتصرف الحل عندما يكبر n من مئة إلى مليون.

أولًا: نتعلم العدّ

هذا برنامج لا يحل مسألة، بل يعدّ فقط كم مرة تعمل الحلقات الثلاث الأشهر. اضغط على الأسطر المضيئة:

count_operations.cpp
#include <iostream>using namespace std; int main() {    int n = 16;    long long single = 0, nested = 0, halving = 0;     for (int i = 0; i < n; i++) {        single++;    }     for (int i = 0; i < n; i++) {        for (int j = 0; j < n; j++) {            nested++;        }    }     for (int x = n; x > 1; x /= 2) {        halving++;    }     cout << "one loop:     " << single << endl;    cout << "nested loops: " << nested << endl;    cout << "halving loop: " << halving << endl;    return 0;}
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
one loop: 16 nested loops: 256 halving loop: 4

مع n = 16 عملت الحلقة الواحدة 16 مرة، والمتداخلة 256 مرة، والحلقة التي تقسم على 2 أربع مرات فقط. الأعداد الثلاثة صغيرة الآن، لكن شاهد ماذا يحدث حين يكبر n:

growth_table.cpp
long long ns[] = {10, 1000, 100000};
for (long long n : ns) {
    int lg = 0;
    for (long long x = n; x > 1; x /= 2) {
        lg++;
    }
    cout << n << ": log=" << lg << "  nlogn=" << n * lg << "  n^2=" << n * n << endl;
}
10: log=3 nlogn=30 n^2=100 1000: log=9 nlogn=9000 n^2=1000000 100000: log=16 nlogn=1600000 n^2=10000000000

حين صار n مئة ألف أصبحت الحلقة المتداخلة عشرة مليارات عملية، بينما بقيت القسمة على 2 عند 16 خطوة! هذا هو الفرق بين حل ينجح وحل ينهار.

تتبّع: حلقة القسمة على 2

راقب كم دورة تحتاج الحلقة قبل أن يصل n إلى 1:

المتغيرات
الناتج حتى الآن

عشرون ثم عشرة ثم خمسة ثم اثنان ثم واحد: أربع خطوات فقط. كلما ضاعفنا n تزيد خطوة واحدة. هذا هو اللوغاريتم (logarithm) الذي نكتبه log n، وهو أجمل ما يمكن أن تراه في عالم الخوارزميات.

رمز O الكبير (Big-O)

نلخّص عدد العمليات برمز O( ) بقاعدتين بسيطتين:

  • أهمل الثوابت: العمل 3n أو 5n أو n + 100 كلها تُسمى O(n).
  • احتفظ بالحد الأكبر: العمل n² + n هو O(n²) لأن n² يطغى حين يكبر n.
الرمزاسمهمثال مألوف
O(1)ثابتقراءة v[i]، أو v.size()
O(log n)لوغاريتميالبحث في set أو map، والبحث الثنائي
O(n)خطيحلقة واحدة على كل العناصر
O(n log n)خطي لوغاريتميsort
O(n²)تربيعيحلقتان متداخلتان على n
O(n³)تكعيبيثلاث حلقات متداخلة
O(2ⁿ)أسّيتجربة كل المجموعات الجزئية
O(n!)عامليتجربة كل ترتيبات n عنصرًا

الرمز يصف أسوأ حالة عادةً. فلو بحثت عن عدد في متجه بحلقة for وقد يكون العدد في آخر مكان، فالحل O(n) حتى لو وجدته أحيانًا في الخطوة الأولى.

توقّع قبل أن تشغّل
predict_count.cpp
int n = 1024;
int cnt = 0;
for (int i = 1; i <= n; i *= 2) {
    for (int j = 0; j < n; j++) {
        cnt++;
    }
}
cout << cnt << endl;

ماذا سيطبع هذا الكود؟ (الحلقة الخارجية تضاعف i كل دورة)

11264

الحلقة الخارجية تأخذ القيم 1 و2 و4 ... و1024، أي 11 دورة. وفي كل دورة تعمل الحلقة الداخلية 1024 مرة. المجموع 11 × 1024 = 11264، وهذا نمط O(n log n).

مختبر تفاعلي: هل سينجح حلّي؟

حرّك شريط n وراقب عدد العمليات لكل نوع من التعقيد. نفترض قاعدة تقريبية: الحاسوب ينفذ نحو مئة مليون (10⁸) عملية بسيطة في الثانية، فإذا زاد العدد عن ذلك صار البرنامج في خطر. (هذه قاعدة للتقدير فقط، والحقيقة تتغير بحسب العملية والجهاز.)

كم يتحمل كل تعقيد؟

بالقاعدة التقريبية 10⁸ عملية، نستطيع أن نخمّن أكبر n يتحمله كل تعقيد خلال ثانية واحدة. استخدم هذا الجدول كبوصلة لا كقانون صارم:

التعقيدأكبر n تقريبًا
O(n)حتى بضعة ملايين (≈ 10⁷)
O(n log n)حتى نحو مليون (≈ 10⁶)
O(n²)حتى بضعة آلاف (≈ 10⁴)
O(n³)حتى بضع مئات (≈ 500)
O(2ⁿ)حتى نحو 20 إلى 25
O(n!)حتى نحو 10 إلى 11

الاستخدام العملي: اقرأ حدود المسألة أولًا. إن كان n حتى 2·10⁵ فأنت تحتاج O(n log n) أو أسرع، ولا تجرّب حلقتين متداخلتين أبدًا. وإن كان n ≤ 20 فالتجربة الشاملة مقبولة!

تكلفة العمليات التي نستخدمها كل يوم

العمليةالتكلفة
v[i] وv.size()O(1)
v.push_back(x)O(1) بالمتوسط
v.insert(v.begin(), x)O(n) (يزيح كل العناصر)
s.insert / find / erase على set وmapO(log n)
unordered_mapO(1) بالمتوسط
sortO(n log n)
cout << endl في حلقة كبيرةبطيء جدًا (يفرّغ المخزن كل مرة)

حلقة تبدو واحدة قد تخفي حلقة! الأمر v.insert(v.begin(), x) داخل حلقة for يجعل الحل O(n²)، لأن كل إدخال يزيح العناصر كلها. ومثله استدعاء s.find على vector داخل حلقة.

وماذا عن الذاكرة؟

للتعقيد وجه آخر هو المساحة (Space Complexity): كم ذاكرة يحتاج برنامجك. المسابقات تضع غالبًا حدًّا نحو 256 ميغابايت. احسب بسرعة: العدد int يحتل 4 بايتات، وlong long يحتل 8:

memory_estimate.cpp
long long n = 10000000;
cout << "ints:       " << n * sizeof(int) / 1000000 << " MB" << endl;
cout << "long longs: " << n * sizeof(long long) / 1000000 << " MB" << endl;
ints: 40 MB long longs: 80 MB

مصفوفة من عشرة ملايين int تأخذ 40 ميغابايت وهذا مقبول، لكن مصفوفة من مليار عدد ستنهار الذاكرة قبل أن تبدأ. فتش دائمًا عن الحدود قبل أن تحجز الذاكرة.

حلقة من نوع آخر: i < j

انظر إلى هذه الحلقة المتداخلة: الحلقة الداخلية تبدأ من i + 1 لا من 0، فلا تعدّ كل الأزواج مرتين:

triangle_loop.cpp
int n = 5;
int cnt = 0;
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        cnt++;
    }
}
cout << cnt << endl;
10

مع n = 5 العدد 10 أي 5 × 4 ÷ 2. وبوجه عام n(n-1)/2، وهو نصف n² تقريبًا، فتسمى أيضًا O(n²) لأن الثوابت تُهمَل.

مشروع الدرس: مقدّر النجاح

أداة صغيرة تحكم هل سينجح حلّك قبل أن تكتبه.

الفكرة

قبل كتابة أي حل تريد أن تعرف: لو كان حلّي بتعقيد معين وحجم المدخلات n، فهل عدد العمليات ضمن ميزانية 10⁸؟ ستبني حاسبة تجيبك فورًا.

المطلوب منك
  1. اقرأ q ثم q استعلامًا، كل استعلام n وkind حيث 1 تعني O(n) و2 تعني O(n log n) و3 تعني O(n²) و4 تعني O(n³).
  2. اكتب دالة تحسب عدد العمليات بالنوع long long (قيمة log n هي عدد مرات قسمة n على 2 حتى يصبح 1).
  3. اطبع الاستعلام بالشكل 100000 O(n): 100000 operations -> OK.
  4. إن زاد العدد عن 100000000 اطبع TOO SLOW بدل OK.
مثالان على التشغيل

التشغيل الأول:

4 100000 1 100000 2 100000 3 1000 4
100000 O(n): 100000 operations -> OK 100000 O(n log n): 1600000 operations -> OK 100000 O(n^2): 10000000000 operations -> TOO SLOW 1000 O(n^3): 1000000000 operations -> TOO SLOW

التشغيل الثاني:

3 1000000 2 10000 3 500 3
1000000 O(n log n): 19000000 operations -> OK 10000 O(n^2): 100000000 operations -> OK 500 O(n^2): 250000 operations -> OK

تحقق ذهنيًا: log₂(100000) يساوي 16 بالقسمة الصحيحة، فالمرتبة n log n تعطي 1600000. ومع n = 1000 تكعيبي نحصل على مليار، وهو أكبر من 10⁸.

بعد أن تجرّب بنفسك: اعرض الحل
will_it_pass.cpp
#include <iostream>
using namespace std;

long long operations(long long n, int kind) {
    int lg = 0;
    for (long long x = n; x > 1; x /= 2) {
        lg++;
    }
    if (kind == 1) return n;
    if (kind == 2) return n * lg;
    if (kind == 3) return n * n;
    return n * n * n;
}

int main() {
    const long long LIMIT = 100000000;
    const char* names[] = {"", "O(n)", "O(n log n)", "O(n^2)", "O(n^3)"};
    int q;
    cin >> q;
    while (q--) {
        long long n;
        int kind;
        cin >> n >> kind;
        long long ops = operations(n, kind);
        cout << n << " " << names[kind] << ": " << ops << " operations -> ";
        if (ops <= LIMIT) {
            cout << "OK" << endl;
        } else {
            cout << "TOO SLOW" << endl;
        }
    }
    return 0;
}

واجبات بعد الدرس

تحديان بسيطان تحلّهما بنفسك بعد انتهاء الدرس. اكتب الحل في ملف .cpp، ثم ترجمه وشغّله وقارن ناتجك بالناتج المتوقع. جرّب أولًا، ثم افتح التلميح إن علقت، ولا تفتح نموذج الحل إلا بعد المحاولة الجادة.

1

عدّ الأزواج

سهل

اقرأ العدد n. اطبع عدد الأزواج (i, j) التي تحقق 0 ≤ i < j < n، بالعدّ داخل حلقتين متداخلتين.

المطلوب
  • استخدم عدّادًا من النوع long long.
  • الحلقة الخارجية على i والداخلية تبدأ من i + 1.
  • اطبع العدد النهائي فقط.
مثال على الإدخال والناتج المتوقع
1000
499500
تلميحات
  • تحقق من جوابك بالصيغة n × (n - 1) / 2.
  • مع n = 1000 الجواب 499500.
نموذج الحل (بعد المحاولة)
count_pairs.cpp
// Challenge 1: how many pairs (i, j) with i < j ?
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long cnt = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            cnt++;
        }
    }
    cout << cnt << endl;
    return 0;
}
2

كم مرة نقسم على 2؟

متوسط

اقرأ العدد n، واطبع عدد المرات التي يمكن فيها قسمة n على 2 (قسمة صحيحة) حتى يصبح 1. هذا هو log₂ n مقرّبًا لأسفل.

المطلوب
  • استخدم long long لأن n قد يصل إلى مليارات.
  • كرّر n /= 2 وعدّ الخطوات ما دام n > 1.
  • اطبع عدد الخطوات.
مثال على الإدخال والناتج المتوقع
1000
9
تلميحات
  • مع n = 1000 الجواب 9، لأن 2⁹ = 512 و2¹⁰ = 1024.
  • جرّب n = 1: الجواب 0 لأن الحلقة لا تعمل أبدًا.
نموذج الحل (بعد المحاولة)
count_halvings.cpp
// Challenge 2: how many halvings until we reach 1 ?
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    int steps = 0;
    while (n > 1) {
        n /= 2;
        steps++;
    }
    cout << steps << endl;
    return 0;
}

ملخص سريع

  • التعقيد يصف **كيف يكبر عدد العمليات** مع كبر حجم المدخلات n، لا الزمن بالثواني.
  • نُهمل الثوابت ونحتفظ بالحد الأكبر: 3n² + 5n هو O(n²).
  • الترتيب من الأسرع للأبطأ: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!).
  • قاعدة تقدير: نحو 10⁸ عملية بسيطة في الثانية. اقرأ حدود المسألة لتعرف التعقيد المطلوب.
  • حلقة تُقسم فيها القيمة على 2 تعمل log n مرة؛ وحلقتان متداخلتان على n تعملان n².
  • احذر الحلقات الخفية: insert في بداية vector داخل حلقة تجعل الحل O(n²).
  • قدّر الذاكرة أيضًا: int = 4 بايت وlong long = 8 بايت، وعشرة ملايين int = 40 ميغابايت.

تحقق من فهمك

اقرأ كل عبارة ثم اختر صحيح أو خطأ. سيظهر التفسير مباشرة بعد إجابتك.

قاموس المصطلحات

المصطلحات الإنجليزية الأهم في هذا الدرس ومقابلها بالعربية:

Time complexityتعقيد الزمن

وصف لكيفية نمو عدد العمليات مع كبر حجم المدخلات.

Space complexityتعقيد الذاكرة

وصف لكمية الذاكرة التي يحتاجها البرنامج.

Big-Oرمز O الكبير

رمز يلخّص نمو العمليات في أسوأ حالة، مثل O(n).

Input sizeحجم المدخلات

الرمز n: عدد العناصر أو قيمة العدد الذي يعالجه البرنامج.

Constant timeزمن ثابت

عملية O(1) لا يتأثر زمنها بحجم المدخلات.

Logarithmicلوغاريتمي

نمو بطيء جدًا: يزيد خطوة عند مضاعفة n، مثل O(log n).

Linearخطي

يزداد العمل بالتناسب مع n، مثل O(n).

Quadraticتربيعي

يزداد العمل بمربع n، مثل O(n²).

Exponentialأسّي

يتضاعف العمل مع كل عنصر إضافي، مثل O(2ⁿ).

Worst caseأسوأ حالة

أكثر عدد عمليات قد يحتاجه البرنامج لأي مدخلات بالحجم n.

TLEتجاوز الزمن

حكم يعني أن البرنامج لم ينته خلال الزمن المسموح.

Amortizedبالمتوسط عبر الزمن

تكلفة العملية موزعة على سلسلة من العمليات، مثل push_back.

عشرة أسئلة بين السهلة والمتوسطة. اختر إجابة واحدة لكل سؤال.
