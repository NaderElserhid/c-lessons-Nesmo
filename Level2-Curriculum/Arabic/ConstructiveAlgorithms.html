Constructive Algorithms — ابنِ الجواب الذي يحقق الشروط

ماذا ستتعلم في هذا الدرس؟

  • تفهم الفرق بين حساب الجواب وبنائه، ولماذا تكفي إجابة صحيحة واحدة
  • تتبع الخطة: حالات صغيرة ثم نمط ثم بناء ثم فاحص
  • تستخدم أدوات البناء: الإزاحة بالباقي والتقسيم زوجي/فردي والتكرار الدوري
  • تتعامل مع الحالات المستحيلة وتثبتها بالتجربة الشاملة على القيم الصغيرة
  • تكتب فاحصًا يتحقق من صحة ما بنيت

ابنِ الجواب بنفسك

في أغلب المسائل نحسب جوابًا واحدًا صحيحًا (مجموع، أصغر قيمة، عدد...). أما في المسائل الإنشائية (Constructive) فالمطلوب أن تبني شيئًا يحقق شروطًا: ترتيب أعداد، نص، جدول، مجموعة. والجميل أن للمسألة غالبًا أكثر من جواب صحيح، وأي واحد منها مقبول! (فيحكم عليك «فاحص» (checker) يتأكد أن ما بنيته يحقق الشروط.)

الأمر كبناء بيت من المكعبات بشروط: «لا تضع مكعبين أحمرين متجاورين». لا يوجد بيت واحد صحيح، وإنما أنت تبحث عن طريقة منظّمة تضمن أن أي بيت تبنيه صحيح، وتعرف متى يكون البناء مستحيلًا.

خطة العمل في كل مسألة إنشائية:

  1. جرّب حالات صغيرة بيدك (n = 1 ثم 2 ثم 3...) وابحث عن نمط.
  2. عمّم النمط إلى قاعدة بناء (إزاحة، تقسيم زوجي/فردي، تكرار دوري، البدء بالأكبر...).
  3. اكتب فاحصًا يتأكد أن الناتج يحقق الشروط، وجرّبه على قيم كثيرة.
  4. تعامل مع المستحيل: أي القيم لا حل لها؟ وكيف تتأكد؟

المثال الأول: لا أحد في مكانه

رتّب الأعداد من 1 إلى n بحيث لا يقف أي عدد في موضعه الأصلي. الحل الأنيق: أزِح الجميع خطوة واحدة (كما يتناوب طلاب على المقاعد). نكتب الحل ثم نكتب الفاحص:

اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
2 3 4 5 1 no fixed point: yes

متى يفشل هذا البناء؟ عندما n = 1: لا يوجد إلا العدد 1 وهو في مكانه حتمًا. وهذه حالة مستحيلة لا يمكن حلها بأي طريقة. تذكّر دائمًا أن تسأل: «هل هناك مدخلات لا حل لها؟».

المثال الثاني: أعداد مختلفة بمجموع معلوم

أعطني n عددًا صحيحًا موجبًا مختلفة مجموعها S بالضبط. أولًا: أصغر مجموع ممكن هو 1+2+...+n، فإن كان S أصغر منه فلا حل. وإلا نبني: 1, 2, ..., n-1 ونضع الباقي كله في العدد الأخير:

الأعداد 1 2 3 14 مختلفة ومجموعها 20. وهذا هو الأسلوب «ابدأ بالأصغر ودع الأخير يمتص الباقي»، وهو متكرر في المسائل الإنشائية.

المثال الثالث: بناء نص دوري

ابنِ نصًا من الحروف a وb وc بطول n لا يحتوي أي مقطع متناظر من ثلاثة حروف (مثل aba). الحل: كرّر abc دوريًا، لأن كل ثلاثة حروف متتالية فيه مختلفة، فلا يتساوى الأول والثالث أبدًا:

مختبر تفاعلي (1): ابنِ ثم افحص

اختر نوع المسألة، ثم حاول ترتيب الأعداد بيدك: انقر على عددين ليتبادلا مكانيهما. الأعداد الحمراء تخالف الشرط. أو جرّب الأزرار الجاهزة لترى أي بناء ينجح!

مسألة مقاعد الحفل: زوجي ثم فردي

وزّع n طلابًا (أرقامهم من 1 إلى n) على صف مقاعد بحيث لا يجلس بجوار بعضهما طالبان رقماهما متتاليان (مثل 4 و5). كيف نبني الترتيب؟ فكّر: لو وضعنا الأعداد الزوجية معًا، فالفرق بين جيرانها 2 دائمًا، وكذلك الفردية! نكتب الحل ونفحصه ونجربه على n من 1 إلى 7:

no_consecutive_neighbors.cpp
#include <iostream>#include <vector>#include <cstdlib>using namespace std; vector<int> build(int n) {    vector<int> r;    if (n == 2 || n == 3) {        return r;    }    for (int x = 2; x <= n; x += 2) {        r.push_back(x);    }    for (int x = 1; x <= n; x += 2) {        r.push_back(x);    }    return r;} bool valid(const vector<int>& p) {    for (size_t i = 0; i + 1 < p.size(); i++) {        if (abs(p[i] - p[i + 1]) == 1) {            return false;        }    }    return true;} int main() {    for (int n = 1; n <= 7; n++) {        vector<int> p = build(n);        cout << "n=" << n << ": ";        if (p.empty()) {            cout << "NO SOLUTION";        } else {            for (int x : p) {                cout << x << " ";            }            cout << (valid(p) ? "(valid)" : "(INVALID)");        }        cout << endl;    }    return 0;}

الحلقة الأولى تضيف الأعداد الزوجية 2 و4 و6، والثانية تضيف الفردية 1 و3 و5. فالمتجه 2 4 6 1 3 5 ويُطبع ملتصقًا: 246135.

الحيلة هنا هي تقسيم الأعداد إلى صنفين لا يتصلان بالشرط (أي زوجي وفردي)، ثم نرتب كل صنف وحده. وأكثر ما يقع الخطأ عند نقطة الربط بين الصنفين، فافحصها بعناية: آخر زوجي وأول فردي.

كيف أعرف أن المسألة مستحيلة؟

لم نضع n = 2 وn = 3 في قائمة المستحيلات اعتباطًا. التحقق: جرّب كل الترتيبات الممكنة للقيم الصغيرة. المكتبة <algorithm> فيها next_permutation التي تمر على كل ترتيبات متجه واحدًا واحدًا:

brute_force_all.cpp
#include <iostream>#include <vector>#include <algorithm>#include <cstdlib>using namespace std; int main() {    for (int n = 1; n <= 7; n++) {        vector<int> p(n);        for (int i = 0; i < n; i++) {            p[i] = i + 1;        }        int count = 0;        do {            bool ok = true;            for (int i = 0; i + 1 < n; i++) {                if (abs(p[i] - p[i + 1]) == 1) {                    ok = false;                }            }            if (ok) {                count++;            }        } while (next_permutation(p.begin(), p.end()));        cout << "n=" << n << ": " << count << " valid arrangements" << endl;    }    return 0;}
اضغط على أي سطر مضيء من الكود لقراءة شرحه هنا...
n=1: 1 valid arrangements n=2: 0 valid arrangements n=3: 0 valid arrangements n=4: 2 valid arrangements n=5: 14 valid arrangements n=6: 90 valid arrangements n=7: 646 valid arrangements

الجدول يؤكد: لا ترتيب صحيح عند n = 2 أو 3، وعند n = 4 يوجد ترتيبان فقط (2 4 1 3 و3 1 4 2)، ثم تتضاعف الاحتمالات. فبنيتنا صحيحة وحالتا الاستثناء صحيحتان. هذا المنهج (قوة غاشمة على القيم الصغيرة) هو أقوى أداة للمبرمج الإنشائي: يكشف النمط ويثبت الاستحالة ويفحص بناءك.

عدد الترتيبات n! ينمو بسرعة هائلة: 10! ≈ 3.6 مليون و13! ≈ 6 مليارات. فاستعمل القوة الغاشمة للقيم الصغيرة جدًا فقط (حتى n ≈ 9 أو 10).

مختبر تفاعلي (2): مولّد الأعداد المختلفة

أعطني n وS وسأبني لك n عددًا موجبًا مختلفًا مجموعها S، أو أخبرك أن ذلك مستحيل. انتبه للحد الأدنى الذي يظهر لك.

مشروع الدرس: مخطط مقاعد الحفل

برنامج يبني ترتيب الجلوس ويفحص نفسه.

الفكرة

في حفل المدرسة تريد ترتيب n طلاب (أرقامهم من 1 إلى n) في صف واحد بحيث لا يجلس رقمان متتاليان متجاورين. إن لم يكن ذلك ممكنًا اطبع NO SOLUTION. وتريد أن يتأكد برنامجك بنفسه من صحة ما بناه.

المطلوب منك
  1. اقرأ n. إن كان 2 أو 3 فاطبع NO SOLUTION وأنهِ البرنامج.
  2. ابنِ الترتيب: الأعداد الزوجية أولًا ثم الفردية، في vector<int>.
  3. اكتب فاحصًا يمر على كل جارين ويتأكد أن abs الفرق بينهما لا يساوي 1.
  4. اطبع الترتيب في سطر واحد تفصل بين أعداده مسافات.
  5. اطبع في السطر التالي Valid: yes أو Valid: no بحسب الفاحص.
مثالان على التشغيل

التشغيل الأول:

6
2 4 6 1 3 5 Valid: yes

التشغيل الثاني (مستحيل):

3
NO SOLUTION

تحقق ذهنيًا: مع n = 6: الزوجية 2 4 6 ثم الفردية 1 3 5. فروق الجيران: 2 و2 و5 و2 و2 وكلها ليست 1. وفي مسابقات البرمجة الحقيقية يقبل «الفاحص» أي ترتيب صحيح آخر مثل 3 1 4 2 5 ....

بعد أن تجرّب بنفسك: اعرض الحل
seating_chart.cpp
#include <iostream>
#include <vector>
#include <cstdlib>
using namespace std;

int main() {
    int n;
    cin >> n;
    if (n == 2 || n == 3) {
        cout << "NO SOLUTION" << endl;
        return 0;
    }

    vector<int> seat;
    for (int x = 2; x <= n; x += 2) {
        seat.push_back(x);
    }
    for (int x = 1; x <= n; x += 2) {
        seat.push_back(x);
    }

    bool valid = true;
    for (int i = 0; i + 1 < n; i++) {
        if (abs(seat[i] - seat[i + 1]) == 1) {
            valid = false;
        }
    }

    for (int i = 0; i < n; i++) {
        cout << seat[i] << (i + 1 < n ? " " : "\n");
    }
    cout << "Valid: " << (valid ? "yes" : "no") << endl;
    return 0;
}

1

نص بلا حرفين متجاورين متماثلين

سهل

اقرأ n. اطبع أي نص طوله n يستخدم الحرفين a وb فقط، ولا يحتوي حرفين متجاورين متماثلين.

المطلوب
  • استخدم الباقي i % 2 لاختيار الحرف.
  • ابنِ النص في متغير string بالإضافة s += ....
  • اطبع النص.
مثال على الإدخال والناتج المتوقع
7
abababa
تلميحات
  • النمط abab... يحقق الشرط دائمًا.
  • هذا النمط دوري بدورة طولها 2، تمامًا كما استخدمنا abc بدورة طولها 3.
نموذج الحل (بعد المحاولة)
alternating.cpp
// Challenge 1: alternating string
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    string s;
    for (int i = 0; i < n; i++) {
        s += (i % 2 == 0 ? 'a' : 'b');
    }
    cout << s << endl;
    return 0;
}
2

أعداد مختلفة بمجموع محدد

متوسط

اقرأ n وS. اطبع n عددًا صحيحًا موجبًا مختلفًا مجموعها يساوي S، أو اطبع NO إن كان ذلك مستحيلًا.

المطلوب
  • احسب الحد الأدنى n × (n + 1) / 2 واطبع NO إن كان S أصغر منه.
  • اطبع 1, 2, ..., n-1 ثم العدد الأخير S - (مجموع ما طبعت).
  • استخدم long long لأن القيم كبيرة.
مثال على الإدخال والناتج المتوقع
4 20
1 2 3 14
تلميحات
  • العدد الأخير أكبر من n-1 دائمًا، فهو مختلف عن البقية.
  • مع n = 4 وS = 20 تخرج الأعداد 1 2 3 14 (ويقبل أي جواب صحيح آخر في المسابقات).
نموذج الحل (بعد المحاولة)
distinct_numbers.cpp
// Challenge 2: n distinct positive numbers with sum S
#include <iostream>
using namespace std;

int main() {
    long long n, S;
    cin >> n >> S;
    if (S < n * (n + 1) / 2) {
        cout << "NO" << endl;
        return 0;
    }
    long long used = 0;
    for (long long i = 1; i < n; i++) {
        cout << i << " ";
        used += i;
    }
    cout << S - used << endl;
    return 0;
}

ملخص سريع

  • في المسائل الإنشائية نبني جوابًا يحقق شروطًا، وغالبًا يوجد أكثر من جواب مقبول يتحقق منه «فاحص».
  • الخطة: جرّب حالات صغيرة، اكتشف النمط، عمّمه، ثم اكتب فاحصًا وجرّب قيمًا كثيرة.
  • أدوات بناء شائعة: الإزاحة بالباقي، تقسيم الأعداد إلى صنفين (زوجي/فردي)، التكرار الدوري، وترك الباقي للعنصر الأخير.
  • اسأل دائمًا: ما القيم المستحيلة؟ أثبت ذلك بالتجربة الشاملة على القيم الصغيرة.
  • next_permutation تمر على كل ترتيبات متجه، وتصلح للقوة الغاشمة عند n صغير جدًا (حتى 9 أو 10).
  • انتبه لنقاط الربط بين الأجزاء المبنية (مثل آخر زوجي وأول فردي).
  • قبل الإرسال قارن بناءك بالفاحص على جميع القيم الصغيرة.

اقرأ كل عبارة ثم اختر صحيح أو خطأ. سيظهر التفسير مباشرة بعد إجابتك.

قاموس المصطلحات

المصطلحات الإنجليزية الأهم في هذا الدرس ومقابلها بالعربية:

Constructiveإنشائي

Checkerفاحص

Permutationتبديلة

Fixed pointنقطة ثابتة

Derangementتبديلة بلا نقاط ثابتة

Patternنمط

Parityالزوجية

كون العدد زوجيًا أو فرديًا.

Periodicدوري

next_permutationالتبديلة التالية
