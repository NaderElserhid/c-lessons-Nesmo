Greedy Algorithms

Take the best choice right now

What will you learn in this lesson?

  • Understand the idea of a greedy algorithm and why it is fast and short
  • Know that greed is not always correct and break it with a counterexample
  • Apply the "sort, then scan" template to budgets, waiting and activities
  • Solve the activity selection problem by sorting by end time
  • Check that greed is correct with the exchange argument and stress testing

Take the best now

At an open buffet you have a single plate. The greedy algorithm says: at every step take the best thing in front of you right now, do not think about the future and do not go back. A cashier giving you change does this: he hands you the largest coin that fits into the amount, then the largest coin that fits into the remainder, and so on.

Imagine climbing a mountain in fog, taking each step upward from where you stand. You may reach the real summit, or you may get stuck on a small hill that leads nowhere. Greedy algorithms are fast and simple, but they succeed only if the problem is of the kind in which blind climbing reaches the top.

The real challenge in greedy is not writing the code (it is very short), but knowing whether greed is correct for this problem. We will learn how to think about that.

The first example: making change

We have coins worth 25, 10, 5 and 1, and we want to pay 63 with as few coins as possible. We take the largest whenever we can:

make_change.cpp
int coins[] = {25, 10, 5, 1};int amount = 63, count = 0; for (int c : coins) {    while (amount >= c) {        amount -= c;        count++;        cout << c << " ";    }}cout << "=> " << count << " coins" << endl;

Six coins, and nothing better is possible. But does greed work always with coins? Try a different set of coins: 4, 3 and 1, and the amount 6:

int coins[] = {4, 3, 1};int amount = 6; int greedy = 0, rest = amount;for (int c : coins) {    greedy += rest / c;    rest %= c;} vector<int> best(amount + 1, 1000000);best[0] = 0;for (int a = 1; a <= amount; a++) {    for (int c : coins) {        if (a >= c) {            best[a] = min(best[a], best[a - c] + 1);        }    }}cout << "greedy = " << greedy << ", optimal = " << best[amount] << endl;
Click any highlighted line of code to read its explanation here...
greedy = 3, optimal = 2

Greed gave us three coins (4 + 1 + 1) while the optimum is two (3 + 3). Greed is not always correct! With American coins (25, 10, 5 and 1) it works, but with some other systems it fails. So do not use greed before you are sure it is correct.

Correct greed: buy the cheapest first

You have a budget and you want to buy the largest possible number of things. Here greed works: always start with the cheapest. Why? Because any more expensive alternative uses more of the budget and leaves you with fewer items:

shopping_budget.cpp
vector<int> price = {40, 10, 25, 5, 30};int budget = 70, spent = 0, items = 0; sort(price.begin(), price.end());for (int p : price) {    if (spent + p > budget) {        break;    }    spent += p;    items++;}cout << "bought " << items << " items, spent " << spent << endl;
Click any highlighted line of code to read its explanation here...
bought 4 items, spent 70

This is the most famous greedy template: sort, then scan. The two steps need O(n log n) (for sorting) and O(n) (for scanning), so the total is very fast. And most greedy problems come down to choosing the right "sorting criterion".

Reducing the wait: shortest first

In a service queue, if we start with the longest customer, everyone after them is delayed. If we start with the shortest, the total wait shrinks:

waiting_time.cpp
vector<int> t = {5, 2, 8, 3}; auto totalWait = [](const vector<int>& v) {    int wait = 0, sum = 0;    for (int x : v) {        sum += wait;        wait += x;    }    return sum;}; cout << "as given: " << totalWait(t) << endl;sort(t.begin(), t.end());cout << "shortest first: " << totalWait(t) << endl;

Activity selection: the most famous greedy example

You have n activities, each with a start and an end time, and you cannot attend two overlapping activities. What is the largest number you can attend? There are several greedy ideas: the earliest start? The shortest duration? The earliest end? The next lab tries all three in front of you:

Interactive lab (2): which greedy criterion is the right one?

The bars are the activities on a timeline. Press each criterion and notice how many activities it gets. Press "Random activities" and repeat the experiment several times: which criterion never loses?

Why does "earliest end" work?

The intuition: the activity that ends earliest leaves the longest remaining time for the other activities. No first choice is better than it: if the optimal solution had a different first activity that ends later, we could swap it for the earliest-ending one without losing anything (because it ends before it, so it overlaps no activity that follows). This argument is called the exchange argument, and it is the most common way to prove that greed is correct. The implementation: sort by end time, then scan the activities and choose every activity that starts after the end of the last activity you chose:

activity_scan.cpp
vector<pair<int, int>> a = {{1, 3}, {2, 4}, {3, 5}, {4, 6}};
int last = 0, count = 0;
for (auto& p : a) {
    if (p.first >= last) {
        count++;
        last = p.second;
    }
}
cout << count << endl;

What will this code print? (the activities are sorted by end time)

3 8

The activity (1,4) is chosen, so the last end becomes 4. The activity (2,5) overlaps and is rejected. The activity (4,6) starts at 4 so it is chosen and the last end is 6. And the activity (6,8) is chosen and the last end is 8. The total is 3 and the last end is 8.

Watch the condition p.first >= last (greater or equal). An activity that starts exactly when the previous one ends is usually allowed, but read the problem statement to know whether touching counts as overlapping.

How do I know greed will work?

  1. Work on your intuition: what is the "best" choice at each step? Try several sorting criteria.
  2. Try small examples by hand, and try to break your idea with a counterexample (as we did with the coins 4, 3 and 1).
  3. Ask about the exchange argument: can any optimal solution be converted to start with my greedy decision without loss?
  4. Check by program: compare your greedy solution with a brute-force solution on all small inputs (as we learned in the casework lesson).

Stress testing is your most loyal friend: writing a slow solution (which tries every possibility) and a greedy solution and comparing them on thousands of small random inputs exposes any wrong greedy idea within seconds.

Lesson project: the school activity fair

A program that picks the largest number of consecutive activities without overlap.

The idea

On the day of the school fair many workshops are held, each with a start and an end time, and a student cannot attend two overlapping workshops. You want a program that tells the student the maximum number of workshops he can attend, and prints his schedule.

What you must do
  1. Read n and then n workshops, each with s the start and e the end.
  2. Store each workshop in a pair with the end first and then the start (so they sort by end time automatically).
  3. Sort with sort and then scan: choose the workshop if its start is ≥ the end of the last chosen workshop.
  4. Print Max activities: k and then each chosen workshop on its own line in the form 9-10.
Two sample runs

First run:

7 9 10 10 12 9 11 11 13 12 14 13 15 10 11
Max activities: 4 9-10 10-11 11-13 13-15

Second run (everything overlaps):

3 1 5 2 6 3 7
Max activities: 1 1-5

Check it in your head: in the first, after sorting by end: we choose 9-10, then 10-11 (it starts exactly at 10), then 11-13, then 13-15. As for 9-11, 10-12 and 12-14, they overlap the chosen ones so we reject them.

After you try it yourself: show the solution
activity_fair.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> byEnd;
    for (int i = 0; i < n; i++) {
        int s, e;
        cin >> s >> e;
        byEnd.push_back({e, s});
    }
    sort(byEnd.begin(), byEnd.end());

    int lastEnd = -1, count = 0;
    vector<pair<int, int>> chosen;
    for (const auto& p : byEnd) {
        int s = p.second, e = p.first;
        if (s >= lastEnd) {
            count++;
            lastEnd = e;
            chosen.push_back({s, e});
        }
    }

    cout << "Max activities: " << count << endl;
    for (const auto& c : chosen) {
        cout << c.first << "-" << c.second << endl;
    }
    return 0;
}

1

The most books

Easy

Read n and budget and then the prices of n books. Print the largest number of books you can buy without exceeding the budget (each book can be bought once).

Requirements
  • Store the prices in a vector<int> and sort them ascending.
  • Buy the cheapest, then the next cheapest, as long as the total does not exceed the budget.
  • Print only the number of books.
Example input and expected output
6 50 20 10 15 30 5 25
4
Hints
  • Stop at the first book you cannot afford (break), since everything after it is more expensive.
  • With the prices 5 10 15 20 25 30 and the budget 50 we buy 5, 10, 15 and 20, that is 4 books.
Sample solution (after you try)
books_budget.cpp
// Challenge 1: buy as many books as possible
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n, budget;
    cin >> n >> budget;
    vector<int> price(n);
    for (int i = 0; i < n; i++) {
        cin >> price[i];
    }
    sort(price.begin(), price.end());

    int spent = 0, count = 0;
    for (int p : price) {
        if (spent + p > budget) {
            break;
        }
        spent += p;
        count++;
    }
    cout << count << endl;
    return 0;
}
2

Rescue boats

Medium

n people want to cross a river, each person's weight is known, and each boat holds at most two people provided the total of their weights does not exceed limit (and any one person alone certainly fits). Print the smallest number of boats.

Requirements
  • Sort the weights.
  • Use two pointers: i for the lightest and j for the heaviest.
  • The heaviest always boards, and if the lightest fits with him, both board; then move the pointers.
Example input and expected output
5 10 2 9 5 5 8
3
Hints
  • In each boat: j--, and if there is room for the lightest, also i++. Increase the boat counter.
  • With the weights 2 9 5 5 8 and the limit 10 we need 3 boats: the 9 alone, (2,8), and (5,5).
Sample solution (after you try)
rescue_boats.cpp
// Challenge 2: rescue boats (at most two people per boat)
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n, limit;
    cin >> n >> limit;
    vector<int> w(n);
    for (int i = 0; i < n; i++) {
        cin >> w[i];
    }
    sort(w.begin(), w.end());

    int i = 0, j = n - 1, boats = 0;
    while (i <= j) {
        if (i < j && w[i] + w[j] <= limit) {
            i++;
        }
        j--;
        boats++;
    }
    cout << boats << endl;
    return 0;
}

Quick summary

  • A greedy algorithm picks the best local choice at every step and never goes back; it is usually fast and short.
  • Greed is **not always correct**: coins {4, 3, 1} and the amount 6 give 3 coins instead of 2.
  • The most famous template: **sort, then scan**, and the key to the solution is choosing the right sorting criterion.
  • To buy the most items with a budget: cheapest first. To reduce waiting: shortest first.
  • To choose the most non-overlapping activities: sort by **end time** and pick whatever starts after the last chosen end.
  • We prove greed correct with the exchange argument, or break it with a small counterexample.
  • Always check by comparing your greedy solution with a brute-force solution on many small inputs.

Glossary

The most important terms in this lesson:

Greedy

An algorithm that picks the best local choice at each step without going back.

Local optimum

The best possible choice at the current step only.

Global optimum

The best possible solution for the whole problem.

Counterexample

A single case that breaks the idea and proves it wrong.

Exchange argument

A proof that any optimal solution can be converted to agree with the greedy decision.

Interval

A span of time with a start and an end.

Overlap

Two intervals sharing part of the time.

Activity selection

The problem of finding the most non-overlapping intervals.

Sort then scan

A common greedy pattern: a sort followed by a single pass.

Two pointers

A technique where we walk from both ends toward the middle.

Canonical coin system

A coin system in which greed always gives the optimal answer.

Brute force

A simple solution that tries every possibility, for comparison.
