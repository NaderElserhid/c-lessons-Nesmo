Time Complexity

How to know a solution will pass before writing it

What will you learn in this lesson?

  • Understand why we count operations instead of measuring seconds
  • Work out the complexity of single loops, nested loops and the divide-by-2 loop
  • Read the Big-O symbol and apply the rules of ignoring constants and keeping the largest term
  • Estimate whether your solution will pass from the problem limits and the 10⁸ operations rule
  • Learn the cost of common container operations and estimate memory use

Why is my program slow?

You wrote a correct solution to a problem, tried it on the small examples and it worked, then you submitted it and got the verdict: Time Limit Exceeded. The cause is not a logic error; it is that your program works in a way that cannot handle large sizes. The study of time complexity teaches you to know this before you write a single line.

Imagine looking for a name in a thousand-page phone book. The first way is to flip page by page (a thousand steps in the worst case). The second is to open at the middle and throw away half the book each time (only ten steps!). Both ways are correct, but the gap between them balloons as the book grows.

We do not measure time in seconds because seconds change with your machine. Instead we count the number of basic operations as a function of the input size n. That tells us how a solution behaves when n grows from a hundred to a million.

With n = 16 the single loop ran 16 times, the nested one 256 times, and the loop that divides by 2 only four times. All three numbers are small now, but watch what happens when n grows:

growth_table.cpp
long long ns[] = {10, 1000, 100000};
for (long long n : ns) {
    int lg = 0;
    for (long long x = n; x > 1; x /= 2) {
        lg++;
    }

10: log=3 nlogn=30 n^2=100 1000: log=9 nlogn=9000 n^2=1000000 100000: log=16 nlogn=1600000 n^2=10000000000

When n became a hundred thousand, the nested loop reached ten billion operations, while dividing by 2 stayed at 16 steps! That is the difference between a solution that passes and one that collapses.

The Big-O symbol

We summarize the number of operations with the symbol O( ), using two simple rules:

  • Ignore constants: the work 3n or 5n or n + 100 are all called O(n).
  • Keep the largest term: the work n² + n is O(n²), because n² dominates when n grows.
SymbolNameA familiar example
O(1)ConstantReading v[i], or v.size()
O(log n)LogarithmicSearching a set or map, and binary search
O(n)LinearOne loop over all the elements
O(n log n)Linearithmicsort
O(n²)QuadraticTwo nested loops over n
O(n³)CubicThree nested loops
O(2ⁿ)ExponentialTrying every subset
O(n!)FactorialTrying every ordering of n elements

The symbol usually describes the worst case. If you look for a number in a vector with a for loop and it might be in the very last place, the solution is O(n) even if you sometimes find it on the first step.

Predict before you run
predict_count.cpp
int n = 1024;
int cnt = 0;
for (int i = 1; i <= n; i *= 2) {
    for (int j = 0; j < n; j++) {
        cnt++;
    }
}
cout << cnt << endl;

What will this code print? (the outer loop doubles i on every turn)

11264

The outer loop takes the values 1, 2, 4 ... 1024, which is 11 turns. On each turn the inner loop runs 1024 times. The total is 11 × 1024 = 11264, which is the O(n log n) pattern.

Interactive lab: will my solution pass?

Move the n slider and watch the number of operations for each kind of complexity. We assume a rough rule: a computer runs about a hundred million (10⁸) simple operations per second, so if the count goes beyond that, the program is in danger. (This is only a rule for estimating; the truth changes with the operation and the machine.)

How much can each complexity handle?

With the rough rule of 10⁸ operations, we can guess the largest n each complexity can handle in one second. Use this table as a compass, not as a strict law:

ComplexityApproximate largest n
O(n)Up to a few million (≈ 10⁷)
O(n log n)Up to about a million (≈ 10⁶)
O(n²)Up to a few thousand (≈ 10⁴)
O(n³)Up to a few hundred (≈ 500)
O(2ⁿ)Up to about 20 to 25
O(n!)Up to about 10 to 11

The practical use: read the problem's limits first. If n goes up to 2·10⁵ you need O(n log n) or faster, and you should never try two nested loops. If n ≤ 20, a complete search is acceptable!

The cost of operations we use every day

OperationCost
v[i] and v.size()O(1)
v.push_back(x)O(1) on average
v.insert(v.begin(), x)O(n) (it shifts every element)
s.insert / find / erase on set and mapO(log n)

A single loop can hide another loop! The command v.insert(v.begin(), x) inside a for loop makes the solution O(n²), because each insertion shifts all the elements. Calling a linear search on a vector inside a loop is the same.

And what about memory?

Complexity has another face: space, meaning how much memory your program needs. Contests usually set a limit of around 256 megabytes. Estimate quickly: an int takes 4 bytes and a long long takes 8:

memory_estimate.cpp
long long n = 10000000;
cout << "ints:       " << n * sizeof(int) / 1000000 << " MB" << endl;
cout << "long longs: " << n * sizeof(long long) / 1000000 << " MB" << endl;
ints: 40 MB long longs: 80 MB

An array of ten million ints takes 40 megabytes, which is fine, but an array of a billion numbers will blow the memory before you even start. Always check the limits before you reserve memory.

A different kind of loop: i < j

Look at this nested loop: the inner loop starts from i + 1, not from 0, so it does not count every pair twice:

triangle_loop.cpp
int n = 5;
int cnt = 0;
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        cnt++;
    }
}
cout << cnt << endl;
10

With n = 5 the count is 10, that is 5 × 4 ÷ 2. In general it is n(n-1)/2, which is roughly half of n², so it is also called O(n²) because constants are ignored.

Lesson project: the pass estimator

A small tool that judges whether your solution will pass before you write it.

The idea

Before writing any solution you want to know: if my solution has a certain complexity and the input size is n, is the number of operations within a budget of 10⁸? You will build a calculator that answers instantly.

What you must do
  1. Read q and then q queries. Each query is n and kind, where 1 means O(n), 2 means O(n log n), 3 means O(n²) and 4 means O(n³).
  2. Write a function that computes the number of operations as a long long (the value of log n is the number of times n can be divided by 2 until it becomes 1).
  3. Print the query in the form 100000 O(n): 100000 operations -> OK.
  4. If the count exceeds 100000000, print TOO SLOW instead of OK.
Two sample runs

First run:

4 100000 1 100000 2 100000 3 1000 4
100000 O(n): 100000 operations -> OK 100000 O(n log n): 1600000 operations -> OK 100000 O(n^2): 10000000000 operations -> TOO SLOW 1000 O(n^3): 1000000000 operations -> TOO SLOW

Second run:

3 1000000 2 10000 3 500 3
1000000 O(n log n): 19000000 operations -> OK 10000 O(n^2): 100000000 operations -> OK 500 O(n^2): 250000 operations -> OK

Check it in your head: log₂(100000) equals 16 with integer division, so the n log n class gives 1600000. And with n = 1000 cubic we get a billion, which is more than 10⁸.

After you try it yourself: show the solution
will_it_pass.cpp
#include <iostream>
using namespace std;

long long operations(long long n, int kind) {
    int lg = 0;
    for (long long x = n; x > 1; x /= 2) {
        lg++;
    }
    if (kind == 1) return n;
    if (kind == 2) return n * lg;
    if (kind == 3) return n * n;
    return n * n * n;
}

int main() {
    const long long LIMIT = 100000000;
    const char* names[] = {"", "O(n)", "O(n log n)", "O(n^2)", "O(n^3)"};
    int q;
    cin >> q;
    while (q--) {
        long long n;
        int kind;
        cin >> n >> kind;
        long long ops = operations(n, kind);
        cout << n << " " << names[kind] << ": " << ops << " operations -> ";
        if (ops <= LIMIT) {
            cout << "OK" << endl;
        } else {
            cout << "TOO SLOW" << endl;
        }
    }
    return 0;
}

Counting pairs

Easy

Read the number n. Print the number of pairs (i, j) that satisfy 0 ≤ i < j < n, by counting inside two nested loops.

Requirements
  • Use a counter of type long long.
  • The outer loop runs over i and the inner loop starts from i + 1.
  • Print only the final count.
Example input and expected output
1000
499500
Hints
  • Check your answer with the formula n × (n - 1) / 2.
  • With n = 1000 the answer is 499500.
Sample solution (after you try)
count_pairs.cpp
// Challenge 1: how many pairs (i, j) with i < j ?
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long cnt = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            cnt++;
        }
    }
    cout << cnt << endl;
    return 0;
}
2

How many times do we halve?

Medium

Read the number n, and print how many times n can be divided by 2 (integer division) until it becomes 1. This is log₂ n rounded down.

Requirements
  • Use long long because n may reach billions.
  • Repeat n /= 2 and count the steps while n > 1.
  • Print the number of steps.
Example input and expected output
1000
9
Hints
  • With n = 1000 the answer is 9, because 2⁹ = 512 and 2¹⁰ = 1024.
  • Try n = 1: the answer is 0, because the loop never runs.
Sample solution (after you try)
count_halvings.cpp
// Challenge 2: how many halvings until we reach 1 ?
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    int steps = 0;
    while (n > 1) {
        n /= 2;
        steps++;
    }
    cout << steps << endl;
    return 0;
}

Quick summary

  • Complexity describes **how the number of operations grows** as the input size n grows, not the time in seconds.
  • We ignore constants and keep the largest term: 3n² + 5n is O(n²).
  • From fastest to slowest: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!).
  • An estimating rule: about 10⁸ simple operations per second. Read the problem limits to know the complexity you need.
  • A loop that divides the value by 2 runs log n times; two nested loops over n run n² times.
  • Beware of hidden loops: insert at the front of a vector inside a loop makes the solution O(n²).
  • Estimate memory too: int = 4 bytes and long long = 8 bytes, and ten million ints = 40 megabytes.

Glossary

The most important terms in this lesson:

Time complexity

A description of how the number of operations grows with the input size.

Space complexity

A description of how much memory the program needs.

Big-O

A symbol that summarizes the growth of operations in the worst case, such as O(n).

Input size

The symbol n: the number of elements, or the value of the number the program processes.

Constant time

An O(1) operation whose time is not affected by the input size.

Logarithmic

Very slow growth: it goes up one step when n doubles, as in O(log n).

Linear

The work grows in proportion to n, as in O(n).

Quadratic

The work grows with the square of n, as in O(n²).

Exponential

The work doubles with every extra element, as in O(2ⁿ).

Worst case

The largest number of operations the program might need for any input of size n.

TLE

A verdict meaning the program did not finish within the allowed time.

Amortized

The cost of an operation spread over a series of operations, as with push_back.
