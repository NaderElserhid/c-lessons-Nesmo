Constructive Algorithms

Build the answer that meets the conditions

What will you learn in this lesson?

  • Understand the difference between computing an answer and building one, and why one correct answer is enough
  • Follow the plan: small cases, then a pattern, then a construction, then a checker
  • Use building tools: a shift with the remainder, an even/odd split, and periodic repetition
  • Handle impossible cases and prove them by exhaustive search on small values
  • Write a checker that verifies what you built

Build the answer yourself

In most problems we compute a single correct answer (a sum, a smallest value, a count...). But in constructive problems you are asked to build something that satisfies conditions: an arrangement of numbers, a string, a table, a set. The nice thing is that a problem often has more than one correct answer, and any one of them is accepted! (A "checker" judges you, making sure that what you built meets the conditions.)

It is like building a house from blocks under a rule: "never put two red blocks side by side." There is no single correct house; instead you look for an organized method that guarantees any house you build is correct, and you know when building is impossible.

The plan for every constructive problem:

  1. Try small cases by hand (n = 1, then 2, then 3...) and look for a pattern.
  2. Generalize the pattern into a building rule (a shift, an even/odd split, periodic repetition, starting with the largest...).
  3. Write a checker that makes sure the output meets the conditions, and try it on many values.
  4. Handle the impossible: which values have no solution? And how do you make sure?

The first example: nobody in their place

Arrange the numbers 1 to n so that no number stands in its original position. The elegant solution: shift everyone by one step (like students rotating seats). We write the solution and then the checker:

When does this construction fail? When n = 1: there is only the number 1 and it is necessarily in its place. That is an impossible case that no method can solve. Always remember to ask: "are there inputs with no solution?".

The second example: distinct numbers with a known sum

Give me n distinct positive integers whose sum is exactly S. First: the smallest possible sum is 1+2+...+n, so if S is smaller than it, there is no solution. Otherwise we build: 1, 2, ..., n-1 and put all the remainder in the last number:

distinct_sum.cpp
long long n = 4, S = 20;long long minSum = n * (n + 1) / 2; if (S < minSum) {    cout << "NO" << endl;} else {    long long used = 0;    for (long long i = 1; i < n; i++) {        cout << i << " ";        used += i;    }    cout << S - used << endl;}
Click any highlighted line of code to read its explanation here...

The numbers 1 2 3 14 are distinct and sum to 20. This is the "start with the smallest and let the last one absorb the rest" style, and it recurs in constructive problems.

The third example: building a periodic string

Build a string from the letters a, b and c of length n containing no three-letter palindromic segment (such as aba). The solution: repeat abc periodically, because every three consecutive letters in it are different, so the first and the third are never equal:

no_palindromes.cpp
int n = 7;string s;for (int i = 0; i < n; i++) {    s += "abc"[i % 3];} bool ok = true;for (int i = 0; i + 2 < n; i++) {    if (s[i] == s[i + 2]) {        ok = false;    }}cout << s << " " << (ok ? "valid" : "invalid") << endl;
Click any highlighted line of code to read its explanation here...
abcabca valid

Periodic patterns through the remainder are the simplest building tools: "abc"[i % 3] gives you the right letter for any position.

The party seating problem: even, then odd

Seat n students (numbered 1 to n) in a row of seats so that no two students with consecutive numbers (such as 4 and 5) sit next to each other. How do we build the arrangement? Think: if we put the even numbers together, the difference between their neighbors is always 2, and likewise for the odd ones! We write the solution, check it, and try it for n from 1 to 7:

no_consecutive_neighbors.cpp
#include <iostream>#include <vector>#include <cstdlib>using namespace std; vector<int> build(int n) {    vector<int> r;    if (n == 2 || n == 3) {        return r;    }    for (int x = 2; x <= n; x += 2) {        r.push_back(x);    }    for (int x = 1; x <= n; x += 2) {        r.push_back(x);    }    return r;} bool valid(const vector<int>& p) {    for (size_t i = 0; i + 1 < p.size(); i++) {        if (abs(p[i] - p[i + 1]) == 1) {            return false;        }    }    return true;} int main() {    for (int n = 1; n <= 7; n++) {        vector<int> p = build(n);        cout << "n=" << n << ": ";        if (p.empty()) {            cout << "NO SOLUTION";        } else {            for (int x : p) {                cout << x << " ";            }            cout << (valid(p) ? What will this code print? (even first, then odd, without separators)

246135

The first loop adds the even numbers 2, 4 and 6, and the second adds the odd ones 1, 3 and 5. So the vector is 2 4 6 1 3 5 and it is printed stuck together: 246135.

The trick here is to split the numbers into two classes that do not connect under the condition (even and odd), and then arrange each class on its own. The mistake most often happens at the joining point between the two classes, so check it carefully: the last even and the first odd.

How do I know the problem is impossible?

We did not put n = 2 and n = 3 on the impossible list at random. The check: try every possible arrangement for the small values. The <algorithm> library has next_permutation, which goes through all the arrangements of a vector one by one:

brute_force_all.cpp
#include <iostream>#include <vector>#include <algorithm>#include <cstdlib>using namespace std; int main() {    for (int n = 1; n <= 7; n++) {        vector<int> p(n);        for (int i = 0; i < n; i++) {            p[i] = i + 1;        }        int count = 0;        do {            bool ok = true;            for (int i = 0; i + 1 < n; i++) {                if (abs(p[i] - p[i + 1]) == 1) {                    ok = false;                }            }            if (ok) {                count++;            }        } while (next_permutation(p.begin(), p.end()));        cout << "n=" << n << ": " << count << " valid arrangements" << endl;    }    return 0;}

n=1: 1 valid arrangements n=2: 0 valid arrangements n=3: 0 valid arrangements n=4: 2 valid arrangements n=5: 14 valid arrangements n=6: 90 valid arrangements n=7: 646 valid arrangements

The table confirms: there is no valid arrangement at n = 2 or 3, at n = 4 there are only two (2 4 1 3 and 3 1 4 2), and then the possibilities multiply. So our construction is right and the two exception cases are right. This approach (brute force on small values) is the strongest tool of the constructive programmer: it reveals the pattern, proves impossibility, and checks your construction.

The number of arrangements n! grows at an enormous speed: 10! ≈ 3.6 million and 13! ≈ 6 billion. So use brute force only for very small values (up to n ≈ 9 or 10).

Lesson project: the party seating chart

A program that builds the seating arrangement and checks itself.

The idea

At the school party you want to arrange n students (numbered 1 to n) in one row so that no two consecutive numbers sit side by side. If that is not possible, print NO SOLUTION. And you want your program to verify by itself that what it built is correct.

What you must do
  1. Read n. If it is 2 or 3, print NO SOLUTION and end the program.
  2. Build the arrangement: the even numbers first and then the odd ones, in a vector<int>.
  3. Write a checker that walks over every two neighbors and makes sure the abs of their difference is not 1.
  4. Print the arrangement on one line with its numbers separated by spaces.
  5. On the next line print Valid: yes or Valid: no according to the checker.
Two sample runs

First run:

6
2 4 6 1 3 5 Valid: yes

Second run (impossible):

3
NO SOLUTION

Check it in your head: with n = 6: the evens 2 4 6 and then the odds 1 3 5. The neighbor differences: 2, 2, 5, 2, 2, and none is 1. In real programming contests the "checker" accepts any other valid arrangement too, such as 3 1 4 2 5 ....

After you try it yourself: show the solution
seating_chart.cpp
#include <iostream>
#include <vector>
#include <cstdlib>
using namespace std;

int main() {
    int n;
    cin >> n;
    if (n == 2 || n == 3) {
        cout << "NO SOLUTION" << endl;
        return 0;
    }

    vector<int> seat;
    for (int x = 2; x <= n; x += 2) {
        seat.push_back(x);
    }
    for (int x = 1; x <= n; x += 2) {
        seat.push_back(x);
    }

    bool valid = true;
    for (int i = 0; i + 1 < n; i++) {
        if (abs(seat[i] - seat[i + 1]) == 1) {
            valid = false;
        }
    }

    for (int i = 0; i < n; i++) {
        cout << seat[i] << (i + 1 < n ? " " : "\n");
    }
    cout << "Valid: " << (valid ? "yes" : "no") << endl;
    return 0;
}

Homework challenges

Two short challenges to solve on your own after the lesson. Write your solution in a .cpp file, compile and run it, and compare your output with the expected output. Try first, open a hint only if you get stuck, and look at the sample solution only after a serious attempt.

1

A string with no two equal neighbors

Easy

Read n. Print any string of length n that uses only the letters a and b and contains no two equal adjacent letters.

Requirements
  • Use the remainder i % 2 to choose the letter.
  • Build the string in a string variable by appending with s += ....
  • Print the string.
Example input and expected output
7
abababa
Hints
  • The pattern abab... always satisfies the condition.
  • This pattern is periodic with a cycle of length 2, just as we used abc with a cycle of length 3.
Sample solution (after you try)
alternating.cpp
// Challenge 1: alternating string
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    string s;
    for (int i = 0; i < n; i++) {
        s += (i % 2 == 0 ? 'a' : 'b');
    }
    cout << s << endl;
    return 0;
}
2

Distinct numbers with a given sum

Medium

Read n and S. Print n distinct positive integers whose sum equals S, or print NO if that is impossible.

Requirements
  • Compute the minimum n × (n + 1) / 2 and print NO if S is smaller than it.
  • Print 1, 2, ..., n-1 and then the last number S - (the sum of what you printed).
  • Use long long because the values are large.
Example input and expected output
4 20
1 2 3 14
Hints
  • The last number is always greater than n-1, so it is different from the rest.
  • With n = 4 and S = 20 the numbers 1 2 3 14 come out (and any other valid answer is accepted in contests).
Sample solution (after you try)
distinct_numbers.cpp
// Challenge 2: n distinct positive numbers with sum S
#include <iostream>
using namespace std;

int main() {
    long long n, S;
    cin >> n >> S;
    if (S < n * (n + 1) / 2) {
        cout << "NO" << endl;
        return 0;
    }
    long long used = 0;
    for (long long i = 1; i < n; i++) {
        cout << i << " ";
        used += i;
    }
    cout << S - used << endl;
    return 0;
}

Quick summary

  • In constructive problems we build an answer that meets conditions, and often more than one answer is accepted, verified by a "checker".
  • The plan: try small cases, discover the pattern, generalize it, then write a checker and try many values.
  • Common building tools: a shift with the remainder, splitting numbers into two classes (even/odd), periodic repetition, and leaving the rest to the last element.
  • Always ask: which values are impossible? Prove it by exhaustive search on small values.
  • next_permutation goes through all arrangements of a vector, and suits brute force when n is very small (up to 9 or 10).
  • Watch the joining points between the built parts (such as the last even and the first odd).
  • Before submitting, compare your construction with the checker on all small values.

Glossary

The most important terms in this lesson:

Constructive

A problem that asks you to build an answer meeting conditions, not just compute one.

Checker

A small program that makes sure the built answer meets the problem's conditions.

Permutation

An arrangement of the numbers 1..n in which each value appears once.

Fixed point

A number that stays in its original position in a permutation.

Derangement

A permutation in which no number stays in its position.

Pattern

A repeating rule that we discover from small cases.

Parity

Whether a number is even or odd.

Periodic

Its pattern repeats after a fixed number of elements.

Impossible case

Values for which no answer meets the conditions.

Brute force

Trying every possibility on small values.

next_permutation

A function that moves a vector to the next arrangement among all of them.

Any valid answer

The problem accepts any output that meets the conditions, not one specific output.
