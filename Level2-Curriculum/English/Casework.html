Casework

Split the problem into small cases

What will you learn in this lesson?

  • Split a problem into exhaustive, mutually exclusive cases and solve each one
  • Order the conditions: exceptions first, then from most specific to most general
  • Tell an else if chain from an independent if, and always use braces
  • Shrink many cases with counting or with a remainder formula
  • Check your solution with boundary values and by comparing it with a brute-force solution

Sorting the mail into boxes

In a post office every letter goes into exactly one box according to its city. No letter is left without a box, and no letter goes into two boxes. With this idea many problems are solved: we split all the possibilities into cases, and solve each case separately in a simple way. This is casework.

Good cases satisfy two conditions: they are exhaustive, so no possibility slips through, and mutually exclusive, so no possibility falls into two cases. And if each case has its simple answer, you have solved the hard problem.

Our tools here are old and familiar: if / else if / else. What is new is the way of thinking: how do we choose the cases? In what order do we check them? And how do we make sure we have not forgotten a case?

The first example: kinds of triangles

We give you three sides, and you must say what kind of triangle they make. Notice the order of the cases: we start with the exceptions (a non-positive side, no triangle forms), then the more specific cases (equilateral) before the more general (isosceles), and finally "what remains". Click the highlighted lines:

triangle_cases.cpp
#include <iostream>#include <string>using namespace std; string classify(int a, int b, int c) {    if (a <= 0 || b <= 0 || c <= 0) {        return "invalid";    }    if (a + b <= c || a + c <= b || b + c <= a) {        return "not a triangle";    }    if (a == b && b == c) {        return "equilateral";    }    if (a == b || b == c || a == c) {        return "isosceles";    }    return "scalene";} int main() {    cout << classify(3, 3, 3) << endl;    cout << classify(3, 3, 5) << endl;    cout << classify(3, 4, 5) << endl;    cout << classify(1, 2, 3) << endl;    cout << classify(0, 4, 4) << endl;    return 0;}

The ordering rule: put the conditions that knock out strange inputs first, then the cases from most specific to most general. If we checked "isosceles" before "equilateral", every equilateral triangle would be misclassified.

The second example: the leap year

A leap year has 29 days in February. Its rule is three ordered cases: if divisible by 400 it is a leap year; otherwise, if divisible by 100 it is not; otherwise it is a leap year if divisible by 4. See the effect of the order:

leap_year.cpp
#include <iostream>using namespace std; bool isLeap(int y) {    if (y % 400 == 0) {        return true;    }    if (y % 100 == 0) {        return false;    }    return y % 4 == 0;} int daysInMonth(int y, int m) {    if (m == 2) {        return isLeap(y) ? 29 : 28;    }    if (m == 4 || m == 6 || m == 9 || m == 11) {        return 30;    }    return 31;} int main() {    int years[] = {1900, 2000, 2023, 2024};    for (int y : years) {        cout << y << ": february has " << daysInMonth(y, 2) << " days" << endl;    }    return 0;}

else if versus a new if

A chain if / else if / else guarantees that only one case runs (the first true one). Writing a new if is an independent question with no relation to what came before:

Predict before you run
predict_chain.cpp
int x = 15;
if (x % 3 == 0) {
    cout << "A";
} else if (x % 5 == 0) {
    cout << "B";
} else {
    cout << "C";
}
if (x % 5 == 0) {
    cout << "D";
}
cout << endl;

What will this code print? (watch the difference between else if and a new if)

AD

The first chain enters only the first true condition (A) and ignores the rest. The second if is independent and its condition is true (15 is divisible by 5), so it prints D. The output is AD.

And do not forget the braces { }: without them the condition governs only one line, and a strange error may appear:

missing_braces.cpp
#include <iostream>
using namespace std;

int main() {
    int x = 5;
    if (x > 3)
        cout << "big" << endl;
        cout << "really big" << endl;
    else
        cout << "small" << endl;
    return 0;
}

The second line after the if is not part of it, so the chain was cut, and the else became an orphan. Make braces a permanent habit.

When the cases shrink into a formula

Sometimes the cases look many but there is a pattern among them. In rock-paper-scissors we have nine possible games, but they boil down to a remainder formula (the modular arithmetic lesson again!):

How do you make sure you have not forgotten a case?

The most dangerous flaw of this method is forgetting a case. You have three lines of defense:

  1. Boundaries: try the small and dividing values: 0, 1, equal values and negatives.
  2. Completeness: ask "what happens if no case holds?" and add a final else that catches the rest.
  3. Brute force: write a slow solution that tries every possibility, and compare it with your fast solution on all the small values:
check_by_brute_force.cpp
#include <iostream>using namespace std; // Can n be written as the sum of two positive even numbers?bool byCases(int n) {    return n % 2 == 0 && n >= 4;} bool byBrute(int n) {    for (int a = 2; a < n; a += 2) {        int b = n - a;        if (b >= 2 && b % 2 == 0) {            return true;        }    }    return false;} int main() {    int mismatches = 0;    for (int n = 1; n <= 50; n++) {        if (byCases(n) != byBrute(n)) {            mismatches++;            cout << "mismatch at n = " << n << endl;        }    }    cout << "checked 50 values, mismatches: " << mismatches << endl;    return 0;}
Click any highlighted line of code to read its explanation here...

This trick (comparing a clever solution with a dumb one on small values) is called stress testing, and it is among the strongest habits of professional programmers. Make it your habit before submitting any solution.

Lesson project: the amusement-park ticket calculator

A program that picks the right price according to age, day and student card.

The idea

You run the ticket window at an amusement park, and your prices depend on the visitor's age, the day of the visit, and whether they have a student card. You want a program that computes the price without mistakes whatever the input.

What you must do
  1. Read three numbers: age, weekend (1 if the day is a weekend, otherwise 0), and student (1 if they have a student card, otherwise 0).
  2. The base price in riyals: under 4 years 0; from 4 to 12 years 10; from 13 to 17 15; from 18 to 59 it is 25 (or 15 if a student); and 60 and over 10.
  3. On the weekend 20% of the price is added (price / 5 with integer division).
  4. Print Ticket price: P SAR.
Two sample runs

First run (a child on an ordinary day):

10 0 0
Ticket price: 10 SAR

Second run (a student on the weekend):

30 1 1
Ticket price: 18 SAR

Check it in your head: in the second, the age is 30 so the base is 25, but the student card makes it 15, and on the weekend we add 20% (3) so it becomes 18. Notice that the age conditions form one chain ordered from smallest to largest, so we do not need to write a lower bound for each case (it is simply "if the previous ones did not hold").

After you try it yourself: show the solution
ticket_price.cpp
#include <iostream>
using namespace std;

int main() {
    int age, weekend, student;
    cin >> age >> weekend >> student;

    int price;
    if (age < 4) {
        price = 0;
    } else if (age <= 12) {
        price = 10;
    } else if (age <= 17) {
        price = 15;
    } else if (age <= 59) {
        price = student ? 15 : 25;
    } else {
        price = 10;
    }

    if (weekend == 1) {
        price = price + price / 5;
    }
    cout << "Ticket price: " << price << " SAR" << endl;
    return 0;
}

Homework challenges

Two short challenges to solve on your own after the lesson. Write your solution in a .cpp file, compile and run it, and compare your output with the expected output. Try first, open a hint only if you get stuck, and look at the sample solution only after a serious attempt.

1

The median of three

Easy

Read three integers, which may be different or equal. Print their median: the number that is neither the smallest nor the largest, without using sort.

Requirements
  • Use only an if / else if / else chain.
  • A number is the median if it lies between the others (whichever of them is larger).
  • Print the median.
Example input and expected output
7 2 9
7
Hints
  • The number a is the median if (a >= b && a <= c) || (a <= b && a >= c) holds.
  • If neither a nor b is the median, then the median is necessarily c.
Sample solution (after you try)
median_of_three.cpp
// Challenge 1: median of three numbers (no sorting)
#include <iostream>
using namespace std;

int main() {
    int a, b, c;
    cin >> a >> b >> c;
    int med;
    if ((a >= b && a <= c) || (a <= b && a >= c)) {
        med = a;
    } else if ((b >= a && b <= c) || (b <= a && b >= c)) {
        med = b;
    } else {
        med = c;
    }
    cout << med << endl;
    return 0;
}
2

Cutting the cake

Medium

A round cake is to be cut into s exactly equal pieces using straight cuts that all pass through its center. Each cut divides the cake along a full diameter. Read s (up to 10¹²) and print the smallest number of cuts.

Requirements
  • Think of three cases: s = 1 needs no cuts at all.
  • An even number of pieces: each cut gives two pieces, so we need s / 2.
  • An odd number greater than 1: equal division is possible only with s cuts.
Example input and expected output
7
7
Hints
  • Use long long because s is large.
  • Try by hand: eight pieces need 4 cuts, and seven pieces need 7.
Sample solution (after you try)
cake_cuts.cpp
// Challenge 2: straight cuts through the center of a round cake
#include <iostream>
using namespace std;

int main() {
    long long s;
    cin >> s;
    long long cuts;
    if (s == 1) {
        cuts = 0;
    } else if (s % 2 == 0) {
        cuts = s / 2;
    } else {
        cuts = s;
    }
    cout << cuts << endl;
    return 0;
}

Quick summary

  • Casework: we split the possibilities into **exhaustive** cases (no possibility slips through) and **mutually exclusive** ones (no possibility falls into two), and solve each case easily.
  • Order the conditions: exceptions first, then from most specific to most general, then else for the rest.
  • A chain if / else if / else runs only one case, and a new if is an independent question.
  • Do not skip the braces { }; without them the condition governs only one line.
  • Sometimes many cases shrink into a formula (such as the remainder in rock-paper-scissors) or into counting (even/odd).
  • Try the boundaries: 0, 1, equal values and negatives, and finish with an else that catches what you did not think of.
  • Compare your solution on small values with a brute-force solution to discover forgotten cases.

Glossary

The most important terms in this lesson:

Casework

Splitting the problem into cases, each solved on its own.

Case

A group of possibilities that share one property.

Exhaustive

The cases cover every possibility with nothing forgotten.

Mutually exclusive

Two cases cannot hold together.

Edge case

A value at the edge of the range, such as 0, 1 or the smallest possible input.

Else-if chain

A chain of conditions that runs only the first true case.

Brute force

A simple solution that tries every possibility without cleverness.

Stress test

Comparing two solutions on many inputs to make sure they agree.

Parity

Whether a number is even or odd.

Leap year

A year with 29 days in February, by the rule of divisibility by 4, 100 and 400.

Equilateral

A triangle whose three sides are equal.

Isosceles

A triangle with at least two equal sides.
