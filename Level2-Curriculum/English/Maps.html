Maps

Linking every key to a value

What will you learn in this lesson?

  • Understand when we need a map and how it links a key to a value
  • Create a map, add, read and remove entries, and walk over its elements
  • Avoid the m[key] trap that creates a key without you meaning to
  • Count frequencies with freq[x]++ and solve tier problems with upper_bound
  • Tell map, unordered_map and multimap apart

The map: every key has a value

In the previous lesson the set only knew "is this element present?". But in most problems we want more than that: How many times did this word appear? What is this student's grade? Which phone number belongs to this name? We need to attach a piece of information to each element.

A map is like a paper dictionary: you look up the word (the key) and find its meaning (the value). Words are never repeated in a dictionary, they are sorted alphabetically, and looking them up is fast.

"Sara"→ 90
"Omar"→ 80
"Lina"→ 82

Technically, a map is a sorted set of keys without duplicates, where each key carries a value. It runs at the same speed, O(log n).

Our first map

We write two types between < >: the key type, then the value type. Click the highlighted lines to read their explanations:

first_map.cpp
#include <iostream>#include <map>#include <string>using namespace std; int main() {    map<string, int> scores;    scores["Sara"] = 90;    scores["Omar"] = 75;    scores["Lina"] = 82;    scores["Omar"] = 80;     cout << "size = " << scores.size() << endl;    for (const auto& p : scores) {        cout << p.first << " -> " << p.second << endl;    }    return 0;}
Click any highlighted line of code to read its explanation here...
size = 3 Lina -> 82 Omar -> 80 Sara -> 90

The assignment scores["Omar"] = 80 did not add a new key; it changed the value of an existing one. And walking over the map gives us pairs sorted by key.

The square-brackets trap

The most dangerous thing about a map is that m[key] does not merely "read": if the key does not exist, it creates it. Watch what happens to the size of the map:

bracket_trap.cpp
map<string, int> stock = {{"apple", 5}, {"pear", 2}}; cout << stock["apple"] << endl;cout << stock["kiwi"] << endl;cout << stock.size() << endl; cout << stock.count("mango") << endl;cout << stock.size() << endl;
Click any highlighted line of code to read its explanation here...
5 0 3 0 3

If you only want to ask "does the key exist?", use count or find, not m[key]. Otherwise your map fills up with phantom keys, and your program may give wrong answers.

The map toolbox

CommandWhat it does
m[k] = vCreates the key or replaces its value
m[k]Reads the value; if the key does not exist it creates it with a default value (0 for numbers)
m.count(k)0 or 1: does the key exist? Without changing the map
m.find(k)An iterator to the pair, or m.end()
m.at(k)Reads the value; if the key does not exist it raises an out_of_range error
m.insert({k, v})Adds only if the key does not exist (does not replace)
m.erase(k)Removes the key and its value
m.size() / m.empty()The number of pairs / is it empty?
find_at_erase.cpp
map<int, string> id = {{3, "Lina"}, {1, "Omar"}};

auto it = id.find(3);
if (it != id.end()) {
    cout << it->second << endl;
}

id.erase(1);
cout << id.size() << endl;

try {
    cout << id.at(9) << endl;
} catch (const out_of_range&) {
    cout << "no key 9" << endl;
}
Lina 1 no key 9

The iterator it points to a whole pair, which is why we write it->second to reach the value (the arrow -> is a shorthand for (*it).second).

Adding with insert versus assigning with [ ]

insert_vs_bracket.cpp
map<string, int> m;
m["a"] = 1;
m.insert({"a", 2});
cout << m["a"] << endl;

m["a"] = 3;
cout << m["a"] << endl;
1 3

insert does not change the value of an existing key, while assignment with brackets does.

The most famous use: counting frequencies

In thousands of problems we want to know how often everything occurs: letters, digits, words. A map does it in one line, freq[x]++:

frequency.cpp
vector<string> words = {"go", "stop", "go", "go", "wait", "stop"};map<string, int> freq; for (const string& w : words) {    freq[w]++;} for (const auto& p : freq) {    cout << p.first << ": " << p.second << endl;}

The tiers trick: upper_bound on a map

Because the keys of a map are sorted, we can search for the "closest key". This trick solves grade and tier problems: each key is the start of a tier, and we want to know the tier of a given point:

tiers.cpp
map<int, string> tiers = {{0, "Bronze"}, {100, "Silver"}, {500, "Gold"}}; int points[] = {30, 100, 250, 999};for (int p : points) {    auto it = tiers.upper_bound(p);    --it;    cout << p << " points -> " << it->second << endl;}
Click any highlighted line of code to read its explanation here...
30 points -> Bronze 100 points -> Silver 250 points -> Silver 999 points -> Gold

The idea: upper_bound(p) gives the first tier that starts after the point, so the correct tier is the one right before it. This style will come back in the binary search lesson.

A map whose values are lists

A value can be of any type, even a vector. This is useful for "grouping" elements under a single key:

grouping.cpp
map<string, vector<int>> marks;
marks["Sara"].push_back(90);
marks["Omar"].push_back(70);
marks["Sara"].push_back(80);

for (const auto& p : marks) {
    int sum = 0;
    for (int x : p.second) {
        sum += x;
    }
    cout << p.first << " avg " << sum / (int)p.second.size() << endl;
}
Omar avg 70 Sara avg 85

unordered_map and key mistakes

Like the set, the map has an unordered version, unordered_map: its average speed is O(1) but the keys have no order. There is also multimap, which allows a repeated key.

unordered_map.cpp
unordered_map<string, int> u;
u["a"] = 1;
u["b"] = 2;
u["a"] += 10;
cout << u["a"] << " " << u.count("b") << " " << u.count("z") << " " << u.size() << endl;
11 1 0 2

And the key type is fixed; if you give it a different type, the compiler refuses:

wrong_key.cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    map<string, int> m;
    m[1] = 5;
    cout << m.size() << endl;
    return 0;
}
What the compiler (g++) says
main.cpp: In function ‘int main()’:
main.cpp:8:6: error: no match for ‘operator[]’ (operand types are ‘std::map<std::__cxx11::basic_string<char>, int>’ and ‘int’)
    8 |     m[1] = 5;
      |      ^

Choose map when you want order or "closest" questions, and unordered_map when you only need fast lookup. And remember that the key of an unordered_map must be a type the compiler knows how to "scramble" (hash), such as numbers and strings.

Lesson project: student council election

A program that sorts the votes and announces the winner.

The idea

The student council election has been held and the votes were gathered on a single sheet, each line holding a candidate's name. You must count each candidate's votes and then announce the winner.

What you must do
  1. Read the number n, then n names, and use a map<string, int> to count the votes for each name.
  2. Print each candidate in the form Sara: 3, sorted alphabetically.
  3. Print Winner: followed by the name with the most votes.
  4. On a tie, the alphabetically earlier name wins (this happens automatically if you update the winner only when the votes are strictly greater).
Two sample runs

First run:

7 Sara Omar Sara Lina Omar Sara Lina
Lina: 2 Omar: 2 Sara: 3 Winner: Sara

Second run (a tie):

4 Ali Zaid Ali Zaid
Ali: 2 Zaid: 2 Winner: Ali

Check it in your head: in the first one, Sara has 3, Omar 2 and Lina 2, so Sara wins. In the second, Ali and Zaid have 2 each, so Ali wins because he comes first in the order.

After you try it yourself: show the solution
election.cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    map<string, int> votes;
    for (int i = 0; i < n; i++) {
        string name;
        cin >> name;
        votes[name]++;
    }

    string winner;
    int best = 0;
    for (const auto& p : votes) {
        cout << p.first << ": " << p.second << endl;
        if (p.second > best) {
            best = p.second;
            winner = p.first;
        }
    }
    cout << "Winner: " << winner << endl;
    return 0;
}

Homework challenges

Two short challenges to solve on your own after the lesson. Write your solution in a .cpp file, compile and run it, and compare your output with the expected output. Try first, open a hint only if you get stuck, and look at the sample solution only after a serious attempt.

1

Letter frequencies

Easy

Read a single word. Print every letter that appears in it together with how many times it appears, sorted alphabetically, one line per letter in the form a 3.

Requirements
  • Use a map<char, int>.
  • Walk over the letters of the word with a for (char c : word) loop.
  • Print the letter, then a space, then the count.
Example input and expected output
banana
a 3 b 1 n 2
Hints
  • The line cnt[c]++ is enough for counting.
  • Walking over the map gives you the letters already sorted, with no extra work.
Sample solution (after you try)
letter_count.cpp
// Challenge 1: letter frequencies
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    string word;
    cin >> word;
    map<char, int> cnt;
    for (char c : word) {
        cnt[c]++;
    }
    for (const auto& p : cnt) {
        cout << p.first << " " << p.second << endl;
    }
    return 0;
}
2

Two numbers with a known sum

Medium

Read n and target, then n numbers. Find two positions i < j (counting from 1) whose numbers add up to target, and print them. If none exist, print IMPOSSIBLE.

Requirements
  • Walk over the numbers in order, keeping the position number j.
  • Before storing the number x, ask: have we already seen target - x? Use count.
  • If we have, print its stored position, then j, and finish.
  • Otherwise store seen[x] = j.
Example input and expected output
5 9 2 7 11 15 1
1 2
Hints
  • Here the map links a "number" to "the position where we saw it".
  • Ask with count before reading with [ ] so you do not create phantom keys.
Sample solution (after you try)
two_sum.cpp
// Challenge 2: two numbers with a given sum
#include <iostream>
#include <map>
using namespace std;

int main() {
    int n, target;
    cin >> n >> target;
    map<int, int> seen;
    for (int j = 1; j <= n; j++) {
        int x;
        cin >> x;
        if (seen.count(target - x)) {
            cout << seen[target - x] << " " << j << endl;
            return 0;
        }
        seen[x] = j;
    }
    cout << "IMPOSSIBLE" << endl;
    return 0;
}

Quick summary

  • A map<K, V> links a **key** to a **value**: keys are unique and sorted, and it needs #include <map>.
  • m[k] = v creates or replaces. And m[k] on its own **creates** the key if it is missing!
  • To ask without changing anything use count or find; for safe reading use at.
  • Every element is a pair: first is the key and second is the value, and we walk over them with for (const auto& p : m).
  • Counting frequencies: freq[x]++ is one line and it is enough.
  • upper_bound on sorted keys solves tier problems: take the result, then step back once.
  • unordered_map is usually faster but has no order, and multimap allows a repeated key.

Glossary

The most important terms in this lesson:

Map

A container that links each key to a value; the keys are sorted and unique.

Key

The element we search by; it is never repeated in a map.

Value

The piece of information attached to a key.

Pair

Two elements together: first and second.

Frequency

The number of times an element appears.

unordered_map

A map that is usually faster but whose keys have no order.

multimap

A map that allows a repeated key.

at

Reads the value of a key and raises an error if it does not exist.

Default value

The value created automatically (0 for numbers).

find

Returns an iterator to the pair, or end().

Iterator

An object that points to an element and reads first and second through the arrow ->.

Grouping

Putting many elements under a single key.
