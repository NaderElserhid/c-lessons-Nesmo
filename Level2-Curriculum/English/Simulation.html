Simulation

Carry out the rules step by step

What will you learn in this lesson?

  • Understand the idea of simulation and identify the state variables before writing the solution
  • Use the arrays dx and dy and remainder arithmetic to move a robot on a grid
  • Compute the next generation of a grid in a separate copy, as in the Game of Life
  • Simulate circles and turns with the queue
  • Detect cycles by storing states in a set when the simulation is long

Run the game as it is

Some problems do not ask for mathematical genius; they tell you: "These are the rules of the game, so what will happen at the end?" A bus stopping at stops, a robot moving on a board, children in a circle where every third one leaves. The solution is to simulate the process yourself, step by step, inside your program, exactly as you would play a board game by hand to find the outcome.

Think of simulation as running a slow game: you write on a sheet of paper the state of the game (where is each piece? how many points? whose turn?), then you apply one rule and update the sheet, and repeat. The program is the sheet and the loop is the rules.

The fixed steps for solving any simulation problem:

  1. Read the rules carefully (mistakes here cost more than any coding mistake).
  2. Write down the state variables: what changes over time?
  3. Apply the rule in the same order that the problem states.
  4. Ask: does the number of steps allow direct simulation? (Remember the complexity lesson!)

The second example: the Game of Life

The Game of Life was invented by the mathematician John Conway. It has very simple rules: every cell on the grid is either alive or dead, and it changes in each "generation" according to its eight neighbors: a live cell survives if it has two or three neighbors, and a dead cell comes alive if it has exactly three. From these rules, shapes arise that move and multiply! The most important lesson in programming terms: we compute the new generation in a separate copy:

The queue: every k-th leaves the circle

n children stand in a circle and count from 1; whoever the number k lands on leaves the game, then the count starts again from the next child, until nobody is left. We simulate it with a queue: a child we pass without removing goes back to the end, and the one who leaves is pulled out:

circle_game.cpp
queue<int> q;for (int i = 1; i <= 5; i++) {    q.push(i);}int k = 2; while (!q.empty()) {    for (int s = 1; s < k; s++) {        q.push(q.front());        q.pop();    }    cout << q.front() << " ";    q.pop();}cout << endl;

When the simulation is long: look for the cycle

What if the problem asks for the result after 10¹² steps? Direct simulation would take forever. The solution is usually that the process enters a cycle that repeats, so we detect it by storing the states we have passed through in a set; when we see a repeated state we know that everything after it repeats, and we use the remainder (the previous lesson!) to jump to the result. An example: the "happy numbers" game (replace the number with the sum of the squares of its digits):

detect_cycle.cpp
auto next = [](int n) {    int s = 0;    while (n > 0) {        s += (n % 10) * (n % 10);        n /= 10;    }    return s;}; for (int start : {19, 4}) {    set<int> seen;    int n = start;    while (n != 1 && !seen.count(n)) {        seen.insert(n);        n = next(n);    }    cout << start << (n == 1 ? " reaches 1" : " loops forever") << endl;}
Click any highlighted line of code to read its explanation here...

The number 19 reaches 1 and the game stops, while the number 4 enters an endless loop (4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4) and never reaches 1. Without cycle detection our program would have run forever!

The most famous simulation mistakes: (1) modifying the state while reading it (use a new copy as in the Game of Life). (2) Changing the order of the rules. (3) Leaving the grid boundaries. (4) Forgetting that the start counts (such as the first cell the robot visits). The permanent cure: try a small example by hand and then compare with your program.

Lesson project: the cleaning robot

A program that simulates a robot on a board and gives a report of its trip.

The idea

A cleaning robot works on a rectangular floor of width W and height H. It starts in cell (0, 0) (the top-left corner) facing east, and a string of commands reaches it. You want a report of its final position, the number of distinct cells it cleaned, and the number of times it bumped into the wall.

What you must do
  1. Read W and H and then the command string. The coordinate x grows toward the east and y grows toward the south.
  2. R turns the robot right, L turns it left, and F moves it one cell forward in its direction.
  3. If the cell in front is outside the board, the robot bumps: it stays where it is and the bump counter goes up.
  4. Store the cells it visited (including the starting cell) in a set<pair<int,int>>.
  5. Print three lines: Final: x y D, then Distinct cells: k, then Bumps: b, where D is one of the letters N E S W.
Two sample runs

First run:

5 4 FFRFFLFFFFFF
Final: 4 2 E Distinct cells: 7 Bumps: 4

Second run (it bumps into the wall):

3 3 RRFFLL
Final: 0 0 E Distinct cells: 1 Bumps: 2

Check it in your head: in the first: FF to (2,0), then R south and FF to (2,2), then L east and FFFFFF: two steps to (4,2) and four bumps. The distinct cells are seven. In the second, it turns right twice to face west so it bumps twice, then turns left twice to face east again.

After you try it yourself: show the solution
robot.cpp
#include <iostream>
#include <set>
#include <string>
using namespace std;

int main() {
    int W, H;
    string cmds;
    cin >> W >> H >> cmds;

    const int dx[4] = {0, 1, 0, -1};
    const int dy[4] = {-1, 0, 1, 0};
    const char name[4] = {'N', 'E', 'S', 'W'};

    int x = 0, y = 0, d = 1, bumps = 0;
    set<pair<int, int>> visited;
    visited.insert({x, y});

    for (char c : cmds) {
        if (c == 'R') {
            d = (d + 1) % 4;
        } else if (c == 'L') {
            d = (d + 3) % 4;
        } else if (c == 'F') {
            int nx = x + dx[d], ny = y + dy[d];
            if (nx < 0 || nx >= W || ny < 0 || ny >= H) {
                bumps++;
            } else {
                x = nx;
                y = ny;
                visited.insert({x, y});
            }
        }
    }
    cout << "Final: " << x << " " << y << " " << name[d] << endl;
    cout << "Distinct cells: " << visited.size() << endl;
    cout << "Bumps: " << bumps << endl;
    return 0;
}

1

Bus capacity

Easy

A bus stops at n stops. At each stop the number of passengers getting off is given, then the number getting on (those getting off never exceed those on the bus). The bus starts empty. Print the largest number of passengers on it at any moment.

Requirements
  • Read n and then, for each stop, leave and enter.
  • Update the current count: people = people - leave + enter.
  • Update the maximum after every stop with max.
Example input and expected output
4 0 3 2 5 4 2 4 0
6
Hints
  • Update the maximum inside the loop, not after it.
  • With the inputs 0 3, 2 5, 4 2 and 4 0, the count reaches 6 at the second stop.
Sample solution (after you try)
tram_capacity.cpp
// Challenge 1: maximum people on the bus
#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    int people = 0, best = 0;
    for (int i = 0; i < n; i++) {
        int leave, enter;
        cin >> leave >> enter;
        people = people - leave + enter;
        best = max(best, people);
    }
    cout << best << endl;
    return 0;
}
2

The elimination circle

Medium

n children stand in a circle numbered 1 to n. We count from child 1, and whoever the number k lands on leaves, then the count starts from the child after them. Print the children's numbers in the order they leave, separated by spaces.

Requirements
  • Use a queue<int> and add the numbers from 1 to n.
  • For each elimination, pass k-1 children to the end of the queue.
  • Print front and then pop.
Example input and expected output
7 3
3 6 2 7 5 1 4
Hints
  • To pass a child: q.push(q.front()); q.pop();
  • With n = 7 and k = 3 the order is 3 6 2 7 5 1 4.
Sample solution (after you try)
circle_order.cpp
// Challenge 2: elimination order in a circle
#include <iostream>
#include <queue>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    queue<int> q;
    for (int i = 1; i <= n; i++) {
        q.push(i);
    }
    bool first = true;
    while (!q.empty()) {
        for (int s = 1; s < k; s++) {
            q.push(q.front());
            q.pop();
        }
        if (!first) {
            cout << " ";
        }
        cout << q.front();
        first = false;
        q.pop();
    }
    cout << endl;
    return 0;
}

Quick summary

  • Simulation means carrying out the problem's rules step by step inside the program, in the same order the problem states.
  • Start by identifying the **state variables** (what changes over time?), then update them inside a loop.
  • For directions we number them and use dx and dy, and turning is a remainder calculation: right (d+1)%4 and left (d+3)%4.
  • When we update a grid where each change depends on its neighbors, we compute the new generation in a **separate copy**.
  • The queue suits circular counting: push those we skip to the back and pull out the one who leaves.
  • If the steps are too many to simulate directly, detect the **cycle** by storing states in a set, then use the remainder.
  • Always try a small example by hand and compare with your program, and watch the grid boundaries and the initial state.

Glossary

The most important terms in this lesson:

Simulation

Carrying out the rules of a process step by step to find its result.

State

The set of variables that describe the current situation of the process.

Step

One application of the rule that changes the state.

Direction array

The two arrays dx and dy that give the movement in each direction.

Grid

A table of rows and columns that represents a board or a map.

Generation

The state of the grid after one full step in the Game of Life.

Neighbor

A cell adjacent to the cell in question.

Queue

A "first in, first out" container with the commands push, front and pop.

Cycle

A series of states that returns to an earlier state and so repeats forever.

Bump

An attempt to leave the boundary of the board.

Boundary check

Making sure a coordinate is inside the grid before using it.

Blinker

A shape in the Game of Life that oscillates between two positions.
