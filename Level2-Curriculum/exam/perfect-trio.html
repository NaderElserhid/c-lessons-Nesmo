Codeforces · Problem D

Perfect Trio

Sort + two pointers — finding three numbers that sum to a target

⏱ 1s per test 💾 256 MB 🏷 3Sum · two pointers 📈 O(N²) time, O(N) space

What you'll learn in this lesson

    01 — Problem

    What's actually being asked

    Three friends are playing "Perfect Trio". They are given a list of celebrities, where the i-th celebrity has exactly Ai followers. To win, they must choose exactly three distinct celebrities whose follower counts sum to exactly S. Determine whether such a trio exists; if it does, output any valid three follower counts, otherwise output -1.

    Input

    Two lines.

    N S
A1 A2 A3 ... AN

    Constraints: 3 ≤ N ≤ 10000, and 0 ≤ Ai, S ≤ 7·108.

    Output

    Three values, or -1.

    a b c   or   -1

    Any valid trio is accepted, printed in any order — this is a special-judge problem, not a single fixed answer.

    Example 1

    in:  3 6
     1 2 3
out: 1 2 3

    Only one possible trio with N = 3, and it already sums to 6.

    Example 2

    in:  6 1000
     182 587 952 374 39 741
out: 39 374 587

    39 + 374 + 587 = 1000. Other trios don't work — try 182+952+? or 741+? by hand to see why.

    Why the subtasks are shaped this way

    SubtaskConstraintPoints
    1N = 37
    2N = 48
    3N = 59

    6N ≤ 10000, S ≤ 7·10⁸19

    Subtasks 1–3 reward brute force. Subtask 5 is friendly to a value-indexed trick that depends on S being small. Subtask 6 removes that crutch — the idea section explains why sort-and-two-pointer passes every one of these with the same code.

    02 — The Idea

    From O(N³) down to O(N²)

    This is the classic 3Sum problem. Checking every possible trio directly costs O(N³) — fine for N up to a few hundred, but with N up to 10,000 that's up to 10¹² checks, far too slow for a 1 second limit.

    The fix: sort the followers first. Fix the smallest of the three values at position i, then search the rest of the array for a pair summing to S − A[i] using two pointers — one starting right after i, one at the far end. Because the array is sorted, moving the left pointer forward only increases the pair's sum, and moving the right pointer backward only decreases it. That monotonic behaviour lets the pair search finish in O(N) instead of O(N²), bringing the whole algorithm down to O(N²).

    Because the algorithm always keeps i < left < right as array positions, the three chosen elements are automatically three different celebrities — even when two of them happen to have the exact same follower count. Duplicate values are never a problem; only duplicate positions would be, and the pointers never allow that.

    Why not a hash set per i?

    You could fix i and use a hash set to look for a complementary pair — also O(N²) on average.

    The subtask split is a hint

    Subtask 5 caps S at 10⁵; subtask 6 allows S up to 7·10⁸. A value-indexed trick (like a counting array sized S+1) only stays cheap in memory while S is small — sort-and-two-pointer never looks at S's magnitude to decide memory use.

    03 — Algorithm

    Sort, fix, sweep

    1

    Sort the followers

    Sort the array A ascending. From now on, positions in the sorted array — not the original input order — are what matter.

    2

    Fix i, open the window

    For i = 0, 1, 2, ... set left = i+1 and right = N-1. This window is where we search for the other two values.

    3

    Compare the triple sum

    While left < right, compute sum = A[i] + A[left] + A[right] and compare it with S.

    4

    Match? You're done

    If sum == S, you've found a valid trio — print A[i], A[left], A[right] and stop.

    5

    Otherwise, slide a pointer

    If sum < S the pair is too small — move left++. If sum > S the pair is too big — move right--.

    6

    Exhausted this i? Move on

    When left meets right with no match, increment i and reopen the window. If i runs past N-3 with nothing found, no trio exists — print -1.

    Sorting costs O(N log N); the nested scan costs O(N²) since each of the N choices of i runs an O(N) two-pointer sweep. For N = 10,000 that's about 10⁸ comparisons — comfortably inside a 1 second limit in a compiled language.

    One more practical note: with values up to 7·10⁸, a sum of three can approach 2.1·10⁹ — right at the edge of a 32-bit signed integer. Use a 64-bit type for the sum to stay safe.
