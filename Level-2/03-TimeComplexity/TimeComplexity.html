الفصل الثالث: التعقيد الزمني (Time Complexity)

تعلّمت حتى الآن حاويتين قويتين من STL: الـ set والـ map. لكن كيف تعرف أنّ الحل الذي كتبته سيكون سريعًا بما يكفي؟ في هذا الفصل ستتعلّم كيف "تقيس" سرعة أي خوارزمية دون تشغيلها فعليًا، وكيف تتوقّع مسبقًا هل سيحصل حلّك على Accepted أم Time Limit Exceeded عند إرساله على Codeforces — وهي بالضبط المهارة التي ستحتاجها لبقية رحلتك في البرمجة التنافسية.

ما هو التعقيد الزمني؟

عندما نكتب برامج، بعض الحلول تعمل أسرع من غيرها. التعقيد الزمني (Time Complexity) هو طريقة لقياس مدى سرعة نمو عدد خطوات الخوارزمية كلما كبر حجم المدخلات.

لا نقيسه بالثواني (لأنّ ذلك يعتمد على سرعة الجهاز)، بل نقيسه بعدد الخطوات التي تزداد عند زيادة حجم المدخلات. هذا يسمح لنا بمقارنة الخوارزميات مع بعضها دون الحاجة لتشغيلها فعليًا.

basic_loop.cpp
for (int i = 0; i < n; i++)
    cout << i << " ";

إذا كان n = 10، يطبع الكود 10 أرقام. إذا كان n = 1000، يطبع 1000 رقم. إذا تضاعف n، فإنّ عدد الخطوات يتضاعف أيضًا.

نقول إنّ هذا الكود يعمل في زمن O(n)، لأنه يحتوي على n خطوة تقريبًا. هذا يعني أنّ الوقت ينمو خطيًا مع حجم المدخلات.

ما معنى الرمز الكبير O (Big O)؟

يوضّح رمز O (Big O) كيف ينمو عدد خطوات الخوارزمية مع زيادة n. نهتم فقط بالنمو الرئيسي (المسيطر)، وليس بالثوابت أو التفاصيل الصغيرة — فمثلًا 2n + 5 وn كلاهما يُكتبان O(n).

المثالالتعقيدالوصف
x = a + b; أو if/elseO(1)وقت ثابت — يعمل فورًا بغض النظر عن حجم n
set::insertO(log n)كل خطوة تقلّل حجم المشكلة إلى النصف تقريبًا
حلقة واحدة على مصفوفةO(n)الوقت ينمو خطيًا
الترتيب (Sorting)O(n log n)أبطأ قليلًا من O(n)، لكن أسرع بكثير من O(n²)
حلقتان متداخلتانO(n²)الوقت ينمو بسرعة كبيرة عند زيادة n
تجربة جميع التوافيق الممكنةO(2ⁿ)نمو أسي — يزداد بشكل هائل بسرعة

كلما كان التعقيد أكبر (بالانتقال من اليسار إلى اليمين في الرسم أدناه)، كلما نما وقت التنفيذ بسرعة أكبر مع زيادة n:

نشاط: مراجعة سريعة لمفهوم Big O

لنراجع بسرعة ما تعلّمناه للتو عن التعقيد الزمني ورمز Big O. حدّد إن كانت كل عبارة صحيحة أم خاطئة.

نقيس التعقيد الزمني بالثواني الفعلية التي يستغرقها البرنامج.

2n + 5 و n كلاهما يُكتبان بنفس التعقيد O(n).

الحلقتان المتداخلتان (Nested Loops) عادة تكونان بتعقيد O(n).

O(n log n) أسرع من O(n²) لمعظم قيم n الكبيرة.

حساب عدد الخطوات: أمثلة عملية

أفضل طريقة لفهم Big O هي عدّ الخطوات فعليًا داخل الكود. لاحظ أنّ العمليات الحسابية البسيطة (+ - * / % ^)، والزيادة/النقصان (++ --)، والاختصارات (+= -= *= /=)، وعبارات if/else كلها تُحسب كخطوة واحدة بزمن ثابت O(1).

1) حلقة واحدة → O(n)

one_loop.cpp
long long sum = 0;                    // 1 خطوة
for (int i = 1; i <= n; i++)          // n مرة
    sum = sum + i;                    // خطوة ثابتة في كل مرة

عدد الخطوات ≈ 1 + n → نتجاهل الثابت 1 → O(n). للتحقق: n·(n+1)/2 تعطي نفس نتيجة الحلقة (لـ n=5: 5·6/2 = 15 = 1+2+3+4+5)، لكن هذه الصيغة المباشرة تُحسب في خطوة واحدة فقط O(1) — وهذا مثال آخر على "تحسين الحلول" الذي سنراه لاحقًا.

2) حلقتان متداخلتان → O(n²)

two_loops.cpp
for (int i = 0; i < n; i++)           // n مرة
    cout << i;
for (int j = 0; j < n; j++)           // n مرة
    for (int k = 0; k < n; k++)       // n مرة لكل j → n² إجمالًا
        cout << j + k;

عدد الخطوات ≈ n + n² → الحد المسيطر هو n² → O(n²).

3) إضافة حلقة ثالثة متداخلة → O(n³)

three_loops.cpp
for (int j = 0; j < n; j++)
    for (int k = 0; k < n; k++)
        for (int l = 0; l < n; l++)   // n × n × n = n³
            cout << j + k + l;

بإضافة حلقة ثالثة متداخلة، أصبح عدد الخطوات n³، فالتعقيد يصبح O(n³) — أبطأ بكثير من O(n²).

4) حلقة مضاعفة → O(log n)

doubling_loop.cpp
for (int i = 1; i < n; i = i * 2)      // يتضاعف i في كل مرة
    cout << i;

بما أنّ i يتضاعف في كل مرة (1, 2, 4, 8, ...)، فإنّ عدد التكرارات اللازمة للوصول إلى n هو تقريبًا log₂(n)، فالتعقيد O(log n).

5) حلقات متداخلة مع مضاعفة → O(n log²n)

nested_log.cpp
for (int i = n / 2; i < n; i++)         // ≈ n مرة
    for (int k = 1; k < n; k = k * 2)    // log n مرة
        for (int j = 1; j < n; j = j * 2) // log n مرة
            cout << i + k + j;

الحاصل: n · log n · log n = O(n log²n).

6) حلقتان عاديتان وحلقة مضاعفة → O(n² log n)

two_plus_log.cpp
for (int i = 0; i < n; i++)             // n مرة
    for (int j = 0; j < n; j++)         // n مرة
        for (int k = 1; k < n; k = k * 2) // log n مرة
            cout << i + j + k;

الحاصل: n · n · log n = O(n² log n).

7) حلقة عادية وحلقة قسمة → O(n log n)

divide_loop.cpp
for (int i = 0; i < n; i++)             // n مرة
    for (int j = n; j > 1; j = j / 3)   // log₃n مرة ≈ O(log n)
        cout << i + j;

القسمة على أي عدد ثابت (2 أو 3 أو غيره) تعطي نفس رتبة النمو O(log n) (فقط الأساس يتغيّر، وهو تفصيل نتجاهله). الحاصل: n · log n = O(n log n).

أفضل، متوسط، وأسوأ الحالات

قد تختلف سرعة نفس الخوارزمية باختلاف شكل المدخلات. لذلك نميّز بين ثلاث حالات، ولكل منها رمز رياضي خاص:

لنطبّق هذا على البحث الخطي (Linear Search): نمرّ على عناصر المصفوفة واحدًا تلو الآخر بحثًا عن قيمة معيّنة، ونتوقف بمجرد إيجادها.

أمثلة محلولة

مثال 1: زيادة الرقم — وقت ثابت O(1)

معطى لك رقم x. قم بزيادة x بمقدار 1، ثم اطبعه.

increment.cpp
#include <iostream>
using namespace std;

int main() {
    int x;
    cin >> x;
    x += 1;
    cout << x << '\n';
}
Input: 7 → Output: 8

قمنا بثلاث عمليات بسيطة: قراءة، زيادة، وطباعة. جميعها عمليات ثابتة الزمن — لا نقول إنّ هذا O(3) لأننا لا نهتم بالثوابت؛ نهتم فقط بالنمو الرئيسي. إذن هذا O(1).

مثال 2: مجموع المال — وقت خطي O(n)

معطى لك n ورقة نقدية قيمتها arr[0] ريال، arr[1] ريال، ...، arr[n-1] ريال. كم مجموع الريالات لديك؟

money_sum.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    int arr[n];
    for (int i = 0; i < n; i++)
        cin >> arr[i];

    long long sum = 0;
    for (int i = 0; i < n; i++)
        sum += arr[i];

    cout << sum << '\n';
}
Input: 4 / 10 20 30 40 → Output: 100

الحلقة الأولى (القراءة) تعمل n مرة، والثانية (الجمع) تعمل n مرة أيضًا. بالمجموع: n + n = 2n، لكننا نتجاهل الثوابت، إذن التعقيد O(n) — إذا تضاعفت المصفوفة، يتضاعف الوقت أيضًا.

مثال 3: النسخ — وقت تربيعي O(n²)

معطى لك n ورقة نقدية. لكل من n أيام، قم بزيادة قيمة كل ورقة بمقدار واحد، واطبع قيم كل الأوراق لكل يوم.

copies.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    int arr[n];
    for (int i = 0; i < n; i++)
        cin >> arr[i];

    for (int days = 1; days <= n; days++) {
        for (int i = 0; i < n; i++) {
            cout << arr[i] + days << ' ';
        }
        cout << '\n';
    }
}
Input: 3 / 1 2 3 Output: 2 3 4 3 4 5 4 5 6

هناك n يوم، وفي كل يوم نمرّ على n ورقة، فيكون المجموع n · n = n² عملية. إذا كان n = 100، فإنّ عدد الخطوات = 10,000. إذا كان n = 1000، فإنّ عدد الخطوات = 1,000,000. لهذا يمكن أن تصبح خوارزميات O(n²) بطيئة جدًا وبسرعة كبيرة.

قاعدة سريعة

تتذكّر من فصل "المسابقات والمنصّات" أنّ لكل مسألة حدًّا زمنيًا (عادة ثانية أو ثانيتان)، وأنّ المعالج يستطيع تنفيذ نحو 10⁸ عملية في الثانية تقريبًا. هذا يعطينا قاعدة عملية سريعة لتخمين نوع الحل المناسب اعتمادًا على حجم n في المسألة:

التعقيد الأقصى المقبولn
O(n!)≤ 10
O(2ⁿ) عادة مقبول≤ 20
O(n²) عادة مقبول≤ 1000
O(n log n) أو أفضل≤ 10⁵
O(n) أو أفضل≤ 10⁷
فقط O(log n) أو O(1)≥ 10⁹

هذا يساعدك على تخمين نوع الحل المناسب لحجم مدخلات معيّن قبل حتى أن تبدأ بكتابة الكود. مثلًا، إذا رأيت N ≤ 3000 في مسألة (كما في مسألة Iso-celestial)، فأنت تعرف مسبقًا أنّ حلًّا بتعقيد O(N²) سيكون مقبولًا، بينما O(N³) سيكون بطيئًا جدًا.

تحسين الحلول

أحيانًا ليس الأمر واضحًا، لكن يمكنك جعل البرنامج أسرع بالتفكير في حلول أذكى.

المجموع البسيط

معطى لك رقم n. أوجد مجموع: -n + (-n+1) + (-n+2) + ... + -1 + 0 + 1 + ... + (n-2) + (n-1) + n.

حل بسيط (خطي O(n)):

simple_sum_naive.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long sum = 0;
    for (int i = -n; i <= n; i++)
        sum += i;
    cout << sum << '\n';
}
Input: 5 → Output: 0

هذا الحل يعمل في زمن O(n).

حل أذكى (ثابت O(1)):

يمكننا عمل أفضل من ذلك. كل عدد يظهر مرة موجبة ومرة سالبة — i و-i — فيلغي كل زوج منهما الآخر، ويبقى فقط الصفر (0) في المنتصف. الحل الأبسط:

simple_sum_smart.cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    cout << 0 << '\n';
}
Input: 5 → Output: 0

هذا الحل O(1)، وقت ثابت وأسرع بكثير من الحل البسيط. عمليًا، عند اختبار الحلّين بقيمة ضخمة مثل n = 300{,}000{,}000، استغرق الحل الخطي نحو 0.19 ثانية، بينما استغرق الحل الثابت أقل من 0.002 ثانية — فرق شاسع رغم أنّ كليهما يعطي نفس الإجابة الصحيحة! دائمًا حاول التفكير في أسرع حل ممكن.

التعقيد المكاني (Space Complexity)

أحيانًا نهتم أيضًا بـ كمية الذاكرة التي يستخدمها البرنامج. هذا ما يُسمى التعقيد المكاني. الفكرة نفسها بالضبط: كيف ينمو استخدام الذاكرة مع زيادة حجم المدخلات؟

space_example.cpp
int arr[n];  // مساحة O(n) — تنمو مع حجم المدخلات
int x;       // مساحة O(1) — ثابتة بغض النظر عن n

غالبًا يوجد توازن بين الزمن والذاكرة: أحيانًا يمكنك جعل الحل أسرع باستخدام ذاكرة إضافية (كما فعلنا مع set لإزالة المكررات)، وأحيانًا العكس صحيح.

تمارين منزلية

1) حدّد التعقيد الزمني للكود التالي

hw1.cpp
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++)
        cout << i + j;

لاحظ أنّ الحلقة الداخلية لا تبدأ من الصفر، بل من i. ما تعقيد هذا الكود؟

عدد مرات تنفيذ الحلقة الداخلية يتناقص مع كل قيمة لـ i: عندما i=0 تُنفَّذ n مرة، وعندما i=1 تُنفَّذ n-1 مرة، وهكذا حتى مرة واحدة. المجموع الكلي هو n + (n-1) + ... + 1 = n(n+1)/2.

رغم أنّ الصيغة الدقيقة هي n(n+1)/2، فإنّ الحد المسيطر فيها هو n²، لذا يبقى التعقيد O(n²) — لا يزال تربيعيًا رغم أنّ عدد العمليات الفعلي أقل من الحلقتين الكاملتين بمقدار النصف تقريبًا.

2) حدّد التعقيد الزمني للكود التالي

hw2.cpp
int lo = 0, hi = n;
while (lo < hi) {
    int mid = (lo + hi) / 2;
    if (arr[mid] < target) lo = mid + 1;
    else hi = mid;
}

هذا هو البحث الثنائي (Binary Search) الذي درسناه سابقًا. ما تعقيده الزمني؟

في كل تكرار، يُقسَّم النطاق [lo, hi) إلى النصف تقريبًا. هذا يشبه تمامًا حلقة المضاعفة التي درسناها، لكن بالاتجاه المعاكس (تقليل بدلًا من تكبير). عدد مرات التقسيم اللازمة للوصول من n إلى عنصر واحد هو log₂(n)، فالتعقيد O(log n) — ولهذا يُعتبر البحث الثنائي أسرع بكثير من البحث الخطي على مصفوفة كبيرة ومرتّبة.

Input: array [1,3,5,7,9,11], target=7 → Found at index 3

3) حسّن الحل من O(n²) إلى O(n)

لديك مصفوفة، والمطلوب التحقق إن كانت تحتوي على عنصرين مجموعهما يساوي قيمة target معيّنة. الحل الساذج التالي يستخدم حلقتين متداخلتين بتعقيد O(n²). أعد كتابته باستخدام set ليصبح التعقيد O(n) تقريبًا (استفد مما تعلّمته في الفصل الأول من هذا المستوى!).

two_sum_naive.cpp — O(n²)
bool found = false;
for (int i = 0; i < n && !found; i++)
    for (int j = i + 1; j < n && !found; j++)
        if (arr[i] + arr[j] == target) found = true;
two_sum_smart.cpp — O(n) تقريبًا
#include <iostream>
#include <set>
using namespace std;

int main() {
    int n, target;
    cin >> n >> target;
    int arr[n];
    for (int i = 0; i < n; i++) cin >> arr[i];

    set<int> seen;
    bool found = false;
    for (int i = 0; i < n; i++) {
        if (seen.count(target - arr[i])) { found = true; break; }
        seen.insert(arr[i]);
    }

    cout << (found ? "Yes" : "No");
}
Input: 4 9 / 2 7 11 15 → Yes (2 + 7 = 9) Input: 4 100 / 1 2 3 4 → No

لكل عنصر، نتحقق في O(log n) إن كان "المكمّل" (target - arr[i]) قد ظهر سابقًا في set. بما أنّ الحلقة تعمل n مرة وكل عملية set تكلّف O(log n)، فالتعقيد الكلي O(n log n) — أسرع بكثير من O(n²) الأصلي عندما يكون n كبيرًا.

قاموس المصطلحات

Time Complexityالتعقيد الزمني

مقياس لنمو عدد خطوات الخوارزمية مع زيادة حجم المدخلات.

Big Oالرمز الكبير O

الترميز المستخدم للتعبير عن أسوأ حالة أو الحد الأعلى لنمو الخوارزمية.

Big Omegaأوميغا الكبيرة

الترميز المستخدم للتعبير عن أفضل حالة أو الحد الأدنى لنمو الخوارزمية.

Big Thetaثيتا الكبيرة

الترميز المستخدم للتعبير عن الحالة المتوسطة أو الحد الدقيق للنمو.

Constant Timeوقت ثابت — O(1)

لا يتغيّر عدد الخطوات بتغيّر حجم المدخلات.

Linear Timeوقت خطي — O(n)

عدد الخطوات ينمو بشكل متناسب طرديًا مع حجم المدخلات.

Quadratic Timeوقت تربيعي — O(n²)

عدد الخطوات ينمو بمربّع حجم المدخلات، غالبًا بسبب حلقتين متداخلتين.

Logarithmic Timeوقت لوغاريتمي — O(log n)

عدد الخطوات ينمو ببطء شديد، غالبًا بسبب تقسيم المشكلة إلى النصف في كل خطوة.

Exponential Timeوقت أسي — O(2ⁿ)

عدد الخطوات يتضاعف مع كل زيادة في حجم المدخلات، غالبًا بسبب تجربة كل الاحتمالات.

Space Complexityالتعقيد المكاني

مقياس لنمو استخدام الذاكرة مع زيادة حجم المدخلات.
