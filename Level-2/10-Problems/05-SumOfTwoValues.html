Sum of Two Values (مجموع قيمتين)

مسألة كلاسيكية من CSES تعلّمك كيف تستخدم الخريطة (map) لتحويل بحث بطيء بزمن O(n²) إلى بحث سريع بزمن O(n log n) يمرّ على المصفوفة مرة واحدة فقط.

Easy CSES 1640

نص المسألة

يُعطى لك مصفوفة من n عدد صحيح، ومهمتك هي إيجاد موقعين مختلفين i وj بحيث a[i] + a[j] = x.

إذا وُجدت عدة أزواج صالحة، يمكنك إخراج أي زوج منها. إذا لم يوجد أي زوج يحقق الشرط، فاطبع IMPOSSIBLE.

القيود

  • 1 ≤ n ≤ 2 × 10⁵

  • 1 ≤ x, a_i ≤ 10⁹

الإدخال

السطر الأول: عددان صحيحان n وx — حجم المصفوفة والمجموع المطلوب.
السطر الثاني: n عددًا — قيم المصفوفة.

المخرجات

إمّا موقعان (1-based) بشكل i j بحيث a[i] + a[j] = x وi ≠ j، أو IMPOSSIBLE إذا لم يوجد أي زوج يحقق الشرط.

مثال

Input:
4 8
2 7 5 1
Output:
2 4

(أحد الأزواج الصحيحة هو a[2] + a[4] = 7 + 1 = 8)

مختبر تفاعلي: شاهد الخريطة تُبنى أثناء المرور

شغّل المحاكاة لترى كيف نمرّ على المصفوفة 2, 7, 5, 1 بحثًا عن مجموع x = 8: عند كل عنصر نحسب المتمّم المطلوب، نبحث عنه في الخريطة، فإن لم نجده نخزّن العنصر الحالي ونكمل:

2
i=1
7

5

1

الخريطة (القيمة → الموقع)
اضغط "شغّل المحاكاة" لمشاهدة المرور خطوة بخطوة.

منهجية الحل: كيف نفكّر في هذه المسألة؟

  • افهم المسألة: نريد موقعين مختلفين مجموع قيمتيهما يساوي x بالضبط.

  • جرّب أمثلة صغيرة يدويًا: خذ مصفوفة من 3-4 عناصر وابحث عن الزوج بنفسك.

  • ابحث عن نمط: لكل عنصر a[i]، المطلوب فعليًا هو معرفة هل رأينا من قبل القيمة x - a[i]؟

  • فكّر في الكفاءة: الحل الساذج بحلقتين متداخلتين يفحص كل زوج، لكنه بطيء جدًا عندما يكون n كبيرًا.

  • اكتب الكود وتحقّق: استخدم خريطة (map) لتسجيل كل قيمة رأيتها مع موقعها، وابحث عن المتمّم أثناء المرور نفسه.

  • افحص الحالات الحدّية: ماذا لو لم يوجد حل؟ وماذا لو تكررت القيم؟

الخطوة 1: لماذا لا نجرّب كل الأزواج؟

أبسط حل هو فحص كل زوج ممكن من المواقع (i, j) والتحقق إن كان a[i] + a[j] = x، بحلقتين متداخلتين. هذا يعمل بزمن O(n²).

لكن بما أن n قد يصل إلى 2 × 10⁵، فإنّ n² يصبح حوالي 4 × 10¹⁰ عملية — وهذا أبطأ بكثير مما يمكن تنفيذه خلال ثانية واحدة. نحتاج طريقة أسرع تمرّ على المصفوفة مرة واحدة فقط.

الخطوة 2: فكرة الخريطة (الاقتران أثناء المرور)

نمرّ على عناصر المصفوفة من اليسار إلى اليمين. عند كل موقع i:

  1. نعرّف need = x - a[i] — القيمة التي نحتاجها لإكمال المجموع.

  2. إذا كانت need موجودة في الخريطة مع موقع سابق j، فقد وجدنا الحل: a[i] + a[j] = x.

  3. وإلّا، نخزّن a[i] مع موقعه i في الخريطة، ونكمل للعنصر التالي.

بما أن كل عنصر يُعالج مرة واحدة، وكل عملية على الخريطة تكلف تقريبًا O(log n)، فإن الخوارزمية كلها تعمل بزمن O(n log n) — سريعة بما يكفي حتى مع أكبر مدخلات ممكنة.

الخطوة 3: الحل الكامل

sum_of_two_values.cpp
#include <iostream>
#include <map>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<long long> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    // value -> index (1-based)
    map<long long, int> pos;

    for (int i = 0; i < n; i++) {
        long long need = x - a[i];

        auto it = pos.find(need);
        if (it != pos.end()) {
            // found a pair: a[i] + need = x
            cout << it->second << " " << (i + 1) << "\n";
            return 0;
        }

        // store current value with its 1-based index
        pos[a[i]] = i + 1;
    }

    cout << "IMPOSSIBLE\n";
    return 0;
}
Input: 4 8 / 2 7 5 1 → Output: 2 4

الخطوة 4: نقاط يجب الانتباه لها

مواقع مختلفة: استخدام خريطة للقيم السابقة فقط (وليس القيمة الحالية) يضمن تلقائيًا أنّ i ≠ j.

المؤشرات ابتداءً من 1: منصة CSES تتوقع مواقع بدءًا من 1، لذا علينا طباعة i + 1 وليس i.

القيم المكرّرة: إذا تكررت قيمة ما، ستحتفظ الخريطة بآخر موقع مُسجَّل لها فقط — وهذا لا يسبب مشكلة لأن أي زوج صالح مقبول.

لا يوجد حل: إذا اكتملت الحلقة دون إيجاد أي زوج، فالجواب هو IMPOSSIBLE.

رغم أن x وa_i يصلان إلى 10⁹ فقط (وهذا يتّسع في int)، استخدمنا long long في الكود كعادة أمان عامة عند التعامل مع مجاميع أو فروق قد تقترب من حدود النوع — لتفادي أي مفاجآت لاحقًا إذا تغيّرت القيود.

هذا النمط — "خريطة تُبنى أثناء مرور واحد" — يظهر في الكثير من مسائل البرمجة التنافسية كلما احتجت للبحث عن قيمة مرتبطة برياضيًا بالعنصر الحالي (كالمتمّم هنا). تذكّره جيدًا، فهو أسرع بكثير من أي حل بحلقتين متداخلتين.
