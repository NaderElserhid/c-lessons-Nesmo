المسألة 6: Twins (التوأمان)

مسألة جشعة (Greedy) كلاسيكية: نريد أقل عدد من العملات بحيث يكون مجموعها أكبر من الباقي. الفكرة الذكية هي أخذ أكبر العملات أولًا — وهذا نفس أسلوب التفكير الذي رأيته في فصل الخوارزميات الجشعة.

Easy Codeforces 160A

نص المسألة

لديك مصفوفة تحتوي على n عدد صحيح تمثّل قيم عملات. حدّد أقل عدد من العناصر التي يجب اختيارها من المصفوفة بحيث يكون مجموع العناصر المختارة أكبر تمامًا (Strictly) من مجموع العناصر المتبقية.

القيود

  • 1 ≤ n ≤ 100

  • 1 ≤ a_i ≤ 100

الإدخال

السطر الأول: عدد صحيح n — عدد العملات.
السطر الثاني: n عددًا — قيم العملات.

المخرجات

عدد صحيح واحد — أقل عدد من العملات المطلوب أخذها.

أمثلة

Input:
2
3 3
Output:
2
Input:
3
2 1 2
Output:
2

مختبر تفاعلي: خذ أكبر العملات أولًا

شغّل المحاكاة على مثال أكبر يحتوي 8 عملات بقيم 5, 3, 8, 2, 6, 1, 4, 7: سنرتّب العملات تصاعديًا ثم نأخذها من الأكبر إلى الأصغر، ونراقب مجموعك مقابل مجموع أخيك حتى تتجاوزه:

1
2
3
4
5
6
7
8
مجموعك
0
مجموع أخيك
36
اضغط "شغّل المحاكاة" لبدء أخذ العملات الأكبر أولًا.

منهجية الحل: كيف نفكّر في هذه المسألة؟

  • افهم المسألة: نريد أقل عدد من العناصر بحيث يكون مجموعها أكبر تمامًا من مجموع الباقي.

  • جرّب أمثلة صغيرة يدويًا: جرّب 3 3 ثم 2 1 2 بنفسك.

  • فكّر بجشع (Greedy): لتقليل عدد العناصر، أيّ عناصر يجب أن نختارها أولًا؟

  • تحقّق من الفكرة: هل أخذ أكبر القيم أولًا يصل إلى الهدف بأقل عدد ممكن دائمًا؟

  • اكتب الكود وتحقّق: رتّب تصاعديًا، ثم امرر من النهاية إلى البداية وتوقّف عند تحقق الشرط.

  • افحص الحالات الحدّية: ماذا لو كان n = 1؟ وماذا لو تساوت كل القيم؟

الخطوة 1: لماذا نأخذ أكبر العملات أولًا؟

نريد الوصول لمجموع يتجاوز نصف total_sum باستخدام أقل عدد ممكن من العناصر. بما أن كل عنصر "يقفز" بمجموعنا بمقدار قيمته، فإنّ أخذ أكبر قيمة متاحة في كل خطوة يعطينا أكبر قفزة ممكنة لكل عنصر نستخدمه — وبالتالي نصل للهدف بأسرع ما يمكن (أي بأقل عدد عناصر).

لتسهيل ذلك، نرتّب المصفوفة تصاعديًا، ثم نمرّ عليها من النهاية (أكبر قيمة) إلى البداية (أصغر قيمة).

الخطوة 2: الحل الكامل

نحسب أولًا total_sum (مجموع كل العملات). ثم نرتّب المصفوفة تصاعديًا ونمرّ عليها عكسيًا (من الأكبر للأصغر)، محتفظين بـselected_sum (مجموع ما اخترناه) وcnt (عدد العناصر المختارة). في كل خطوة نتحقق: هل selected_sum > total_sum - selected_sum؟ إن تحقق ذلك، فقد وجدنا الإجابة.

twins.cpp
#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;

    int a[n];
    int total_sum = 0;

    for (int i = 0; i < n; i++) {
        cin >> a[i];
        total_sum += a[i];
    }

    sort(a, a + n);

    int selected_sum = 0;
    int cnt = 0;

    for (int i = n - 1; i >= 0; i--) {
        selected_sum += a[i];
        cnt++;

        if (selected_sum > total_sum - selected_sum) {
            cout << cnt << endl;
            break;
        }
    }
}
Input: 2 / 3 3 → Output: 2
Input: 3 / 2 1 2 → Output: 2

الخطوة 3: فحص الحالات الحدّية

عملة واحدة (n=1): نأخذها فورًا (مجموعك = قيمتها، مجموع أخيك = 0)، فالإجابة دائمًا 1.

كل القيم متساوية: مثال 1 1 1 1 — يجب أخذ 3 عملات من أصل 4 لتجاوز الباقي (3 > 1)، فأخذ نصف العناصر بالضبط لا يكفي أبدًا بسبب شرط "أكبر تمامًا" (Strictly Greater).

لماذا لا نحتاج long long؟ بما أنّ n ≤ 100 وa_i ≤ 100، فإنّ total_sum لا يتجاوز 10,000 — وهذا يتّسع بأمان تام داخل النوع int.

هذه المسألة مثال جيد على "الجشع المُثبَت بالمنطق": ليس كل حل جشع صحيحًا، لكن هنا يمكننا تبرير لماذا أخذ الأكبر أولًا يعطي دائمًا أقل عدد من العناصر. لاحظ أيضًا كيف استخدمنا الترتيب (Sorting) لتسهيل تطبيق هذه الفكرة الجشعة بكفاءة.
