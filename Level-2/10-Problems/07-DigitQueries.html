المسألة 7: Digit Queries (استعلامات الخانات)

سلسلة لا نهائية من كل الأعداد الصحيحة الموجبة ملصوقة ببعضها، وعليك إيجاد الخانة عند موضع قد يصل إلى 10¹⁸ — دون بناء السلسلة نفسها بالطبع! الحل يعتمد على تجميع الأعداد حسب عدد خاناتها والقفز بين الكتل مباشرة.

Medium CSES 2431

نص المسألة

اعتبر السلسلة اللانهائية الناتجة عن لصق جميع الأعداد الصحيحة الموجبة بالترتيب:

1234567891011121314151617181920212223...

لدينا q استعلام. في كل استعلام، يُعطى لك موقع k (مرقّم بداية من 1) داخل هذه السلسلة اللانهائية. مهمتك هي طباعة الخانة (digit) الموجودة في الموقع k.

القيود

  • 1 ≤ q ≤ 1000

  • 1 ≤ k ≤ 10¹⁸

مثال

Input:
3
7
19
12
Output:
7
4
1

مختبر تفاعلي: تخطَّ الكتل حتى تصل إلى الخانة المطلوبة

شغّل المحاكاة لإيجاد الخانة عند الموضع k = 200: سنطرح أطوال الكتل (خانة واحدة، خانتان، ثلاث خانات...) واحدة تلو الأخرى حتى نصل إلى الكتلة الصحيحة، ثم نحدّد العدد والخانة بداخله بالضبط:

اضغط "شغّل المحاكاة" لإيجاد الخانة عند الموضع k = 200.

منهجية الحل: كيف نفكّر في هذه المسألة؟

  • افهم المسألة: نريد الخانة رقم k في سلسلة لا نهائية دون بناء السلسلة فعليًا.

  • جرّب أمثلة صغيرة يدويًا: احسب يدويًا الخانة عند k=7 وk=19 وk=12 وتحقّق من المثال.

  • ابحث عن نمط: جمّع الأعداد حسب عدد خاناتها (خانة واحدة، خانتان، ثلاث...) وستجد أن كل مجموعة تساهم بعدد ثابت من الخانات.

  • قسّم إلى حالات: استخدم هذا التقسيم للقفز مباشرة إلى الكتلة الصحيحة بدل المرور رقمًا رقمًا.

  • اكتب الكود وتحقّق: جرّبه على أمثلة المسألة الثلاثة.

  • افحص الحالات الحدّية: ماذا يحدث عند أكبر قيمة ممكنة لـ k؟ وهل قد يفيض أي متغيّر؟

الخطوة 1: لماذا لا يمكننا بناء السلسلة فعليًا؟

بما أن k قد يصل إلى 10¹⁸، فإن بناء السلسلة حتى هذا الموضع يحتاج مساحة وزمنًا هائلين — لا يمكن حتى تخزين بادئة بهذا الطول. نحتاج طريقة رياضية تحسب الخانة المطلوبة مباشرة دون المرور على كل رقم قبلها.

الخطوة 2: تجميع الأعداد حسب عدد الخانات

لاحظ أن الأعداد تنقسم بشكل طبيعي إلى كتل حسب عدد خاناتها:

عدد الخاناتالمدىعدد الأعدادإجمالي الخانات
11 – 999
210 – 9990180
3100 – 9999002700

بشكل عام، لكتلة الأعداد ذات d خانة: أول عدد فيها هو base = 10^(d-1)، ويوجد فيها 9 × base عددًا، فتساهم بإجمالي 9 × base × d خانة.

لأي موضع k: نبدأ بـ d=1 وbase=1، ونحسب طول الكتلة الحالية. إذا كان k أكبر من طول الكتلة، نطرحه وننتقل للكتلة التالية (d++, base *= 10). نتوقف عندما يقع k داخل الكتلة الحالية.

بعد إيجاد الكتلة الصحيحة، نرقّم داخلها بدءًا من الصفر: k0 = k - 1، فيكون index_of_number = k0 / d (أي عدد داخل الكتلة) وindex_in_number = k0 % d (أي خانة داخل هذا العدد)، والعدد الفعلي هو num = base + index_of_number.

الخطوة 3: الحل الكامل

digit_queries.cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int q;
    cin >> q;

    while (q--) {
        long long k;
        cin >> k;

        long long d = 1;       // current digit length
        long long base = 1;    // 10^(d-1)

        // Step 1: find the block (digit length d) that contains position k
        while (true) {
            long long count_numbers = 9 * base;
            long long block_len = count_numbers * d;

            if (k > block_len) {
                k -= block_len;
                d++;
                base *= 10;
            } else {
                break;
            }
        }

        // Step 2: find the exact number and digit within this d-digit block
        long long k0 = k - 1;
        long long index_of_number = k0 / d;
        long long index_in_number = k0 % d;

        long long num = base + index_of_number;

        string s = to_string(num);
        char answer_digit = s[index_in_number];

        cout << answer_digit << endl;
    }

    return 0;
}
Input: 3 / 7 19 12 → Output: 7, 4, 1

لكل استعلام، حلقة البحث عن الكتلة قصيرة جدًا: d لن يتجاوز 18 تقريبًا لأن k ≤ 10¹⁸. لذلك زمن كل استعلام قريب من ثابت، والتعقيد الكلي O(q log k).

الخطوة 4: حذر من تجاوز السعة

استخدم النوع long long لكل من k وbase وblock_len، لأن هذه القيم قد تصل إلى مليارات المليارات مع k حتى 10¹⁸.

ضمن هذه القيود، لن يتجاوز d القيمة 18 تقريبًا، لذا فإن حاصل ضرب 9 * base * d يبقى ضمن حدود النوع long long دون أي فيض.

جرّب دائمًا أكبر قيمة ممكنة (k = 10¹⁸) كحالة حدّية أساسية — الحل أعلاه يعطي الإجابة 3 عندها.

هذا النمط — تقسيم مسألة كبيرة إلى "كتل" ذات خصائص موحّدة، ثم القفز بينها بدل المرور عنصرًا عنصرًا — يظهر كثيرًا في مسائل تتعامل مع مدىً هائل من الأرقام. تذكّر هذه الفكرة كلما رأيت قيدًا ضخمًا مثل 10¹⁸.
