Sum of Three Values (مجموع ثلاث قيم)

تطوير طبيعي لمسألة "مجموع قيمتين": نثبّت عنصرين ونستخدم البحث الثنائي لإيجاد الثالث بسرعة، فنحوّل حلًا بزمن O(n³) إلى حل بزمن O(n² log n).

Medium CSES 1641

نص المسألة

يُعطى لك مصفوفة من n عدد صحيح، ومهمتك هي إيجاد ثلاث قيم في مواقع مختلفة i, j, k يكون مجموعها x.

القيود

  • 1 ≤ n ≤ 5000

  • 1 ≤ x, a_i ≤ 10⁹

الإدخال

السطر الأول: عددان صحيحان n وx — حجم المصفوفة والمجموع المطلوب.
السطر الثاني: n عددًا — قيم المصفوفة.

المخرجات

اطبع ثلاثة أعداد صحيحة: مواقع القيم المختارة (مرقّمة من 1). إذا كان هناك أكثر من ثلاثية صالحة، يمكنك طباعة أي منها. إذا لم توجد أي ثلاثية تحقق الشرط، فاطبع IMPOSSIBLE.

مثال

Input:
4 8
2 7 5 1
Output:
1 3 4

مختبر تفاعلي: ثبّت عنصرين وابحث ثنائيًا عن الثالث

شغّل المحاكاة على مصفوفة 9, 2, 6, 3, 8, 1 بحثًا عن مجموع x = 14. سنرتّب القيم أولًا مع الاحتفاظ بمواقعها الأصلية، ثم نثبّت كل زوج (i, j) ونبحث ثنائيًا عن المتمّم في الباقي:

منهجية الحل: كيف نفكّر في هذه المسألة؟

  • افهم المسألة: نريد ثلاثة مواقع مختلفة مجموع قيمها يساوي x بالضبط.

  • اربطها بمسألة أسهل: هذه تشبه "مجموع قيمتين" لكن بعنصر إضافي — كيف نبني عليها؟

  • فكّر في التعقيد: الحل الساذج بثلاث حلقات متداخلة يعمل بزمن O(n³) — بطيء جدًا هنا.

  • ثبّت واحدًا أو اثنين: إذا ثبّتنا عنصرين، يتبقى إيجاد عنصر واحد فقط بقيمة محددة — وهذا يمكن بالبحث الثنائي إن كانت المصفوفة مرتّبة.

  • اكتب الكود وتحقّق: رتّب مع الاحتفاظ بالمواقع الأصلية، ثم ثبّت زوجًا وابحث عن الثالث.

  • افحص الحالات الحدّية: هل قد يفيض مجموع ثلاث قيم كبيرة النوع int؟

الخطوة 1: لماذا لا نجرّب كل الثلاثيات؟

الحل العنيف بالكامل يفحص جميع الثلاثيات الممكنة بثلاث حلقات متداخلة، في زمن O(n³). لكن بما أن n قد يصل إلى 5000، فإن n³ يصبح 125 × 10⁹ عملية — أبطأ بكثير مما يمكن تنفيذه خلال ثانية واحدة.

الخطوة 2: ثبّت عنصرين وابحث ثنائيًا عن الثالث

الفرز مع الاحتفاظ بالمواقع الأصلية: نخزن كل عنصر مع موقعه الأصلي في زوج (value, index)، ثم نفرز حسب القيمة. بهذا يمكننا استخدام البحث الثنائي على القيم، مع القدرة على استرجاع المواقع الأصلية عند الطباعة.

تثبيت عنصرين والبحث عن الثالث: نكرّر على جميع الأزواج (i, j) بحيث i < j. لكل زوج، نحسب need = x - a[i] - a[j]، ونبحث ثنائيًا عن need في المجال [j+1, n-1] فقط. إن وجدناه عند موقع k، نطبع المواقع الأصلية الثلاثة.

بما أننا نبحث دائمًا فقط في مواقع أكبر من j، فإن المواقع الثلاثة i, j, k ستكون مختلفة تلقائيًا دون أي فحص إضافي.

التعقيد: الفرز O(n log n)، والحلقة المزدوجة O(n²) بحث ثنائي واحد لكل زوج O(log n) → الإجمالي O(n² log n)، وهو سريع بما يكفي لـ n ≤ 5000.

الخطوة 3: الحل الكامل

sum_of_three_values.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long x;
    cin >> n >> x;

    vector<pair<long long,int>> a(n);
    for (int i = 0; i < n; ++i) {
        long long v;
        cin >> v;
        a[i] = {v, i + 1}; // store value and original 1-based index
    }

    sort(a.begin(), a.end()); // sort by value

    // Fix two indices (i, j) and binary search for the third
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            long long need = x - a[i].first - a[j].first;

            int lo = j + 1, hi = n - 1;
            while (lo <= hi) {
                int mid = (lo + hi) / 2;
                if (a[mid].first == need) {
                    cout << a[i].second << " "
                         << a[j].second << " "
                         << a[mid].second << "\n";
                    return 0;
                } else if (a[mid].first < need) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
    }

    cout << "IMPOSSIBLE\n";
    return 0;
}
Input: 4 8 / 2 7 5 1 → Output: 4 1 3 (ثلاثية صحيحة أخرى: a[4]+a[1]+a[3] = 1+2+5 = 8)
Input: 6 14 / 9 2 6 3 8 1 → Output: 2 4 1

الخطوة 4: حذر من تجاوز السعة

استخدم long long للقيم ولـ x، لأن x وa_i قد يصلان إلى 10⁹، ومجموع ثلاث قيم قد يصل إلى 3 × 10⁹ — وهذا يتجاوز حدود النوع int (حوالي 2.1 × 10⁹).

تأكّد دائمًا من أن البحث الثنائي يكون في المجال [j+1, n-1] فقط (وليس [0, n-1]) لضمان أن المواقع الثلاثة مختلفة تلقائيًا.

إذا لم توجد أي ثلاثية صالحة، تأكّد أن البرنامج يطبع IMPOSSIBLE فقط بعد تجربة كل الأزواج (i, j) الممكنة دون استثناء.

لاحظ النمط المتكرر: "ثبّت عنصرًا أو أكثر، واستخدم بحثًا أسرع للباقي" هو أسلوب شائع جدًا لتحويل حلول بطيئة إلى حلول عملية. هنا استخدمناه لتحويل O(n³) إلى O(n² log n) بمجرد إضافة الفرز والبحث الثنائي.
