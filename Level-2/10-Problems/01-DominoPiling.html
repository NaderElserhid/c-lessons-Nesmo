المسألة 1: Domino Piling (تبليط الدومينو)

مسألة كلاسيكية سهلة من Codeforces تُطبّق مباشرة أسلوب "العمل على الحالات" الذي تعلّمناه: نقسّم المسألة حسب زوجية أبعاد المصفوفة، ونحلّ كل حالة على حدة قبل أن ندمجها في كود واحد بسيط وسريع.

Easy Codeforces 50A

نص المسألة

توجد مصفوفة ثنائية الأبعاد مكوّنة من N صف وM عمود. لديك عدد غير محدود من القطع (Dominoes) ذات الحجم 2 × 1، وتريد وضع أكبر عدد ممكن من هذه القطع في المصفوفة بحيث:

  • كل قطعة تغطي خانتين كاملتين.

  • جميع القطع لا تتقاطع.

  • جميع القطع تكون داخل المصفوفة بشكل كامل.

مختبر تفاعلي: شاهد الحل يُبنى أمامك

قبل أن نشرح الحل، شاهد الحالات الثلاث بصريًا، كلٌّ في مصفوفة توضيحية — اضغط كل زر لمشاهدة القطع تُوضع خطوة بخطوة تمامًا كما يفعل الكود:

الحالة الأولى: N زوجي (مثال 4×3) — تغطية عمودية كاملة

اضغط "ابدأ التغطية" لمشاهدة تغطية مصفوفة N=4 (زوجي), M=3 بالكامل عموديًا.

الحالة الثانية: M زوجي (مثال 3×4) — تغطية أفقية كاملة

اضغط "ابدأ التغطية" لمشاهدة تغطية مصفوفة N=3, M=4 (زوجي) بالكامل أفقيًا.

الحالة الثالثة: كلاهما فردي (مثال 3×3) — طريقة مختلطة وخانة متبقية

اضغط "ابدأ التغطية" لمشاهدة كيف نضع القطع في مصفوفة 3×3 عندما يكون البعدان فرديين.

لاحظ كيف يطابق كل مختبر بالضبط ما يفعله الكود سطرًا بسطر: في الحالتين الأولى والثانية تُغطّى المصفوفة بالكامل، بينما في الحالة الثالثة تبقى خانة واحدة يستحيل تغطيتها. الآن لننتقل لفهم لماذا يحدث هذا رياضيًا.

منهجية الحل: كيف نفكّر في هذه المسألة؟

قبل النظر إلى الحل، لنتّبع نفس المنهجية التي نستخدمها في كل مسألة برمجة تنافسية:

  • افهم المسألة: نريد أكبر عدد من قطع 2×1 نضعها في مصفوفة N×M دون تقاطع أو خروج عن الحدود.

  • جرّب أمثلة صغيرة يدويًا: ماذا لو كانت المصفوفة 1×1؟ أو 2×2؟ أو 2×3؟

  • ابحث عن نمط: قارن النتائج وحاول ربطها بعدد الخانات الكلي N × M.

  • قسّم إلى حالات: هل النمط يتغيّر حسب زوجية N أو M؟

  • اكتب الكود وتحقّق: جرّب الكود على كل الأمثلة.

  • افحص الحالات الحدّية: ماذا يحدث عند N=1 وM=1؟

الخطوة 1: نجرّب أمثلة صغيرة

قبل التفكير في صيغة عامة، لنحسب الإجابة يدويًا لبعض المصفوفات الصغيرة:

نلاحظ نمطًا: الإجابة قريبة جدًا من (N × M) / 2 — لكن ماذا لو كان N × M فرديًا (كما في حالة 1×1)؟ عندها لا يمكن أن يكون عدد القطع كسريًا، فنحتاج للتقريب لأسفل، وهنا تحديدًا يظهر السبب في تقسيم المسألة إلى حالات.

الخطوة 2: التحليل بأسلوب العمل على الحالات

في هذه المسألة لدينا 3 حالات، ونحلّلها بأسلوب "العمل على الحالات" الذي تعلّمناه سابقًا:

  • إذا كان N عددًا زوجيًا (N % 2 == 0): يمكننا تغطية المصفوفة كاملة بوضع القطع بشكل عمودي. عدد القطع المستخدمة سيكون (N × M) / 2، لأنّ المصفوفة تحتوي على N × M خانة، وكل قطعة تغطي خانتين.

  • إذا كان M عددًا زوجيًا (M % 2 == 0): يمكننا تغطية المصفوفة كاملة بوضع القطع بشكل أفقي. عدد القطع سيكون أيضًا (N × M) / 2.

  • إذا كان كلّ من N وM عددين فرديين: أولًا نضع القطع بشكل عمودي ابتداءً من الصف الأول، مما يترك صفًا كاملًا غير مغطى (لأنّ N فردي). في ذلك الصف نضع القطع بشكل أفقي، فتتبقى خانة واحدة فقط غير مغطاة (لأنّ M فردي). بالتالي عدد القطع المستخدمة سيكون (N × M - 1) / 2.

domino_piling.cpp
#include <iostream>
using namespace std;

int main() {
    int N, M;
    cin >> N >> M;

    if (N % 2 == 0) {
        cout << (N * M) / 2 << endl;
    }
    else if (M % 2 == 0) {
        cout << (N * M) / 2 << endl;
    }
    else {
        cout << (N * M - 1) / 2 << endl;
    }
}

لاحظ أنّ الصيغتين الأولى والثانية متطابقتان ((N × M) / 2) — يمكن دمج الحالتين الأوليين فعليًا في حالة واحدة "إذا كان N × M زوجيًا"، لكن تحليلها بشكل منفصل (عمودي أو أفقي) يساعد على فهم لماذا تعمل الصيغة، لا فقط حفظها.

الخطوة 3: فحص الحالات الحدّية

ماذا يحدث عند أصغر قيمة ممكنة؟ إذا كان N = 1 وM = 1، فإنّ الكود يدخل الحالة الثالثة (كلاهما فردي)، فيحسب (1 × 1 - 1) / 2 = 0 — وهذا صحيح تمامًا، فخانة واحدة لا تكفي لأي قطعة. هذا يؤكّد أنّ حلّنا يتعامل بشكل صحيح مع أصغر الحالات الممكنة دون الحاجة لأي معالجة خاصة إضافية.
