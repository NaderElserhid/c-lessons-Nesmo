البحث الثنائي (Binary Search)

في الفصل الماضي تعلّمت كيف ترتّب البيانات باستخدام دالة sort بتعقيد O(n log n). الآن سنستثمر تلك البيانات المرتّبة لصالحنا: بدلًا من فحص كل عنصر واحدًا تلو الآخر، سنتعلّم كيف "نخمّن بذكاء" لنصل إلى الإجابة في خطوات قليلة جدًا — حتى لو كانت البيانات مليون عنصر. هذه هي فكرة البحث الثنائي، وهي واحدة من أهم الأدوات في البرمجة التنافسية.

البحث الخطي (Linear Search)

تخيّل أنّ لديك قائمة من الأرقام وتريد التحقق مما إذا كان رقم معيّن موجودًا فيها. أبسط طريقة هي المرور عبر القائمة عنصرًا عنصرًا:

linear_search.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {4, 8, 15, 16, 23, 42};
    int target = 15;

    for (int i = 0; i < arr.size(); i++) {
        if (arr[i] == target) {
            cout << "Found at index " << i;
            return 0;
        }
    }
    cout << "Not found";
}
Found at index 2

يُسمّى هذا البحث الخطي لأنّك تنتقل خطيًا عبر القائمة، عنصرًا بعد عنصر. يعمل دائمًا وبشكل صحيح، لكنه قد يكون بطيئًا إذا كانت القائمة طويلة — قد تحتاج للتحقق من كل عنصر.

إذا كان هناك مليون رقم، فهذا يعني حتى مليون عملية تحقق في أسوأ الحالات. تذكّر من الفصل الثالث أنّ هذا يعني تعقيدًا زمنيًا O(n).

تخيّل الآن أنّك تبحث عن اسم في دليل هاتف مطبوع. لن تبدأ من الصفحة الأولى وتقرأ اسمًا اسمًا. بل ستفتح الدليل في المنتصف، وتتحقق إن كنت في الجزء الصحيح أبجديًا، ثم تتجاهل نصف الصفحات دفعة واحدة. هذا بالضبط هو البحث الثنائي.

فكرة البحث الثنائي

البحث الثنائي يشبه لعبة "خمّن الرقم". في كل مرة تختار القيمة الوسطى وتسأل:

  • هل هذه القيمة صغيرة جدًا؟

  • هل هي كبيرة جدًا؟

  • أم هي صحيحة بالضبط؟

بناءً على الإجابة، تُقطع مساحة البحث إلى النصف في كل مرة. هذا يجعل البحث أسرع بكثير من البحث الخطي — لكنه يعمل فقط إذا كانت البيانات مرتّبة مسبقًا (ولهذا درسنا الترتيب في الفصل الماضي أولًا!).

البحث الثنائي الكلاسيكي

مثال: لدينا مصفوفة مرتّبة [1, 3, 5, 6, 7, 9, 11]. ابحث عن الرقم 7 واطبع موقعه إن وُجد.

الحل خطوة بخطوة

نبدأ بالنطاق الكامل، ثم نضيّق البحث تدريجيًا.

أولًا، نجد العنصر في المنتصف، وهو 6. نسأل: هل 7 أصغر أم أكبر من 6؟ هو أكبر، وبما أنّ المصفوفة مرتّبة، فهذا يعني أنّ 7 سيكون بعد 6. يمكننا تجاهل النصف الأول بالكامل.

المصفوفة المتبقية منطقيًا هي [7, 9, 11]. العنصر في المنتصف هو 9. الرقم 7 أصغر من 9، أي أنه يقع قبله. نتجاهل 9 وكل ما بعده.

أخيرًا، يتبقى [7] فقط. العنصر الأوسط هو 7 بالضبط — وهذا ما نبحث عنه!

قمنا بثلاث مقارنات فقط: قارنّا 6 مع 7، ثم 9 مع 7، ثم 7 مع 7.

binary_search.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {1, 3, 5, 6, 7, 9, 11};
    int target = 7;
    int left = 0, right = arr.size() - 1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] == target) {
            cout << "Found at index " << mid;
            return 0;
        } else if (arr[mid] < target)
            left = mid + 1;
        else
            right = mid - 1;
    }

    cout << "Not found";
}
Found at index 4

التعقيد الزمني

كل خطوة تقطع النطاق إلى النصف. إذا كان هناك n عنصر، فإنّ البحث الثنائي يحتاج تقريبًا log₂(n) خطوة فقط — أي تعقيد O(log n). حتى لو كان هناك مليون رقم، فهذا يعني حوالي 20 عملية تحقق فقط بدلًا من مليون عملية في البحث الخطي!

نشاط: مراجعة سريعة للبحث الثنائي

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

البحث الثنائي يعمل بشكل صحيح على أي مصفوفة، سواء كانت مرتّبة أم لا.

في كل خطوة، يقارن البحث الثنائي الهدف مع العنصر في منتصف النطاق الحالي.

تعقيد البحث الثنائي هو O(log n)، بينما تعقيد البحث الخطي هو O(n).

إيجاد أول عنصر أكبر من أو يساوي X

البحث الثنائي يمكنه فعل أكثر من مجرد إيجاد رقم محدد — يمكن استخدامه أيضًا لإيجاد مواضع أو حدود (boundaries) في مصفوفة مرتّبة.

مثال: لديك المصفوفة [2, 4, 6, 8, 10]. اعثر على أول عنصر أكبر من أو يساوي 7.

first_geq.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {2, 4, 6, 8, 10};
    int x = 7;

    int left = 0, right = arr.size() - 1;
    int ans = -1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] >= x) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    if (ans == -1) cout << "No element found";
    else cout << "First element >= " << x << " is at index " << ans;
}
First element >= 7 is at index 3

أي أنّ arr[3] = 8 هو أول عنصر أكبر من أو يساوي 7. لاحظ الفرق عن البحث الكلاسيكي: بدلًا من التوقف فور العثور على قيمة صالحة، نحفظها في ans ثم نستمر بالبحث يسارًا (right = mid - 1) علّنا نجد مرشحًا أفضل (فهرسًا أصغر).

الخوارزمية العامة

  • ابدأ بمؤشرين left وright.

  • احسب منتصف النطاق mid.

  • إذا كانت القيمة الوسطى هي الإجابة (أو مرشحًا لها)، سجّلها.

  • إذا كانت صغيرة جدًا، حرّك left إلى mid + 1.

  • إذا كانت كبيرة جدًا (أو مرشحًا يمكن تحسينه)، حرّك right إلى mid - 1.

  • كرّر حتى يصبح left > right.

نشاط: مراجعة سريعة لإيجاد المواضع والحدود

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

في مسألة "أول عنصر ≥ X"، عندما يكون arr[mid] ≥ X، نحفظ mid كمرشح ونستمر بالبحث في النصف الأيسر (يسارًا) بحثًا عن فهرس أصغر.

البحث الثنائي يمكن استخدامه فقط لإيجاد قيمة مطابقة تمامًا، ولا يمكن استخدامه لإيجاد مواضع أو حدود.

البحث الخطي مقابل البحث الثنائي

لنقارن عدد العمليات التي يحتاجها كل بحث للوصول إلى الإجابة، مع زيادة حجم المصفوفة n:

nالبحث الخطي O(n)البحث الثنائي O(log n)
10≤ 10≤ 4
1,000≤ 1,000≤ 10
1,000,000≤ 1,000,000≤ 20

مع مليون عنصر، البحث الثنائي يحتاج حوالي 20 عملية تحقق فقط مقابل مليون عملية للبحث الخطي — وهذا فرق هائل بفضل قطع النطاق إلى النصف في كل خطوة، لكنه يتطلّب دائمًا أن تكون البيانات مرتّبة أولًا (ولهذا درسنا الترتيب قبل هذا الفصل مباشرة).

تمارين منزلية

1) تتبّع البحث الثنائي

لديك المصفوفة المرتّبة [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91] (11 عنصرًا، الفهارس من 0 إلى 10). طبّق البحث الثنائي الكلاسيكي بحثًا عن الهدف 72. حدّد الفهرس النهائي وعدد المقارنات.

المقارنة الأولى: left=0, right=10 → mid=5 → arr[5]=23. بما أنّ 23 < 72، نتحرك يمينًا: left = 6.

المقارنة الثانية: left=6, right=10 → mid=8 → arr[8]=56. بما أنّ 56 < 72، نتحرك يمينًا: left = 9.

المقارنة الثالثة: left=9, right=10 → mid=9 → arr[9]=72. تطابق! توقفنا.

Found at index 9 after 3 comparisons

2) أول عنصر أكبر تمامًا من X

عدّل خوارزمية "أول عنصر ≥ X" لتصبح "أول عنصر أكبر تمامًا (>) من X". طبّقها على المصفوفة [2, 4, 6, 8, 10] بحثًا عن أول عنصر أكبر من 6.

hw2.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {2, 4, 6, 8, 10};
    int x = 6;

    int left = 0, right = arr.size() - 1;
    int ans = -1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] > x) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    if (ans == -1) cout << "No element found";
    else cout << "First element > " << x << " is at index " << ans;
}
First element > 6 is at index 3

الفرق الوحيد عن "أول عنصر ≥ X" هو استخدام > بدلًا من >= في الشرط.

3) عدّ العناصر الأصغر من X

لديك المصفوفة المرتّبة [1, 3, 5, 7, 9, 11]. استخدم البحث الثنائي لحساب عدد العناصر الأصغر من 6 (بدون المرور على كل العناصر).

hw3.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> arr = {1, 3, 5, 7, 9, 11};
    int x = 6;
    int n = arr.size();

    int left = 0, right = n - 1;
    int ans = n; // إذا لم نجد أي عنصر >= x، فكل العناصر أصغر من x

    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] >= x) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    cout << "Count of elements less than " << x << " = " << ans;
}
Count of elements less than 6 = 3

الفكرة الذكية: فهرس أول عنصر ≥ x يساوي بالضبط عدد العناصر الأصغر من x (لأنّ كل ما قبله في مصفوفة مرتّبة أصغر منه). العناصر 1, 3, 5 هي الأصغر من 6، وعددها 3 — بالضبط ما أعطتنا إياه الخوارزمية!

تحقق من فهمك

١. ما الشرط الأساسي لكي يعمل البحث الثنائي بشكل صحيح؟

يجب أن تكون المصفوفة قصيرة (أقل من 10 عناصر)
يجب أن تكون البيانات مرتّبة مسبقًا
يجب ألّا تحتوي المصفوفة على أرقام سالبة

٢. ما تعقيد البحث الخطي الزمني؟

O(log n)
O(n)
O(n²)

٣. ما تعقيد البحث الثنائي الزمني؟

O(n)
O(log n)
O(n log n)

٤. في البحث الثنائي، إذا كان arr[mid] < target، ماذا نفعل؟

نحرّك right إلى mid - 1
نحرّك left إلى mid + 1
نتوقف فورًا لأنّ العنصر غير موجود

٥. كم مقارنة تقريبًا يحتاجها البحث الثنائي للبحث بين مليون عنصر؟

حوالي 1,000,000
حوالي 1,000
حوالي 20

٦. في مسألة "أول عنصر ≥ X"، ماذا نفعل عندما نجد arr[mid] ≥ X؟

نحفظه كمرشح (ans = mid) ثم نبحث يسارًا (right = mid - 1) عن مرشح أفضل
نتوقف فورًا لأنه بالضرورة الإجابة النهائية
نتجاهله ونبحث يمينًا فقط

٧. لماذا لا يمكن تطبيق البحث الثنائي مباشرة على مصفوفة غير مرتّبة؟

لأنّ تجاهل نصف المصفوفة يعتمد على معرفة أنّ كل ما بعد mid أكبر (أو أصغر) منه، وهذا لا يصحّ إلا في بيانات مرتّبة
لأنّ المصفوفات غير المرتّبة لا تدعم عملية القسمة
فعليًا يمكن تطبيقه مباشرة بنفس الكفاءة دون أي مشكلة

٨. متى تتوقف حلقة البحث الثنائي (while) في الكود الكلاسيكي؟

بعد 10 تكرارات دائمًا
عندما يصبح left > right
عندما يصبح mid = 0

٩. كيف نحسب فهرس أول عنصر يساوي أو يتجاوز قيمة معيّنة بمعرفة نتيجة "أول عنصر ≥ X"؟

لا علاقة بين الاثنين
هذا الفهرس نفسه يساوي عدد العناصر الأصغر من X في مصفوفة مرتّبة
يجب دائمًا طرح واحد من الفهرس

١٠. أيّ من التالي وصف صحيح للعلاقة بين الترتيب والبحث الثنائي؟

الترتيب خطوة تمهيدية ضرورية غالبًا قبل استخدام البحث الثنائي بفعالية
البحث الثنائي يرتّب المصفوفة تلقائيًا أثناء عمله
لا توجد أي علاقة بين الترتيب والبحث الثنائي
