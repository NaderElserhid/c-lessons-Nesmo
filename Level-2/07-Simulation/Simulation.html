المحاكاة (Simulation)

حتى الآن تعلّمت أدوات قوية: المجموعات، الخرائط، الترتيب، البحث الثنائي، والحسابيات المعيارية. لكن ليست كل مسألة تحتاج خوارزمية ذكية — أحيانًا كل ما تحتاجه هو أن "تحاكي" ما يحدث فعليًا، خطوة بخطوة، تمامًا كما لو كنت تشغّل برنامجًا صغيرًا داخل برنامجك. في هذا الفصل ستتعلّم كيف تحوّل وصف مسألة طويلًا إلى حلقة بسيطة تتبع القواعد حرفيًا.

ما هي المحاكاة؟

مشاكل المحاكاة (Simulation) تتعلّق بتقليد عمليات حقيقية أو منطقية خطوة بخطوة. يُطلب منك أن "تحاكي" ما يحدث — تمامًا مثل تشغيل برنامج صغير داخل برنامجك!

في البرمجة التنافسية، المحاكاة تعني اتباع قواعد المسألة بعناية وتنفيذ كل خطوة كما هي موصوفة تمامًا. لست بحاجة لخوارزمية معقّدة — فقط قم بتكرار ما يحدث عادةً باستخدام الحلقات.

مثال: تخمين كولاتز (Collatz Conjecture)

اعتبر العملية التالية: ابدأ بعدد معيّن n. في كل خطوة:

  • إذا كان n زوجيًا، استبدله بـ n / 2.

  • إذا كان n فرديًا، استبدله بـ 3n + 1.

اطبع عدد الخطوات التي استغرقتها العملية قبل أن يصبح n مساويًا لـ 1.

قد تتساءل: هل هذه العملية تصل دائمًا إلى 1؟ في الحقيقة، لا أحد يملك إجابة قاطعة على ذلك — إنها مسألة رياضية مشهورة وغير محلولة! لكن يمكننا ببساطة محاكاتها ورؤية ما يحدث لأي عدد نجرّبه.

collatz.cpp
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    int steps = 0;
    while (n != 1) {
        if (n % 2 == 0) {
            n /= 2;
        } else {
            n = 3*n + 1;
        }
        steps++;
    }
    cout << steps << "\n";
    return 0;
}

متى نستخدم المحاكاة؟

المحاكاة ممتازة عندما:

  • تعطيك المسألة قائمة خطوات أو أفعال مفصّلة.

  • لا يوجد اختصار رياضي واضح.

  • يمكنك فقط اتباع العملية مباشرة.

أمثلة شائعة:

  • الألعاب (مثل tic-tac-toe، snake، وغيرها).

  • التحرّك على شبكة (روبوتات، سيارات، أشخاص يمشون).

  • التحويلات النصية (تحرير نص، تدوير).

  • إدارة العناصر (طوابير، مكدّسات، أو مهام مع الوقت).

نمط المحاكاة العام

معظم مسائل المحاكاة تتبع نفس النمط:

pattern.txt

    read next action

أنت أساسًا تقوم "بتشغيل" القواعد خطوة بخطوة.

نشاط: مراجعة سريعة لمفهوم المحاكاة

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

مسائل المحاكاة تحتاج عادة لابتكار خوارزمية رياضية معقّدة جدًا.

تخمين كولاتز مُثبَت رياضيًا بأنّ كل عدد يصل في النهاية إلى 1.

عندما n = 3، تستغرق عملية كولاتز 7 خطوات للوصول إلى 1.

نمط المحاكاة العام يعتمد على تهيئة المتغيرات، ثم تكرار تحديثها حسب القواعد حتى انتهاء الأفعال.

مثال: روبوت على شبكة

روبوت يبدأ عند (0, 0). يستقبل سلسلة من الحركات مكوّنة من الحروف N, S, E, W. اطبع إحداثياته النهائية.

robot.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string moves;
    cin >> moves;
    int x = 0, y = 0;
    for (char c : moves) {
        if (c == 'N') y++;
        else if (c == 'S') y--;
        else if (c == 'E') x++;
        else if (c == 'W') x--;
    }
    cout << x << " " << y;
}

إذا كان الإدخال NNEEWS، ينتهي الروبوت عند (1, 1).

مثال: محاكاة لعبة

يوجد عدّة أبطال في اللعبة، ولكلٍّ منهم قوة خاصة به. في كل ثانية، يقوم أضعف بطل A بإلحاق ضرر بأقوى بطل B، ويُقلّل من قوة B بمقدار قوة A. تنتهي اللعبة عندما تصل قوة أحد الأبطال إلى 0. اطبع عدد الثواني التي استمرّت فيها اللعبة.

game_simulation.cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n; cin >> n;
    vector<int> strength(n);
    for (int &x : strength) cin >> x;

    int seconds = 0;
    while (true) {
        sort(strength.begin(), strength.end());
        if (strength[0] == 0) break;
        strength[n-1] -= strength[0];
        seconds++;
    }
    cout << seconds;
}

ملحوظة: أحيانًا توجد طرق لتجاوز بعض خطوات المحاكاة وجعلها أسرع بكثير. هل يمكنك التفكير في طريقة كهذه في هذا المثال؟ (تلميح: جرّب حالة وجود بطلين فقط، وفكّر في فصل الحسابيات المعيارية!) سنكتشف الإجابة في التمارين المنزلية.

نشاط: مراجعة سريعة لأمثلة الروبوت واللعبة

حدّد إن كانت كل عبارة صحيحة أم خاطئة.

في مثال الروبوت، الحرف 'N' يعني الحركة جنوبًا (تقليل y).

إذا كان الإدخال NNEEWS، ينتهي الروبوت عند الإحداثيات (1, 1).

في محاكاة اللعبة، أضعف بطل هو من تنقص قوته في كل ثانية.

أحيانًا يمكن إيجاد اختصار رياضي يجعل المحاكاة أسرع بكثير من تنفيذ كل خطوة على حدة.

نصائح لمشاكل المحاكاة

  • اتبع القواعد حرفيًا. لا تحاول التفكير الزائد — فقط نفّذ ما تقوله المسألة.

  • استخدم الحلقات والشرطيات للتعامل مع الحالات المختلفة.

  • اطبع الخطوات الوسيطة أثناء التصحيح لتتأكد أن منطقك مطابق للوصف.

  • كن حذرًا مع الحدود (مثل الخروج من الشبكة أو استخدام فهارس خاطئة).

  • استخدم حالات صغيرة لاختبار الكود يدويًا.

  • حاكِ البرنامج بالقلم والورق لفهم ما يحدث فعلًا قبل برمجته خطوة بخطوة.

نصيحة أداء

أحيانًا، قد تكون المحاكاة بطيئة جدًا إذا كانت العملية تستغرق مليارات الخطوات. في هذه الحالات، تحتاج لإيجاد أنماط أو اختصارات:

  • إذا كانت العملية تتكرر بعد عدد معيّن من الخطوات، استخدم الرياضيات لتجاوز الدورات (مثل الحسابيات المعيارية).

  • إذا لم يعد الناتج يتغيّر بعد فترة، توقّف مبكرًا.

المزايا والعيوب

المزايا: مباشرة جدًا — لا حاجة لخوارزميات معقّدة. سهلة التنفيذ والفهم. تعمل مع أي عملية تعتمد على قواعد تقريبًا.

العيوب: قد تكون بطيئة للمدخلات الكبيرة. سهل ارتكاب أخطاء صغيرة عند اتباع العديد من الخطوات. التصحيح قد يستغرق وقتًا إذا لم تُطبَع النتائج الوسيطة.

تمارين منزلية

1) اختصار محاكاة اللعبة (لبطلين فقط)

عندما يكون هناك بطلان فقط بقوّتين a وb، فإنّ العملية "الأضعف يضرب الأقوى بمقدار قوته" هي بالضبط نفس عملية خوارزمية إقليدس (Euclidean Algorithm) بالطرح المتكرر لإيجاد القاسم المشترك الأكبر! بدلًا من طرح واحد تلو الآخر (بطيء)، استخدم القسمة الصحيحة و% لتسريع العملية.

hw1_fast_game.cpp
#include <iostream>
using namespace std;

long long fastSeconds(long long a, long long b) {
    long long count = 0;
    while (a > 0 && b > 0) {
        if (a < b) {
            count += b / a;
            b %= a;
        } else {
            count += a / b;
            a %= b;
        }
    }
    return count;
}

int main() {
    cout << fastSeconds(4, 10) << endl;
}
4

بدلًا من طرح a من b مرة واحدة في كل ثانية (وهو بطيء إذا كان الفرق كبيرًا)، نستخدم b / a لمعرفة كم مرة سيحدث ذلك دفعة واحدة، ثم b % a للانتقال مباشرة إلى النتيجة النهائية لتلك المرحلة. تم التحقق من تطابق هذه الطريقة مع المحاكاة الفعلية (خطوة بخطوة) على 2000 حالة عشوائية مختلفة.

2) روبوت بحدود شبكة

عدّل محاكاة الروبوت بحيث تكون الشبكة محدودة بين (0, 0) و(5, 5). أي حركة تخرج الروبوت عن هذا النطاق يجب تجاهلها (يبقى الروبوت في مكانه).

hw2_bounded_robot.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string moves;
    cin >> moves;
    int x = 0, y = 0;
    int minB = 0, maxB = 5;

    for (char c : moves) {
        int nx = x, ny = y;
        if (c == 'N') ny++;
        else if (c == 'S') ny--;
        else if (c == 'E') nx++;
        else if (c == 'W') nx--;

        if (nx >= minB && nx <= maxB && ny >= minB && ny <= maxB) {
            x = nx; y = ny;
        } // وإلا، نتجاهل الحركة والروبوت يبقى في مكانه
    }
    cout << x << " " << y;
}

مثال: الإدخال SSSSSSWWWWWW (كله حركات جنوبًا وغربًا من نقطة البداية 0,0):

0 0

لأنّ الروبوت يبدأ عند الحدّ الأدنى بالفعل، فكل حركة S أو W ستُخرجه عن النطاق [0, 5] وتُتجاهل، فيبقى عند (0, 0).

3) محاكاة تدوير نص

لديك النص "ABCDE". حاكِ عملية تدوير النص لليسار خطوة واحدة، مكرّرة k = 2 مرة (كل خطوة: انقل أول حرف إلى نهاية النص).

hw3_rotate.cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string s = "ABCDE";
    int k = 2;
    for (int i = 0; i < k; i++) {
        char first = s[0];
        s = s.substr(1) + first;
    }
    cout << s << endl;
}
CDEAB

الخطوة الأولى: "ABCDE" → "BCDEA". الخطوة الثانية: "BCDEA" → "CDEAB". هذه محاكاة مباشرة تمامًا كما وصفنا: نفّذ كل خطوة كما هي.

تحقق من فهمك

١. ما التعريف الأدق لمسائل المحاكاة؟

اتّباع قواعد المسألة وتنفيذ كل خطوة كما هي موصوفة تمامًا
إيجاد صيغة رياضية مختصرة تتجاوز كل الخطوات
استخدام خوارزمية ترتيب معقّدة دائمًا

٢. كم خطوة يستغرقها تخمين كولاتز للوصول إلى 1 عندما n = 3؟

(0, 0)

٥. في محاكاة اللعبة، ماذا يحدث لقوة أقوى بطل في كل ثانية؟

تزداد بمقدار قوة أضعف بطل
تنقص بمقدار قوة أضعف بطل
تصبح صفرًا فورًا

٦. متى تكون المحاكاة الخيار الأنسب لحل مسألة؟

عندما تصف المسألة خطوات أو أفعالًا دقيقة بدون اختصار رياضي واضح
فقط عندما تكون المدخلات ضخمة جدًا (مليارات العناصر)
فقط في مسائل الرسوم البيانية (Graphs)

٧. ما نمط المحاكاة العام الأساسي؟

تهيئة المتغيرات، ثم حلقة تكرّر التحديث حسب القواعد حتى انتهاء الأفعال، ثم طباعة النتيجة
فرز المدخلات ثم تطبيق بحث ثنائي
حساب المعكوس المعياري أولًا دائمًا

٨. ما أكبر عيب محتمل لحل قائم على المحاكاة؟

لا يمكن كتابته بلغة C++
قد يكون بطيئًا جدًا إذا كانت العملية تستغرق عددًا هائلًا من الخطوات
لا يمكن استخدام الحلقات فيه

٩. ما النصيحة الأهم عند تصحيح أخطاء حل محاكاة؟

تجربة المدخلات الكبيرة أولًا مباشرة
طباعة النتائج الوسيطة للتأكد من مطابقة المنطق للوصف
حذف كل التعليقات من الكود

١٠. متى يمكننا "تسريع" حل محاكاة بطيء؟

عندما نكتشف نمطًا متكررًا أو اختصارًا رياضيًا يُغني عن تنفيذ كل خطوة بمفردها
هذا مستحيل دائمًا في مسائل المحاكاة
فقط بزيادة سرعة المعالج
