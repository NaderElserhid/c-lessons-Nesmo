التعريف والمفاهيم الأساسية

الـ Graph هو هيكل رياضي يُستخدم لتمثيل العلاقات بين عناصر منفصلة تُسمّى Vertices (أو Nodes). العلاقة الواحدة بين عنصرين تُسمّى Edge، وهي تعبّر عن ارتباط مباشر بين زوج من الـ Vertices.

رياضيًا يُكتب الـ Graph كـ G = (V, E) حيث V هي مجموعة الـ Vertices وE هي مجموعة الـ Edges.

🏙️ مثال تفاعلي: شبكة المدن والطرق

اضغط على أي مدينة لترى مدن مرتبطة بها مباشرة (الجيران). يمكنك إضافة مدن وحذفها.

اضغط على أي نقطة لترى معلوماتها • عدد المدن: 5 • عدد الطرق: 6
💡
مثال واقعي: تخيّل عدة مدن في دولة، بعض أزواج المدن بينهم طرق والبعض الآخر لا. إذا كنت تخطط للسفر من المدينة u إلى المدينة v، قد تحتاج تمرّ على مدينة أو أكثر كمدن وسيطة في الطريق. هذه بالضبط المسألة التي يحلّها الـ Graph!
🎯
لماذا نستخدم Graphs؟ تمثيل المسائل على شكل Graphs يسمح لنا بحلّها بكفاءة باستخدام خوارزميات جاهزة مثل: BFS لإيجاد أقصر مسار، DFS لاستكشاف الرسم البياني، Dijkstra للمسارات الموزونة، وغيرها.
2

أنواع الرسوم البيانية

🔀 Undirected Graph

الـ Edges ليس لها اتجاه محدد. إذا كانت هناك علاقة بين u وv، فالعلاقة متبادلة في الاتجاهين. يُشار إليه بمصطلحات مثل bidirectional أو undirected.

➡️ Directed Graph

الـ Edges لها اتجاه محدد. Edge من u إلى v تختلف عن Edge من v إلى u. يُشار إليه بمصطلحات مثل unidirectional أو directed.

⚖️ Weighted Graph

كل Edge لها قيمة (وزن) مرتبطة بها. مثلًا، قد تمثّل المسافة بين المدن أو وقت السفر. الصيغة تُكتب كـ edge(u,v,w) حيث w هو الوزن.

🔗 Weighted + Directed

الأكثر تعقيدًا — الـ Edges لها اتجاه ووزن معًا. شائع في مسائل أقصر مسار مثل Dijkstra أو Bellman-Ford. مثلًا: شبكة طيران بأوقات رحلات محددة الاتجاه.

📝
ملاحظة مهمة: في الصياغة edge(u, v, w) بدون ذكر اتجاه محدد، نفترض أن الـ Edge غير موجّهة (undirected). أما إذا ذُكر صراحةً أن الـ Graph موجّه (directed)، فيكون الـ Edge من u إلى v فقط.
3

صيغة المدخلات في المسابقات

الطريقة الأكثر شيوعًا لإعطاء الـ Graph في مدخلات المسألة هي:

أولًا نقرأ العددين N وM، حيث N يمثّل عدد الـ Vertices وعدد الـ Edges على الترتيب. ثم في كل واحد من الأسطر الـ M التالية يُعطى زوج أعداد صحيحة u v (وأحيانًا وزن w). هذا يعني أن هناك Edge بين الـ Vertices u وv. وإذا كان الـ Graph موجّهًا، فعادةً يكون من u إلى v إلا إذا ذُكر غير ذلك.

📥 مثال على مدخلات

المدخلات (Input)
5 6 1 2 1 3 2 4 3 4 4 5 2 5
تفسير المدخلات
N=5 vertices, M=6 edges Edge: 1 ↔ 2 Edge: 1 ↔ 3 Edge: 2 ↔ 4 Edge: 3 ↔ 4 Edge: 4 ↔ 5 Edge: 2 ↔ 5
💡
نصيحة: من أفضل الممارسات أن تجعل كل الحاويات (containers) المتعلقة بالـ Graph معرّفة بشكل global. أغلب خوارزميات الرسوم البيانية يُفضّل تنفيذها باستخدام دوال (functions)، ويكون الوصول للـ Graph أسهل بكثير إذا كانت المتغيرات global. مهم جدًا تعرف القيود على متغيرات مثل N وM لضبط أحجام الحاويات وتجنّب الوصول خارج الحدود (Out of Bounds).
⚠️
تحذير: نفترض في هذا الشرح أن الـ Graph لا يحتوي على Multiple Edges، أي لا يوجد زوج من الـ Vertices مرتبطين مباشرةً بأكثر من Edge واحدة.
4

الاستعلامات الأساسية للمقارنة

قبل أن نختار طريقة التخزين، يجب أن نفهم الاستعلامات التي سنحتاج تنفيذها، لأن كل طريقة لها نقاط قوة وضعف:

📦 التعقيد المكاني

كم مقدار الذاكرة التي تحتاجها هذه الطريقة بالنسبة لـ N وM؟

🔍 هل Edge موجودة؟

ما زمن التحقق من وجود Edge بين vertex رقم u وvertex رقم v؟

🔁 المرور على الجيران

ما زمن المرور على كل الـ Vertices المجاورة لـ v المعيّن؟

5

طرق التخزين

أبسط طريقة لتخزين الـ Edges. بما أن الـ Edges تُعطى على شكل قائمة أزواج، نخزّنها مباشرةً في array من أزواج. كل عنصر في الـ Array هو زوج (u, v) يمثّل Edge بين vertex رقم u وvertex رقم v.

هذه الطريقة مناسبة عندما نحتاج فقط المرور على كل الـ Edges، مثل خوارزمية Kruskal لإيجاد Minimum Spanning Tree.

C++
const int maxN = 100'000; const int maxM = 200'000; pair<int,int> E[maxM]; // array الـ Edges int main() { int n, m; cin >> n >> m; for (int i = 0; i < m; i++) { int u, v; cin >> u >> v; E[i] = {u, v}; // نخزّن كل Edge كزوج } }
📝
للـ Weighted Graphs: نعرّف struct يحتوي القيم الثلاث (u, v, w)، أو نستخدم std::tuple أو std::array<int,3>. يُفضّل تجنّب الـ Nested Pairs لأنها تجعل الكود أقل وضوحًا.
الاستعلام التعقيد
التعقيد المكاني (Space)O(M)
التحقق من وجود EdgeO(M)
المرور على جيران VertexO(M)

الطريقة الأكثر شيوعًا في المسابقات! ننشئ N قوائم، كل واحدة عبارة عن vector، بحيث أن القائمة رقم i تخزن كل الجيران (Neighbors) للـ Vertex رقم i.

هذه الطريقة هي الأمثل لمعظم خوارزميات الرسوم البيانية مثل BFS وDFS والتي تحتاج المرور على جيران كل Vertex.

C++
const int maxN = 100'000; const int maxM = 200'000; // +1 لأن الـ Vertices غالبًا تبدأ من 1 vector<int> adj[maxN + 1]; int main() { int n, m; cin >> n >> m; for (int i = 0; i < m; i++) { int u, v; cin >> u >> v; adj[u].push_back(v); // أضف v لجيران u adj[v].push_back(u); // إذا undirected أضف u لجيران v } } // للـ Weighted Graphs نستخدم pair // vector<pair<int,int>> adj[maxN + 1]; // adj[u].push_back({v, w}); // v الجار ووزنه w

🔍 عرض تفاعلي لـ Adjacency List

اضغط "بناء الـ Adjacency List" لرؤية النتيجة...
⚡
نصيحة التعقيد: رغم أن المرور على جيران Vertex واحد يبدو O(degree)، إلا أنه إذا جمعنا على كل الـ Vertices، فالمجموع الكلي يساوي O(N + M). هذا يجعل هذه الطريقة فعّالة جدًا!
🔧
تحدٍّ للتفكير: هل تقدر تعدّل هذا الـ Container بحيث تسرّع عملية "التحقق من وجود Edge" بدون أن تؤثر على باقي الاستعلامات؟ تلميح: فكّر في استخدام unordered_set بدل vector.
الاستعلامالتعقيد
التعقيد المكاني (Space)O(N + M)
التحقق من وجود EdgeO(degree(v))
المرور على جيران VertexO(degree(v))

هذه الطريقة تنشئ مصفوفة بحجم N × N من القيم المنطقية (Booleans)، نسمّيها G، بحيث أن G[u][v] = true إذا كان هناك Edge مباشرة بين u وv، وfalse في غير ذلك.

تتميّز بسرعة التحقق من وجود Edge، لكنها تستهلك ذاكرة كبيرة، لذا تُستخدم فقط عندما يكون N صغيرًا.

C++
const int maxN = 1'000; // صغير بسبب O(N²) للذاكرة const int maxM = 200'000; // +1 لأن الـ Vertices غالبًا تبدأ من 1 bool G[maxN + 1][maxN + 1]; int main() { int n, m; cin >> n >> m; for (int i = 0; i < m; i++) { int u, v; cin >> u >> v; G[u][v] = true; G[v][u] = true; // إذا undirected } } // للـ Weighted Graphs: // int G[maxN+1][maxN+1]; // 0 تعني لا توجد Edge // G[u][v] = w; // وزن الـ Edge
